## 建议的最小演进方向（方案，未实现）

建议继续使用现有 SQL/FTS5/Chroma 和题库权限，优先调整信息保留与任务边界。DeepTutor 的多模态材料保留可以借鉴，是否需要知识图谱应由跨概念关联检索效果决定；当前没有证据证明换图数据库是“每章 50 道”的前提。

1. **先形成可用的教材正文索引。** 将原件、OCR 正文、结构化块和摘要建成显式关联的产物，正文可独立 ready，摘要作为可重试派生任务。对现有 OCR done 教材复用缓存；不得通过未授权运行直接发起新的付费模型调用。实现时需设计状态和迁移，不在研究中直接改行为。
2. **保留数学出题所需结构。** 稳定保存 document_id、chapter_id、section_id、page_start/end、block_type；区分定义/定理/证明/例题/习题/解答/图片。公式、题干及解答保持关联；摘要索引用于找章、找知识点，正文与原题索引用于命题和变式。
3. **增加章节蓝图和持久批次。** 一个章节一个父任务，明确小节覆盖、题型、难度和目标 50；每批 5–10 道作为可配置起点，保存已验收题、来源、失败原因和剩余题数，跨批去重及补缺。题量达到但审核未通过时不能记完成。
4. **统一范围与质量契约。** 先修复对话 scope 传递；章节过滤贯穿生成、修补、重出；多教材使用明确文档集合与章节映射。评审不可用或 veto 单独进入待人工复核，不能通过凑数量当作已合格。
5. **按数学题型验证。** 对适用计算题加入符号/数值检查并核验定义域、参数与唯一性；证明题、图形题另设人工抽审和图文证据。模型独立解题可以保留，但不替代验证状态。

建议验收：至少两本不同数学教材，覆盖跨章同名知识点、一章较长/含图公式、一个完整 50 题章节；检查每题文档/章节/页码与原题关联，验证覆盖配额、重复、答案与定义域。人为中断后只补未完成批次；摘要服务失败不能清掉已发布正文。上述验收是后续实施要求，本次没有执行真实模型生成或宣称准确率。

## 3. 对原始记录逐项核查

### 问题 1：共享检索片段与 agentic 检索

结论：成立；但缺口不只有检索策略。

- [question_gen.py:432](../../backend/app/services/rag/question_gen.py#L432)按文档名、范围和题型检索一次；[规划:449](../../backend/app/services/rag/question_gen.py#L449)与该题型单题批次共用 hits，规划考点 hint 没有进入独立检索。
- [规划:386](../../backend/app/services/rag/question_gen.py#L386)只截取参考内容前 1500 字符，输出点列表不去重，失败后继续无规划命题。单题使用完整 hits，不是只读相同 1500 字符。
- 默认检索重排后为 6 片，不随本轮题数或章节覆盖自动扩充；文档内 section 不能作为现有章节硬过滤。见[检索](../../backend/app/services/rag/retrieval.py#L98)、[向量过滤](../../backend/app/services/rag/vectorstore.py#L138)。
- 本地资料只有简化稿索引，原题/解答不在独立题块中；仅增加搜索轮数不会恢复被简化移除的依据。
- 当前切片会把前一块尾部作为重叠文本并入下一块，可能与下一块 section 不一致。本地切片头部已能看到目录/上一块内容与当前 section 混合，不能把 section 字符串当作整片每个字符的严格出处。

后续建议（待确认）：先完整保留正文、原题和定位，再做章节覆盖规划；每份单题蓝图按考点、方法、原题依据单独检索。检索代理可以改写查询、取邻接块和原题/解答，必须受资料范围、预算与证据充足条件约束。缺材料时不能凭模型自评“已找到”放行。

效果检查应使用固定任务与已标注证据，对比当前检索、逐蓝图检索与 agentic 检索：来源/章节命中、必要条件和完整例题解答是否齐备、最终正确性、重复率、合格率、足量交付、调用数与耗时。不能只比较模型对自己检索结果的满意度。本次未执行外部检索 A/B 实验。

### 问题 3：合法 JSON 被误当作质量通过

结论：成立；当前 schema 主要归一化字段与类型，不等于业务有效性检查。

[Question schema](../../backend/app/schemas/question.py#L70)缺少跨字段硬规则：选择题恰好四个非空选项及标签唯一、答案标签集合有效、单选恰好一个正确标签、多问答案覆盖、题干答案解析非空等。数学正确性仍需独立求解和工具验证，不能用 schema 代替。

直接加载实际 schema 的合成输入验证确认：0/2/5 选项、标签重复、选项文本为空、空题干、空答案、空解析、单选答案 AB、非法标签 Z、selfCheck.passed=false 均被接受；第四个选项缺少 text 时被过滤，整题以 3 个选项通过。缺少必填字段、非法题型及 score=0 则被拒绝，说明问题是业务约束缺失，不能笼统说没有任何校验。

本地 23 道多选题中至少 2 道选项数量分别为 2 和 3，不满足当前提示词的四选项要求。审核只把题干而非独立 options 字段传入盲评；题干有时又内嵌选项，所以不能笼统说评审从未看到选项，但没有稳定的完整题面审核契约。见 [question_review.py:341](../../backend/app/services/question_review.py#L341)。

提示词还存在训练目标冲突：[question_gen.py:280](../../backend/app/services/rag/question_gen.py#L280)带细分考点时要求“不要只换数字”，而 variant_data 的来源定义恰为保留原题结构替换数据；应按本次已确认的重复规则协调，不应全局禁止教师明确要求的改数据训练。

### 问题 4：有审核但内容和格式仍错误

结论：本地数据已提供具体反例；不能据三个样例估计全部题目正确率。

| 题目 ID | 已核实问题 | 审核记录 |
| --- | --- | --- |
| q-02f6bd3605 | 多选仅 A/B 两项，保存答案 AB；解析明确推导 B 错误、只有 A 正确 | passed=true、veto=false |
| q-793ee186e3 | 多选仅 A/B/C 三项；把反常积分的发散项 C 判为收敛，保存答案 AC | passed=true、veto=false |
| q-3af8ba2274 | 极限答案为 1/2，解析反复推导正无穷，长 4984 字符且末尾截断、美元符号未闭合 | passed=false、veto=false |

独立数学核验：

1. 对第一题，`e^x cos x = 1+x-x^3/3+o(x^3)`，故 `(e^x cos x-1-x)/x^2 → 0`，选项 B 给出的 1/2 错误。
2. 第二题 C 为 `∫₀¹ 1/(x |ln x|²) dx`，令 `t=-ln x` 化成 `∫₀∞ t⁻² dt`；在 t=0 发散，因为 `∫ε¹ t⁻² dt=1/ε-1→∞`。解析误称该积分收敛且等于 1。
3. 第三题 `arctan(x)/ln(1+x²) ~ 1/x`，x→0⁺ 时为正无穷。Python 标准库算得 x=0.1、0.01、0.001 时约为 10.016617、100.001667、1000.000167；数值只辅助说明，极限结论依据等价无穷小。

格式检查实际输出：

```text
questions=88
formulas=2393
parse_error_segments=0
questions_with_parse_errors=0
unbalanced=[{id:q-3af8ba2274, field:analysis, dollar_count:443}]
```

必须纠正初筛误报：8 道题出现的 `\\[4pt]`/`\\[6pt]` 属于 cases 环境的合法换行间距，不是 display 定界符错误；前端实际支持美元和反斜杠四类定界符。KaTeX 能解析已经提取的片段不说明整段无截断或内容正确，未闭合美元符号需要另外检查。本次未运行浏览器视觉验收或 Word 导出检查。

## 4. 原因判断与限制

已直接确认的程序路径：审核 unknown 可放行；缺题从 rejected 按难度距离补回且未排除 veto；最终解题只覆盖答案解析，不比较双方结论；解题失败保留旧值；持久化无最终结构/一致性关卡且将批次设 done。见 [审核:628](../../backend/app/services/question_review.py#L628)、[补回:697](../../backend/app/services/question_review.py#L697)、[解题:554](../../backend/app/services/question_review.py#L554)、[持久化:32](../../backend/app/services/generation.py#L32)。

这些路径足以解释为什么系统不能阻止问题题目交付；但当前没有具体历史调用轨迹，不能认定某个样例一定经过哪次修补或补回。题干、选项、答案、解析和 review 可被后续编辑却没有版本化审核失效机制，亦见 [questions.py:80](../../backend/app/api/questions.py#L80)。

隔离复现实际审核纯函数还确认：目标为高难度时，空对象 `{}` 被默认评分 3、默认 passed=true 解释为通过；缺陷码 A 与 passed=true 同时出现时不触发否决；单选独立结果 `A or B` 会归一成 AB；执行实际最终补齐代码块时 veto=true 的拒绝候选仍被加入 accepted。未把这些局部复现称为完整审核端到端测试。

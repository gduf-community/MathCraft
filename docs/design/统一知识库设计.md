# 统一知识库设计：考研数学出题 Agent 方案（云端优先）

> 修订日期：2026-10-31
>
> 代码基线：`81b42d9`。本文是待实施方案，分别说明已有能力和需要补齐的工作。
>
> 本次修改文档，未修改运行代码，未调用真实云端 OCR，也未产生新的解析或出题质量实测结果。

## 1. 这份方案到底要做什么

本方案要把上传的教材、习题和答案，整理成出题 Agent 能够可靠使用的材料：读得出内容、找得到指定范围、拿得到完整题目，并能回查出处。

例如，用户要求：“只根据我选中的这本教材，在指定章节内出几道参数变式题。”系统应先检查这本书是否已经可用，再读取符合范围的完整材料，生成后保留参考原文和原页。找不到、材料缺条件或图示不可用时，应明确说明原因。

正文围绕六件事展开：

1. **让扫描教材读得出来**：通过 MinerU 云端识别正文、公式、表格和图片，保留原始页码。
2. **让资料进库后确实可用**：区分文件接收、解析、索引和发布，处理质量检查、缓存、重建及失败恢复。
3. **让检索遵守用户选择**：选哪本书就读哪本书，普通检索、题号检索和回退都遵守同一范围。
4. **让模型拿到完整材料**：保留题干、条件、选项、公式、图示和跨页内容，避免截断后交给模型。
5. **让生成题可以追溯**：每道题能回查参考了哪份资料、哪一页，并区分原题与变式参考。
6. **让资料按考研数学组织**：增加卷种、考点、考纲版本等标签，逐步建立题目与答案关联、原题数量统计。

本次明确纳入的四项要求，在正文中的位置如下：

| 要求 | 要做到什么 | 主要章节 |
| --- | --- | --- |
| 检索范围 | 所有检索路径限定在选定文档内，并检查索引和来源是否有效 | 第 5 节 |
| 完整证据 | 将完整题目及公式、图示、页码传给出题流程，超长时明确处理 | 第 6、7 节 |
| 入库质量与恢复 | 补混合扫描识别、公式质量检查、云端任务恢复和缓存复用 | 第 3、4 节 |
| 考研专用结构 | 记录卷种、考点、考纲版本，关联题目与答案并统计原题 | 第 8 节 |

现有知识库管理、文件存储、LlamaIndex、向量与 BM25 检索、解析缓存和版本化索引继续使用。工作集中在这些已有模块的缺口上。

## 2. 现在已经有什么，还缺什么

“已有”表示代码具备对应能力，不代表目标扫描教材已经通过完整出题验收；“待补齐”是本方案真正需要实施的内容。

| 内容 | 目前已有 | 还要补齐 |
| --- | --- | --- |
| 知识库入口 | 正式建库、上传、重建和查询入口已经统一 | 继续复用，补文档可用性检查 |
| 扫描 PDF | 检测整本无文字层且有页面图像的 PDF，强制 MinerU 云端 OCR | 处理混合扫描、只有页眉文字、乱码或公式缺失等情况 |
| 解析与缓存 | 统一解析结果、内容寻址缓存；非空产物可进入完成缓存 | 检查公式、页码、图表和资产；先复用合格缓存，再校验新云端任务凭据 |
| 云端恢复 | 已完成分片 ZIP 可以复用 | 保存进行中的远端任务身份，重启后继续查询，避免盲目重复上传 |
| 索引 | LlamaIndex、向量 / BM25、embedding 绑定、版本目录和发布验证 | 检查指定文档是否确实进入所选版本，来源改变后限制旧内容 |
| 文档限定 | 出题侧已传递选定文档参数 | 题号分支和不同检索引擎都要执行范围检查；修正普通文本被误排除的问题 |
| 完整材料 | 普通检索已有原文、页码和部分资产信息 | 题号来源仅 200 字、普通来源原文有 6000 字符截断；需消除静默截断并保留完整证据 |
| 来源回查 | 底层已有原页和图像资产能力 | 出题适配层保留这些信息，最终逐题关联，不能只写书名 |
| 数学结构 | 通用文本切分，已有局部题号识别 | 完整题目切分、跨页关系、题目与答案关联、可靠原题计数 |
| 考研规则 | 已有题型、难度和章节范围输入 | 增加卷种、考点和考纲版本等结构化约束，明确标签审核状态 |

当前检索到非空文本，并不能单独证明系统读对了文档、保留了全部条件或生成了正确答案。后续验收分别检查这些环节。

## 3. 让扫描教材读得出来

### 要解决什么问题

扫描教材的文字、公式和图表都可能是页面图片。即使某些页面带有少量可提取文字，也可能只有页眉，正文仍需要 OCR。数学资料还需要保留上下标、正负号、分段条件和图形关系。

### 现在做到哪一步

当前代码已对“全部没有文字层且存在页面图像”的 PDF 强制调用 MinerU 云端，并移除了 loader 中的 LiteParse 隐式 OCR 回退。混合扫描和数学内容质量检查仍不完整。

### 还要改什么

1. **首期使用 MinerU 官方云端精准解析 API**，读取 Markdown、结构 JSON 和图片；扫描资料强制 OCR，启用公式与表格识别。
2. 按页检查文字、图像和解析质量，识别混合扫描、只有页眉、乱码及关键公式缺失。原生 PDF 的现有提取结果满足用途时可继续使用；不满足时按已启用的云端策略重解析。
3. 将云端输出整理成项目统一的正文、公式、表格、图片和页面信息，后续索引与出题流程只读取统一结果。
4. 分片和抽样后仍对应原 PDF 页码。内部页序、PDF 物理页序和印刷页码分开记录；页码未知时显示未知。
5. 图片保存为受管理的资产，关联原页和位置。内嵌 base64 图片必须外置，不能把大段图片编码送进文本 embedding。
6. 检查图片引用、页序和块顺序。以后允许切换解析器时，每个原始页只选一个主结果，避免重复题干和冲突公式。

云端 `pipeline` / `vlm` 与历史本地 MinerU 4.0.12 Standard 不能直接视为相同模型。用同样十页比较后选择云端模型，质量与耗时以新实测为准。

**本地安装模型、4.x CLI/SDK 适配、GPU 和 OOM 调优移到后续可选工作。** 首期网页使用者不需要安装 MinerU；部署方仍需安装项目后端依赖并提供云端配置。

### 怎样算完成

固定十页经正式解析链路后，正文、关键公式、图表和原页映射均可核对；混合扫描不会因为一页有文字就被直接认定为可用。缺公式、缺图或页码不可靠时，系统能指出问题并限制用途。

## 4. 让资料进库后确实可用

### 要解决什么问题

上传完成只说明文件已经收到。它之后还需要解析、质量检查、建立索引并发布；云端排队或下载中断时，也应能判断已经完成了什么、下一步如何继续。

### 现在做到哪一步

项目已有索引任务、解析缓存、已完成分片检查点和版本发布。当前解析主要检查非空产物；扫描任务先检查云端凭据再查缓存，进行中的远端任务尚未完整持久化。

### 还要改什么

**把状态说明白。** 页面分别展示文件已接收、等待解析、上传云端、排队、解析、下载、质量检查、索引构建和发布结果。排队期间显示真实状态，不编造百分比。解析完成后仍需检查质量和索引是否发布。

**入库前检查质量。** 检查缺页、空页、乱码、公式占位符、关键公式、块顺序、图表和资产完整性。质量结果分为通过、带警告和失败：

- 通过：可以进入对应用途的正常索引。
- 带警告：说明具体问题，只允许明确接受这些缺陷的用途。
- 失败：保留错误原因，不发布可用的完成缓存或候选索引。

公式、条件或图示不完整的资料，不得作为严格原题的完整证据。统计数量只是检查信号，关键内容仍需要样本核对。

**优先复用已经完成的产物。** 原文件、有效解析配置和质量规则一致时，可以复用合格缓存。读取已验收缓存不要求 Token 仍然有效；确需新外发时，再检查云端启用状态与凭据。身份无法确认的旧缓存标为未知，并给出重解析路径。

**云端中断后有恢复办法。** 扩展现有分片检查点，及时保存远端任务 ID、分片页范围、阶段和产物摘要。恢复先查询已知任务，已在排队或解析的分片不重新上传。提交是否成功未知时明确提示，不能无限重试或假定远端没有收到。

**重建时保护可用版本。** 新版本通过重新加载、检索和来源检查后才发布。新任务失败或取消时，来源仍有效的旧版本继续服务；原文件已经删除或改变时，旧索引中的对应内容不得继续用于出题。

### 怎样算完成

- 文件上传成功但索引失败时，界面能区分两者并说明原因。
- 合格缓存存在时，重建可以复用，无需再次 OCR；日常提问不重新 OCR。
- 服务重启后可以继续查询已经提交的云端任务，不盲目重复上传。
- 取消停止本地等待、后续分片和候选版本发布，并说明远端可能仍在执行。
- 云端暂时不可用时，来源仍有效的已发布索引可以查询。

## 5. 让检索遵守用户选择

### 要解决什么问题

用户选了 A 教材，就应只使用 A 教材。即使 B 教材也有同样题号，或 A 教材中没有命中，也不能自动混入 B 教材的内容。

### 现在做到哪一步

出题调用已经传递文档限定参数，但题号检索提前执行且没有接收该范围；部分检索引擎没有落实文档限定。普通文本还可能因缺少 PDF 页面状态被误排除。

### 还要改什么

1. 普通检索、题号精确检索和回退共用前置检查：选定知识库与文档 → 检索引擎支持该范围 → 有兼容的已发布索引 → 原文件与索引中的身份一致 → 执行检索。
2. 在召回前限定语料，向量与 BM25 都遵守范围。不能先全库找结果，再丢弃其中不合适的材料。
3. 题号检索只读取允许的文档和兼容解析结果，支持子目录中的资料；同题号歧义也只在允许范围内计算。
4. 题号未找到时，可以明确提示或在同一范围内普通检索；严格原题请求不能用相似题代替指定题目。
5. 文档未索引、来源已变化、范围内无命中、引擎不支持范围，分别返回明确结果。显式空范围或非法范围不能变成全库搜索。
6. 非 PDF 文本按其自身内容和身份判断能否检索；PDF 需要 OCR 或无法定位时，按用途限制使用。

首期以通过范围验收的 LlamaIndex 实现提供文档级出题。GraphRAG、LightRAG 和远程实现需证明同样约束后再开放；PageIndex 需要当前出题链没有的工具读取循环，保留明确的不支持状态。

### 怎样算完成

同库两本教材都有“习题 2-13”，用户选择 A 后，普通检索、题号检索及回退均只返回 A 的证据。A 尚未索引、已被替换或没有该题时，系统给出对应结果，不扩大查询范围。

## 6. 让模型拿到完整材料

### 要解决什么问题

数学题缺少一个条件、分段范围、选项或图示，就可能改变答案。列表中用于展示的短摘要，不能直接作为完整出题材料。

### 现在做到哪一步

题号检索的来源正文只保留前 200 字；普通检索来源原文有 6000 字符截断。出题适配层也尚未保留全部页码、版本和资产字段。

### 还要改什么

1. 分开保存“展示摘要”和“模型使用的原文”。展示可以简短，原文必须标明完整程度。
2. 以完整题目或完整知识块组织材料，保留题干、条件、选项、公式、关联图表和跨页续题；长题用可追踪的子块及父题关系保存。
3. 普通检索和题号检索都返回一致的文档、原文件摘要、索引版本、原文、页码、资产引用和完整性状态。
4. 材料超过模型预算时，优先减少题目或证据块数量，并给出说明。单题仍超长时要求缩小范围或分步读取，不能静默截断条件后继续出题。
5. 必须看图才能理解的题目，应把受支持的图像或原页接入读取流程；模型无法读取时限制自动使用，并保留人工核对入口。“见图”两字不能证明图形条件已传入。
6. 检索引擎返回的生成回答与教材原文分开。出题采用可验证的来源原文，不把引擎生成回答当作原始证据。

### 怎样算完成

超过 200 字的长题、跨页条件、全部选项及必要图示能够完整传到出题流程。材料不完整或超预算时，系统明确拒绝、缩小范围或标记待核对，不能无提示继续生成。

## 7. 让生成题可以追溯

### 要解决什么问题

题目旁边只有一个书名，仍然无法检查模型究竟参考了什么。同一次检索得到的所有材料，也不一定都被用于每一道题。

### 现在做到哪一步

底层已经有页码、原页和图像资产能力；出题适配层会丢失部分字段，最终题目主要记录书名，尚未形成完整的逐题来源关联。

### 还要改什么

1. 每份输入证据分配本次请求内可校验的编号，记录文档、文件指纹、索引版本、原文、页码和图像引用。
2. 模型返回每道题实际使用的证据编号。服务端检查编号属于本次允许材料，再补齐可信的书名、页码和访问地址。
3. 原题来源标为“原题”；改数据、换背景或新题标为“变式参考”或“考点参考”。参考教材不等于教材中存在生成后的题干与答案。
4. 前端为每道题提供原文、PDF 原页和图片入口。未知页码显示未知；证据不完整时显示待核对原因。
5. 原文件被替换或删除后，回查提示来源已经失效；旧题保留原有可读内容，不生成虚构页码或来源。

### 怎样算完成

从某一道生成题进入来源页，能看到它实际使用的证据和正确原页。模型自造证据编号、引用其他文档，或把变式标成教材原题时，服务端能发现并处理。

## 8. 让资料按考研数学组织

### 要解决什么问题

“某本数学教材”不足以表达它适合哪个卷种、哪一版考纲、哪些考点，也不足以直接统计有多少道可用原题。需要在现有资料上逐步整理这些关系。

### 现在做到哪一步

当前有题型、难度、章节范围和来源模式输入，但范围主要用于检索词与提示词；通用切分没有建立可靠的题目目录，原题数量函数返回未知。卷种、考点和考纲版本尚未形成完整约束。

### 还要改什么

**先补资料标签。** 为资料及需要细分的章节、题目记录以下信息：

| 信息 | 用途 |
| --- | --- |
| 学科、章节、考点标识 | 按高等数学、线性代数、概率统计等内容定位材料，使用统一考点名称与标识 |
| 适用卷种 | 明确适用于数一、数二、数三中的哪些范围，允许一份材料有多个已确认标签 |
| 考纲版本 | 说明适用的是哪份已确认考纲；记录依据与审核状态，不能仅凭库名或模型猜测 |
| 资料类型 | 区分教材、定理方法、例题、习题、真题、答案和解析 |
| 来源版本、年份与原题号 | 需要时追溯教材版次或真题年份；信息未知时留空并说明 |
| 题型、解法、难度及审核状态 | 逐步支持选题与难度校准，区分机器建议标签和已确认标签 |

这些是现有文档、结构化题目及索引的附加信息，不另建一套知识库注册系统。考纲与考点依据由管理员提供或确认，机器可辅助标注；请求必须满足的标签未知时，严格模式明确提示材料尚未确认。

**再让标签参与筛选。** 先确定卷种、考纲版本、文档和考点允许范围，再在该范围内检索，最后把同样约束交给生成器。不能只在提示词里写“不要超纲”。现有 `scope` 继续表达章节或考点，不复用成卷种字段。

**保留三个物理库的产品目标。** 数一、数二、数三沿用 `math1 → math-1`、`math2 → math-2`、`math3 → math-3` 的服务端允许映射。每次出题读取一个允许库中的选定资料；通用教材可分别索引，并在同一运行时范围内复用合格解析缓存。

三库解决跨库访问限制，教材内部仍需章节和考点筛选。混合教材放入数二库后，不能自动认为整本内容都适用于数二。完整卷种功能上线前，必须通过服务端映射、标签筛选和前端选择的联合验收。

**建立完整题目记录。** 从解析结果中识别题目起止、子题、选项、公式、图示、跨页续题及对应答案、解析。每道题记录身份、原文位置和关系；定理方法仍可按知识块检索，原题按完整题目读取。

**明确关联与统计。** 答案可以在本页、书末或另册，通过可验证的题目身份关联，记录确定、待核对或缺失。按选定文档、卷种、考点和题型统计已确认题目及可用原题；未知数量单列，不能用检索返回的片段数代替题数。关联不确定、内容不完整的题目，不计入严格模式可用数量。

**区分原题与变式。** 严格原题直接读取已确认题目，保留题干、条件和选项；模型如协助排版，其输出仍需与原文校验，排版规范化不得改变数学含义。数量不足或结构未知时明确说明，不能让模型补造“书中原题”。变式与新题单独保存生成结果及参考关系，生成答案不能冒充原教材答案，也不能自动回灌成已确认真题。

### 怎样算完成

- 请求指定卷种、考纲版本和考点时，实际读取与返回的证据都符合已确认范围；缺少依据时有明确结果。
- 同一本书内，题干、跨页内容和书末答案能关联到同一道题，低置信度关系能被识别。
- 用户要求若干道某题型原题时，系统先检查已确认可用数量，数量不足就说明不足。
- 原题、变式和新题的来源标识正确；改数据后的题目不被标为教材原题。

## 9. 知识库和出题 Agent 怎样配合

知识库负责提供范围正确、内容完整、来源可查的材料。出题流程负责根据材料命题，并检查生成结果。两部分各自验收。

一次请求按以下顺序处理：

1. 用户选择知识库、文档，以及本次需要的卷种、考纲版本、考点、题型和来源模式。
2. 服务端检查文档、索引、标签和检索引擎能力，固定本次允许范围。
3. 读取完整题目或知识块，检查是否满足当前用途；严格原题还需确认结构和数量。
4. 将证据编号、完整材料及约束交给生成流程，按预算控制数量。
5. 原题请求读取已确认内容；变式或新题生成后，检查格式、数学内容及来源关系。
6. 服务端保存逐题来源与审核状态，前端展示题目并提供回查入口。

**在出题侧补充数学质量检查。** 当前输出结构校验、题型检查和归一化题干去重继续保留；新增检查条件是否充分、定义域是否正确、答案与解析是否一致、选择题答案是否唯一，以及改参数后题目是否仍成立。去重逐步结合原题身份和语义相似，单纯删除空格无法识别所有重复题。

对适合的问题，可以使用符号计算、数值检查或独立解题复核，并记录检查覆盖范围；无法可靠确认时保留教师审核状态。检索命中和引用有效都不能单独证明数学答案正确。

考研难度需要结合已标注样题和教师评价校准。现有“低 / 中 / 高 / 地狱”属于通用难度输入，不直接等同于考研难度分布。资料和题型标签可先支持检索，自动组卷的题型比例、分值及覆盖规则随专门产品批次接入。

## 10. 分几步实施，每一步交付什么

每一步都区分“能演示”和“已经验收”。扫描十页、原题结构和卷种功能各自验证后再对外宣称相应能力。

| 批次 | 主要工作 | 交付与进入条件 |
| --- | --- | --- |
| 准备：固定样本和最小标签 | 接续历史报告；固定十页及人工核对内容；确定卷种、考点、考纲版本和资料类型字段 | 已有实验、新真值与待验证结果可区分；不直接采用模型猜测的考纲标签 |
| 第一批：选对资料，传完整材料 | 修全部检索路径的范围和版本检查；修文本误排除；贯通完整证据及逐题来源 | 指定文档不串书，长题不静默截断，来源可校验；先用现有合格资料验收 |
| 第二批：扫描数学资料稳定入库 | 云端同页对照、混合扫描识别、质量检查、缓存优先、任务恢复、图片与页码处理 | 固定十页通过正式解析、索引、检索和引用链路；恢复测试通过后扩到全书 |
| 第三批：按考研范围取题 | 三物理库与服务端映射、已确认标签筛选；建立最小完整题目和答案关联 | 联合验收卷种、考纲、考点及文档限制；确认过的资料可用于对应考研请求 |
| 第四批：可靠原题和变式 | 扩展题目结构、跨页与答案另册、原题统计、数学复核和难度校准 | 严格原题数量与来源可检查；变式按覆盖范围校验，未确认结果保留审核状态 |
| 部署交付：按上线范围验收 | 单管理员网站、持久磁盘、后端凭据、进度 / 错误界面、来源回查与恢复 | 可以与前述批次逐步推进；只宣称已经通过的能力，正式考研原题功能需满足相关批次 |

本地 MinerU 安装与适配、GPU / OOM 调优、Docling 数学回退、公共库 overlay、跨库融合、默认重排、独立任务队列和自动清理继续延期。现有可选适配器保留，按实际需求另行验收。

以下均为待标注、待实测及校准的目标，不是已经测得的效果：

| 指标 | 首轮目标 | 计算前提 |
| --- | --- | --- |

真实云端对照与数学质量验收另行显式运行，记录模型选择、已知版本、原始产物摘要、失败页、重试和各阶段耗时。现有云端路由替身测试只能证明路由与错误行为。

## 12. 部署成网站后怎样使用

管理员在后端配置 MinerU 云端、embedding 和 LLM，保管凭据并维护资料。网页使用者上传或选择资料、查看进度和题目，无需安装本地 OCR 模型。原件、解析产物、图片和索引保存在后端持久磁盘，做好备份。

云端 OCR 只在需要解析时执行，正常问答读取已发布索引。总耗时分别记录上传、排队、远端解析、下载、质量检查和索引；云端与本地可能使用不同模型和资源，不能预设质量相同，也不能只估算网络时间。

当前项目保持单租户。首期网站按单管理员方式部署，沿用 README 的访问网关边界，凭据和无认证管理接口不能直接暴露给公开访问者。多用户认证、授权和用户资料隔离需要单独设计，三个卷种库不承担用户权限隔离。

云解析由管理员显式启用，页面说明将向 MinerU 发送资料。日志和普通前端响应不包含 Token、签名上传 / 下载链接、完整教材或 base64 图像。资料不适合外发时说明无法使用当前云端路径；本地部署需另行验收并显式选择。

## 附录 A：开发时需要统一的字段和结果

本附录供实施使用，字段均为目标约定。保留现有字段和入口，新增字段在对应批次固定，不表示当前已实现。

### A.1 资料、题目和来源记录

| 记录 | 至少需要的信息 |
| --- | --- |
| 文档检查 | `document_key`、`source_digest`、原文件是否存在、所选 `index_version`、索引状态、解析身份、质量状态及警告 |
| 解析结果 | 沿用 ParsedDocument；正文、结构块、资产目录、原文件摘要、parser signature；增加有版本的质量记录 |
| 结构块 | 块标识、类型、文本 / LaTeX、`page_index`、位置坐标及坐标约定、资产引用 |
| 考研标签 | `subject`、`chapter`、`knowledge_point_ids`、`exam_types`、`syllabus_version`、资料类型、标签依据与审核状态 |
| 结构化题目 | `exercise_key`、原题号、题型、完整题干 / 选项、子题及跨页关系、答案 / 解析关联、来源块、图像和置信状态 |
| 原题统计 | 当前文档 / 卷种 / 考点 / 题型范围、确认题数、当前用途可用题数、未知状态；排除未确认和不完整材料 |
| 来源证据 | `evidence_id`、`kb_id`、文档及源摘要、索引 / 解析身份、块标识、`evidence_text`、页码、位置、图像、`completeness` 和警告 |
| 生成题来源 | 本次实际使用的证据编号、原题 / 变式 / 考点参考关系、回查定位及审核状态 |

`document_key` 沿用 raw 下的 POSIX 相对路径，和文件摘要一起判断是不是原来的那份资料；不另造跨重命名文档 ID。`exercise_key` 绑定源文件与结构分析身份，重建关系可核对，不假定不同教材版次中的题号天然指向同一题。

标签可以挂在文档、章节或题目上，只有整份资料均适用时才继承文档标签。混合资料需保留局部范围；标签规则变化记录版本并重建相关筛选信息，旧索引缺失字段时标为未知。

PDF 内部 `page_index` 使用零基页号，展示标签另存。坐标需记录归一化范围、页面尺寸及旋转，并经原页渲染验证。图像缺失或坐标无法确认时保留不完整状态，不能仅删除错误引用后宣布完整。

### A.2 接口与错误

沿用 `/api/knowledge-bases/*`、RAGService 和现有出题适配层。检索继续兼容 `query / content / answer / sources / provider`，在 sources 上增加完整证据，避免另建一份含义相同的结果清单。出题流程在进程内调用，不反向请求自身 HTTP。

文档检查由 raw 清单、解析记录和所选索引派生，不建立平行注册表。新增标签、检查状态和逐题来源采用兼容字段；旧题保持可读。实现时同步后端 schema、前端 types、OpenAPI 和接口文档。卷种字段与现有 `scope` 分开；必需条件缺失时明确拒绝，不自动放宽。

已有错误保留 `scanned_pdf_mineru_cloud_not_configured`、`scanned_pdf_mineru_cloud_failed`、`reasoning_as_retrieval_required`。待实现错误语义包括：

- 范围不支持：`document_scope_unsupported`；文档未索引：`document_not_indexed`。
- 来源缺失 / 改变：`source_missing` / `source_changed`。
- 解析质量失败 / 证据不完整：`parse_quality_failed` / `evidence_incomplete`。
- 题目结构或数量未知：`exercise_analysis_unavailable`；确认数量不足需单独报告。
- 考研标签未知、请求范围不兼容：返回具体缺失依据与范围问题，错误名在该批次固定。
- 云端提交未知 / 等待预算耗尽：`cloud_submission_unknown` / `cloud_wait_budget_exceeded`。
- 云端限流 / 产物无效：`cloud_rate_limited` / `cloud_result_invalid`。

普通无命中正常返回空结果；解析失败、范围不支持和原题结构未知分别说明。HTTP 状态码与现有异常映射在实施时确定。

## 附录 B：云端恢复、缓存与版本的实现约束

### B.1 复用现有云端适配器

继续由 ParseService 调用现有 MinerU cloud adapter：申请上传链接 → PUT 文件 → 按 batch_id 轮询 → 下载 ZIP → 校验与归一化 → 质量检查。使用 `/api/v4/file-urls/batch` 和 `/api/v4/extract-results/batch/{batch_id}`，不换成只有 Markdown 的 Agent 轻量 API。

当前扫描强制云端策略优先于显式本地引擎；云端失败不隐式切换本地 MinerU、LiteParse、Docling 或其他云服务。TXT / MD 沿用无损读取，其他格式按现有适配器处理；显式诊断引擎失败即报告失败。

可选解析依赖按需加载，缺少时报告不可用，不阻止服务启动；模型或依赖安装必须显式触发。管理配置沿用现有 settings 与部署密钥机制，不增加另一套凭据文件。

上次于 2026-10-31 核对的[官方精准解析 API 文档](https://mineru.net/doc/docs/)列出单文件 200 MB / 600 页、每天 2000 页最高优先级，超出后优先级降低。部署时按账号与最新服务规则复核；最高优先级额度不等于硬失败上限，也不代表固定价格或 SLA。

本仓库当前默认每片 180 页、配置上限 200 页，是客户端约束。先保留保守分片，补字节大小和解压体积检查，在十页与超时恢复验收后再调整。现有默认 300 秒轮询预算需结合排队与文档规模复验，不能据此保证整书完成。

### B.2 把进行中的任务保存下来

在现有 `parse_cache/.mineru-segments` 机制内扩展，记录源摘要、有效解析身份、分片原页范围、请求身份、batch_id / 可用文件标识、阶段、更新时间、重试预算、脱敏错误及产物摘要。取得远端任务 ID 后立即原子保存，再进入上传和轮询。

本地阶段区分 `submitting / uploading / queued / parsing / downloading / validating / completed`，同时保留上游实际状态。分阶段设置连接、上传、等待、解析和下载预算；等待超预算保留继续操作，不自动视为远端失败。现有索引任务停滞判断也需识别有效排队与轮询状态。

恢复先查远端：已上传的任务继续等；确认未上传时按协议和链接有效期恢复上传；是否接收未知时明确记录。上游未承诺幂等时，不能把 data_id 当去重保证或宣称 exactly-once。查询 / 下载等可安全重试操作对网络瞬断、429、部分 5xx 有界退避，尊重限流提示；认证、损坏文件和质量错误不无限重试。

完成分片经过 ZIP 格式、受限解压路径、资产、页映射和结构校验后才写完成标记，整文档汇总检查后再进入正常缓存。完成 ZIP 复用不等于进行中任务已支持恢复。相同请求用现有锁语义协调，具体锁粒度需验证并发场景。

本地取消停止后续工作，不宣称已取消远端。进程重启后显示可继续状态，取消任务不自动重新外发。Token 不写入任务记录；如恢复确需有时效的签名链接，仅留在受限后端存储，不进入日志和公开响应。

### B.3 缓存、索引和文件布局

解析身份包含云端模式 / 服务身份、模型选择、OCR / 公式 / 表格 / 语言 / 分片参数及 adapter、统一结构、质量规则版本，排除 Token。保存原始 ZIP、统一产物、已知远端版本和摘要；远端未披露精确版本时记录未知，固定 `pipeline` / `vlm` 名称不能保证将来重跑一致。

解析缓存不包含卷种选择或索引状态；同一运行时范围内可跨库复用，不扩展为跨用户共享缓存。题目分析绑定源摘要、解析身份和分析规则版本；考纲筛选绑定标签规则版本。

文件仍放在既有位置：原件 `knowledge_bases/<kb>/raw/`，任务 `.indexing-run.json`，发布索引 `version-N/`，原页目录 `source_pages.json`，图片 `visual_assets/`，解析产物 `parse_cache/`。不建立平行知识库目录；新增派生信息的文件名在对应批次固定。

索引沿用 provider / embedding 绑定与现有版本解析，不增加独立 active 指针。向量与 BM25 的融合继续复用，报告实际可用模式，BM25 缺失时明确降级。embedding 模型稳定 ID 和引用保护保留，云端 OCR 切换不要求更换 embedding。

候选版本重新加载并通过向量、检索、来源及 BM25 状态检查后发布。增量添加也可能写完整新版本，需记录磁盘成本。自动删除历史缓存、旧版本及旧轻量链路数据均延期，避免破坏仍在使用的证据。

测量大教材的限定语料构造、索引加载和检索成本，再按实际瓶颈优化。任务诊断保留实际文档范围、版本、解析身份、检索方式、质量警告、失败与恢复原因，不记录秘密配置和教材全文。

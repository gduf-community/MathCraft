## 5. 验收方法复核与更正

这三类验收脚本问题不作为产品缺陷，受影响结果已撤回并重新核对：

1. 不存在的 `unknown.pdf` 应为 `source_missing`，不能把它作为“存在但未索引”的样本；已另建真实存在、尚未入索引的文本验证后者。
2. `/reindex` 的空表单可能返回 `noop=true, task_id=null`。上一轮实施记录中“再次重建且无云请求”的检查只能证明没有外发，不能单独证明完成了一次缓存重建。本轮显式携带现有假 embedding 绑定，要求 task_id 存在、noop=false、新版本发布，并比较四类云调用计数。
3. 异步任务接受后，旧终态可能仍短暂可见；验收必须匹配本次 task_id。重复使用已成功的故障样本又可能直接命中缓存，因此每次故障注入使用全新摘要，检查故障请求确已触发。

原始尝试记录保留在隔离目录，最终统计只使用复核后的结果，不将未触发的故障算通过。

## 6. 已确认的使用限制

| 限制或风险 | 本轮证据与影响 |
| --- | --- |
| 扫描底图与教材图示尚未区分 | 两册所有页都有扫描图像，当前 `visual_status=present` 使整册证据保持 incomplete；服务端拒绝严格出题是预期保护，但扫描教材的可用性仍有缺口 |
| 证据仍以整文档为保守单元 | 受控长文本能完整传递、过预算明确拒绝；尚无可靠原题/语义单元，真实整册 OCR 后的长度和可用性没有验证 |
| 规则检查不是内容质量核对 | 产物结构、页码和文件通过，不足以证明漏字、上下标、符号、条件、图示或数学正确性 |
| 重建与任务状态容易被误读 | noop 与真实重建、上次任务与当前任务必须分辨；验收脚本已更正，产品说明和交互还可改善 |
| 失效资料仍可被选中 | 浏览器能看到 source_changed / 未索引提示，但仍可选择，随后由服务端拒绝；没有越界生成证据，选择和拒绝之间的反馈可提前 |
| 恢复中的人工处理入口不足 | 已知任务可继续；提交未知、上传未知、过期链接等仍需管理员核对，不能盲目清记录或重传 |

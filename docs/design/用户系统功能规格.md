# 用户系统功能规格

状态：方案讨论中，尚未授权开始业务实现。核对日期：2026-11-04。

## 目标与范围

补齐教师与学生的账号开通、登录、个人资料和账号管理闭环。当前实施分支为 `main`；保留 `main` 用于知识库及公共模块、`agent` 用于智能体模块的分工。

## 已确认决策

- 正式使用阶段采用管理员创建或邀请开通账号，不开放自由注册；创建与邀请的具体流程待确认。
- 开发阶段保留默认教师、学生账号，方便切换身份验证业务。
- 本次用户系统属于公共基础能力，在 `main` 开发。

## 当前实现证据

- 后端入口为 `backend/app/main.py`，用户与个人模型设置存储在 SQLAlchemy 模型中。
- `/api/auth/login`、`/me`、`/logout`、`/change-password`、`/password` 已有实现；密码使用 bcrypt，会话使用 Redis。
- `/api/users/me` 支持个人资料更新，相关子路径支持头像与个人模型设置。
- `backend/scripts/seed.py` 已提供 `teacher`、`student`、`student2` 开发示例账号，公开示例密码为 `123123`。已存在的账号跳过，不重置其密码。
- 当前脚本需要人工执行；本轮未执行初始化或连接运行数据库，不能断言本机已创建这些账号。
- 登录页表单初始账号、密码为空；刷新登录态通过 `/api/auth/me` 恢复。
- 当前没有自由注册或忘记密码恢复接口；登录页改密仍要求原密码。
- 现有状态拦截与资源权限依赖不等于已经实现管理员管理后台。

以上为源码静态核查，未作运行验收。

## 核心流程与待确认项

1. 管理员创建或邀请账号：待确认管理员职责、入口、首个管理员的初始化方式。
2. 开发登录：使用默认教师或学生账号，经现有真实认证接口登录。快捷填充、初始化触发方式待确认。
3. 正式账号首次登录、初始密码交付与忘记密码处理：待确认。
4. 账号禁用、重新启用、角色调整与既有业务数据处理：待确认。

## 接口与数据契约

本轮不新增接口或数据库字段。现有契约以根 `openapi.json` 和 `backend/app/schemas/` 为准；新管理与邀请接口需在需求确认后另行定义。

## 异常边界

- 默认开发账号不能代表生产用户开通方案；现有 seed 跳过同名账号，不能据此保证示例密码仍可用。
- 开发快捷入口应经过真实密码与角色校验；其可见环境与触发方式待用户确认。
- 改密后的会话撤销并发、Redis 失败与禁用后重新启用的会话策略需要专项设计和验证。
- 多字段登录标识的跨字段冲突、密码输入边界及头像校验是已发现的实现缺口，修复范围待确认。

## 验收标准

- 已确认：教师与学生在开发环境均有可用的默认账号；正式使用阶段没有自由注册入口。
- 已确认：用户系统开发位于 `main`，不改变智能体模块的分支归属。
- 待补充：账号开通与管理员权限、首次登录、密码恢复、会话撤销及默认账号初始化的可执行验收场景。

## 核心流程

### 主登录页与身份选择

1. 未登录时显示恢复后的登录页，用户可手动切换“学生／教师”单选项；选择改变引导和提交文案，并作为登录结果的身份匹配条件。开发账号填充仍是独立的受限入口。
2. 主卡以账号密码登录为主，尺寸与间距进一步对齐历史快照；不在未登录主卡内铺开修改密码表单。邮箱验证码登录通过独立弹窗提供，继续使用已绑定并验证的邮箱及现有认证能力。账号仍由管理员开通。
3. 登录请求继续调用当前 API，不把选择项作为可修改账号权限的请求字段。收到响应后，以服务端 `user.role` 为准。
4. 普通登录时，学生／教师角色匹配后调用 `signIn` 进入工作台。角色不匹配时先退出刚建立的会话，提示选择对应身份后重新登录，保持未登录页面；不得在前端改写角色或默认进入错误身份工作台。
5. 普通登录返回 `admin` 时直接进入现有管理员面板，不要求选择器提供管理员选项。登录页绑定邮箱流程使用下述临时认证边界，不调用 `signIn`。账号恢复、刷新、退出以及跨标签身份校验仍使用当前 session 机制。

重置密码继续使用现有字符／字节限制、两次密码一致性校验及重置后的会话失效语义。Turnstile 由当前公开认证配置决定是否需要，提交、过期或失败后按现有流程更新票据。

“忘记密码”打开独立弹窗，先提供“联系管理员”和“已绑定邮箱验证码重置”两个选择。前者展示一般联系指引，并仅从现有公开认证配置的 `admin_contact` 解析有效邮箱：有有效邮箱时可显示邮箱及 `mailto:` 入口，点击只打开本机邮件客户端，由用户自行确认发送，不调用后端代发邮件。无有效邮箱时隐藏邮箱行和发邮件入口，保留一般指引及两个找回方式，不展示占位地址。后者进入现有邮箱验证码与新密码重置流程。

管理员页面配置联系邮箱仅为未来计划，本轮不新增配置页面、保存接口或配置字段，也不读取或改写敏感配置。弹窗需支持可访问名称、键盘关闭与焦点恢复，短视口下表单和按钮可滚动到达；忙碌、错误、验证码及 Turnstile 状态继续遵守现有认证规则。

`AuthDialog.tsx` 已复用 `ConfigurationDialog`，邮箱登录直接进入邮箱表单，找回密码先进入方式选择。发码中的 `onBusyChange` 与提交状态共同决定弹窗忙碌状态：请求期间禁用关闭、Esc 退出、返回及步骤切换，遮罩点击不关闭；请求结束后恢复操作。关闭或切换步骤清除验证码、challenge 与新密码，退出弹窗恢复触发控件焦点。两种找回选择、无邮箱时隐藏邮件入口、Escape 关闭后的焦点回归及 375×480 滚动可达性已通过本轮完整认证 e2e。

动态视觉视口、安全区留白和内部滚动为布局实现；恢复后的 `auth-stage` 已补充使用 `env(safe-area-inset-*)` 的 padding。浏览器移动视口检查不等于手机真机验证，本轮尚未验证真机刘海／底部手势区或真实软键盘行为，不将这些场景记录为通过。

### 登录页绑定邮箱

登录主卡不提供独立绑定入口，邮箱登录弹窗通过“尚未绑定邮箱？先绑定”切换到绑定流程：

1. 先输入现有账号密码，按当前公开认证配置完成 Turnstile，并依据服务端返回角色执行现有身份校验。认证仅建立后续绑定所需的临时会话，不调用 `signIn`，不进入任何工作台；角色不匹配时撤销会话并提示重新选择。
2. 认证通过后，无邮箱和历史未验证邮箱均可进入绑定步骤。已验证邮箱不通过此入口覆盖或更换邮箱，保留现有账号设置流程。
3. 使用 `email_bind` 用途发送验证码，再提交邮箱、challenge 和验证码到 `bindEmail`；账号认证后清除密码，不再传入绑定接口。未经邮箱验证码验证不能绑定。
4. 绑定成功后按绑定接口的会话失效规则返回密码登录，不自动进入工作台。返回邮箱登录、取消或退出流程前撤销临时会话并清理验证码与临时状态；撤销失败保留退出错误与“重试退出”，不能切换到邮箱登录或声称退出完成。

完整认证 e2e 已覆盖绑定错密码、不进入工作台、取消退出返回 503 后保留弹窗并重试、业务 Token 清空、发码期间禁关、绑定失败保留输入、成功返回登录，以及已绑定账号与错选角色后的会话撤销。

取消绑定时撤销失败保留弹窗及退出重试入口。`ToastProvider` 的挂载 key 仅按 identity 区分，使 session 代次变化后的 `logoutError` 更新不会重挂 `LoginPage` 并丢失弹窗；提示仍按 generation 过滤，旧会话反馈不能进入新会话。最终 build（含 typecheck）、lint、完整认证 e2e、两项会话脚本与 59 组整合回归均已在该修复后通过。

### 出题界面

三个 GenerateTab 文件已恢复历史欢迎文案、四个快捷提问入口、至少两行输入框和文档拖拽提示；快捷提问只填草稿。输入区和消息区参考 `5155f8a`，同时保留快速出题、创新命题、知识答疑和数据管理四模式，以及图片附件、公式、进度和暂停。发送消息仍校验已选择的题库和文档，图片用途及限制沿用[四模式说明](对话四模式与主线整合.md)。

所有历史用户消息恢复“编辑后重发”及“回退并重新发送”入口，最新助手回复保留重新生成。生成中、确认请求中或存在待确认操作时，相关发送、模式切换、快捷提问及历史消息操作均保留忙碌保护。

编辑把该用户消息及附件放回草稿，并裁切前端消息序列；回退重发也从选定位置裁切前端消息，再沿用当前会话发送。现有服务端聊天 API 没有历史截断（truncate）接口，本轮未修改 `AppContext` 或接口。因此这些操作不能保证服务端上下文同步退回历史节点，服务端可能仍保有后续轮次；不将其描述为服务端历史撤销或独立对话分支。

数据删除／改名保留 `ConfirmCard` 的影响预览、接受和拒绝入口。`pendingConfirm` 存在时强制进入可显示确认卡的消息区域，即使 `messages` 为空也不显示会遮蔽确认步骤的欢迎态。当前状态层在待确认时阻止继续发送，卡片入口必须保持可达。会话清空、切换文档、退出和异步返回继续遵循当前隔离规则。

## 接口与数据契约

视觉恢复阶段沿用既有协议；后续绑定优化已移除绑定请求的 `current_password`，同步更新 `openapi.json` 与 `docs/api.md`。其余路径、方法、响应及 WebSocket 消息不变。

| 能力 | 沿用接口／契约 |
| --- | --- |

## 异常与边界

- 角色不匹配：等待退出处理后提示正确身份；本地状态清理，服务端撤销失败时沿用退出错误及“重试退出”，不能调用 `signIn` 或声称服务端退出已确认。
- 认证配置、验证码、人机验证或网络异常：沿用具体错误提示与重试；忙碌和限流期间禁止重复提交，不用历史旁路绕过验证。
- 邮箱未绑定、验证码过期或重置失败：展示当前接口错误并保留对应恢复入口；无法找回时显示管理员联系提示。
- 联系邮箱为空或无法解析：隐藏邮箱行与发邮件入口，保留一般联系指引和两种找回选择；有效邮箱的 `mailto:` 仅唤起邮件客户端，不承诺客户端可用、邮件已发送或管理员已收到。
- 登录页绑定邮箱：临时认证不进入工作台；已绑定账号不走首次绑定分支，验证码未验证不能绑定。取消后需撤销临时会话，失败时保留退出重试，不能仅关闭弹窗就视为服务端会话已撤销。
- 窄屏、长表单、长错误及软键盘：宣传区按响应式规则收起，固定舞台适配视觉视口，卡片内部可滚动到所有字段与按钮；装饰不遮挡操作。
- 出题模式或确认请求异常：保留当前反馈，确认执行成功后列表刷新失败不恢复可重复执行的操作；旧请求不能回填新账号或新文档。
- 历史消息编辑／回退：只影响前端序列，现有接口不截断服务端历史，重发不能保证消除后续轮次对模型上下文的影响；该限制保持明确，不用界面裁切声称服务端已撤销。
- 全站 Toast：样式恢复不得改变现有提示内容、触发、消失／关闭、播报及会话边界；覆盖长文本、错误与成功提示，避免样式导致文本截断或关闭操作不可达。
- 历史快照：旧契约与当前后端不兼容，原核验未为展示效果替换认证响应或修改快照。5174 对照现已结束，入口不可达符合停服状态，不再按启动故障处理；目录删除受阻需如实记录，不能称为已清理。

## 验收标准

1. 历史恢复验收曾要求 5173 与 5174 按固定端口独立启动，5174 的历史受控文件与指定提交一致，原样边界不因代理、注入当前组件或接口适配而改变。该临时对照现已结束，当前仅保留验收记录。
2. 主登录桌面视觉恢复历史背景、左右布局、宣传与玻璃卡片；窄屏、短视口、长表单及错误提示下所有操作仍可到达，键盘焦点和身份单选可用。补充 375×480 浏览器视口下重置长表单按钮可达检查，单独记录执行结果，不替代真实软键盘或真机安全区验证。
3. 学生／教师可真实手动选择；分别验证匹配成功、不匹配后退出与提示、退出撤销失败及重试。admin 不受该选择拦截，进入现有管理员面板。
4. 密码、邮箱验证码、重置、Turnstile、会话恢复与退出保持当前行为；不新增角色请求字段，不回退持久化凭据或当前权限检查。
5. agent 欢迎区、快捷提问、至少两行输入框与拖拽提示按指定基准恢复；四模式、图片附件、公式和进度仍可用，快捷提问只填草稿，不直接发请求。
6. 所有历史用户消息可编辑或回退重发，最新助手回复可重新生成；验证相关忙碌保护。历史回退按前端裁切范围验收，不宣称服务端历史同步截断。

# 用户系统实施规格

## 邮箱绑定免密码契约调整（2026-11-12）

用户已确认：有效登录态、无已验证邮箱（含历史未验证邮箱）及目标邮箱的 `email_bind` 验证码即可绑定。`EmailBindingBody` 仅继承 `CodeBody`，`PUT /api/users/me/email-binding` 不再校验当前密码；额外提交 `current_password` 按严格请求契约返回 422。无有效 Bearer 时，即使持有刷新 Cookie 和正确邮箱码也拒绝绑定。已验证邮箱禁止由绑定入口覆盖；换绑双 proof、解绑密码、版本及全会话撤销继续沿用既有流程，无数据库迁移。

实际测试、契约生成和本机服务加载记录见[账号系统整合与审查修复](../implementation/账号系统整合与审查修复.md)的“邮箱绑定免密码调整与验证（2026-11-12）”。

## 本机 Turnstile 开关与验收边界

本机允许按下述条件临时跳过 Turnstile 人机验证。账号密码、账号启用状态、JWT/SQL 会话与撤销、Origin/CSRF、邮箱验证码、限流及 proof 消费、角色和资源归属校验继续生效；SMTP 故障仍按原规则处理，不因开关放行邮箱登录或恢复所需验证码。

`TURNSTILE_ENABLED` 默认 `true`。配置为 `false` 时，仅 `APP_ENV=development/test` 允许启动；production 在配置校验时拒绝启动。对允许启动的实例，仅实际 ASGI peer 为回环 IP（如 `127.0.0.1` 或 `::1`）的请求跳过，其他 peer 仍完整执行 Turnstile。Host、Origin、`Forwarded` 或 `X-Forwarded-For` 等头不能扩大跳过范围。

GET `/api/auth/config` 的 `AuthConfig.turnstile_enabled` 为必填 boolean，返回当前请求的有效状态：满足上述三项条件为 `false`，其余允许服务的请求为 `true`。前后端分别按各自请求判定，不把一次 config 的结果当作后续异源请求的豁免凭据。有效禁用时后端不调用 Cloudflare，前端不渲染人机验证 widget、不加载其脚本、不因缺票据或 site_key 阻止提交。有效启用时保留完整票据、action、hostname 与站点配置验证，拒绝空票据，不因请求 schema 允许空字符串而放行。

开关变更须重启后端并重新加载前端配置，不支持热切换；恢复开启时以 `TURNSTILE_ENABLED=true` 启动，移除覆盖时也须确认其余受控配置为默认 `true`。本机进程操作及验证结果见[账号系统整合与审查修复](../implementation/账号系统整合与审查修复.md)的 2026-11-09/10 记录。

| 验收项 | 验收边界 |
| --- | --- |
| 默认与配置校验 | 未设置开关默认 true；production false 启动拒绝；development/test false 可启动 |
| 请求级有效状态 | development/test false 分别覆盖实际 peer 127.0.0.1、::1；config 返回 false；非本机 peer 返回 true 且仍需完整验证，伪造 Host/Origin/转发头不改变范围 |
| 请求契约与空票据 | email-code、account login 的 turnstile_token 缺省及空字符串可解析；仅有效禁用请求跳过，有效启用请求仍拒绝空票据 |

| 前端登录与全部发码入口 | 按当前 config boolean 处理；false 不加载脚本且缺票据/公钥不阻止提交；true 继续要求验证；不依据浏览器 hostname 自行放宽 |

| GET/POST /api/auth/development-account?role=teacher或student | development＋显式开关，本机 peer/Host/Origin，拒绝转发头 | account、password、role，仅填充 account 密码登录；前端用 POST JSON {}，生产不挂载；role 查询仅选择开发样例，不是登录身份选择 |

POST /api/auth/register 与 POST /api/auth/login/password 删除，不保留兼容建号或学工号认证；purpose=register 不再接受。UserNo 资料维护接口继续保留，普通资料接口仍不能修改邮箱和认证状态。

## 当前邮箱核心流程与异常边界

1. 绑定：密码登录后进入个人安全设置；管理员在管理面板的自身安全区域操作。无已验证邮箱时，向目标邮箱申请 purpose=email_bind 验证码，发码必须携带有效 Bearer 并通过 Turnstile。挑战绑定当前 user_id、auth_version、原邮箱快照和目标邮箱；历史未验证邮箱按此流程处理，不自动验证旧值。
2. 提交绑定：PUT /api/users/me/email-binding 发送 email、challenge_id、code。服务端依赖有效 Bearer 登录态，重新验证无已验证邮箱条件、挑战用途/主体/版本/邮箱快照和目标邮箱唯一性；SQL 事务内消费 proof、写入邮箱及验证时间、递增版本、撤销全部会话。current_password 不属于绑定请求契约。
3. 换绑：已有已验证邮箱时，沿用 POST email-change 建立事务，向旧、新邮箱分别发送 email_change_old/email_change_new 码，再 PUT email 提交双 proof；不得直接使用 email_bind 替代双码校验。
4. 解绑：DELETE /api/users/me/email 的 JSON 请求体为 {current_password}；清空邮箱及其规范化值、验证时间，email_verified=false，同事务递增版本并撤销全部会话。再次绑定须重新取得 email_bind 专用验证码。
5. 成功与失败：三类邮箱变更均返回 204，清目标用户 Cookie，前端清理该用户会话并回默认密码登录页，不自动续期或重放变更。密码错误、邮箱冲突、错码/过期/重放、跨用途/跨用户、认证版本或原邮箱快照变化时不改变邮箱和资源归属。不得将 SMTP 失败或邮箱码登录失败降级为无需验证。

绑定、换绑、解绑共享既有验证码、AuthProof、版本和会话撤销机制。提交时再次核对唯一性与版本，防止并发绑定、换绑、解绑或改密沿用旧验证；不把 Redis 与 SQL 的独立提交表述为跨存储原子事务。

## 当前验证码与会话规则

公开 login/reset_password 挑战绑定用途、规范化邮箱、用户 ID 和认证版本；发码、邮箱登录验码、密码重置验码三处构造绑定一致。安全复核发现仅 purpose/email/version 无法隔离同版本邮箱跨用户转移，补 user_id 的修复已通过相关回归。邮箱解绑后转给他人时，旧 login/reset 码均不能登录或重置新账号；部署后旧未消费挑战因绑定变化失效，需重新发码，无数据库迁移。

验证码默认 6 位、300 秒有效、最多 5 次错误；每邮箱每用途 60 秒冷却、每小时 5 次，来源 IP 每小时 30 次，配置可调整。Redis Lua 控制限额、最新挑战和验证状态，只存独立密钥的 HMAC 摘要；最终消费通过同一业务 SQL 事务中的 AuthProof 唯一键保证，事务回滚可安全重试。旧刷新摘要保留到会话到期，proof 只在 Redis 挑战实际消失后清理。

login/reset_password 在 HTTP 响应完成后发邮件；不适用收件人不投递，SMTP 故障只记脱敏固定日志、挑战不激活，已返回的 202 不变。email_bind 发码绑定登录主体、认证版本和原邮箱快照；换绑发码从事务解析旧/新邮箱。两者均需 Bearer，同步 SMTP 故障删除挑战并返回 EMAIL_SERVICE_UNAVAILABLE/503。邮件成功且挑战仍为最新才激活；限额不因故障清零。公开发码后台任务不持久化，进程中断可丢失投递，不能将 202 当作已送达。

JWT 固定 HS256，默认 900 秒；claims 包含 sub/sid/auth_version/jti/iat/exp/iss/aud/type。每次认证查询 SQL 用户启用状态、认证版本与会话状态；刷新凭据为高熵不透明值、只存摘要、默认绝对 604800 秒到期且逐次 CAS 轮换，重放撤销对应会话。改密、恢复、邮箱绑定/换绑/解绑、管理员重置/禁用在同事务更新版本及撤销会话；签发时核对原凭据验证版本。

mc_refresh 为 HttpOnly、生产 Secure、SameSite=Lax、Path=/api/auth、无 Domain；mc_csrf 同路径且可由脚本读取，config 同时返回 csrf_token。refresh/logout 必须满足精确可信 Origin、application/json 和双提交 CSRF。改密、恢复、邮箱绑定/换绑/解绑只在请求 Cookie 属于目标用户时删除，普通退出更严格地只删除同 sid Cookie。

前端 [session.ts](../../frontend/src/api/session.ts) 以同一 Web Lock 串行登录、刷新、退出及安全操作的 Cookie 响应处理；需要续期时先在锁外完成，锁内不重放安全写操作。access 只存内存；sessionStorage 只存用户/角色/sid 约束及退出阻断意图。恢复须匹配用户与角色，跨账号共享 Cookie 不触发自动身份切换；通知按用户或会话定向。业务请求仅对明确 ACCESS_TOKEN_EXPIRED 重试一次，旧代次响应和 blob 不回填。退出失败保留内存撤销凭据供原页面重试并阻止重载恢复；无本地 access 时不匿名注销 Cookie 所属账号。没有 Web Locks 支持时明确拒绝会话协调，不静默降级。

## 当前资料、模型设置与资源边界

资料保存等待服务端确认，性别不默认写“男”；前端清空性别/手机号映射为 null。三角色按 email_verified 展示绑定或换绑，并提供当前密码解绑；管理员无需进入教学工作台即可在自身安全区域配置邮箱。学工号继续作为资料维护，不因邮箱状态隐藏或承担登录功能。头像 API 读取上限加一个字节，默认限 5 MB、PNG/JPEG/WebP；当前个人中心仍显示昵称首字，不提供头像上传控件。

个人模型配置统一放在设置页“模型与服务”，由 [PersonalModelSettings](../../frontend/src/components/settings/PersonalModelSettings.tsx) 提供；个人中心仅保留资料与安全设置。清除须显式勾选；保存未确认保留输入，已保存但读回失败提示重新读取并禁止沿用旧状态测试。测试只用已保存的有效配置；DeepSeek 优先用户 Key，后备应用配置；MinerU 优先用户 Token，后备系统默认。配置状态/掩码表示个人值，不能据此证明默认值可用。向量与重排由平台管理员维护，普通用户只读查看活动模型，配置与索引切换流程见[设置拆分设计](设置拆分与保存反馈设计.md)。

题库创建仅教师；创建者按 account 添加启用教师/学生，creator/editor/readonly 三档，平台管理员不能借角色访问教学资源，编号自助加入返回 BANK_JOIN_DISABLED/404。学生已有资源保留归属与访问，不能新建；转让只给启用教师。空间随机加入码与被移除成员保护、试卷复盘答案边界见整合文档。

| 验收项 | 通过标准 |

| 前端静态检查与构建 | 类型检查、lint 区分既有诊断、生产构建完成 |

| 文档链接 | 七份文档相对本地链接存在 |
| 历史兼容、邮箱安全与审计 | 原 account/密码/ID/资源不变，学工号仅资料；绑定限制、双码换绑、解绑后 email_verified=false/204/全撤销/默认密码登录；缺失/未验证邮箱仅信息 |

| 后端最终验收 | 适用认证/资料/审计及全量 pytest、Ruff/Pyright 与最终安全修复结果 |

# 用户系统实施规格

状态：用户已于 2026-11-04 接受认证设计；本规格待实现，不代表功能已上线。
目标分支：main；agent 长期分支继续仅用于智能体模块。
发布记录：[GitHub Issue #3](https://github.com/gduf-community/MathCraft/issues/3)，标签 ready-for-agent。

## Problem Statement

个人教师和学生需要独立注册、可靠登录和自行恢复账号，而不依赖管理员开通。当前系统已有用户及资源归属，但缺少自助注册、邮箱验证码、完整密码恢复、人机验证和可立即撤销的 JWT 会话；旧登录标识混用、资料直改邮箱和撤销会话的失败窗口也需要一并消除。开发者需要可配置的教师、学生默认账号，以降低本地联调成本，同时不能向生产引入默认密码或认证旁路。

## Solution

提供邮箱验证注册、邮箱验证码登录及学工号密码登录。注册后自动进入对应工作台；用户可在个人中心安全维护学工号、密码和绑定邮箱。所有发码和密码登录接入 Turnstile，使用短期 JWT 与可撤销刷新会话。开发账号通过后端环境配置及显式初始化命令创建，开发快捷按钮只填充、不自动登录。保持现有用户 ID、角色权限和数据归属不变。

## User Stories

1. 作为个人教师，我希望无需邀请或管理员审批即可注册，以便独立使用服务。
2. 作为学生，我希望选择学生身份注册，以便进入自己的工作台。
3. 作为注册者，我希望验证邮箱归属，以便后续使用邮箱登录及恢复密码。
4. 作为注册者，我希望填写显示名称、密码和确认密码，以便建立完整账号。
5. 作为注册者，我希望不填写学工号、学校或手机也能完成注册，以便先使用服务。
6. 作为注册者，我希望不再额外创建用户名，以便减少重复填写。
7. 作为注册者，我希望注册成功立即登录并进入对应工作台，以便无需再次完善资料。
8. 作为用户，我希望用邮箱验证码登录，以便未绑定学工号也能访问账号。
9. 作为用户，我希望用学工号和密码登录，以便沿用日常编号。
10. 作为未注册访问者，我希望看到独立注册入口，以便明确完成注册而非被自动建号。
11. 作为用户，我希望身份或密码不匹配时拒绝登录，以便保护角色边界。
12. 作为用户，我希望验证码过期、错误、次数耗尽或发送过频时收到可理解的提示，以便正确重试。
13. 作为用户，我希望重发验证码后旧码失效，以便只使用最新邮件。
14. 作为忘记密码的用户，我希望通过绑定邮箱重置密码，以便自行恢复访问。
15. 作为重置密码的用户，我希望验证码填错时保留已输入的新密码与确认密码，以便无需重复填写。
16. 作为重置密码的用户，我希望重置成功后全部设备下线并返回登录页，以便旧凭据失效。
17. 作为已登录用户，我希望验证当前密码后修改密码，以便保护账号。
18. 作为用户，我希望更换邮箱时验证旧、新邮箱，以便防止未经授权的换绑。
19. 作为用户，我希望换绑成功后全部设备重新登录，以便旧邮箱和旧会话不再访问账号。
20. 作为用户，我希望能在个人中心添加、修改和移除学工号，以便维护登录标识。
21. 作为用户，我希望学工号变更需要当前密码且冲突时不覆盖他人，以便保持标识安全唯一。
22. 作为用户，我希望未绑定或移除学工号后仍可邮箱登录，以便不会被锁在账号外。
23. 作为用户，我希望可同时登录多个设备，以便跨设备使用。
24. 作为用户，我希望普通退出仅撤销当前设备，以便不干扰其他设备。
25. 作为用户，我希望页面刷新和访问令牌过期时安全续期，以便减少重复登录。
26. 作为用户，我希望认证服务异常时不会绕过校验，以便故障不降低安全性。
27. 作为已有用户，我希望升级后保留题库、试卷、收藏及个人配置归属，以便不丢失历史数据。
28. 作为开发者，我希望在后端 .env 配置默认教师和学生账号，以便灵活联调。
29. 作为开发者，我希望显式初始化可重复执行且不重置已有密码或角色，以便保护本地数据。
30. 作为开发者，我希望教师和学生按钮仅填充对应账号并手动登录，以便仍验证正常认证流程。
31. 作为部署者，我希望生产禁止默认账号初始化和开发凭据接口，以便不暴露开发能力。
32. 作为部署者，我希望 SMTP、JWT 和 Turnstile 从部署配置读取并严格校验，以便不提交真实凭据。

## Implementation Decisions

### 领域与模块边界

- 在既有认证、用户资料、数据模型、配置、邮件服务和前端认证状态边界内扩展；路由负责编排，验证码、会话和人机校验使用内聚服务，不创建平行用户系统。
- 注册仅需邮箱、验证码、显示名称、密码、确认密码和教师/学生身份；学工号可空。单账号单身份，初版不可切换，无管理员角色。
- 保留不可变用户 ID；历史内部 account 不再是可输入登录标识，新用户内部生成。identity 从 role 派生，历史不一致必须先报告处理。
- 邮箱去首尾空白，按不区分大小写的登录策略建立规范化与唯一约束；不合并点号或加号标签。学工号去首尾空白、保留前导零、大小写敏感、全平台唯一，移除存 NULL。数据库约束处理并发竞争，不仅预查询。
- 新密码为 8–64 字符，且 UTF-8 不超过 bcrypt 72 字节，不静默截断；兼容既有哈希，不因新长度策略拒绝旧密码登录。

### 流程与对外契约

- 分离邮箱验证码和学工号密码登录，均校验教师/学生身份；不支持邮箱密码、手机或历史用户名登录，不保留可绕过新流程的通用旧入口。
- 拟议契约：GET /api/auth/config；POST /api/auth/email-code、/register、/login/email、/login/password、/refresh、/logout、/password/reset；GET /api/auth/me；PUT /api/auth/password。
- 安全资料契约：POST /api/users/me/email-change；PUT /api/users/me/email、/user-no。普通资料更新不得直接改邮箱、学工号、角色、密码或认证状态。
- 用户与初始模型设置同事务创建；若账号已提交但会话创建失败，明确提示“账号已创建，请登录”，不假报注册已回滚，不重复建号。正常注册成功返回当前用户、短期 access token 和刷新 Cookie；注册自动登录。密码重置、修改密码、换绑邮箱成功后撤销全部会话并返回登录，不自动创建新会话。
- 换绑事务绑定用户、旧/新邮箱快照和认证版本，有效 10 分钟；发码必须有有效登录态，收件人由事务解析。旧、新邮箱各自的验证码都通过才原子提交；旧邮箱不可访问不提供绕过或申诉入口。
- 学工号增改删验证当前密码；标识冲突或密码错误不修改数据；提交时再次校验认证版本，不能沿用并发改密前的密码验证结果，不改变用户 ID、身份与资源归属。显示名称去空白后不得为空。
- 未注册邮箱登录与重置不建号，发码响应避免泄露账号是否存在；登录页始终提供注册入口。业务错误结构一致，限流 429 加 Retry-After，依赖不可用 503；不返回秘密或堆栈。
- 前端明确 loading、失败、成功及禁用状态；错误或过期验证码及网络失败保留新密码/确认密码于组件内存，成功、离开或主动清空时销毁，不持久化。

### 验证码、SMTP 与人机验证

- 邮件码为随机 6 位数字、5 分钟有效、最多错误 5 次；每邮箱每用途重发间隔 60 秒、每小时最多 5 次，每来源 IP 每小时最多 30 次，均可配置。
- 分离注册、登录、重置、旧邮箱换绑及新邮箱换绑用途；challenge 绑定规范化邮箱、用途及必要的变更事务/认证版本；不可预测 ID，重发旧 challenge 失效。
- Redis 保存独立密钥 HMAC 摘要与状态，原子控制尝试和消费；涉及 SQL 的操作通过唯一消费凭证及事务版本条件防止并发重复执行，并定义提交失败与重试恢复，不把两个存储的独立提交误认为原子事务。
- SMTP 明确 TLS/STARTTLS、认证和超时；失败不遗留有效可消费码，也不清零滥用限流。日志不输出密码、验证码、Cookie 或令牌。测试用假发件箱。
- 所有邮箱发码及学工号密码登录执行 Turnstile 前端挑战和服务端 Siteverify，固定核验 hostname/action。过期、重复、失败与网络异常不得放行，重试需新挑战或同一 Siteverify 幂等键。
- 开发可配官方测试密钥，自动化使用假验证服务；生产缺真实配置、误用测试配置或外部服务不可用时拒绝认证入口。上线按 hostname 配置，不等待服务器 IP 才开始实现；可信代理配置控制来源 IP，不信任任意转发头。

### JWT、刷新与即时撤销

- 访问 JWT 15 分钟，固定 HS256，签名密钥至少 32 随机字节；使用成熟库，校验固定算法、签名、iss/aud、sub/sid、类型、iat/exp、认证版本和会话状态。
- 数据库持久化设备会话和用户认证版本；每次认证查询用户 active、版本及会话有效性，权限以当前用户与资源关系为准，不依赖角色快照。
- 修改密码、重置与换绑在同一事务修改数据、增加认证版本并撤销会话。登录和刷新以原校验版本作事务条件，防旧密码校验后签发新版本会话；以 SQLite 实际并发语义验证。
- 撤销提交后新进入的认证检查必须拒绝旧 JWT；敏感写入在事务提交前再次核验版本。已执行操作无法回撤；状态存储故障不退化为仅验签名。
- 高熵不透明刷新令牌仅存摘要，绝对最长 7 天，每次原子轮换，保留旧摘要以识别重放并撤销对应会话族。普通退出仅撤销当前 sid，幂等清 Cookie，不接受任意他人 sid。
- 访问令牌只存内存；刷新 Cookie 为 HttpOnly、生产 Secure、SameSite=Lax、Path=/api/auth，无 Domain。刷新/退出校验精确 Origin、CSRF 及 JSON 请求边界，CORS 不允许凭据通配来源。
- 页面恢复用刷新 Cookie 获取 access token，再读取用户。单标签刷新单飞，多标签协调；业务请求仅在认证确认未执行时最多刷新重试一次，不盲目重放非幂等操作。刷新终止失败清状态，响应丢失可能要求重新登录。

### 开发账号与迁移

- 后端 .env 配置显式开发开关及教师、学生各自邮箱、学工号、密码和显示名称；配置名及生产校验纳入样例，实际文件不入库。
- 显式开发初始化在写入前校验环境与完整配置；可创建已验证的开发邮箱，生产拒绝。幂等只跳过确定同一预期账号；冲突、角色不符报错，绝不覆盖、合并、重置或输出密码。
- 开发按钮只填充身份/学工号/密码，仍手动提交并走 Turnstile 与真实认证。仅受控本机开发、显式开关允许专用 no-store 填充端点；前后端都只绑定回环地址，精确 Origin，禁止共享入口/外部代理，生产不挂载，不把密码编入前端产物。
- 迁移先增加可兼容字段，再检查缺邮箱、未验证邮箱、标识大小写冲突及角色异常；不自动认证历史邮箱、不猜测、不静默合并。发布前由数据拥有者按受控迁移清单补齐，无法安全补齐则阻断发布。
- 保留资源外键与用户 ID；切换后拒绝旧 mc_ token 并清旧浏览器存储；删除旧登录和公开旧密码改密旁路。真实数据迁移前备份，不在本规格阶段读取数据库或执行迁移。
- 实现时同步真实 OpenAPI、生成接口文档、前端类型、启动与配置说明；此规格不提前改写当前运行契约。

## Testing Decisions

- 沿用已接受设计中的验收方案：主接缝为现有 HTTP API 测试客户端，覆盖从注册/登录到受保护资源访问的外部行为；参考既有认证与资料接口测试，不绑定私有函数结构。
- SMTP 和 Siteverify 使用依赖注入假服务，时间与随机性可控；使用临时数据库和专用隔离 Redis。运行前确认夹具会清空的逻辑库专供测试，禁止接入未知 Redis、真实邮箱或 Cloudflare。
- 必测注册成功/缺学工号/邮箱及学工号并发冲突、两种登录、身份不匹配、未注册不建号、禁用用户和资源隔离不退化。
- 必测验证码用途/邮箱/事务绑定、到期、错误次数、重发、并发消费、SMTP 失败及 SQL 提交失败后的恢复；安全操作失败不产生部分变更。
- 必测旧/新邮箱双验证、普通资料接口无法绕过、学工号密码验证、版本竞争、并发登录/刷新与全设备撤销；退出当前设备不影响其他设备。
- 必测 JWT 错算法/签名/iss/aud/时间/用户/版本/会话、刷新重放和轮换、Cookie 属性及 CSRF/Origin；依赖故障 fail closed。
- 并发验收以可重复调度的真实 SQLite 事务竞争为证据，不用串行 mock 替代；在既有客户端/服务依赖替换点注入 SMTP、Siteverify、时钟及 Redis/SQL 故障，仅在现有接缝不足时新增最小适配层。
- 浏览器级验证注册直达工作台、页面恢复、并发/多标签刷新、重置成功返回登录、验证码错误保留两个密码输入。断言用户可观察行为，而非组件实现快照。
- 显式初始化通过命令级测试验证环境拒绝、幂等、跨账号冲突与不输出密码；迁移用合成历史数据验证用户 ID/归属保留及异常阻断；生产构建确认无开发凭据和开发端点。
- 实现后运行相关后端测试及认证/隔离全量测试、Ruff、适用 Pyright、前端 typecheck/lint，以及认证路由/生产构建相关 build。仅文档阶段检查差异、引用和覆盖，不运行数据库或 Redis 测试。

## Out of Scope

管理员与管理后台、邀请/审核、组织/成员体系、多人协作及知识库分享授权、身份切换、短信、邮箱密码登录、SSO、MFA、人工申诉、账号注销；本次不开发智能体模块、不修改协作约定，不创建真实凭据或执行生产迁移。

## Further Notes

- 本规格来自用户连续确认及整体接受的设计，不再重新采访；测试接缝沿用其已接受的验收方案。实现前若需新增接缝或改变用户可见行为，应显式确认差异。
- 本轮只形成并发布规格，不实施业务代码，也不把 ready-for-agent 解释为功能已完成。
- 实施顺序：迁移与会话基础 → 验证码/邮件/Turnstile/注册登录 → 密码和安全资料 → 开发便利与完整验收。
- 具体模块位置、环境变量及迁移风险清单保留在已接受的设计文档中；发布 Issue 的正文自包含，不依赖未推送本地文档才能执行。

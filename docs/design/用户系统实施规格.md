## 本机 Turnstile 临时开关实施边界（2026-11-09，已实现并在本机启用）

本次针对用户无法登录临时跳过本机 Turnstile 人机验证。账号密码、账号启用状态、JWT/SQL 会话与撤销、Origin/CSRF、邮箱验证码、限流及 proof 消费、角色和资源归属校验继续生效；SMTP 故障仍按原规则处理，不因开关放行邮箱登录或恢复所需验证码。

`TURNSTILE_ENABLED` 默认 `true`。配置为 `false` 时，仅 `APP_ENV=development/test` 允许启动；production 在配置校验时拒绝启动。对允许启动的实例，仅实际 ASGI peer 为回环 IP（如 `127.0.0.1` 或 `::1`）的请求跳过，其他 peer 仍完整执行 Turnstile。Host、Origin、`Forwarded` 或 `X-Forwarded-For` 等头不能扩大跳过范围。

GET `/api/auth/config` 的 `AuthConfig.turnstile_enabled` 为必填 boolean，返回当前请求的有效状态：满足上述三项条件为 `false`，其余允许服务的请求为 `true`。前后端分别按各自请求判定，不把一次 config 的结果当作后续异源请求的豁免凭据。有效禁用时后端不调用 Cloudflare，前端不渲染人机验证 widget、不加载其脚本、不因缺票据或 site_key 阻止提交。有效启用时保留完整票据、action、hostname 与站点配置验证，拒绝空票据，不因请求 schema 允许空字符串而放行。

本次已向新后台启动进程注入 `TURNSTILE_ENABLED=false` 并重启本机后端，保持回环绑定并使用 `--no-proxy-headers`，不修改真实 `.env`、`local_secrets.py` 或密钥。恢复时停止该进程，以 `TURNSTILE_ENABLED=true` 重启后端，再重新加载前端获取配置；若仅移除临时环境覆盖，须保证其余受控配置仍为默认 `true`。运行进程不热更新环境，本机重启已确认；恢复开启行为通过隔离配置、验证器及浏览器测试确认，当前服务继续保持关闭。

## 当前邮箱核心流程与异常边界

1. 绑定：密码登录后进入个人安全设置；管理员在管理面板的自身安全区域操作。无已验证邮箱时，向目标邮箱申请 purpose=email_bind 验证码，发码必须携带 Bearer 并通过 Turnstile。挑战绑定当前 user_id、auth_version、原邮箱快照和目标邮箱；历史未验证邮箱按此流程处理，不自动验证旧值。
2. 提交绑定：PUT /api/users/me/email-binding 发送 email、current_password、challenge_id、code。服务端重新验证当前密码、无已验证邮箱条件、挑战用途/主体/版本/邮箱快照和目标邮箱唯一性；SQL 事务内消费 proof、写入邮箱及验证时间、递增版本、撤销全部会话。
3. 换绑：已有已验证邮箱时，沿用 POST email-change 建立事务，向旧、新邮箱分别发送 email_change_old/email_change_new 码，再 PUT email 提交双 proof；不得直接使用 email_bind 替代双码校验。
4. 解绑：DELETE /api/users/me/email 的 JSON 请求体为 {current_password}；清空邮箱及其规范化值、验证时间，email_verified=false，同事务递增版本并撤销全部会话。再次绑定须重新取得 email_bind 专用验证码。
5. 成功与失败：三类邮箱变更均返回 204，清目标用户 Cookie，前端清理该用户会话并回默认密码登录页，不自动续期或重放变更。密码错误、邮箱冲突、错码/过期/重放、跨用途/跨用户、认证版本或原邮箱快照变化时不改变邮箱和资源归属。不得将 SMTP 失败或邮箱码登录失败降级为无需验证。

绑定、换绑、解绑共享既有验证码、AuthProof、版本和会话撤销机制。提交时再次核对唯一性与版本，防止并发绑定、换绑、解绑或改密沿用旧验证；不把 Redis 与 SQL 的独立提交表述为跨存储原子事务。

## 当前验证码与会话规则

公开 login/reset_password 挑战绑定用途、规范化邮箱、用户 ID 和认证版本；发码、邮箱登录验码、密码重置验码三处构造绑定一致。安全复核发现仅 purpose/email/version 无法隔离同版本邮箱跨用户转移，补 user_id 的修复已通过相关回归。邮箱解绑后转给他人时，旧 login/reset 码均不能登录或重置新账号；部署后旧未消费挑战因绑定变化失效，需重新发码，无数据库迁移。

验证码默认 6 位、300 秒有效、最多 5 次错误；每邮箱每用途 60 秒冷却、每小时 5 次，来源 IP 每小时 30 次，配置可调整。Redis Lua 控制限额、最新挑战和验证状态，只存独立密钥的 HMAC 摘要；最终消费通过同一业务 SQL 事务中的 AuthProof 唯一键保证，事务回滚可安全重试。旧刷新摘要保留到会话到期，proof 只在 Redis 挑战实际消失后清理。

login/reset_password 在 HTTP 响应完成后发邮件；不适用收件人不投递，SMTP 故障只记脱敏固定日志、挑战不激活，已返回的 202 不变。email_bind 发码绑定登录主体、认证版本和原邮箱快照；换绑发码从事务解析旧/新邮箱。两者均需 Bearer，同步 SMTP 故障删除挑战并返回 EMAIL_SERVICE_UNAVAILABLE/503。邮件成功且挑战仍为最新才激活；限额不因故障清零。公开发码后台任务不持久化，进程中断可丢失投递，不能将 202 当作已送达。

JWT 固定 HS256，默认 900 秒；claims 包含 sub/sid/auth_version/jti/iat/exp/iss/aud/type。每次认证查询 SQL 用户启用状态、认证版本与会话状态；刷新凭据为高熵不透明值、只存摘要、默认绝对 604800 秒到期且逐次 CAS 轮换，重放撤销对应会话。改密、恢复、邮箱绑定/换绑/解绑、管理员重置/禁用在同事务更新版本及撤销会话；签发时核对原凭据验证版本。

mc_refresh 为 HttpOnly、生产 Secure、SameSite=Lax、Path=/api/auth、无 Domain；mc_csrf 同路径且可由脚本读取，config 同时返回 csrf_token。refresh/logout 必须满足精确可信 Origin、application/json 和双提交 CSRF。改密、恢复、邮箱绑定/换绑/解绑只在请求 Cookie 属于目标用户时删除，普通退出更严格地只删除同 sid Cookie。

前端 [session.ts](../../frontend/src/api/session.ts) 以同一 Web Lock 串行登录、刷新、退出及安全操作的 Cookie 响应处理；需要续期时先在锁外完成，锁内不重放安全写操作。access 只存内存；sessionStorage 只存用户/角色/sid 约束及退出阻断意图。恢复须匹配用户与角色，跨账号共享 Cookie 不触发自动身份切换；通知按用户或会话定向。业务请求仅对明确 ACCESS_TOKEN_EXPIRED 重试一次，旧代次响应和 blob 不回填。退出失败保留内存撤销凭据供原页面重试并阻止重载恢复；无本地 access 时不匿名注销 Cookie 所属账号。没有 Web Locks 支持时明确拒绝会话协调，不静默降级。

## 历史记录｜Problem Statement

个人教师和学生需要独立注册、可靠登录和自行恢复账号，而不依赖管理员开通。当前系统已有用户及资源归属，但缺少自助注册、邮箱验证码、完整密码恢复、人机验证和可立即撤销的 JWT 会话；旧登录标识混用、资料直改邮箱和撤销会话的失败窗口也需要一并消除。开发者需要可配置的教师、学生默认账号，以降低本地联调成本，同时不能向生产引入默认密码或认证旁路。

## 历史记录｜Solution

提供邮箱验证注册、邮箱验证码登录及学工号密码登录。注册后自动进入对应工作台；用户可在个人中心安全维护学工号、密码和绑定邮箱。所有发码和密码登录接入 Turnstile，使用短期 JWT 与可撤销刷新会话。开发账号通过后端环境配置及显式初始化命令创建，开发快捷按钮只填充、不自动登录。保持现有用户 ID、角色权限和数据归属不变。

## 历史记录｜Implementation Decisions

### 历史记录｜领域与模块边界

“无管理员角色”和内部 account 不可输入是原邮箱分支范围；当前三角色及账号登录契约见上文。

- 在既有认证、用户资料、数据模型、配置、邮件服务和前端认证状态边界内扩展；路由负责编排，验证码、会话和人机校验使用内聚服务，不创建平行用户系统。
- 注册仅需邮箱、验证码、显示名称、密码、确认密码和教师/学生身份；学工号可空。单账号单身份，初版不可切换，无管理员角色。
- 保留不可变用户 ID；历史内部 account 不再是可输入登录标识，新用户内部生成。identity 从 role 派生，历史不一致必须先报告处理。
- 邮箱去首尾空白，按不区分大小写的登录策略建立规范化与唯一约束；不合并点号或加号标签。学工号去首尾空白、保留前导零、大小写敏感、全平台唯一，移除存 NULL。数据库约束处理并发竞争，不仅预查询。
- 新密码为 8–64 字符，且 UTF-8 不超过 bcrypt 72 字节，不静默截断；兼容既有哈希，不因新长度策略拒绝旧密码登录。

### 历史记录｜流程与对外契约

本节“不支持历史用户名登录”针对已移除的通用 OR 查询旁路；当前另有受限无邮箱 /login/account，不恢复旧旁路。

- 分离邮箱验证码和学工号密码登录，均校验教师/学生身份；不支持邮箱密码、手机或历史用户名登录，不保留可绕过新流程的通用旧入口。
- 拟议契约：GET /api/auth/config；POST /api/auth/email-code、/register、/login/email、/login/password、/refresh、/logout、/password/reset；GET /api/auth/me；PUT /api/auth/password。
- 安全资料契约：POST /api/users/me/email-change；PUT /api/users/me/email、/user-no。普通资料更新不得直接改邮箱、学工号、角色、密码或认证状态。
- 用户与初始模型设置同事务创建；若账号已提交但会话创建失败，明确提示“账号已创建，请登录”，不假报注册已回滚，不重复建号。正常注册成功返回当前用户、短期 access token 和刷新 Cookie；注册自动登录。密码重置、修改密码、换绑邮箱成功后撤销全部会话并返回登录，不自动创建新会话。
- 换绑事务绑定用户、旧/新邮箱快照和认证版本，有效 10 分钟；发码必须有有效登录态，收件人由事务解析。旧、新邮箱各自的验证码都通过才原子提交；旧邮箱不可访问不提供绕过或申诉入口。
- 学工号增改删验证当前密码；标识冲突或密码错误不修改数据；提交时再次校验认证版本，不能沿用并发改密前的密码验证结果，不改变用户 ID、身份与资源归属。显示名称去空白后不得为空。
- 未注册邮箱登录与重置不建号，发码响应避免泄露账号是否存在；登录页始终提供注册入口。业务错误结构一致，限流 429 加 Retry-After，依赖不可用 503；不返回秘密或堆栈。
- 前端明确 loading、失败、成功及禁用状态；错误或过期验证码及网络失败保留新密码/确认密码于组件内存，成功、离开或主动清空时销毁，不持久化。

### 历史记录｜验证码、SMTP 与人机验证

- 邮件码为随机 6 位数字、5 分钟有效、最多错误 5 次；每邮箱每用途重发间隔 60 秒、每小时最多 5 次，每来源 IP 每小时最多 30 次，均可配置。
- 分离注册、登录、重置、旧邮箱换绑及新邮箱换绑用途；challenge 绑定规范化邮箱、用途及必要的变更事务/认证版本；不可预测 ID，重发旧 challenge 失效。
- Redis 保存独立密钥 HMAC 摘要与状态，原子控制尝试和消费；涉及 SQL 的操作通过唯一消费凭证及事务版本条件防止并发重复执行，并定义提交失败与重试恢复，不把两个存储的独立提交误认为原子事务。
- SMTP 明确 TLS/STARTTLS、认证和超时；失败不遗留有效可消费码，也不清零滥用限流。日志不输出密码、验证码、Cookie 或令牌。测试用假发件箱。
- 所有邮箱发码及学工号密码登录执行 Turnstile 前端挑战和服务端 Siteverify，固定核验 hostname/action。过期、重复、失败与网络异常不得放行，重试需新挑战或同一 Siteverify 幂等键。
- 开发可配官方测试密钥，自动化使用假验证服务；生产缺真实配置、误用测试配置或外部服务不可用时拒绝认证入口。上线按 hostname 配置，不等待服务器 IP 才开始实现；可信代理配置控制来源 IP，不信任任意转发头。

### 历史记录｜JWT、刷新与即时撤销

当前退出必须绑定本标签 Bearer 的 sid；只有同 sid Cookie 被清除，不能把“幂等清 Cookie”解释为清除另一账号或设备的共享 Cookie。

- 访问 JWT 15 分钟，固定 HS256，签名密钥至少 32 随机字节；使用成熟库，校验固定算法、签名、iss/aud、sub/sid、类型、iat/exp、认证版本和会话状态。
- 数据库持久化设备会话和用户认证版本；每次认证查询用户 active、版本及会话有效性，权限以当前用户与资源关系为准，不依赖角色快照。
- 修改密码、重置与换绑在同一事务修改数据、增加认证版本并撤销会话。登录和刷新以原校验版本作事务条件，防旧密码校验后签发新版本会话；以 SQLite 实际并发语义验证。
- 撤销提交后新进入的认证检查必须拒绝旧 JWT；敏感写入在事务提交前再次核验版本。已执行操作无法回撤；状态存储故障不退化为仅验签名。
- 高熵不透明刷新令牌仅存摘要，绝对最长 7 天，每次原子轮换，保留旧摘要以识别重放并撤销对应会话族。普通退出仅撤销当前 sid，幂等清 Cookie，不接受任意他人 sid。
- 访问令牌只存内存；刷新 Cookie 为 HttpOnly、生产 Secure、SameSite=Lax、Path=/api/auth，无 Domain。刷新/退出校验精确 Origin、CSRF 及 JSON 请求边界，CORS 不允许凭据通配来源。
- 页面恢复用刷新 Cookie 获取 access token，再读取用户。单标签刷新单飞，多标签协调；业务请求仅在认证确认未执行时最多刷新重试一次，不盲目重放非幂等操作。刷新终止失败清状态，响应丢失可能要求重新登录。

### 历史记录｜生产认证密钥生成与配置交付（2026-11-05）

- 验收标准：不存在明文 stdout 认证密钥生成入口；根目录树与实际文件一致，配置文档与样例覆盖字段、默认值、来源及上述边界，本地链接有效。仅核对静态差异与链接，不接入真实凭据、SMTP/Cloudflare、数据库或 Redis，不据此宣称上线验收完成。

- 上传复用认证操作边界：确保会话、记录代次、只在认证阶段明确拒绝执行的 `ACCESS_TOKEN_EXPIRED` 401 刷新并重试一次；若并发已有新 token 直接复用。其他 401、角色／用户变化、退出与旧成功响应均不得跨会话重放或回填。进度回调保持。

## 4. 甲的交付和依赖

### 4.1 M1 与 G0 证据归档

甲接入 SDK 原生 tracing，首条 trace 前替换默认处理器链，仅导出至本地 Phoenix；模型业务流量与追踪出口分开核验。关联 run、会话、账号、批次、阶段及工具；导出前对白名单正文及嵌套属性、异常、缓冲载荷脱敏，使用有界缓冲、重试和退出刷新。

G0 允许验收专用内存事件收集器，用来关联执行事实、成功／失败／降级与追踪。它不要求运维 SQL，也不承担生产台账、持久幂等或独立周期心跳。内存证据应归档为可复核的合成样例与记录；进程内捕获成功不能代替本地 Phoenix 根／子 spans 持久可查证据。

甲负责验证 Phoenix 初始清理，归档锁定版本、受支持机制、唯一调度责任、配置和实际删除证据，G0 后交乙维护 M8。不能因交接再启动第二套 Phoenix 清理调度。

### 4.2 G0 后的 M2／M3 与 runs API

甲实施 SQL 运行摘要、事件幂等、受理／开始／阶段／权威终态及独立于模型调用的周期心跳。重复、乱序事件及迟到心跳不能回退已确认终态；摘要写入失败报告采集缺口，不伪造业务失败。甲提供事实与统一统计服务，乙负责疑似等待、长运行、心跳过期的观察判断；runs 接口读取同一判断来源。

甲负责题量、最终版本审核覆盖、真实重出尝试、结果、耗时和降级证据，提供运行与质量统计服务给乙。交接应包含输入窗口及时间基准、去重键、已知样本／排除样本、分子分母、覆盖状态和未知原因。概览按 `accepted_at` cohort，质量告警按 `finished_at` 窗口；乙使用同一服务的明确口径，不复制公式。

审核证据必须关联题目标识、内容版本及实际审核范围：

- 改变题目内容或重出替换后，不沿用旧版本通过证据；审核只覆盖部分内容时，不外推为整题通过。
- 缺少匹配最终版本及所需范围的证据为 `unknown`；明确跳审才计跳审，缺证据不能标为跳审。
- 本任务采集与展示已有审核事实，不自动追加模型复审；若要改变业务审核策略，应另行确认。
- 最终版本重复审核按题去重；零成果、缺采集或审核未知不能冒充审核完整或质量 `met`。

旧 `regenerated` 的准确含义是**每次尝试去重后、评估前候选数之和**，不是重出次数，也不是最终交付保留数。比如两次尝试在该位置分别有 3、2 个候选，旧值为 5，尝试次数为 2，最终保留数仍取决于后续评估和交付。新指标单独记录真实尝试，不从旧值反推。

甲交付自身模型、请求／响应 schema、迁移及顺序依赖说明，由乙统一编排；runs 列表／详情与统计服务保持同一事实来源。

## 5. 乙的交付和依赖

### 5.1 M4／M5 及三个查询 API

乙实现分作用域依赖观测、受控探测、新鲜度、连续失败／恢复证据，区分个人凭据与共享服务故障；后台查询不触发付费模型探测。SQL 不可用时报告真实不可用，不以缓存伪装为健康。

乙依据甲的权威执行事实判断疑似等待、长运行与心跳过期，维护观察标记、触发／恢复／复发轮次、去重和站内通知。不强停、不合成失败／取消、不改写业务终态；新鲜心跳只解除相应心跳条件，不能消除仍存在的长运行条件。默认规则沿用模块说明及契约：等待超过 30 秒并连续观察 120 秒、运行超过 600 秒、心跳过期超过 90 秒；缺证据或监测中断不补造连续观察。

质量告警消费甲的统计服务，以最近 5 分钟已完成且质量可判定的去重 run 为样本，至少 10 个且 attention 比例达到 20% 才触发；同一 run 多原因在总体只计一次。同口径足样本且比例低于 20% 连续 120 秒才恢复，低样本或未知重置恢复计时并保留待检测。乙不自行重算审核覆盖、重出和质量状态公式。频繁重出阈值未校准时标未配置，不自行告警。

乙交付 overview／dependencies／alerts，复用甲的统计服务及已有管理员权限边界；告警通知保持 SQL 幂等和现有通知机制，不以页面刷新驱动生成或恢复。

### 5.2 M8 与集成统筹

乙接收甲的 Phoenix 初始清理验证，维护后续清理和检测调度。Phoenix 原生调度或应用经受支持接口调度二选一，记录唯一责任；若选原生调度，乙维护其配置与结果，应用不再执行第二套。不得操作 Phoenix 私有表。

乙同时负责 M9：记录采集延迟、事件丢弃、Phoenix 导出失败／积压、告警评估停滞、清理失败、通知投递失败、运行／trace 关联缺失和存储空间状态；实现 warning／critical 容量判断及配置生效值展示。管理员查看运行、告警、trace 和正文的访问审计由乙落库，本人检查权限和审计边界；审计失败不得放行正文。

M8 在现有 lifespan 管理检测与清理，限定 single worker／单实例；默认正文 3 天、SQL 摘要 14 天、每日清理，可配置、有界、分批、可重入且可恢复。活动运行和仍需检测的 unknown 运行，以及活动／待检测故障的最小判定、去重、恢复、通知状态受到保护；每日复核保护原因，解除后按到期规则清理。摘要保护不延长正文期限，不要求保留全部故障历史。SQL 与 Phoenix 清理分别记录结果，一方失败不伪造另一方成功。

乙统筹迁移顺序、OpenAPI 和生成 API 文档；甲提供自身模型／schema／迁移，乙协调依赖、迁移链与接口覆盖，本人检查前后端契约。生成文档后逐条核对五个实际路径及字段，不能只以脚本退出成功作为完成。

共享配置、依赖声明和 `app.main`／lifespan 等 main 接线实行单编辑者协调：每批修改前明确编辑者及双方接入清单，其余人提供接入需求，避免同时改写。该职责不等于未经确认一律合入 `main` 分支；后续实现开工时按仓库约定确认目标分支。

## 8. G0 后联调、异常与总验收

后续验收依次覆盖 SQL 持久化与迁移、运行事件幂等及独立周期心跳、完整质量统计、探测与告警、五个查询 API、SQL 14 天清理和活动保护，以及运维链路自监控、容量保护和正文访问审计；这些是 G2／G3 交付条件，不倒置为 G0 前置。

| 联调场景 | 验收结果 | 主要交付方 |
| --- | --- | --- |
| 受理未开始、开始前失败、正常完成、明确取消、重复／迟到事件 | 权威状态准确，重复不累加，监测不制造终态；疑似条件单独展示 | 甲事实，乙观察，本人联调 |

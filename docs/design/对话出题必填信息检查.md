# 对话出题必填信息检查

状态：已实现（2026-10-30），2026-11-11 随四模式整合更新来源要求，2026-11-19 升级为模型模板化抽取、题型级难度与自然追问。

## 目标与使用范围

保留 `/api/chat` 的多轮信息抽取、累积与追问流程。教师明确题型、每种题型数量与难度（整体或按题型）、出题范围后，才启动快速出题。题量没有默认 5 道的行为；参数化 `/api/generate` 继续遵循其原有契约，`TypeCountBody` 支持可选的题型级 `difficulty`（低|中|高|地狱）。当前知识点流水线不再要求选择题目来源，显式来源值仍兼容，未提供时使用 `variant_data`；四模式差异见[整合说明](对话四模式与主线整合.md)。

## 核心流程

1. 信息抽取由模型按固定 JSON 模板填写：知识点范围、题型列表（题型、数量、该题型难度）、总题量、整体难度、混合难度标记、来源模式与图片说明。只填教师明确表达的内容，未提及一律 `null`，同义词先归一（简单→低等）。同一题型给出多个难度档（如难度分别是简单、中等、高难）时按混合难度处理，整体难度档保留原始描述供生成指令使用。
2. 将新信息合入已有要求。教师没有重新说明数量或难度时，保留之前明确的值；新增题型未给数量时保持缺失，不补默认值。
3. 逐项检查题型、各题型数量、范围和难度。难度已被整体难度或任一题型难度满足时不再追问；缺少题型时一并询问题型与数量；题型已知时，只列出数量缺失的题型。空白范围也视为缺失。
4. 信息不完整时先由模型生成自然追问（只问缺失项、不重复已确认信息，失败或未配置模型密钥时回退固定模板），并返回追问、累计状态、空题目列表及 `done=false`，不调用题目生成服务。没有追问轮数上限。
5. 全部信息齐备后构造生成参数：题型级难度写入 `TypeCount.difficulty`，整体难度缺省时取第一个题型难度，再缺省回退中档；参数构造也拒绝不完整要求，避免绕过编排检查时回退默认数量。

## 数据契约与异常边界

请求与响应字段不变。`slot_state.types` 为题型、数量与题型级难度的列表；尚未确认的 `count` 与未说明的题型级 `difficulty` 为 `null`。`slot_state` 沿用前端逐轮回传方式。

数量沿用 `TypeCount` 的约束，每种题型为 1–100 道。布尔值、非整数、非有限数字、零、负数和超过上限的数量不能作为有效数量；在没有有效历史数量时继续追问。已有有效数量不会被后续未提及数量的抽取结果清空。

生成与审核链路按题型难度执行：命题提示词、考点规划、题目标注与盲评目标档均优先使用题型级难度，未单独指定难度的题型回退整体难度档；混合难度分布只作用于没有题型级难度的题型。换模板重出与配额补齐携带对应题型的难度。

模型负责从教师自然语言中抽取信息，后端负责结构和完整性检查。历史会话中已经填入的 5 无法辨别是教师明确要求还是旧代码默认值；本次不追溯改写历史状态，需要重新确认的旧会话应重新开始。

## 验收标准

- 只给题型但未给数量时持续追问，不出题。
- 多题型中仅一部分明确数量时，只追问尚缺数量的题型。
- 后续补齐数量后，保留先前已明确的数量，齐备后才调用生成。
- 范围缺失、且整体难度与题型级难度均未给出时，不生成。
- 按题型分别说明难度（如 5 道低难度选择题、2 道高难度填空题）时不追问难度，缺范围只追问范围。
- 同一题型给出多个难度档时按混合难度出题，不追问难度。
- 非法数量不能启动生成，不能自动截断小数或默认补为 5。
- 回归测试使用假的抽取与生成服务，不连接真实模型或知识库。

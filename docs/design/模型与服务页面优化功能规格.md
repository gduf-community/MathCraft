## Problem Statement

教师已能配置主语言模型、辅助任务模型、嵌入模型和共享连接，但目前主要通过 Profile 与模型下拉框切换编辑对象。提供方、连接与模型之间的关系不够直观，用户难以浏览已有配置、定位某个模型、判断当前默认模型，以及理解先连接提供方再添加模型的顺序。

教师需要在保留 MathCraft 视觉习惯的前提下，更容易找到提供方、创建多个连接，并以模型为单位浏览和编辑。参考图展示了更清楚的导航、提供方卡片、模型列表和详情区；其中后台任务逐项覆盖等额外能力超出本轮确认范围，不能随布局优化一并引入。

页面重排还必须保持正式配置与草稿的真实边界，避免编辑对象被误当成默认选择、连接测试被误认为模型可调用，或因简化表单丢失已有引用与凭据。

## Solution

### 导航与视觉

保留 MathCraft 应用主导航及设置中的其他分区。在模型与服务区域采用左侧子导航、右侧内容区，按“提供方、主语言模型、辅助任务模型、嵌入模型”组织；进入该区域默认展示提供方。

参考 DeepTutor 的布局、组件组织和添加流程，沿用 MathCraft 的蓝白配色、字体、圆角、边框、图标和反馈方式。宽屏提供方目录使用双列卡片；主语言模型和嵌入模型在右侧内容区内再分模型列表与详情两列。窄屏按阅读顺序堆叠，确保输入与操作可达，不挤压成不可用的多栏。

### 提供方与连接

提供方页面分“已配置”和“添加提供方”。已配置卡片以模型连接为操作对象，显示连接名称、模型提供方和关联模型用途。同一提供方允许建立多个连接，分别用于不同账号或服务地址。

添加区域提供搜索、按真实能力筛选和双列提供方卡片。选择提供方后，在右侧内容区进入连接配置视图，填写名称、地址、凭据和当前后端支持的参数；提供返回列表入口，返回保留当前模型目录编辑。能力标签只表示适配能力，不保证账号权限、具体模型可用性或推理成功。

### 主语言模型与嵌入模型

两页均采用左侧添加入口、搜索框、模型卡片列表，右侧添加或配置区。搜索支持模型和提供方名称；卡片展示模型名称、所属连接和默认标记，选中卡片仅切换编辑对象，设为默认是独立操作。

添加模型时先选择支持当前用途的已配置提供方连接，再按当前接口能力发现模型或手动填写模型标识。没有可用连接时，引导进入提供方管理。保留已有独立连接、Profile 和引用配置的兼容入口，不强制迁移或将多个模型重建为丢失关联的新记录。

### 辅助任务模型

参考后台任务截图的分组设置行：左侧名称和说明，右侧模型选择。继续提供“跟随主模型”“引用指定主模型”“独立配置”三种模式。独立配置复用本轮模型编辑体验所需的既有能力，不因切换模式清除已有独立配置。本轮不增加对话标题、开场建议等逐任务覆盖。

### 草稿与反馈

四个子页共享同一模型目录草稿，子页切换保留当前编辑。继续区分未保存编辑、已保存草稿和正式生效；提供保存草稿、应用更改、丢弃和重新读取。加载、忙碌、空态、搜索无结果、校验失败与后端失败均有真实反馈。失败保留可恢复输入，离开或重新读取时沿用已有未保存提醒。

## Implementation Decisions

1. **范围与模块职责**：调整设置导航、模型目录编辑容器、提供方连接工作区、模型列表与详情、辅助任务设置行；保持设置 API 适配器和模型目录为共同事实来源，不另建模型存储或长期明文凭据缓存。
2. **实体边界**：模型提供方是服务厂商或平台；模型连接是一组可复用访问信息。提供方已配置卡片对应连接实例，不以厂商名合并多个连接。Profile、模型内部 ID、提供方模型标识继续保持不同含义。
3. **模型展示映射**：以模型为列表单位，从现有目录映射可编辑项，保持内部 ID、Profile 归属、活动选择和引用不变；不要求把既有多模型 Profile 拆成新记录。相同提供方模型标识可由不同连接或用途区分，不能以展示名替代内部 ID。
4. **编辑与选择**：当前查看的模型和用途默认选择独立。模型列表上的默认标记反映当前编辑目录的活动选择；页面另显示正式配置或草稿状态，草稿默认变更不得冒充正式生效。
5. **提供方目录与筛选**：使用后端返回的提供方目录与可核实用途信息。筛选只表达已支持的能力，不从厂商品牌推断账号权限；不得新增虚假的搜索、语音、图像等服务入口。目录无匹配和无可用连接均需明确空态。
6. **添加与返回**：新增连接先选提供方，再配置参数。模型添加先选支持当前用途的已配置连接，再发现或手动添加。返回列表与子页切换保存当前本地目录编辑，不触发自动正式应用；已有连接来源或引用的兼容编辑继续可达。
7. **现有字段兼容**：保留当前连接与模型支持的协议、服务用途覆盖、版本、代理、额外请求头、凭据池、能力声明、上下文信息、嵌入维度等字段和适用限制。高级字段可渐进展开，但不得通过重建有限字段对象裁剪配置。
8. **辅助任务语义**：沿用 inherit、reference、profiles。跟随主模型解析当前正式主模型；草稿中的预览不得表述成正式解析结果。已有未知覆盖字段继续原样保留，不新增逐任务覆盖编辑界面。
9. **读取与草稿**：读取正式目录、提供方目录和已存草稿；有草稿时优先作为编辑基线。四个子页共用编辑状态与脏状态；保留开放字段、其他服务以及草稿 extensions。
10. **保存与应用契约**：保存整份目录至草稿。应用使用无请求体的 POST，只消费已存草稿；本地未保存编辑存在时禁止应用。应用后重新读取正式目录及草稿并核对，读取或校验失败不能宣称已成功或已回滚。
11. **丢弃与重新读取**：沿用既有丢弃目录草稿、撤销本地编辑及重新读取行为。操作可能涉及整份草稿扩展时说明范围，不伪装成仅丢弃当前卡片；有未保存编辑时沿用现有确认。
12. **模型发现契约**：保留既有模型列表探测和语言模型获取的接口差异与调用限制，不通过界面合并绕过版本、代理、请求头、凭据池或掩码限制。模型发现成功只说明对应发现流程成功。
13. **引用与删除**：共享连接、Profile、模型的删除沿用全目录引用检查；被引用项禁止直接删除并显示原因。通过布局优化不得把引用隐式复制成独立明文连接。
14. **凭据与失败处理**：保持掩码代表保留、更换与明确清除的既有语义。显示错误前沿用脱敏处理；失败时保留可恢复输入，请求忙碌时防止重复提交，不把后端失败转成假成功。
15. **嵌入变更**：保留身份变更检查与应用前确认；默认选择变化不自动重建知识库，仅换凭据不当作身份变化。无法可靠确定影响范围时明确表达，遵守正式知识库作为唯一入口的架构决策。
16. **布局与可达性**：沿用现有视觉令牌与通用控件；宽屏使用已确认双列组织，窄屏按顺序堆叠。保持可见标签、键盘焦点、选中状态和状态反馈，不只靠颜色区分状态。
17. **接口变更边界**：本轮原则上复用现有契约，不新增业务服务或逐任务路由字段；若实施发现现有字段无法支撑已确认行为，应明确记录差异并同步契约文档，不静默扩大能力。

## Testing Decisions

### 验证接缝与原则

以用户页面操作到设置 HTTP 边界，再到保存/应用后读回结果作为主要行为链。复用现有设置 API、隔离设置目录和假服务，避免为卡片内部状态另设测试接口。此策略沿用讨论中的验收基线，属于实施建议，不声称用户逐项选择了测试工具。

只验证外部可观察行为与配置结果。纯布局、样式和可逆低影响变更通过页面检查、键盘与窄屏验收，不编写与组件实现一一对应的镜像测试。新增自动化应优先覆盖易破坏的引用、草稿隔离和凭据保留，避免只断言按钮存在或响应状态码。

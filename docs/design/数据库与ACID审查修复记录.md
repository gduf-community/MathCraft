## 目标与约定

修复《审查数据库设计与 ACID》列出的 13 项并发和故障恢复问题，范围为现有试卷、题库、学习空间、出题、对话与 OCR 流程。学习空间已有前端入口，本次只调整已有页面；不新增任务管理后台或未实现业务界面。

所有试卷增加独立的关闭状态，关闭后禁止开始作答和交卷。整卷及卷内单题删除必须先关闭，整卷删除还要求所有发布空间停止作答。已有作答后不得替换题目；删除保留历史题目快照、答案和成绩，复盘与统计使用原作答快照。仅从组卷记录移除已发布试卷不等于整卷删除。

SQL 保存任务所有者、运行标识、状态和结果关联，Redis 为可重建的缓存与辅助租约；任务表不保存模型凭据。服务重启后未完成任务标为中断，由用户重试，不自动重跑模型。取消和结果提交均核对具体运行标识。

参数化任务后续补齐按任务取消、启动请求幂等及执行退出门禁：取消中仍禁止受理新任务，已发出的线程工作退出后才确认取消终态；清空覆盖已提交但尚未展示的题目。迁移 `o0b1c2d34567` 接续 `n9a0b1c23456`，新增请求标识与执行结束时间。当前行为、异常边界与本轮验证见[快速出题取消与清空](快速出题取消与清空.md)。

SQL 与 Chroma、文件系统不提供分布式事务；删除采用持久化意图、不可用中间状态及幂等恢复，成功完成才返回 204。OCR 缓存校验完成后原子发布，拒绝复用未完成缓存。

## 状态与历史数据

| 对象 | 状态或字段 | 含义 |
| --- | --- | --- |
| 试卷 | `status=draft/published` | 是否已发布，与能否作答分别判断 |
| 试卷 | `closed=false/true` | 整卷开放／关闭；时间窗和空间停止状态仍独立生效 |
| 试卷 | `deleted=true` | 业务删除，仅保留历史，不允许恢复开放或继续编辑 |
| 空间发布 | `stopped=false/true` | 仅停止或恢复该空间的作答，不覆盖整卷关闭状态 |
| 作答 | `answering/grading/submitted` | 待交卷／已领取批卷权／已提交；重启将中断批卷恢复为待交卷 |
| 出题任务 | `queued/running/done/failed/interrupted` | SQL 为权威状态；最后三种为终态 |
| 删除操作 | `pending/vectors_deleted/sql_deleted/completed` | 已登记／向量已删／SQL 已清／文件已清；阶段可幂等重试 |

创建作答时固定题目 ID 顺序与总分。卷内移除只标记 `removed`，不改旧快照的题号、分数或答案；批卷中的试卷暂不允许删题或删卷。交卷先在短事务领取唯一运行标识，事务外调用模型，再锁定试卷、重新检查账号状态、认证版本、作答状态、关闭和发布门禁，一次保存答案及成绩。失败只释放本轮处理权，原答案保留。

普通列表默认隐藏业务删除的试卷；`GET /api/papers?include_history=true` 可包含本人试卷的已交卷归档。已有组卷记录保留个人历史复盘入口，学习空间保留学生本人已有交卷的归档，以及教师的历史讲解与统计入口；归档不提供写操作。教师通过仅创建者可用的 `GET /api/papers/{id}?history=true` 获取包含已移除题目的历史快照。已关闭／删除试卷优先打开最近一次已交卷记录，未完成的重做不会遮住旧成绩。

## 任务、删除与缓存边界

原有 SQLite、Redis 和 Chroma 本来就有持久化部署能力。此前缺少的是业务事实的可靠落点：进程退出后，单靠后台函数和 Redis 临时键无法证明任务属于谁、哪一轮仍有效、结果是否已写入。本次新增 `generation_tasks` 保存所有者、请求参数、run、状态、批次及脱敏结果；模型凭据仅在内存执行上下文中传递。任务受理在同一用户的 SQL 门禁内检查进行中任务，旧执行者只能修改自己的 run；Redis Lua 比较 token 后才续租或释放。

对话的槽位、模式、待续消息及图片、运行和取消标识一并存入 SQL；成功轮次的两条消息、生成批次与会话状态在同一事务提交。模型和审核开始前结束 SQL 读写事务，审核语料在短读事务中物化后释放连接，进度更新和取消不依赖仍被模型调用占用的连接。取消绑定请求读取到的具体 run，旧取消不能落到后继运行。

删除先预热向量存储，再在资料变更门禁内记录不可用状态、索引 generation 和文件清单。向量清理、SQL 清理和文件清理分别持久推进；重试使用记录中的 generation，不能误删重建后的集合。SQL 已清但文件占用时仍保留恢复记录；原 DELETE 重试与启动恢复继续完成。资料入库中拒绝删除；上传与重新解析在写门禁内重检题库状态与权限，不能在已固定清理清单后新增资料。未完成删除阻止索引重建，包含题库 SQL 已清、原件尚待清理的窗口。

OCR 的 `full.manifest.json` 绑定源 PDF 的 SHA-256、字节数、页范围、分片号及解析参数，并记录 Markdown 的字节数和哈希。正文与清单使用同目录临时文件、刷盘及原子替换，清单最后发布；两次替换之间退出、正文截断、来源或参数变化均视为缓存未命中。无完成清单的旧缓存会重新识别，不通过放宽校验继续复用。

### 本轮已确认的业务决策

以下已获用户确认，实现与验证结果分别记录于后文：

1. 对已有作答的发布关系，拒绝物理移除；教师使用已有停止作答或整卷删除流程，继续保留历史复盘和统计。没有作答的发布关系仍可在停止后移除，避免为了一个未暴露的页面操作另建归档状态。
2. 催交遵循现有页面的可操作范围：整卷已关闭、已删除或本空间已停止作答时均不可催交；在统一业务入口内检查，覆盖直接请求。
3. 对话中的“删除试卷”默认与组卷记录页面一致；明确要求整卷删除时才使用对应操作，并复用关闭、所有发布停止及批卷门禁。确认预览必须说明实际影响，不自动关闭试卷或停止空间。
4. 在现有空间试卷行补充“从本空间移除”按钮及确认说明。移除前必须停止本空间作答，后端在同一试卷事务门禁内按 `paper_id + space_id` 检查本空间任意状态的作答；已有作答就拒绝移除，其他空间已有作答不影响本空间撤下。失败留在确认框显示原因，可改用停止作答。仅影响该空间的发布，不删除整卷或其他空间发布。

### 本轮实现

- 学习空间新增“从本空间移除”。后端 DELETE 与更新 `space_ids` 共用试卷写门禁和按空间的作答检查；有作答时保留发布关系，历史作答与教师统计入口继续有效。催交在同一门禁内刷新关闭、删除和本空间停止状态，并检查冷却时间。
- 对话数据 DSL 明确 `mode=record|paper`。默认移除组卷记录；只有明确的整卷删除请求才使用 `paper`。确认预览说明实际影响，执行按试卷 ID 排序，在同一事务内调用既有删除服务，任一失败整体回滚。

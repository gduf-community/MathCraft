## 3. G0 独立准备的实现

固定组合：Python 3.14.0、Agents SDK 0.20.0、OpenInference adapter 2.7.0、OTel 1.45.2、httpx 0.28.1；依赖见工具 `pyproject.toml` 与 `uv.lock`。Phoenix 21.0.0 amd64 镜像锁定 digest `sha256:b5bcec3455bd5c431f52737fc62046c081752b483e3fff40c63f40783736bcad`，限 2 CPU / 2 GiB。

本地 Phoenix 使用新目录、独立认证和 7 天限期系统导出 key；仅发布 `127.0.0.1:6016`。首条 SDK trace 前用 `exclusive_processor=True` 替换默认处理器；结束后清空恢复的默认链，防止退出时回落云端。运行时 socket 守卫拒绝非回环地址，模型和工具完全在进程内执行。

脱敏覆盖合成凭据字段、嵌套 JSON、Header、Cookie、URL 参数、异常文本、JWT／私钥形式；认证／密码／模型设置的正文整体排除。OTLP resource、scope、span、event、link 与 status 均在捕获和入队前处理。只保存脱敏载荷，不保存原始异常或导出响应正文。当前仅合成正文，真实业务白名单还需结合交接收紧。

队列 64 项、worker 每批最多 8 项、单项不超过 256 KiB，重试最多 2 次、请求超时 0.5 秒；显式 flush 最多 3 秒、关闭等待约 2 秒。满队列直接记丢失，导出边界异常记缺口，不回写业务失败。上述上限只约束本工具的导出路径，不代表 SDK 全部活跃状态或生产并发已受控。

### 清理选择与维护交接

唯一机制为 **应用通过 Phoenix 公开 REST 时间窗 API**：`DELETE /v1/projects/{project_identifier}/traces?start_time=...&end_time=...`，按 trace 的开始时间执行左闭右开 UTC 窗口，并级联删除其 spans。测试已归档 204 与删除后复读，不能只凭 204 判断真实删除。

工具的 `POLICY` 记录正文 3 天、每日一次、24 小时窗口、每次最多 8 窗口。隔离项目原生规则 `maxDays:0` 禁用；废弃的整点清理试验项目亦转为禁用策略，避免遗留另一套调度。早期试验日志／样例保留，不能误算为成功证据。

本批没有注册周期任务，三天／每日是已归档的目标配置和手动验证参数，尚未接到生产生命周期。G0 后乙/M8 接收同一公开接口、策略、UTC 边界和样例，实施持久游标、任务周期、失败结果、有限批次及恢复；不能同时开启原生过期规则。正式项目清理配置、SQL 14 天与活动摘要保护仍在 G0 后实现。

固定 Phoenix 21 的原生 sweeper 先等下一整点，Cron 分钟必须为 0，不能把“创建策略后 150 秒内应执行”的假设当证据。技术来源、替代方案及限制见 [技术核验](运维后台G0技术核验.md)。

> 状态：已实现；实际 SQL 迁移、Chroma 原路径与运行设置服务已核验，完整后端全量基线已通过，末轮定向验证与独立审查已完成。日期：2026-11-10。

## 目标与使用范围

应用设置仅保留“模型与服务”。题库相关配置使用已有题库管理入口；embedding、向量数据库等系统模型与检索配置归管理员页面。配置保存结果使用明显的小弹窗：成功为绿色底色，错误为红色底色，视觉形式参考用户提供的截图。

本轮针对当前 main 的教师、学生工作台与管理员页面。保留既有账号、题库成员和资源归属边界，不修改 AGENTS.md。现有未提交修改属于工作区基线。

## 已确认并实现的决策

- 管理员页面采用后台管理布局：左侧栏切换功能，右侧展示内容。延续账号管理、平台概览与自身安全能力，增加系统模型与检索配置。
- 管理员首版可编辑嵌入模型、重排模型及对应服务地址和凭据。向量数据库继续使用本地 Chroma，展示存储位置与状态，首版不编辑路径或切换数据库类型。
- 个人中心只保留个人资料和安全设置，不保留模型配置表单或状态摘要；个人 DeepSeek Key、MinerU Token 及模型状态统一放设置页。
- 应用设置移除旧知识库连接、知识库引擎和文档解析分区，题库相关操作使用已有题库管理；不因移除旧表单改变当前文档自动解析行为。
- 配置保存及模型测试使用统一小弹窗：顶部居中，图标、文字和关闭按钮；成功为绿色底色约 3 秒，错误为红色底色约 6 秒。字段错误仍在表单附近保留，保存期间显示进行状态。
- 嵌入模型或服务 URL 变更先保存为待应用配置，管理员另行确认“重建索引并应用”；仅更新活动嵌入凭据或重排配置时供后续请求使用，不重建索引。
- 重建复用已解析的 SQL 切片，不重复 OCR；旧配置与旧索引继续支持读取、查询和出题，资料变更暂时暂停。全部新向量完成后切换活动版本，失败保留旧版本并允许重试。
- 普通设置和管理员模型配置均保护编辑草稿：有未保存修改时，内部导航通过 `window.confirm` 确认放弃修改，取消后留在原页面并保留草稿；保存中阻止内部导航，未保存或操作进行中通过 `beforeunload` 提醒关闭／刷新页面可能丢失内容。

## 核心流程

管理员页面以 `AdminPanel` 左侧导航切换平台概览、账号管理、模型与检索、账号安全，右侧展示内容。`RagSettingsPanel` 分别展示活动配置、待应用嵌入配置、编辑草稿、重建状态与只读 Chroma 信息。默认嵌入模型为 `BAAI/bge-m3`，默认重排模型为 `BAAI/bge-reranker-v2-m3`；平台覆盖保存在 SQL `rag_settings`，未覆盖时沿用部署地址与既有凭据兜底。

1. 教师或学生从设置页维护个人模型服务凭据；题库操作从题库管理进入。
2. 平台管理员从管理员页面查看或维护系统模型与检索配置。
3. 提交时显示进行状态并防止重复提交；依据服务端结果展示绿色成功或红色错误弹窗。
4. 保存嵌入模型或 URL 变更只产生 `pending`，不自动重建或切换；与其一并提交的嵌入凭据跟随待应用配置，活动嵌入凭据不提前替换。活动嵌入模型与 URL 不变时，单独更新凭据供后续请求使用；重排模型、URL、凭据更新同样供后续请求使用。
5. 管理员测试可直接探测当前草稿，不落库；与个人模型测试只使用已保存配置的规则不同。保存后再确认重建，服务端先检查没有未完成入库任务，再返回 `202` 并通过进程内 `BackgroundTasks` 执行。页面在重建期间每 2 秒读取状态，也可离开后返回刷新。
6. 重建只处理活动题库中 `ready` 文档的 `document_chunks`，保留 SQL chunk ID、chunk_index（跨批次不重置）、章节与类型，校验切片数量和向量维度，写入带新 generation 后缀的 Chroma 集合；不重跑解析、OCR 或改写 SQL/FTS 文本。即使没有资料，也先探测新模型再切换。
7. 全部成功后以一次 SQL 提交切换活动配置和 generation、清空 `pending`；一次检索固定配置和索引快照，在途检索仍可读旧集合。失败不切换，保留 `pending` 和脱敏错误，管理员可重试。将嵌入模型和 URL 改回活动值再保存可取消待应用变更。

## 接口与数据契约

- 个人模型配置继续以 `/api/users/me/model-settings` 为现有契约。
- 题库管理继续以 `/api/banks` 及其文档接口为现有契约。
- 管理员接口由 `backend/app/api/admin_rag.py` 注册，请求与响应定义见 `backend/app/schemas/rag_settings.py`；API 文档入口为 [docs/api.md](../api.md) 和 [openapi.json](../../openapi.json)。不使用旧 `/api/settings` 或 `/api/knowledge-bases`。
- 小弹窗显式区分成功和错误，覆盖范围、显示时间与关闭方式遵循上文已确认决策。

| 方法与路径 | 请求与结果 |
| --- | --- |
| `GET /api/admin/rag-settings` | 仅管理员；返回 `active`、`pending`、`vector_store`、`rebuild`、`revision`；Chroma 可用性来自 heartbeat，不证明完整检索可用 |
| `PUT /api/admin/rag-settings` | 提交 `revision`、`embedding_model`、`embedding_base_url`、`rerank_model`、`rerank_base_url` 及可选 `embedding_api_key`、`rerank_api_key`；200 返回最新状态 |
| `POST /api/admin/rag-settings/test` | 提交 `service=embedding/rerank`、`model`、`base_url` 及可选 `api_key`；使用草稿和对应已保存凭据／部署兜底，不保存，成功返回 `ok/message` |
| `POST /api/admin/rag-settings/rebuild` | 提交当前 `revision`，返回 `202` 状态快照；仅表示任务提交，完成以 `rebuild.status` 为准 |

响应不含明文凭据，仅有配置状态和掩码；凭据省略、`null`、空串或纯空白均保留，没有管理员清除凭据接口。URL 限 HTTP(S)，禁止内嵌用户名密码、查询参数、片段。模型标识最长 160 字符、URL 最长 512 字符、凭据最长 4096 字符。`revision` 过期时保存／重建返回 `409 RAG_SETTINGS_CONFLICT`，前端保留草稿并要求载入最新已保存配置后重新编辑，避免覆盖其他管理员修改。

`rebuild.status` 为 `idle/queued/running/succeeded/failed`，附 `progress/stage/error`；`pending=null` 表示没有待重建的嵌入配置。活动配置、待应用配置和重建任务由 `RagSetting` 单行管理，运行时快照在 `services/rag_runtime.py` 固定模型与索引版本。

## 异常边界

- 未获服务端写入确认时不得提示保存成功。
- 写入已确认但读回失败时，应说明“已保存，最新状态读取失败”，避免误导重复提交。
- `queued/running` 期间保存配置、重复重建、上传、重解析、删除文档和整库删除返回 `409 RAG_REBUILD_BUSY`；已有未完成入库时重建返回 `409 RAG_INGESTION_BUSY`，没有 `pending` 时返回 `409 RAG_NO_PENDING_CONFIG`。题库成员与名称等不写索引的操作沿用各自权限，并非所有业务写入暂停。
- 测试失败返回脱敏的 `400 RAG_SERVICE_UNAVAILABLE`；网络、凭据、Chroma 或切片一致性失败不切换活动版本。单文档“重新解析”仍先清理旧切片，不具备本节平台模型重建的失败回退保证。
- 管理员配置不授予管理员读取教师或学生私有题库内容的权限。
- 全局 `ToastProvider` 位于认证上下文内、业务上下文外，管理员与普通用户共用；成功用 `status/polite`、错误用 `alert/assertive` 播报，均可手动关闭，会话失效清除提示，拒绝旧会话的迟到反馈。

## 部署与运维边界

- 发布该实现前，先备份 SQL 与 Chroma，并在受控副本核对后从 `backend/` 执行 `uv run alembic upgrade head`，将 `h3c4d5e6f789` 升级到新增 `i4d5e6f7a890`。线上部署仍须独立完成迁移。
- SQLite 为 WAL 模式：文件级备份须在停止写入并保证同一快照后包含主库和仍存在的 `-wal`，`-shm` 同步留存供核对；或使用 SQLite backup API 得到包含已提交 WAL 内容的完整快照。仅复制 `.db` 不能当作完整备份，SQL、Chroma 和上传／OCR 目录须按实际配置分别保护。
- 新迁移创建平台配置单行，初始空覆盖和空 generation 沿用原 `kb_*` 集合，不复制本地敏感配置。已切换 generation 或正在重建时，降级会拒绝，须先恢复兼容的旧模型与旧索引。
- 当前部署仅支持单 worker 进程（`--workers 1`）。后台重建不是持久化队列，启动时将中断的 `queued/running` 标为 `failed`，保留活动索引和待应用配置，需管理员重新发起；不承诺多 worker 协调或自动续跑。
- 启动同时将 `uploaded/parsing/ocr/chunking/embedding` 文档标记 `failed`，包含排队尚未开始的资料，避免重启后永远阻塞重建；资料仍需人工重新解析，SQL 收尾不等于同步改写 Redis。
- 成功后的旧集合及失败留下的部分新集合均保留，会持续占用磁盘；当前没有自动回收或清理接口。运维清理前须核对活动 generation、正在重建的 generation 及仍被在途检索快照使用的旧版本，不得误删活动／在途索引，不可仅按集合年龄或前缀直接删除。

本机恢复已核验：实际 `backend/.venv` 使用 Chroma 1.5.9，默认系统 `TEMP/TMP` 所指目录不可写导致原生 `code 14`。此前新建、相对及 POSIX 路径 probe 也复现；仅给启动进程设置可写 `TEMP/TMP` 后原生 probe 成功，未升级依赖、未清库、未迁移向量目录。含 WAL 的 `backup-20261110-155735/` 及补充快照 `consistent-before-migration.db` 位于 `output/implementation/documents-recovery-20261110/`。实际迁移 `h3c4d5e6f789 → i4d5e6f7a890` 已完成，users=3／banks=1／documents=1／chunks=0 不变、quick_check=ok；Chroma 副本假向量 add/get/query 后已清理 probe 集合，原路径 heartbeat／list 成功，collection=0（旧失败在首次初始化，没有历史索引记录）。证据文件及操作说明见 [后端 README](../../backend/README.md#本机-sqlite-备份与-chroma-临时目录恢复2026-11-10已核验)。

运行设置服务确认 `vector_store.available=true`、pending=false、rebuild idle；原 PDF 仍 failed、chunks=0、原件存在，没有自动重解析。没有可复用的活动管理员会话，未伪造／创建会话；运行 OpenAPI 四个管理员配置操作已确认，但未据此宣称管理员已认证 HTTP／UI 验收。末轮定向验证与独立审查由主代理补充，文档同步不修改真实配置或全局系统环境。

## 题库上传、预览与失败反馈增量

本节属于现有题库资料流程的增量，入口仍为 `/api/banks`；不恢复已移除的普通设置分区，也不新增预览后端接口。完整流程与错误表见 [知识库模块说明](知识库模块说明.md#5-上传解析存储与进度) 和[预览边界](知识库模块说明.md#61-前端预览上限分页超时与取消)。

- 新建、编辑和查看题库共用格式／空文件／名称+大小+修改时间去重校验，支持 PDF、DOCX、XLSX、MD、markdown、TXT；同名不同大小或修改时间允许上传，大小上限以服务端为准。文件选择为 multiple，虚线区接收全部拖入文件并串行提交，提供高亮及键盘选择；忙时再次加入明确报错。
- 新建在首个请求受理前保留名称和文件，首拒绝保留草稿；部分成功记录已创建 `bankId`，已受理文件移出草稿，重试只处理未受理文件。批量进行中禁止关闭，新建全部受理成功再关闭并显示绿色提示；部分失败保留草稿并显示红色详情，不把排队受理当作完成解析。
- 失败文档通过可访问按钮展开 `errorMessage/stage/ocrStatus`，正文可选择复制；创建者／可编辑成员可重新解析，只读成员查看详情。重新排队成功绿色、失败红色、进行中信息色；成功、失败与进度 100 分别判断。
- MD／TXT 预览最多 2 MiB、60 秒，校验媒体类型与 UTF-8；文本每页最多 40 块／2 万字符单位，MD 超长单块降为有截断提示的纯文本，TXT 保留原始文本。仅挂载当前页公式，错误可重试并提供下载。PDF 点击时同步预开窗口，经认证获取 PDF Blob，180 秒超时；下载也为 180 秒。关闭、切换文档或注销取消请求并回收对象 URL，主动取消不当作失败。DOCX／XLSX 明确不支持内联预览，提供下载。
- 上传／重新解析的 `onChanged()` 触发 `refreshKbs`，同时刷新当前题库 docs。编辑／查看弹窗删除成功后调用 `onChanged(documentId)`，BankTab 先经 `AppContext.invalidateDocument` 立即移除当前 docs 中的该项、清空对应选择并递增请求版本，再异步刷新；刷新失败仍保持缓存失效，会话、当前题库和请求版本阻止旧响应恢复已删项。
- 服务端 `purge_document/purge_bank` 在事务内清理 SQL，向量／collection 删除成功后才 commit，最后删除当前 storage_path 文件；向量失败 rollback，保留 SQL／文件供重试。跨存储仍非原子：向量已删而 commit 失败需重新解析恢复向量，unlink 失败会留下文件。前端缓存同步不等于已回收 OCR／Redis 缓存或所有派生文件。
- 嵌入错误区分鉴权、限流、超时、连接、服务端、请求和无效响应；Chroma 区分初始化、集合访问、写、查询、读、删、健康操作。上述嵌入／存储错误使用安全中文消息和受限诊断字段；检索／删除按边界返回 503，后台入库保存失败详情。客户端另区分超时、HTTP、类型、文本体积和弹窗拦截错误，不以旧索引或空列表掩盖存储故障。
- 末轮 Redis 修复已捕获进度写入的 `RedisError`，记录受限诊断后继续调度／处理，排队边界四项定向验证通过；OCR／未知异常已采用结构化分类和固定安全文案，脱敏及重试回归通过，不计入此前全量基线；进程内后台任务仍不是持久化队列。

## 验收标准（验证记录见文末）

- 应用设置只展示模型与服务，不再发出旧知识库、引擎或文档解析设置请求。
- 建库与文档操作仍通过现有题库管理完成，教师与学生权限保持当前约定。
- 系统配置仅管理员可访问，凭据不回显；空凭据保留、草稿测试不保存、版本冲突不覆盖。
- 嵌入模型／URL 保存为 `pending`，明确区分保存和生效；重建复用 SQL 切片、不重复 OCR，读继续、资料写暂停，成功切换、失败回退与重试、重启中断按上述契约验收。
- 活动嵌入凭据和重排配置更新对后续请求生效；在途检索使用既有快照，不混用新旧嵌入空间。
- 保存成功与错误使用明确的文字、图标和对应底色，支持辅助技术播报；错误不能仅靠颜色区分。
- 覆盖普通用户与管理员、顶部居中绿色 3 秒／红色 6 秒提示、手动关闭及会话隔离；保存未获确认不提示成功，个人模型写后读回失败明确提示并禁用测试。
- 核对普通设置与管理员模型配置的未保存导航确认、取消保留草稿、保存中阻止导航及关闭／刷新页面的 `beforeunload` 保护。

# 出题解题一致性与公式渲染修复

## 背景

2026-11-17 两批生成任务（50 题与 60 题）暴露四类缺陷。

1 选择题的选项内容与解析推导出的结论不一致，个别题目正确选项文本根本不在解析里出现。
2 解析里的 LaTeX 被破坏，`\neq` 变成换行加 `eq`，矩阵与多行推导被拆成碎片。
3 解析混入模型的自我纠错草稿，例如「计算得到 6，不对，好像有误」。
4 高难度题目出现 3×3=6 这类低级算术错误。

本文记录三类根因、修复方案与验收口径。改动集中在出题与解题链路，不涉及 HTTP 接口。

## 根因

### 一 JSON 转义吃掉反斜杠

模型在 JSON 字符串里写 `\neq` 而不是 `\\neq` 时，`json.loads` 会把 `\n` 当换行、`\f` 当换页、
`\t` 当制表、`\r` 当回车、`\b` 当退格。`\left` 这类首字母非法的则直接抛非法转义。

`json_repair` 无法修复，实测它对同一段公式会保留 `\left` 而吃掉 `\right`，
结果是半段正确半段损坏，比整体失败更难发现。

仓库自带的 `latex_utils.fix_delimiters` 还有一处反向破坏。原有实现用
`text.replace("\\n", "\n")` 把字面反斜杠 n 全部转成换行，连正确的 `\neq`、`\nabla`、`\nu` 也一并拆断。

### 二 思考开关写法与部署不匹配

解题链路原本通过 `extra_body={"thinking": {"type": "enabled"}}` 开启推理。
自部署的 vLLM 服务忽略该字段且不报错，`message.reasoning` 始终为空，
等于解题模型一直在无推理状态下作答。实测唯一生效的写法是 `chat_template_kwargs={"thinking": true}`。

静默忽略是最难发现的一类故障，因为它不产生任何错误信号。

### 三 求解与讲解缺少交叉校验

原实现一次调用同时产出答案、干扰项与解析。模型可能在解析里算出 5、
把答案写成 17，两者各自成立却互相矛盾，程序只校验格式不校验语义。

典型样本：行列式题 `D=(2+3)×6-(1+4)×5`，第一步求解得 17，第二步解析推导得 5，
选项围绕 17 生成，解析里写着 5，正确值 5 根本不在选项中。

### 四 裸环境被逐命令包裹

模型常把 `\begin{aligned}...\end{aligned}` 整段裸写在 `$` 之外。原有包裹逻辑只处理单个命令
及其 `{}` 参数，于是 `\begin{aligned}` 被单独包成 `$\begin{aligned}$`，
内部的 `\begin{pmatrix}` 又被各自包裹，公式结构彻底散架。

同时，定界配对判断数的是「数学段个数」而非 `$` 个数。整段只有一处行内公式时数学段为 1，
被判成奇数不配对，函数直接返回并跳过全部修复，导致上述问题长期未被纠正。

## 方案

### 解析前补反斜杠

`latex_utils.escape_bare_commands_in_json` 在 `json.loads` 之前扫描原始文本，
对已知 LaTeX 命令与非法转义序列统一补成双反斜杠。已成对的 `\\` 成对跳过，不会重复加杠。

入口有三处，覆盖全部模型输出：`llm.chat_json`、评审与修补的低温调用、出题流式解析。

### 解析后还原控制字符

`latex_utils.restore_escape_artifacts` 按命令白名单把「控制字符加命令后缀」还原成命令。
还原要求命令名后不是字母，避免把真实换行后的普通单词误判。两字母命令不参与还原，误判成本过高。

`fix_delimiters` 的换行转换改为 `\\n(?![a-zA-Z])`，`\neq`、`\nabla`、`\nu`、`\notin` 得到豁免。

### 思考开关自适应

`llm` 按 `chat_template_kwargs` 与 `thinking.type` 两种写法顺序探测，
成功后按 `(base_url, model)` 缓存，后续调用不再重复试探。
只对 400、404、422 这类参数拒绝降级，鉴权、限流、超时直接抛出，避免一次失败被放大成两次等待。

### 解题拆两步

`SOLVE_ANSWER_SYSTEM` 只求解并输出最终答案，`SOLVE_EXPLAIN_SYSTEM` 依据已定答案写解析与干扰项。

解析必须额外返回 `conclusion` 字段，如实填写自己推导出的结果。
`_answers_agree` 比对 `conclusion` 与答案，纯数值要求完全相同，
避免 5 与 25 因包含关系被判成一致。

不一致时重新求解，上限两次。两次仍不一致则放弃该题，宁可少给一题，
不让选项与解析互相矛盾的题进题库。

### 草稿痕迹拦截

解析命中 `DRAFT_TRACES`（不对、好像、重新算、让我想想等）判为不合格，重写一次。
提示词同时要求以确定语气直接陈述，把解析写成能直接印在答案册上的讲解。

### 裸环境整段包裹

新增 `_match_environment`，从 `\begin{env}` 配对到 `\end{env}` 后整体包裹。
多行环境用 `$$` 定界，矩阵类留在行内。分段与最终校验共用未转义美元 token，
区分 `$` 与 `$$` 并检查配对，拒绝未闭合或混用定界符；`\$` 保持货币符号语义。
过度转义按环境上下文修复；矩阵与多行环境中，行分隔后紧接命令的奇数反斜杠序列保留，
避免将 `\\` 换行和后续 `\frac` 合并成单个命令。其他多余反斜杠按既有规则折叠。

### 选项统一净化

正确答案与干扰项走同一套 `_clean_option_text`。此前只清洗正确答案，
导致选项里一半带 `$` 一半裸奔。

选择题的正确项与干扰项合计恰好四项，全部在去除空白与美元定界符后检查唯一性；
同时验证字段类型、多选正确项数量、公式及完整题目契约，不能仅凭答案与解析结论相同放行。

### 事务、取消与候选写回

审核要求传入无活动事务、无待写变更的 Session，语料在自有短读事务中物化；
所有模型调用与进度回调都在该读事务结束后执行，不提交或回滚调用者的业务事务。

出题、评审、两步求解与参数探测保留显式取消回调，每次新请求、重试、回退前复核取消。
取消异常向上传播，不转成普通失败或触发补齐；模型流在收流、解析失败和取消时均关闭。

并发求解只修改候选副本，等待全部工作线程结束并复核取消后统一写回。
已有有效题目求解失败时保留原答案、解析与选项；新命题与修补产物只有独立求解成功后才能交付。
模型调用复用带来源标记的完整运行时快照，个人凭据鉴权失败时切换完整平台配置，
回退及思考参数探测均保留调用参数、预算与取消语义。

### 前端兜底

`frontend/src/lib/latex.tsx` 增加渲染前清洗，还原 HTML 实体、双反斜杠定界与被吃掉的控制字符。
后端入库前已修一遍，这一层针对历史数据与跨端返回。
双反斜杠起止定界成对还原，控制字符修复要求命令后不是英文字母，保留普通英文换行。
保留矩阵换行后紧接命令的奇数反斜杠序列；离线回归使用真实 React SSR 与 KaTeX 检查渲染结果。

## 数据契约

`SOLVE_EXPLAIN_SYSTEM` 的输出结构由两项变为三项，仅内部协议，不影响 HTTP 接口与 `openapi.json`。

```json
{"analysis": "解析", "conclusion": "推导出的最终结果",
 "distractors": ["干扰项"], "confidence": "high|mid|low"}
```

非选择题不带 `distractors`。`conclusion` 缺失时不拦截，避免因模型漏填误杀题目。

## 异常边界

| 情况 | 处理 |
| --- | --- |
| 求解返回空答案或字段缺失 | 候选判为未解；新题剔除，已有有效题保留原内容 |
| 解析未通过 LaTeX 定界校验 | 重写一次，仍失败剔除 |
| 解析含草稿痕迹 | 重写一次，仍失败剔除 |
| 解析结论与答案不一致 | 重新求解，两次仍不一致剔除 |
| 选项数量不符、字段类型错误或归一化后重复 | 候选拒绝写回；新题不得交付 |
| 修补阶段模型自填答案 | 未经独立求解一律作废，不进入题库 |
| 思考开关两种写法均被拒 | 退回服务端默认，记录警告，不阻断链路 |
| 收流、审核或求解期间取消 | 关闭流并等待已启动工作退出，不写回候选、不重试补齐 |

## 验收

- 反斜杠：`\neq`、`\frac`、`\times`、`\theta`、`\beta`、`\rho`、`\right`、`\begin`、`\log`
  在 JSON 解析与定界修复全链路后保持完整。
- 裸环境：`\begin{aligned}` 整段被 `$$` 包裹，`latex_issue` 返回 None。
- 定界符：未闭合 `$$`、混用 `$` 与 `$$` 被拒绝，转义美元货币符号保持原义。
- 思考开关：自部署服务返回的 `message.reasoning` 非空，选中的变体下标被缓存。
- 一致性：行列式与矩阵乘法原题复跑，选项内容与解析结论一致。
- 事务与取消：模型前释放审核读事务；调用者业务事务保持原状；取消后不写回部分候选，
  不发起新模型请求、凭据回退或补齐。
- 答案保护：已有有效题在求解失败时保持原内容，新题的重复选项或未经独立验证答案不能交付。
- 测试批次和实际验证结果记录在现有智能体分支合并验收记录，不以历史通过数代表新版本结果。

## 不涉及

HTTP 接口、请求响应字段与 WebSocket 消息均未变化，`openapi.json` 与 `docs/api.md` 无需重新生成。
依赖与启动方式未变化。

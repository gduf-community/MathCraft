# 认证密钥本地初始化设计

日期：2026-11-09。状态：本地脚本与启动说明已实现，临时配置专项回归通过；未操作真实配置。

## 目标与范围

提供显式执行的 `backend/scripts/init_auth_secrets.py`，为本机后端生成并保存认证密钥。
只处理 `AUTH_JWT_SECRET` 和 `AUTH_CODE_SECRET`；不创建用户、不迁移数据库、不连接
Redis、SMTP 或外部服务，也不导入应用配置或读取 `local_secrets.py`。

## 执行流程与配置契约

1. 从脚本位置定位 `backend/.env`，不随执行目录变化，不读取根目录 `.env`。
2. 文件不存在时以 `backend/.env.example` 为模板；存在时保留原有配置和注释。
3. 先验证 dotenv 语法、两项认证配置的唯一性及现有值；空值或缺项才需要生成。
4. 每项独立使用 `secrets.token_urlsafe(48)`，提供 48 随机字节，编码为 64 个 URL
   安全字符；已有非空值至少 32 UTF-8 字节且两项不同，原样保留。
5. 将完整结果写入同目录临时文件，刷新后原子替换；重复执行不轮换密钥。
6. stdout/stderr 只输出固定结果或错误类别，不输出密钥、文件内容或异常原文。

从 `backend/` 执行：

```powershell
uv sync
uv run python scripts/init_auth_secrets.py
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

脚本不会在服务启动时自动运行。后端仍优先读取进程环境变量，再读取 `backend/.env`；
同名环境变量可覆盖文件值，修改文件后应重启后端。同一部署的各实例应共享同一组
认证密钥，不能分别初始化后直接当作一个部署使用。

## 异常边界

- 不覆盖已有非空密钥；值太短、两项相同、认证键重复或包含变量插值时拒绝修改。
- dotenv 语法错误、路径不可写或写入失败时返回非零，错误不回显配置值。
- 不跟随 `.env` 文件符号链接；本地锁只协调本脚本的并发执行，避免重复生成。
  运行时不要同时用编辑器或其他程序保存 `.env`；写前检查可以发现已发生的变化，
  但无法锁住不遵守本地锁的外部写入，检查与替换之间仍有并发覆盖窗口。
- 失败不留下含密钥的临时文件；已有文件在原子替换之前保持原样。
- SMTP、Turnstile 和模型服务凭据仍由各服务商提供，不由此脚本生成。
- 真实 `.env` 不进入版本库；本任务只在临时目录和假配置上验证，不修改个人配置。

## 验收标准

在临时目录使用假模板，覆盖首次创建、补齐单项、已有值保留与重复执行、注释及
换行保留、引号空值、错误配置无写入、写入失败清理、并发锁和路径定位。
检查 stdout/stderr 不包含生成值或假配置中的敏感标记，并确认不加载应用或访问网络。
运行相关脚本回归与 Python 静态检查；本功能不改变 HTTP 接口或数据库迁移。

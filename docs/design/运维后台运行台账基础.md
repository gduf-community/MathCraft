| `requested_count` | Integer，非空正整数 | 有效参数的请求数量，受理后不变 |
| `delivered_count` | Integer，可空、非负整数 | 已保存数量快照；完成可为 0，明确失败或取消为 0，受理／运行／未知为空 |
| `error_code` | String(32)，可空 | 下述有限分类，不接受异常或自由文本 |
| `accepted_at` / `last_observed_at` | DateTime，非空 | 受理时间／最近一次新事实的观察时间 |

写入接口只接受 1–40 位 ASCII 标识字符（字母、数字、`_ . : -`）。所有时间必须带时区，写入统一转换为 UTC；SQLite 读回时补回 UTC 时区。表不使用自动 `updated_at`，查询和幂等重放均不刷新观察时间。

资源和批次 ID 是历史快照，不设置删除级联外键，删除会话、资料、批次或题目不清空运行记录和原保存数量。账号硬删除由 RESTRICT 阻止，现有停用账号流程保持原样。非空台账的 Alembic 降级会拒绝执行，避免静默丢失历史；本批不提供清理或历史恢复工具。

`accept` 校验账号存在、文档所属题库、对话会话的账号／题库／文档一致性；完成写入校验批次账号、题库、文档及 `done` 状态。资源访问权限仍由未来调用入口在受理前校验，本模块不提供鉴权或管理员查询。

## 写入接口与事务所有权

`RunLedger(session_factory=SessionLocal)` 可注入独立 Session 工厂，测试不使用真实数据库。

| 方法 | 事务与调用条件 |
| --- | --- |
| `accept(...) -> str` | 使用自己的 Session 独立提交受理；不接收调用方 Session。同一 ID 与相同受理字段重放返回原 ID，关联不同则拒绝；并发相同受理由唯一约束去重 |
| `start(run_id, observed_at=...)` | 自有短事务，执行器实际开始后调用；重复开始不是心跳 |
| `complete_in_transaction(db, run_id, batch_id=..., observed_at=...)` | 必须已有调用方事务，且批次及全部题目已显式 flush；不 flush、提交、回滚或关闭调用方 Session。校验事务内题目数与 `GenerationBatch.question_count`，同事务更新关联、数量和完成状态 |
| `fail(run_id, error_code=EXECUTION_ERROR, ...)` | 调用方已确认失败、未保存批次，并已回滚业务事务后调用；自有事务 |
| `cancel(run_id, ...)` | 执行器已确认停止且未保存批次；暂停请求或断连本身不足以调用；自有事务 |
| `unknown(run_id, error_code=OUTCOME_UNKNOWN, ...)` | 提交结果不明或中断的明确观察；自有事务，只记录未知，不检测中断或虚构结束时间 |

独立方法应在业务写事务开始前或回滚后调用，避免 SQLite 同库写锁等待；调用方也不得用有绑定外部业务事务的工厂冒充独立 Session 工厂。批次完成应是业务 flush 后、commit 前的最后一个台账步骤，之后不再改变本次保存数量。

调用方必须传入本次生成实际返回的批次 ID，不能从“最近批次”或会话相同推断关联。结构化归属校验不替代这一调用条件。

`complete_in_transaction` 返回时仅表示当前事务已写入；只有调用方 commit 成功后才能对外认定 `completed`。业务失败或提交前失败，批次和完成记录共同回滚，受理／开始事实仍在。提交结果不明时，先结束原事务、用新 Session 回查已知批次及运行；有已提交完成事实则保留，没有确认依据时记录 unknown，不能无条件记失败。本批不修改现有内部提交的 `persist_batch`，实际入口接入时仍需安排这一事务接点。

模块通过状态与观察时间的比较并交换防止并发旧写覆盖；冲突抛 `RunConflictError`，调用方必须回滚后重读，不得继续提交已冲突的业务事务。方法不承诺模型执行恰好一次，也不把两个未传相同 ID 的受理请求自动合并。

## 状态及错误分类

- `accepted → running → completed / failed / canceled / unknown`。
- 受理后、执行前的明确提交失败或确认取消，可以直接进入 failed 或 canceled；中断未知也可在开始前记录。
- unknown 在取得较新的执行、保存、失败或取消证据后可补正；完成仍要求已有开始事实。
- completed 是批次保存事实，相同批次重放保留原快照；不同批次关联被拒绝。后续开始、失败、取消或未知观察不覆盖已完成记录。
- failed 和 canceled 为已确认停止，幂等重复可接受，其他较新转换拒绝；较旧的普通开始／停止事件忽略。
- 较旧或未开始的批次完成事件拒绝，防止调用方误提交一个未关联的新批次。时间相同的事件仍受状态顺序约束；跨执行器须使用同步时钟。
- finished_at 只表示应用记录确认终态的时间，不宣称为数据库物理提交的精确瞬间。unknown 始终没有 finished_at，不是失败或超时的别名。

失败分类：`NEED_CONFIRM`、`MODEL_ERROR`、`RETRIEVAL_ERROR`、`GENERATION_ERROR`、`NO_PERSISTABLE_QUESTIONS`、`PERSISTENCE_ERROR`、`TASK_SUBMISSION_ERROR`、`EXECUTION_ERROR`。确认取消固定为 `USER_CANCELED`；未知仅使用 `EXECUTION_INTERRUPTED`、`OUTCOME_UNKNOWN`。

无法可靠细分的明确失败使用 EXECUTION_ERROR。不解析回复、根 span、SSE closed、Redis 进度或异常全文来猜终态；已恢复的中间错误不单独将最终保存的运行判失败。表无正文、异常、提示词、凭据、质量明细、Token 或费用列，接口也不接受这些载荷。

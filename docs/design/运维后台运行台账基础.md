# 运维后台运行台账基础

状态：**M2 台账基础、M1 实际出题入口和 M3 管理员查询已在本地整合；前端 V2 已隔离联调，部署待验收。** 当前验收见[整合记录](../implementation/运维后台本地整合验收.md)，本文维护基础设计契约；各批实测、提交基线与交接集中在该整合记录。

## 目标与范围

为每次实际出题保存稳定运行 ID、受理与执行状态、历史交付数量及有限错误分类。继续使用普通 OpenAI 客户端；不引入 Agents SDK、告警、质量统计、清理调度或正文追踪。实际入口规则见[出题入口接入](运维后台出题入口接入.md)。

## 存储与关联

实现为 `app/models/ops_run.py`、`app/services/ops_runs.py` 和增量迁移 `n9a0b1c23456`，接在主线汇合节点 `m8f9a0b12345` 后。主线 `j5e6f7a8b901` 仍为 ACID 恢复迁移，另一支是正文证据 `j5e6f7a89012` 与出题运行 `k6f7a8b90123`；两支先由 `m8f9a0b12345` 汇合，再创建运维台账。台账升级只创建空表及索引，不回填旧批次，不修改既有表或运行数据。尚未升级的部署不会自动拥有该表。

### 旧 V2 同号迁移的部署兼容性

旧 V2 曾使用 `j5e6f7a8b901` 创建 `ops_runs`，与主线 ACID 恢复迁移同号。若数据库已应用旧 V2，`alembic_version` 的这个值无法区分两套历史：整合后的 Alembic 会把它视为 ACID 已执行，但实际可能缺少 ACID 列和表；后续创建 `ops_runs` 也可能因表已存在失败。普通升级和单独修改版本标记都无法自动修复这种歧义，也不能假设非 SQLite 数据库的 DDL 会完整回滚。

部署前应先备份数据库及其关联的已提交日志，在受控副本核对部署来源、版本记录、`ops_runs` 的结构和数据，以及 ACID、正文证据和出题运行各迁移的实际结构；再根据事实单独制定保留历史数据的修复与迁移方案，并在副本验证后由部署负责人执行。不要直接对可疑库运行 `upgrade head`、删除已有台账或仅用 `stamp` 覆盖版本。本次不提供自动兼容或操作真实数据库。

| 字段 | 类型与空值 | 事实口径 |
| --- | --- | --- |
| `run_id` | String(40)，非空主键 | 一次实际受理；显式 ID 优先，其次 `current_run_id()`，否则独立生成 `run_` ID |
| `entrypoint` | String(16)，非空 | 仅 `conversation` / `parameterized`；同步和后台参数化使用同一入口值 |
| `owner_user_id` | String(40)，非空 | 实际发起账号，不是题库所有者；外键 `users.id ON DELETE RESTRICT` |
| `session_id` | String(40)，可空、不唯一 | 对话必填；参数化为空，同一会话可多次出题 |
| `task_id` | String(40)，可空、非空值唯一 | 仅后台任务填写；对话为空，同步参数化不伪造任务 ID |
| `bank_id` / `document_id` | String(40)，非空 | 受理时已校验的资源 ID |
| `batch_id` | String(40)，可空、非空值唯一 | 完成时关联已保存批次；其他状态为空 |
| `status` | String(16)，非空 | 六种规定状态，有数据库 CHECK 约束 |
| `requested_count` | Integer，非空正整数 | 有效参数的请求数量，受理后不变 |
| `delivered_count` | Integer，可空、非负整数 | 已保存数量快照；完成可为 0，明确失败或取消为 0，受理／运行／未知为空 |
| `error_code` | String(32)，可空 | 下述有限分类，不接受异常或自由文本 |
| `accepted_at` / `last_observed_at` | DateTime，非空 | 受理时间／最近一次新事实的观察时间 |
| `started_at` / `finished_at` | DateTime，可空 | 实际开始／已确认终态时间；未知不填写结束时间 |

写入接口只接受 1–40 位 ASCII 标识字符（字母、数字、`_ . : -`）。所有时间必须带时区，写入统一转换为 UTC；SQLite 读回时补回 UTC 时区。表不使用自动 `updated_at`，查询和幂等重放均不刷新观察时间。

运行时间列使用 `UTCDateTime`，显式通过 `python_type` 返回 `datetime`，供查询层按列类型内省；
类型声明不改变 UTC 转换、数据库列结构或空值规则。查询层若按 SQLAlchemy 类型类判断，
仍需识别 `TypeDecorator` 的底层 `impl`，不能仅检查列类型是否为 `DateTime` 实例。

资源和批次 ID 是历史快照，不设置删除级联外键，删除会话、资料、批次或题目不清空运行记录和原保存数量。账号硬删除由 RESTRICT 阻止，现有停用账号流程保持原样。非空台账的 Alembic 降级会拒绝执行，避免静默丢失历史；本批不提供清理或历史恢复工具。

`accept` 校验账号存在、文档所属题库、对话会话的账号／题库／文档一致性；完成写入校验批次账号、题库、文档及 `done` 状态。资源访问权限由调用入口在受理前校验，台账模块本身不提供鉴权或管理员查询。

## 写入接口与事务所有权

`RunLedger(session_factory=SessionLocal)` 可注入独立 Session 工厂，测试不使用真实数据库。

| 方法 | 事务与调用条件 |
| --- | --- |
| `accept(..., db=None) -> str` | 默认使用自己的 Session 独立提交；传入 `db` 时在调用方事务中写入并 flush，由调用方提交或回滚。同一 ID 与相同受理字段重放返回原 ID，关联不同则拒绝；独立并发受理由唯一约束去重 |
| `start(run_id, observed_at=...)` | 自有短事务，执行器实际开始后调用；重复开始不是心跳 |
| `complete_in_transaction(db, run_id, batch_id=..., observed_at=...)` | 必须已有调用方事务，且批次及全部题目已显式 flush；不 flush、提交、回滚或关闭调用方 Session。校验事务内题目数与 `GenerationBatch.question_count`，同事务更新关联、数量和完成状态 |
| `fail(run_id, error_code=EXECUTION_ERROR, ...)` | 调用方已确认失败、未保存批次，并已回滚业务事务后调用；自有事务 |
| `cancel(run_id, ...)` | 执行器已确认停止且未保存批次；暂停请求或断连本身不足以调用；自有事务 |
| `unknown(run_id, error_code=OUTCOME_UNKNOWN, ...)` | 提交结果不明或中断的明确观察；自有事务，只记录未知，不检测中断或虚构结束时间 |

独立方法应在业务写事务开始前或回滚后调用，避免 SQLite 同库写锁等待；调用方也不得用有绑定外部业务事务的工厂冒充独立 Session 工厂。异步任务受理使用调用方 Session，使任务和台账在同一事务提交；批次完成在题目 flush 后、commit 前写入，之后不再改变本次保存数量。

调用方必须传入本次生成实际返回的批次 ID，不能从“最近批次”或会话相同推断关联。结构化归属校验不替代这一调用条件。

`complete_in_transaction` 返回时仅表示当前事务已写入；只有调用方 commit 成功后才能对外认定 `completed`。业务失败或提交前失败，批次和完成记录共同回滚，受理／开始事实仍在。提交结果不明时，先结束原事务、用新 Session 回查既有 SQL 事实，已提交完成的记录优先。实际入口在 `persist_batch` 中加入完成记录；异步任务状态或对话消息与会话状态由调用方一起提交，提交异常按证据记录 unknown，不能无条件记失败。

模块通过状态与观察时间的比较并交换防止并发旧写覆盖；冲突抛 `RunConflictError`，调用方必须回滚后重读，不得继续提交已冲突的业务事务。方法不承诺模型执行恰好一次，也不把两个未传相同 ID 的受理请求自动合并。

## 状态及错误分类

- `accepted → running → completed / failed / canceled / unknown`。
- 受理后、执行前的明确提交失败或确认取消，可以直接进入 failed 或 canceled；中断未知也可在开始前记录。
- unknown 在取得较新的执行、保存、失败或取消证据后可补正；完成仍要求已有开始事实。
- completed 是批次保存事实，相同批次重放保留原快照；不同批次关联被拒绝。后续开始、失败、取消或未知观察不覆盖已完成记录。
- failed 和 canceled 为已确认停止，幂等重复可接受，其他较新转换拒绝；较旧的普通开始／停止事件忽略。
- 较旧或未开始的批次完成事件拒绝，防止调用方误提交一个未关联的新批次。时间相同的事件仍受状态顺序约束；跨执行器须使用同步时钟。
- finished_at 只表示应用记录确认终态的时间，不宣称为数据库物理提交的精确瞬间。unknown 始终没有 finished_at，不是失败或超时的别名。

失败分类：`NEED_CONFIRM`、`MODEL_ERROR`、`RETRIEVAL_ERROR`、`GENERATION_ERROR`、`NO_PERSISTABLE_QUESTIONS`、`PERSISTENCE_ERROR`、`TASK_SUBMISSION_ERROR`、`EXECUTION_ERROR`。确认取消固定为 `USER_CANCELED`；未知仅使用 `EXECUTION_INTERRUPTED`、`OUTCOME_UNKNOWN`。

无法可靠细分的明确失败使用 EXECUTION_ERROR。不解析回复、根 span、SSE closed、Redis 进度或异常全文来猜终态；已恢复的中间错误不单独将最终保存的运行判失败。表无正文、异常、提示词、凭据、质量明细、Token 或费用列，接口也不接受这些载荷。

## 实际接入状态与剩余边界

- 参数化同步、`/start` 与后台任务、快速及创新对话出题已接入；部署先完成迁移，之后只为新受理生成记录。
- 后台显式传递 accept 返回的 ID，Phoenix 装饰器复用该 ID，关闭扩展时台账独立可用。
- 对话在有效参数齐备并决定生成时受理；澄清、切换、答疑和数据管理不受理。同会话每次实际出题使用不同 ID，同 worker 内重叠消息返回 CHAT_BUSY/409。
- 原题不足、审核零结果、模型错误、批次提交、回复与进度失败、确认取消的映射见 [入口接入](运维后台出题入口接入.md)。
- 执行中断、提交不明与本进程关闭的登记中任务可触发 unknown。启动恢复要求单 worker，且没有其他共享数据库的运行实例；同一事务将未完成持久任务／运行中会话标为 interrupted，并将所有仍为 accepted/running 的对话台账及关联持久任务的未终结台账记为 unknown 和 EXECUTION_INTERRUPTED。无持久任务关联的参数化台账不被扫描，也没有过期扫描。
- 乙从 SQL 消费快照及空值，已实现管理员概览、列表、详情、筛选分页与查询 OpenAPI；前端 V2 适配及隔离联调已完成。甲的入口批次只补充原消息接口 CHAT_BUSY/409 契约，查询契约见[查询 V2](运维查询V2接口与查询设计.md)。
- 不用旧批次补造受理／开始历史；查询实施时须标明新台账覆盖起点。



## 验收标准

- 独立临时 SQLite 验证六状态、合法与非法转换、UTC、归属、重放及并发受理；同会话多次实际出题保持不同 ID。
- 调用方提交前独立 Session 不可见批次与完成事实；提交后同时可见，回滚后同时撤销。幂等重放和查询不刷新观察时间。
- 保存数量不随题目删除重算；完成事实不被迟到失败、取消或未知覆盖，不接收正文、凭据及异常全文。
- 真实 Alembic 验证唯一 head、原业务数据保留、空台账不回填、约束和非空历史降级保护；旧 V2 同号库必须单列失败与兼容边界。
- 实际执行结果、独立 SQL 烟测及主线整合批次见[本地整合验收](../implementation/运维后台本地整合验收.md)，不同批次不累计。

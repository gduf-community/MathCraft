## 实现约定

- 质量记录带规则版本，区分通过、警告和失败；记录问题、涉及原页、解析身份和资产检查结果，不记录完整教材或凭据。规则通过不代表公式、题目边界或数学正确性已经核对。
- PDF 页级检查区分可提取正文、疑似扫描/页眉文字、乱码和空白。需要 OCR 的资料仍走已配置的 MinerU 云端，禁止隐式本地回退；良好文字 PDF、TXT/MD 等继续原路径。
- 解析缓存按来源与有效解析身份匹配；有兼容缓存时先加载并重新校验，只有确需外发才校验 Token。旧产物缺少质量记录时重新检查，不能猜测已验收，不能删除旧数据。
- 在 `.mineru-segments` 中保存云任务请求身份、分片页范围、远端任务 ID、阶段和产物摘要，取得任务 ID 后原子保存。恢复先查询已有任务；提交是否被接收未知时明确报告，不自动再次提交。
- `task.json` 不保存 Token 或签名地址；只保存调用凭据的单向指纹，使任务查询继续使用提交时的凭据。恢复上传用的签名地址单独保存在后端 `.transport.json`，本地最多保留 23 小时的可用期，不进入进度、证据或普通前端响应。POSIX 文件为创建者私有权限，Windows 继承运行时目录 ACL。
- 安全查询和下载有限重试；等待超预算保留任务身份。取消停止本地后续动作并明确远端可能继续；下一次显式重建才允许继续已有任务。
- ZIP、资产和页映射检查通过后才保存完成分片；整文档质量未失败才标记正常缓存，带警告的材料继续保留使用限制。失败不发布候选索引，仍有效的旧版本保持可读。
- 分片同时受页数和 200 MiB 客户端字节上限约束；超限继续二分，单页仍超限时拒绝外发。合并后恢复零基原页索引，保留嵌套图片路径并隔离分片同名图片。RAG 资产收集及覆盖记录递归读取这些图片，页码不靠文件名猜测。
- `quality.json` 使用 `parse-quality-v1`，保存来源摘要、逐页扫描特征、问题及已读取资产摘要/尺寸。规则版本进入解析签名；旧缓存先检查，再复制到新签名目录，保留原件。文档检查和逐题来源公开 `quality_status`、`quality_policy`，旧记录缺字段显示未知，前端明确“解析产物检查不代表数学已复核”。

## 错误与恢复边界

| 情形 | 结果 |
| --- | --- |
| 已有 batch_id，断线/排队/等待预算耗尽 | 显式重建先查询原任务；不重新申请任务或重复 PUT |
| POST 是否被接收未知 | `cloud_submission_unknown`；保留请求身份，先由操作者核对远端 |
| PUT 响应丢失，远端仍为 waiting-file | `cloud_upload_unknown`；该状态不足以证明未上传，不盲目重传 |
| 已知未上传，但私有链接过期或缺失 | `cloud_upload_expired`；保留任务，需核对处理 |
| 429 / 部分 5xx / 短暂网络错误 | 查询/下载有界重试；长 Retry-After 返回 `cloud_rate_limited`，不提前请求 |
| 无效 ZIP、越界/矛盾页码、缺失/损坏图片 | `cloud_result_invalid` 或 `parse_quality_failed`；无完成标记、不发布候选 |
| 远端明确失败 | `cloud_remote_failed`；不自动新建另一任务 |
| 取消或进程终止 | 本地停止/标记中断；显式重建恢复已知任务，不承诺远端取消 |

锁按来源/解析身份和云分片协调跨进程重复请求。等待其他请求超时返回 `parse_busy`；不承诺上游 exactly-once。任务损坏、上传未知、远端终止失败等情况尚无专门管理界面，需要管理员核对，不应删除记录后盲目重试。

质量检查覆盖空产物、明显替换字符和公式占位、页码范围/冲突、坐标基本合法性、本地资产是否存在和能否解码；不做公式等价判断，不证明 bbox 精确对齐或全部图形已被提取。缺少原页映射明确警告；有扫描图像不等于能识别其中所有图示。图像实际未被模型读取时严格用途继续拒绝。质量检查通过也不补造原题结构和数量。

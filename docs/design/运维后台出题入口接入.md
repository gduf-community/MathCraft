## 实际受理与事务

- 同步参数化：资源、凭据及参数校验成功后，HyDE 与生成前独立记录 accepted、running。
- `/start`：校验及并发锁成功后先持久化 accepted，再初始化进度和注册后台任务；后台实际开始才写 running。显式传递同一 run_id，Phoenix 后台根 span 复用该 ID；扩展关闭时台账照常使用。
- 对话：仅快速出题与创新命题取得有效生成参数、决定生成时调用受理回调。澄清、模式切换、答疑、数据管理不建出题运行；同会话各轮独立。
- `persist_batch` 在原有批次提交前 flush 全部业务行，并让 completed、batch_id 和保存数量参与同一事务。对话回复另一次提交；回复、序列化、Redis 或取消请求失败不能覆盖已保存事实。
- 提交前明确失败且已确认回滚记 failed；开始 commit 后异常或回滚无法确认记 unknown，并通过新 Session 读取既有 SQL 事实，已 completed 的事实优先。调用方不得从异常文案猜状态。

## 停止与未知

- 已受理后原题不足：failed/NEED_CONFIRM；后续确认后的执行另建运行。
- 对话生成或审核后没有可保存题目：failed/NO_PERSISTABLE_QUESTIONS。参数化沿用现行空批次保存行为，保存成功为 completed/0，不增加质量语义。
- 暂停接口只写请求标记；执行检查点确认停止且没有批次时才记 canceled。同一会话在当前单 worker 部署内串行处理，重叠消息返回 CHAT_BUSY/409；先校验账号及会话归属。
- 异常类型映射有限错误分类；未知类别为 EXECUTION_ERROR，不保存异常全文。模型 HTTP 失败与根 span 结果均不能替代业务终态。
- BaseException 执行中断和当前进程关闭时登记的在途运行记 unknown，结束时间为空。关闭封口只处理本进程登记的 ID，不扫描历史或其他进程。硬退出后仍需受控核对，未实现跨进程恢复、过期扫描或自动重启封口；Redis 过期不会改掉 SQL 终态。

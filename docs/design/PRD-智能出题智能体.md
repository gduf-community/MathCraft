# MathCraft 考研数学智能出题系统总体需求文档

**状态**：总体需求基线；核心范围已由教师需求讨论确认，细节仍待确认。

**更新日期**：2026-10-30。

**首批用户**：使用数学一、数学二、数学三资料开展命题与组卷的教师。

**交付边界**：本文件描述目标产品，不代表相关功能均已实现；当前以单教师闭环为优先建设范围。

**需求来源**：[智能体出题工作流程](../智能体出题工作流程.docx)及关于考研范围、整份资料选择与原文预览、手动保存及清理版本、待组卷列表和独立组卷页面的讨论。

MathCraft 帮助教师将题目、试卷或教材上传到知识库，完成解析后，在出题对话界面选择一个或多个解析结果，通过配置面板提出初次要求，再以多轮对话优化题目。教师选择整份教材对应的解析结果，在对话中说明章节与页码；知识库页面可预览解析前的原始资料。题目修改先形成未保存候选，教师确认后独立保存版本；每道题最多保存 20 个版本，达到 15 个已保存版本时提醒教师，并允许手动批量清理。教师可以边出题边将满意版本加入待组卷列表，随后进入独立组卷页面确认或更换各题版本。

本文件替代原有通用出题 PRD 的范围与阶段划分，作为后续功能规格和设计文档的总体依据。模型设置、个人中心、知识库等已有专题文档继续有效；需求发生冲突时，以本文件中较新的已确认需求为准，并在实施前同步相关专题文档。

- **流程目标**：原始出题流程提出的目标，应保留在总体规划中；具体实现与验收细节仍需讨论。
- **方案建议**：为落实需求提出的设计方向，尚未作为具体实现定案。

## 二、问题与目标

教师需要在多份教材、例题和试卷之间组织出题依据，反复修改题干、答案与解析，并从不同修改结果中选择适合的题目。若资料范围、题目版本和组卷引用仅存在于聊天记录或页面内存中，就难以可靠恢复工作，也容易把旧题干与新答案混用。

目标是让每次出题都有明确依据，每道题都有独立版本，教师能够持续修改、比较和选择，最终得到可追溯的组卷结果。系统应明确展示生成、保存、检查和教师确认的不同状态。

当前优先建设教师出题闭环。学生接收与作答、账号邀请、多人工作空间、角色权限和协作冲突处理属于后续规划；不得把现有演示页面视为这些能力已经上线。

### 教师用户故事

- 作为考研数学教师，我希望自由指定数学一、二、三及其章节范围，以便按自己的教学任务出题。
- 作为教师，我希望上传题目、试卷或教材，并选择多个解析结果，以便组合真实资料作为出题依据。
- 作为教师，我希望通过面板提出初次要求，再通过多轮对话修改，以便逐步得到符合要求的题目。
- 作为教师，我希望每题独立保留不同版本，以便比较修改结果并再次使用。
- 作为教师，我希望在知识库页面预览解析前的原文，以便在选择整份教材后用对话明确章节和页码。
- 作为教师，我希望确认后才保存修改版本，并在版本接近上限时得到提醒和批量清理入口，以便控制版本数量。
- 作为教师，我希望边出题边把满意版本加入待组卷列表，再在独立页面确认或更换版本，以便逐题审阅后集中组卷。

## 三、考试范围与出题要求

### 3.1 覆盖范围

**已确认**：支持数学一、数学二、数学三的全部章节，由教师自由指定考试类别与内容范围。全章节覆盖表示各章节均纳入产品支持范围，不表示每个出题任务都必须覆盖全部章节。

**方案建议**：以可维护的考试类别、科目、章节与知识点目录承载范围配置，允许教师补充文字描述、排除内容及跨章节要求。考纲年份、目录来源、维护方式，以及单任务是否允许混合考试类别仍待确认；本文不固定具体年度的考纲明细。

### 3.2 初次配置面板

| 内容 | 需求与设计方向 |
| --- | --- |
| 资料选择 | 已确认：在出题对话界面多选解析结果；教材按整份选择，章节与页码通过自然语言补充 |
| 考试与知识范围 | 已确认：教师自由指定数学一、二、三及章节范围；具体目录交互待设计 |
| 题目结构 | 流程目标：配置题型、数量、分值和总分 |
| 难度与教学目标 | 流程目标：指定难度、考查能力和补充要求；难度分档与定义待确认 |
| 出题方式 | 流程目标：按知识点新编、参考例题变式、根据错题生成练习；首轮实现顺序待确认 |
| 输出内容 | 流程目标：答案、详细解析、评分标准、图形及交付格式 |

**方案建议**：教师未逐题配置时，由系统提出题量、分值、知识点与难度分配计划供确认。面板变更和对话变更进入同一份有效计划；发生冲突时显示变更范围，不能悄悄覆盖另一处要求。

## 四、上传解析与多选资料

### 4.1 资料准备

1. 教师把题目、试卷或教材上传到知识库。
2. 知识库解析资料，展示处理状态和失败原因。
3. 教师可在知识库页面预览解析前的原始内容，核对资料与需要使用的章节或页码。
4. 教师进入出题对话界面，选择整份教材对应的解析结果；可以选择多个解析结果。
5. 教师通过对话说明各份资料要使用的章节与页码；系统结合面板要求形成本次出题任务。

题目、试卷和教材是资料的业务类型，不等同于具体文件格式。首轮支持哪些文件格式、图片或手写题目，继续依据解析能力另行确认。

### 4.2 解析结果的含义与可用性

**已确认**：教师选择的是资料对应的解析结果，不是仅选择知识库名称或未经处理的原始文件。教材的选择粒度为整份解析结果，章节和页码范围通过出题对话指定；无需先在选择器中逐章节或逐页勾选。试卷是否进一步拆分成独立题目供选择，仍待确认。

**方案建议**：可选择项展示来源文件、解析状态、结果标识和可识别的章节或页码，支持预览。解析结果应能追溯到原文件及其处理版本；不能只用可能重名的文件名标识。

解析完成与检索索引就绪应分别表达。选中尚不能用于检索的结果时，系统应解释缺少哪一步，并支持等待、重试或调整选择，不能显示为可出题后再静默忽略。是否允许跨知识库选择仍待确认。

### 4.3 多份资料共同出题

- **已确认**：多选解析结果可以共同用于一个出题任务。
- **流程目标**：说明题目所依据的资料、章节、页码或知识点；资料不足时向教师说明缺口。
- **方案建议**：检索范围限定在已选结果内，保留每条依据的来源映射；资料重叠、内容冲突或重复试题应能提示。
- **流程目标**：不得擅自扩大资料范围、减少题量或降低难度。需要补充资料或调整计划时，由教师决定。
- **方案建议**：任务记录所选资料的具体版本；资料重新解析后，先提示差异，再由教师决定是否迁移任务依据。

### 4.4 原始内容预览与对话范围

**已确认**：知识库页面需要预览解析前的内容，即上传资料的原文。此处不等同于展示解析后的文本，也不表示必须在解析启动前完成预览。

**方案建议**：预览支持辨认原文中的题目、公式、图形、章节和页码，并标识当前查看的来源文件。具体文件格式的预览方式、缩放、跳页及转换能力在交互规格中细化。

教师可以在选择整份教材后，通过对话指定“使用这份教材的第三章，第 40—60 页”。**方案建议**：系统把自然语言范围转成可见的任务约束，并在后续检索时遵守；整份选择不意味着可以忽略教师限定的章节和页码。

多份资料的指代不清、原书印刷页码与文件页序不一致，或解析结果缺少定位信息时，系统应先澄清，不能自行猜测后继续生成。页码对应及缺失时的补救方式待确认。

## 五、出题与多轮优化流程

1. **选择依据**：教师可先在知识库页面预览原文，再在出题对话界面选择一个或多个解析结果；教材按整份选择。
2. **配置初次要求**：通过面板指定考试范围和其他出题条件，用自然语言说明所选资料中的章节、页码与补充要求。
3. **核对计划**：系统显示理解后的要求、资料范围和待解决问题；按原流程目标，由教师明确确认计划和资料范围。
4. **生成题目**：系统按计划生成题目、答案及要求的配套内容，显示进度和已完成结果。
5. **逐题优化**：教师选择题目及基础版本，使用对话或编辑器修改；修改形成未保存候选，不自动新增版本或覆盖已保存内容。
6. **逐题保存与选用**：教师确认后保存版本，可以将满意的已保存版本加入待组卷列表，再继续查看下一题；已保存版本达到 15 个时提醒并提供批量清理入口，每题最多保留 20 个已保存版本。
7. **集中组卷**：出题完成后，点击组卷按钮进入独立组卷页面，查看此前选用结果，确认或继续更换每题版本，再确定题目顺序与分值并检查整卷。
8. **成果确认**：形成组卷结果与候选文件，教师检查并确认；交付格式和确认规则另行细化。

**流程目标**：支持“把第二题改成证明题”“补充答案步骤”“第三题超范围，请更换”等自然语言操作，只处理受影响题目，并检查关联答案和解析。

**方案建议**：每次修改显示作用题目、作为修改基础的版本及受影响内容。全局要求改变时先说明哪些题目需要调整；教师选择单题时，对话显示目标，避免误改整套题。系统检查结果应以结构化问题清单展示，不要求教师通过阅读模型内部推理判断进度。

## 六、题目与逐题版本

### 6.1 题目身份与完整内容

**已确认**：每一道题独立保存多个版本。题目身份与试卷题号分离，调整排序不应改变题目身份。

**方案建议**：每个版本保存完整的题干、条件、选项、图形引用、答案、解析、分值、评分标准、知识点、难度说明和资料依据；按需增加预计答题时间、命题意图及考查能力。避免把某一版本的题干与另一版本的答案拼接。

### 6.2 保存与修订规则

- **已确认**：多个版本可以保留，教师能够选择指定版本参与组卷；关闭页面后仍可重新读取已保存内容。
- **已确认**：在某个版本上修改题目不自动保存新版本；对话或手动编辑产生未保存候选，由教师确认保存。已保存内容不因编辑而被静默覆盖。
- **方案建议**：手动保存时新增版本，记录修改说明、基础版本及检查结果；保存成功后才能作为可长期引用的版本。
- **方案建议**：区分“修改本题形成新版本”和“另出一道变式题形成新题目”，同时保留两者关联。
- **已确认**：草稿编辑与已保存版本分开，不能把每轮对话或每次编辑自动计为已保存版本。版本命名、未保存候选的暂存与恢复方式待确认。
- **方案建议**：教师离开有未保存修改的题目时，提示保存或放弃；草稿恢复即使实现，也不能自动成为正式版本。
- **方案建议**：旧请求晚返回时不能覆盖教师较新的修改；并发修改需要检测版本冲突。
- **流程目标**：修改题干、条件、答案或解析后，重新检查受影响内容；单纯排版修改不必重做数学内容。

### 6.3 检查与确认的归属

**方案建议**：检查和教师确认绑定具体版本。新版本不自动继承旧版本的审核结论；旧版本及其历史确认仍可追溯。将“已保存”“检查通过”“检查未完成”“待教师确认”分别显示，不能把保存成功当作数学正确性保证。

### 6.4 版本上限、提醒与手动清理

- **已确认**：每道题最多保存 **20 个版本**，已保存版本达到 **15 个**时提醒教师，允许手动批量选择并清理版本。
- **验收边界**：保存第 15 个版本时触发提醒；当前保留 19 个版本时可以再保存 1 个；已有 20 个时不能继续新增已保存版本。手动清理后按当前保留数量计算额度；未保存候选不因编辑而计入已保存版本。
- **待确认**：上限与提醒阈值是否允许配置、达到阈值后的重复提醒频率及删除恢复策略；当前已确认值为上限 20、提醒阈值 15。未保存候选是否另有暂存额度也需细化，不能隐式算作新保存版本。
- **方案建议**：版本列表显示已用数量与上限，并提供明确的批量清理入口；达到上限时保留当前候选，提示先清理再保存，不自动删除历史版本。
- **方案建议**：清理前显示所选版本及其待组卷或已保存试卷引用；清理动作要求明确确认。对仍被引用的版本采用阻止删除或保留不可变快照的方案，具体规则待确认，不能形成失效引用。
- **方案建议**：教师清理版本后仍能区分保留版本的身份，不能因数量变化而把原有引用指向其他内容。

## 七、指定版本组卷

### 7.1 出题过程中的待组卷列表

**已确认**：教师在出题过程中可以把多个题目各自满意的版本加入待组卷列表，加入后继续查看下一道题。列表保存明确的题目与版本选择，后续修改或新增版本不自动替换该选择。

**方案建议**：列表展示题目、版本、分值和检查状态，并支持查看、移除或替换所选版本。“保存版本”和“加入待组卷”是不同动作；未保存候选应先由教师保存，不能因加入列表而悄悄生成版本。按钮是否提供“保存并加入”等显式组合操作待设计。

### 7.2 独立组卷页面

**已确认**：出题完成后，教师点击组卷按钮进入独立组卷页面。页面带入待组卷列表，教师可以确认现有选择，也可以继续为每道题选择其他已保存版本。

教师可以组合不同题目的不同版本，不要求统一使用最新版本。例如：

| 题目 | 已保存版本 | 本次组卷选择 |
| --- | --- | --- |
| 题目 A | v1、v2、v3 | v2 |
| 题目 B | v1、v2 | v2 |
| 题目 C | v1、v2 | v1 |

### 7.3 试卷版本与成果

**方案建议**：试卷保存具体题目版本、顺序、分值和排版设置，形成可追溯的整卷快照。A 之后产生 v4 时，已经选择 A-v2 的试卷继续使用 A-v2；教师主动更新引用后产生新的试卷修订。

**流程目标**：整卷检查题量、总分、知识点覆盖、难度分布、重复或相似题，以及试卷、答案、解析和评分标准的对应关系。系统报告实际完成量、未解决问题和检查状态，由教师决定继续修改或最终确认。

**流程目标**：支持学生卷、参考答案、详细解析、评分标准、教师讲义及相关源文件。Word、LaTeX、PDF 的优先顺序和首轮模板待确认；本轮未确定具体导出实现。

## 八、质量检查与异常边界

| 场景 | 目标行为 | 需求状态 |
| --- | --- | --- |
| 解析失败或索引未就绪 | 显示原因与可操作入口，不悄悄忽略所选资料 | 流程目标及方案建议 |
| 资料不足或范围冲突 | 说明缺口，等待补充资料或调整要求 | 流程目标 |
| 模型输出不完整或题量不足 | 保留有效结果，说明差额和失败状态，不报告完整交付 | 流程目标及方案建议 |
| 数学检查无法判定 | 明确标记检查未完成或需要教师复核 | 流程目标 |
| 单题修订 | 对话与编辑不自动保存新版本；检查候选的关联内容，保存后将结论绑定对应版本，并更新受影响的整卷检查 | 已确认及流程目标 |
| 版本达到提醒阈值或上限 | 达到 15 个已保存版本时提醒；最多保留 20 个，已有 20 个时阻止继续新增；允许手动批量清理，候选保留及引用保护按专题规格细化 | 已确认及方案建议 |
| 清理被引用版本 | 提示引用影响并保护待组卷及历史试卷，具体删除策略待确认 | 方案建议 |
| 请求重试或重复保存 | 避免重复创建题目、版本或组卷结果 | 方案建议 |
| 暂停、重启或刷新 | 保留已保存结果；恢复执行前核对任务状态，不覆盖教师修改 | 流程目标 |
| 资料重解析或删除 | 不能静默改变历史题目和试卷依据，具体保留策略待确认 | 方案建议 |

**方案建议**：将字段与分值等程序检查、适用的数学工具检查、模型审查和教师审核分开记录。建立覆盖各考试类别、章节和题型的评估样例，逐步验证正确性和教学适用性；不把模型自评当作质量结论。

## 九、任务记录与逻辑数据契约

以下是后续设计应承载的业务关系，不是已上线 API 或确定的数据库结构：

| 对象 | 关键内容与关系 |
| --- | --- |
| 资料解析结果 | 稳定标识、原文件关联、处理版本、状态、内容及位置依据；可用性包含检索准备状态 |
| 出题任务 | 多个整份解析结果引用、对话确定的章节页码约束、初次要求、有效计划、对话上下文、进度及未解决问题 |
| 题目 | 独立身份、所属任务、版本集合；与具体试卷题号分离 |
| 未保存候选 | 基础题目与版本、当前修改、检查及保存状态；不同于已保存版本，暂存恢复策略待确认 |
| 题目版本 | 教师手动保存的完整内容、基础版本、修改说明、来源引用与检查状态；受版本上限管理 |
| 待组卷列表 | 出题期间累计选择的题目与具体版本，进入独立组卷页面后可继续更换 |
| 检查及确认记录 | 绑定被检查或确认的具体版本，记录结论、问题及时间 |
| 试卷及其版本 | 精确引用题目版本，记录顺序、分值、检查及确认状态 |
| 导出成果 | 引用固定试卷版本和模板配置，记录格式及生成状态 |

任务模块统一维护保存、修订和状态推进规则；对话与面板调用同一业务能力。后续实现时保持前端类型、后端 schema、OpenAPI 和 API 文档同步。本轮只更新需求文档，不新增或修改接口。

模型凭据仍通过现有设置能力管理，运行时题目、解析结果、索引和导出成果不得提交到仓库。

## 十、分阶段建设建议

以下阶段是建设顺序建议，不代表交付日期或功能已完成。三个考试类别及全部章节始终保留在总体范围内。

| 阶段 | 交付重点 | 主要验收 |
| --- | --- | --- |
| 一 资料到题目版本闭环 | 知识库原文预览、整份解析结果多选与对话范围、统一任务、生成修改、手动保存、版本上限与清理 | 多资料共同出题；修改不自动存新版本，确认保存后可重新读取，无关题目保持不变 |
| 二 指定版本组卷 | 出题过程待组卷列表、独立组卷页面与版本切换、顺序分值、整卷检查及一种确定后的导出格式 | 边出题边选用，进入组卷页后可换版本，后续修改不改变已保存试卷 |
| 三 质量与恢复完善 | 按知识点新编、例题变式、错题练习的策略完善，章节题型评估，暂停恢复及图形排版增强 | 依据固定样例评估质量；任务中断后正确继续并保留教师修改 |
| 四 协作扩展 | 账号、邀请、工作空间与任务权限、分工审核、审计及版本冲突处理 | 资料隔离、授权校验和审核责任可追溯 |

已有模型设置与教师个人中心的实现记录继续作为基础能力证据，见[个人中心与应用设置实施记录](个人中心与应用设置实施记录.md)和[模型直接配置实施记录](模型直接配置实施记录.md)。多选资料、逐题版本持久化与指定版本组卷需单独实现和验收，不能用已有设置测试或组卷演示代替。

## 十一、验收标准与成功指标

以下为目标验收，不是本次执行结果；核心场景对应已确认需求，细化指标在专题规格中继续确认。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A01 | 考试与章节选择 | 数学一、二、三及全部章节纳入支持目录，教师可自由指定任务范围；各范围生成质量另行评估 |
| A02 | 资料准备 | 题目、试卷和教材可经知识库解析；失败与可用状态明确，支持格式按解析规格验收 |
| A03 | 多选解析结果 | 在出题对话界面选择至少两个解析结果，教材按整份选择；对话指定的章节页码进入任务约束，无隐式扩大范围 |
| A04 | 面板与对话协同 | 面板提出初次要求后，对话修改进入同一任务；冲突或不明确的修改有可见反馈 |
| A05 | 逐题修改 | 修改目标题并同步处理答案和解析，无关题目内容保持不变；教师确认保存前不新增已保存版本 |
| A06 | 逐题版本保存 | 每题至少可保留并重新读取两个版本，关闭页面后内容仍在，历史内容不会被新版本覆盖 |
| A07 | 指定版本组卷 | 可选择 A-v2、B-v2、C-v1 组卷，题目产生更新版本后原试卷仍引用所选版本 |
| A08 | 检查与确认 | 显示被检查的具体版本、结果及未完成项，保存、检查和教师确认状态可区分 |
| A09 | 异常与部分交付 | 资料不足、生成失败、题量不足与检查无法判定均明确呈现，不擅自降级要求 |
| A10 | 成果一致性 | 在确定导出格式后，学生卷、答案及解析引用同一试卷快照；再次修改可保留旧成果 |
| A11 | 暂停恢复 | 在对应阶段实现后，从保存位置恢复，不丢失版本，不重复生成已完成题目，不覆盖教师修改 |
| A12 | 解析前原文预览 | 知识库页面可查看上传资料的原始内容；预览对象与出题选择的解析结果具有可辨认的来源关联 |
| A13 | 手动保存版本 | 基于已保存版本连续对话或编辑后，已保存版本数量保持不变；教师确认保存后增加一个版本，原版本可继续读取 |
| A14 | 版本上限与清理 | 保存后达到 15 个版本时出现提醒，保留数量可达到 20 个但不能超过 20 个；可手动批量清理并释放额度，未保存修改不增加版本数量；重复提醒、引用保护及候选保留按专题规格验收 |
| A15 | 边出题边选用 | 将多个题目的满意版本加入待组卷列表后可以继续审阅下一题，已选版本不被后续修改自动替换 |
| A16 | 独立组卷确认 | 点击组卷进入独立页面后保留已有选用结果，并可为每题切换其他已保存版本再确认 |

资料解析成功率、来源命中率、数学正确性、范围符合度和教师采用情况应分别统计。评估样例、通过阈值及人工审核方式待确认；全章节可选不等同于全章节质量已验收。

## 十二、待确认事项

1. 是否允许跨知识库选择；试卷是否支持拆题选择。教材整份选择及通过对话指定章节页码已确认。原文预览的支持格式、页码映射和定位缺失处理待细化。
2. 考纲年份、章节与知识点目录来源，以及教师自定义目录的范围。
3. 版本上限与提醒阈值是否可配置、重复提醒频率，以及命名、比较、清理恢复、引用保护和批量操作中不可清理项的处理规则。每题最多 20 个版本、达到 15 个时提醒、修改不自动保存、教师确认保存及手动批量清理已确认。
4. 单题修订与另存为新题的交互；从历史版本继续修改时如何展示关系；未保存候选是否暂存及如何提示离开。
5. 首轮题型、难度定义、分值配置，以及新编、变式和错题练习的建设顺序。
6. 同一道题的不同版本能否同时入卷；待组卷列表的移除、替换与持久化细节，组卷页面换版是否同步列表；逐题审核、整卷审核、最终确认和存在未解决问题时的组卷与导出规则。出题中选用及独立组卷页面换版本已确认。
7. 首轮文件格式、公式与图形处理要求，Word、LaTeX、PDF 的导出优先顺序。
8. 数据保存位置、备份、历史资料保留及任务暂停恢复的执行粒度。
9. 固定评估资料、考研数学审核样例、质量阈值及教师反馈采集方式。
10. 多人协作的启动时机、部署方式与权限模型；学生接收和作答另行规划。

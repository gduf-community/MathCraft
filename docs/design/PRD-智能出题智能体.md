# 智能出题智能体产品需求文档

**状态**：Draft  
**适用版本**：MathCraft 当前单租户版本及后续迭代  
**产品对象**：数学教师（当前）；学生（后续学习空间与个人中心）  
**文档来源**：[智能体出题工作流程.docx](../智能体出题工作流程.docx)

## 一、产品概述

MathCraft 为数学教师提供基于知识库的智能出题、题目审核和组卷能力。教师先选择知识库文档、章节、知识点、题型、题量和难度，再通过自然语言补充要求。智能体根据资料生成题目、答案和解析，教师逐题或整套审核后完成组卷，并保留可追溯的结果。

当前版本以单租户出题闭环为交付目标；账号、多人工作空间、成员角色和审计属于后续产品阶段，不计入当前版本完成条件。

## 二、问题与机会

教师在准备数学练习和试卷时，需要反复查找教材、拆分知识点、编写不同题型、整理答案解析，并在修改题目后同步检查答案和评分标准。现有流程缺少资料依据、题目状态和整卷检查的统一记录，容易出现超出章节范围、知识点覆盖不足、题目重复和答案不同步等问题。

产品需要让教师能够明确指定出题依据，看到生成过程和题目依据，修改受影响的题目，并在正式使用前完成可检查的人工确认。

## 三、目标与非目标

| 目标 | 非目标 |
| --- | --- |
| 支持按知识点、例题或错题生成数学题目 | 当前版本实现完整的多人协作平台 |
| 支持题型、题量、难度、分值和知识范围配置 | 当前版本实现账号注册、邀请和成员管理 |
| 支持自然语言多轮调整出题要求 | 当前版本覆盖所有外部 RAG 服务的生产可用性 |
| 支持题目预览、编辑、筛选、收藏和组卷 | 当前版本实现复杂的在线 Word/LaTeX 排版编辑器 |
| 让知识库上传、索引、检索状态可观察、可验证 | 将运行时模型密钥写入代码、测试或文档 |

## 四、用户故事

- 作为数学教师，我希望选择教材和章节后生成题目，以便题目有明确资料依据。
- 作为数学教师，我希望配置题型、题量和难度，以便控制试卷结构。
- 作为数学教师，我希望用自然语言要求修改某一道题，以便只重新处理受影响的内容。
- 作为数学教师，我希望看到题目、答案、解析、知识点和分值，以便逐题审核。
- 作为数学教师，我希望把已审核题目组卷并发布到学习空间，以便形成可使用的练习或试卷。
- 作为项目维护者，我希望验证上传、解析、索引、检索和进度推送，以便判断知识库效果是否达标。

## 五、核心流程

### 5.1 出题流程

1. 教师进入智能出题页面，选择知识库和文档。
2. 教师在参数栏选择题型、题量、难度和知识范围。
3. 教师通过对话补充教材章节、例题、错题、图形、答案和评分标准等要求。
4. 系统检查资料和配置是否满足要求；资料不足时明确提示缺口。
5. 系统生成题目、答案、解析、知识点、难度和分值。
6. 教师在题目预览页逐题查看、编辑、删除、收藏或筛选题目。
7. 教师通过对话提出局部修改或整套修改要求，系统更新相关题目并同步检查答案和解析。
8. 教师确认题目后进入组卷，选择题目模块、学习空间和是否保存组卷记录。
9. 系统展示生成结果和发布结果，教师完成最终人工确认。

### 5.2 知识库验证流程

1. 创建知识库并上传 PDF、DOCX、XLSX、Markdown 或 TXT 文件。
2. 查看解析、索引和进度状态。
3. 等待索引完成或处理失败重试。
4. 使用检索接口验证召回内容、来源文件和排序分数。
5. 对不同文档类型、不同知识点和不同查询建立固定验证样例。
6. 记录召回率、来源准确性、错误类型和未覆盖场景。

## 六、功能范围

### 当前版本必须完成

- 智能生成页面和题目预览页面。
- 知识库选择、文档选择和出题参数配置。
- `/api/chat`、`/api/generate` 等出题接口联调。
- 知识库创建、上传、索引、进度推送和检索验证。
- 题目筛选、编辑、删除、收藏和组卷交互。
- 默认 LlamaIndex 流程的上传、索引和检索端到端验证。
- 题库管理页面接入真实知识库接口，移除固定知识库和固定文档依赖。

### 后续版本

- 学生学习空间：查看教师发布内容并做题；其前端延后开发。
- 题目收藏页面：前端已实现（mock 数据，刷新即重置），后端持久化待接入。
- 组卷记录页面。
- 题库管理完整页面和高级连接器管理。
- 教师个人中心及独立设置中心已按本地规格实现并完成本地验收，结果见[实施记录](个人中心与应用设置实施记录.md)。教师资料限头像、昵称、教师身份、任教学段与年级，独立持久化；个人中心后续覆盖学生。设置分为模型与服务、知识库引擎、文档解析；模型用途仅含主语言模型、辅助任务模型（支持「跟随主模型」）、嵌入模型，并提供提供方与连接管理。
- Word、LaTeX、PDF 等成果导出。
- 版本保留、暂停恢复和任务断点。
- 账号、邀请、成员角色、任务权限、审计和多人协作冲突处理。

## 七、关键数据和接口要求

- 知识库、文档、题目、组卷记录和学习空间必须使用稳定 ID。
- 题目至少包含题型、题干、选项、答案、解析、知识点、难度、分值和来源文档。
- 知识库索引状态至少包含状态、阶段、进度、任务 ID、错误信息和更新时间。
- 检索结果至少包含内容、来源文件和分数；需要支持 `top_k` 和引擎检索模式。
- 前端类型定义、后端 schema、OpenAPI 快照和 API 文档必须保持一致。
- 模型和提供方凭据只能通过设置接口写入运行时数据目录，不能进入 PRD、代码或测试样例。

## 八、成功指标

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 默认引擎索引成功率 | 固定测试集 100% 完成或返回明确错误 | 后端端到端测试 |
| 检索来源命中率 | 基准问题的期望来源进入指定 `top_k` | 检索评估报告 |
| 索引进度可见性 | 成功、失败、取消均有终态消息 | WebSocket 测试 |
| 前端核心流程可用性 | 从选择文档到生成、预览、组卷可完成 | 前端联调验收 |
| 题目字段完整性 | 生成结果满足前端题目契约 | API 契约测试 |
| 题目修改影响范围 | 局部修改不会无故重做整套题目 | 对话场景验收 |

## 九、分阶段交付

### 阶段一：主链路稳定

完成智能生成、题目预览、参数配置、对话出题和基础组卷的联调，确认默认知识库流程可用。

### 阶段二：前端页面补齐

按当前页面样式补齐题目收藏（前端已实现，mock 数据；组卷与编辑本期仅提示）、组卷记录、题库管理、教师个人中心和设置中的模型配置，并统一公共状态、API 和类型。设置入口放在左侧底部，默认打开「模型与服务 → 主语言模型」，分为模型与服务、知识库引擎、文档解析；模型用途仅主语言模型、辅助任务模型和嵌入模型，并支持提供方与连接管理。模型草稿/应用与引擎、解析器、个人资料的独立保存不可混同。学习空间是学生查看教师发布内容和做题的区域，本期保留导航、未开放提示和组卷占位流程，不交付真实学生闭环；个人中心本期仅五项教师资料并独立持久化。范围与交互见[个人中心与模型配置页面设计](个人中心与模型配置页面设计.md)；对应的[本地功能规格](个人中心与应用设置功能规格.md)已完成本期实现与本地验收，结果见[实施记录](个人中心与应用设置实施记录.md)，不发布远端工单。

### 阶段三：知识库效果验证

完成默认引擎的文档类型验证、检索基准集、进度稳定性和错误场景验证，再评估可选 RAG 引擎和外部连接器。

### 阶段四：成果和协作能力

完成文件导出、版本保留、暂停恢复，再单独规划账号、工作空间、角色权限、审计和多人协作。

## 十、验收标准

- 教师可以选择真实知识库文档并生成指定题型和数量的题目。
- 生成结果可以在预览页查看、筛选、编辑、删除和收藏。
- 题目修改后，受影响的答案和解析能够同步更新或明确提示需要重新生成。
- 知识库上传、索引、检索和失败状态都有可观察结果。
- 组卷结果包含题目数量、分值和目标学习空间。
- 当前版本不把未实现的账号、多工作空间和权限能力展示为已完成能力。
- 功能代码、接口契约、测试和设计文档在同一提交中同步更新。

## 十一、待决策事项

- 题目生成结果是否需要后端持久化，还是先保持当前会话级状态。
- Word、LaTeX 和 PDF 导出的优先顺序及模板范围。
- 知识库效果评估采用哪些固定教材、问题集和通过阈值。
- 多人协作是否作为独立产品阶段建设，以及是否恢复上游多用户模块。

## M1 追踪接入与 Phoenix


**职责**

- 建立 SDK Agent 原生 tracing → 本地 Phoenix 的单出口，在首条 trace 前替换默认处理器链，不保留默认云端导出或双写。
- 关联运行、会话、批次、阶段及工具调用；按白名单采集出题相关对话与 API 请求／响应正文。

**输入输出**

- 输入可由现有两类入口调用的 SDK Agent、阶段事件及合成模型／工具响应；输出 `run_id`、`trace_id` 与可选会话／批次关联。
- 输出本地 trace 查询证据、阶段与失败／降级证据、导出状态和追踪可查看状态；此时不要求先建设运维 SQL 表。

**依赖**

- 依赖 SDK Agent 主体及本地 Phoenix；接入时核验并固定 SDK、适配器、Phoenix 的兼容版本和受支持的保留能力。
- 本模块 G0 是 M2–M8 真实后端接入与贯通的前置门槛；仅 M7 界面、类型、API 适配和 DEV 演示按文首例外先行。安装 SDK、合成页面或存在 trace 均不能单独替代真实验收。

**异常边界**

- 导出断连、超时和缓冲耗尽仅影响追踪维度；缓冲、重试、退出刷新有界，不阻塞出题或改写执行、质量结果。
- 导出受理不代表持久化完整；未采集、延迟、过期、未找到、不可用、无权限和未知分别表达，不承诺补回已丢失正文。
- 凭据、Cookie、密码、认证令牌及认证 API 排除；输入、输出、元数据、异常与导出载荷均在写出前脱敏。

**验收要点**

- 两类真实业务入口使用假模型／工具贯通 SDK Agent 至本地 Phoenix，覆盖成功、失败、降级及并发；确认无默认云端追踪出口。
- 同会话多运行、跨账号及并发工具不串 trace；白名单正文可查，合成敏感标记在各导出边界均被排除。
- 验证导出故障、恢复、缓冲上限、有界退出及实际项目的正文保留能力，形成可复核的 G0 证据。

## M2 运行记录与执行状态


**职责**

- 记录受理、实际开始、阶段、独立心跳、结束及业务关联，以 SQL 持久化运行摘要与采集覆盖。
- 分离执行状态、质量状态和 trace 状态；受理不等于开始，HTTP 成功、批次落库或 trace 存在均不代表质量通过。

**输入输出**

- 输入 M1 的关联标识及执行体事件；输出运行摘要、阶段时间线、等待／耗时、心跳、采集缺口和观察标记。
- 执行状态采用 `accepted|running|completed|failed|cancelled|unknown`，未知字段用 `null` 或 `unknown` 并说明原因，不补 0、false 或成功。

**依赖**

- 依赖 G0 通过、权威执行事件、SQL 持久化及既有用户／会话／批次关联；Redis 可作缓存，不是摘要唯一数据源。
- 心跳独立于模型调用，默认每 15 秒发送；观察默认每 15 秒评估，间隔可配置，观察新鲜度与运行心跳分别判断。

**异常边界**

- `failed` 必须来自权威失败事件，`cancelled` 必须有执行体确认停止；重复事件和迟到心跳不得覆盖已确认终态。
- 实际运行超过 10 分钟、无心跳超过 90 秒只标疑似超时／失联；无首次心跳时按已知开始时间判断，缺少依据时显示未知。
- 监测器不得强停或合成业务终态；摘要写入失败暴露采集缺口，SQL 不可用时如实报告，不伪造业务失败或完整摘要。

**验收要点**

- 覆盖受理未开始、开始前失败、正常完成、明确失败／取消及未知状态；同会话多运行保持独立关联。
- 验证事件幂等与顺序、阶段并行和重复尝试；阶段耗时之和不冒充运行墙钟耗时，缺采集不造完整时间线。
- 新鲜心跳只解除对应心跳异常，超时条件单独判断；只有权威终态结束运行，监测中断不等于恢复。

## M3 交付质量观测


**职责**

- 独立记录题量满足、最终版本审核覆盖、真实重出尝试和降级原因，展示可观测的交付规则结果。
- 质量状态采用 `met|attention|not_evaluated|unknown`；`met` 只表示交付规则达标，不承诺数学内容正确。

**输入输出**

- 输入目标数量、最终交付集合、最终版本审核证据、重出事件及降级事件；输出计数、质量原因和证据已知样本比率。
- 明确不足、跳审、审核未通过仍交付或降级任一成立即 `attention`；已知异常与其他未知项同时保留。

**依赖**

- 依赖 M2 的执行状态、结束时间及采集覆盖，以及执行体的最终交付与审核事件；向 M5 提供去重运行及质量原因。
- `met` 要求正常完成、题量已知满足、无降级，且应审最终版本全部明确通过或明确不要求审核。

**异常边界**

- 执行完成但降级显示 `completed + attention`；HTTP 成功或 trace 存在不推导质量通过，审核证据未知不得判 `met`。
- 未知和未采集值不补 0；无有效分母时比率为 `null`，并标明无样本、未采集或覆盖不完整。
- 重出按真实尝试次数、结果和耗时采集，不用 `regenerated` 的去重保留数替代；频繁重出阈值按 G0 合成执行样本校准。

**验收要点**

- 核对最终交付题目的最终版本审核，重复审核只计一题，重出替换后重新计算覆盖；零成果不冒充审核完整。
- 重出成功后被去重丢弃仍保留真实尝试事实；阈值未校准显示未配置，不凭空触发频繁重出告警。
- 质量明细始终可见；同一 run 多原因在各原因桶可分别出现，在总体异常运行数中只计一次。

## M4 依赖健康监测


**职责**

- 观测模型、嵌入、重排、Redis、向量库、SQL 和 Phoenix，区分共享平台依赖与个人凭据作用域。
- 基于实际调用或明确标注的受控探测输出当前健康判断，不因打开后台触发模型调用或付费出题。

**输入输出**

- 输入安全调用结果、受控探测结果和检查时间；输出依赖逻辑标识、作用域、来源、新鲜度、连续计数和安全错误码。
- 状态为 `healthy|degraded|unavailable|unknown`；默认观测有效 300 秒，过期为未知，从未观测的时间与计数为空。

**依赖**

- 依赖 G0、既有依赖调用边界、SQL 观测摘要和 M8 调度；共享故障判断及恢复证据供 M5 使用。
- SQL 保存观测与去重依据；Redis 故障不应删除已落库摘要，不以 Redis 锁作为监测存活的必要条件。

**异常边界**

- 同一共享依赖连续 3 次失败触发告警，连续 2 次成功恢复；成功重置失败序列，失败重置恢复成功序列。
- 个人凭据失败只归属对应账号，不能升级为共享故障；网络故障不冒充鉴权失败，无观测不显示健康。
- Redis 是现有认证依赖，故障时不能承诺整站登录或业务可用；SQL 故障真实不可用，不以缓存假装摘要服务正常。

**验收要点**

- 验证 3 次失败、单次成功、恢复中再失败及 2 次连续成功，检测空窗不能补算连续证据。
- 区分个人错误与共享服务故障，覆盖过期观测、部分降级、探测失败与监测停止，错误信息不包含连接串或凭据。
- Redis 故障下以授权本地 SQL 诊断核验摘要仍在，不绕过认证增加匿名入口；Phoenix 故障不改写运行结果。

## M5 异常聚合与站内告警


**职责**

- 聚合依赖、等待、疑似超时／失联、权威失败事件和质量异常，维护触发、持续、恢复及复发轮次。
- 复用现有管理员站内通知，不新增外部通知、人工确认、屏蔽、强停、代重试或运行状态修改能力。

**输入输出**

- 输入 M2–M4 的有效证据；输出 SQL 异常轮次、聚合键、首次／最近发生、影响次数、关联运行和通知幂等状态。
- 同类持续故障 10 分钟内去重，不重复通知；满 10 分钟不强制重发，恢复后复发开启新轮，可立即告警。

**依赖**

- 依赖 M2 的权威事件、M3 的质量样本、M4 的依赖证据、现有通知机制和 M8 检测循环；去重与水位落 SQL。
- 同一聚合键最多一个活动轮次；通知写入与去重状态一致，重复事件、重启和通知重试不得重复创建同一提醒。

**异常边界**

- 等待超过 30 秒且未实际开始的条件持续 120 秒才告警；开始或权威结束解除，观察中断重置连续计时。
- 质量取最近 5 分钟内按 `finished_at` 纳入的 `completed` 且质量为 `met|attention` 的去重 run；样本 ≥10 且 attention ≥20% 触发。
- 同 run 多原因只计一次；同口径样本 ≥10 且 attention <20% 持续 120 秒才恢复，低样本／未知保持待检测并重置恢复计时。

**验收要点**

- 覆盖触发与恢复阈值边界、连续观察中断及同 run 多原因去重；概览受理窗口不混用质量告警的结束时间窗口。
- 权威失败事件告警在记录并通知后关闭，关闭不代表业务成功；超 10 分钟／无心跳 90 秒仅形成疑似异常。
- 已读、刷新、调阈值或检测重启均不冒充恢复；缺证据保留活动轮次并标未知，恢复后新轮不被旧去重窗口吞掉。

## M6 运维查询接口与权限

**当前状态：五个 ops 后端接口全部待实现。** M7 的 TypeScript 类型、真实请求适配及合成响应不构成后端实现证据，也不代表 G1 后端契约冻结。本轮仅更新 `docs/api.md` 入口说明，不重新生成 OpenAPI 或接口正文。

**职责**

- 提供恰好五个只读 ops 查询接口，统一管理员鉴权、字段、空值、筛选、分页、错误及资源归属语义。
- 使用既有身份边界，管理员资格不自动授予 Phoenix 权限；普通教师／学生不得读取运维正文或其他账号数据。

**输入输出**

- 输入授权查询条件及 M2–M5 的 SQL 摘要，输出概览、运行列表／详情、依赖快照和异常轮次；字段以配套契约为准。
- 接口为 `GET /api/admin/ops/overview`、`GET /api/admin/ops/runs`、`GET /api/admin/ops/runs/{run_id}`。
- 另有 `GET /api/admin/ops/dependencies`、`GET /api/admin/ops/alerts`；通知读写沿用现有接口，不增加第六个 ops 接口。

**依赖**

- 依赖现有管理员认证、SQL 数据和本地 trace 映射；契约名称保持《运维后台接口与联调契约》，实现时同步 OpenAPI 与 API 文档。

**异常边界**

- 查询不触发探测、不抓取 Phoenix 控制台拼装摘要，不提供运行干预；SQL 故障按契约返回真实不可用。
- 单条 trace 无权、过期、未知或不可用放在详情 trace 对象，不冒充 MathCraft 登录失效；权限未知不返回可用正文链接。
- 摘要不存在或过期统一 404；`alerts` 可按 `alert_id` 定位保留轮次，不因默认时间窗误报过期。

**验收要点**

- 核对五条路径及所有只读边界，检查非管理员拒绝、越权防护、分页稳定性、空集合和不可用错误。
- 执行／质量／trace 语义与空值保持一致，未知不补 0；查询保留期与活动保护记录的行为符合契约。
- 验证平台与 Phoenix 独立授权、脱敏摘要和安全链接，接口与生成文档覆盖实际路径，不以脚本退出成功替代核对。

## M7 运维后台界面

**当前状态：用户授权按 v1 契约在 G0 前先行实现完整前端，前端与合成交互已验收。** 原四入口、三新入口及管理员通知属于本轮前端范围，后端运维能力仍按 M1–M6／M8 的门槛推进。

**职责**

- 保留平台概览、账号管理、模型与检索、账号安全四区及原有操作，新增出题运行、依赖状态、异常中心三个入口。
- 展示运行筛选、详情时间线、独立质量摘要、依赖来源与新鲜度、异常轮次和站内提醒，复用现有样式及通知体验。

**输入输出**

- 输入 M6 五个接口与现有通知响应；输出带类型映射的列表、详情、筛选分页、错误反馈和本地 Phoenix 定位入口。
- 加载、错误、空集、未知、未配置、过期、无权限分别展示；执行结果、质量结果和 trace 可查看状态分别呈现。

**依赖**

- 先行开发依赖 v1 联调基线、既有前端 API 层及身份与权限上下文；真实接入仍依赖 G0、G1 及 M6 后端。告警判断由服务端提供，浏览器不另算规则，DEV 合成结果不是实际规则执行证据。
- 正文查看依赖 Phoenix 独立授权及有效可读证据，页面不复制存储正文，不显示凭据或认证调用内容。

**异常边界**

- 疑似超时／失联不显示为已失败或已强停，`unknown` 不显示为 0；质量样本不足不显示通过，重出阈值未校准显示未配置。
- 正文到期而摘要仍在时继续展示摘要；Phoenix 无权限不诱发平台退出登录，旧通知关联已清理时明确显示过期。
- 快速切换入口／筛选时迟到响应不覆盖当前页面，卸载时异步任务有界收尾；重复刷新不重复弹出同一通知。
- 默认请求真实 API，真实错误显示错误和重试，不自动回退 mock；仅登录后的管理员可在 DEV 显式勾选合成演示，生产没有演示入口或 demo 模块。
- 演示仅覆盖运维统计、运行、依赖、异常、通知；旧平台资源／历史批次统计、账号、模型与安全始终使用真实接口。演示通知操作只影响内存，不改变真实通知或故障恢复状态。

## M8 保留清理与调度


**职责**

- 默认正文 3 天、SQL 摘要 14 天，每日清理；期限与调度均可配置，分批可重入，不承诺到秒删除或数据库文件立即缩小。
- 在现有 lifespan 管理检测与清理，限定 single worker／单实例；同一持久化范围只有一个调度实例，不新增任务队列。

**输入输出**

- 输入保留配置、SQL 清理水位、活动状态及 Phoenix 受支持的清理能力；输出安全作业结果、失败码、下次时间和延后清理原因。
- 正文从根 trace 创建起算；运行／阶段从受理、依赖历史从检查、通知关联从创建起算，告警按最近发生／恢复时间较晚者起算。

**依赖**

- 依赖 SQL 持久化、M1 已核验的 Phoenix 保留能力和 M2–M5 状态；检测去重不依赖 Redis，SQL 与正文清理分别记录结果。
- Phoenix 原生调度或应用经受支持接口触发只选一种并记录，不直接操作私有表；多 worker／多副本能力另行设计验收。

**异常边界**

- 保护活动运行及无权威终态仍需检测的 unknown 运行摘要；保护活动／待检测故障的判定、去重、恢复和通知所需最小状态。
- 每日复核保护原因，解除后正常清理；保护不延长正文 3 天期限，不永久保留全部故障历史，迟到 span 仍受原到期边界限制。
- 启停、等待、重试和单次批量有界，防自身重叠；重启按 SQL 水位补扫，不按停机天数并发补任务或补造连续检测证据。

**验收要点**

- 合成到期记录验证正文关闭／物理清理、摘要续存和统一过期响应；活动运行及待检测故障超过 14 天仍保留必要判定能力。
- 覆盖重复执行、中途失败、查询并发、重启补扫与 Phoenix 停机；正文清理失败不阻断 SQL 清理，不伪称已删除。
- 核验单 worker 加单实例约束及有界退出；Redis 故障不丢 SQL 去重状态，SQL 故障明确不可用，故障恢复不改写业务终态。

# 运维后台模块说明

状态：**M1 实际入口、M2 台账与 M3 查询已在本地整合；M4 前端已完成 V2 适配与隔离联调，部署待验收。** 本文使用职责分工描述模块。查询接口与验证边界见[查询 V2 实现与交接](运维查询V2接口与查询设计.md)，整合验收见[本地整合记录](../implementation/运维后台本地整合验收.md)。

## M1 出题入口运行记录

覆盖对话出题和参数化出题。已通过 `GenerationRun` 接入普通 `openai.OpenAI` 调用链及任务生命周期，写入最小 `ops_runs`。实际受理才建记录，`/start` 到后台沿用 ID，批次与 completed 同事务保存；暂停请求须执行器确认才记 canceled。接点及边界见 [入口接入](运维后台出题入口接入.md)。

记录入口、账号、会话或任务、题库／文档、批次、状态和时间。状态只使用 `accepted`、`running`、`completed`、`failed`、`canceled`、`unknown`；无法确认终态时保留 `unknown`。

不记录模型正文、工具正文、完整对话、题目内容或复杂质量指标。

## M2 运行摘要存储

已新增最小 `OpsRun` 模型、增量迁移 `n9a0b1c23456` 及 `RunLedger` 写入模块，作为后台运行查询的事实来源；Redis 只用于临时进度。字段为 `run_id`、`entrypoint`、`owner_user_id`、`session_id/task_id`、`bank_id`、`document_id`、`batch_id`、`status`、`requested_count`、`delivered_count`、`error_code` 和受理／开始／结束／最后观测时间，只保留能确认的值。

受理可独立持久化，也可与持久任务使用同一事务；完成关联只参加调用方批次事务，不隐式提交调用方 Session。升级创建空表，不回填旧批次；资源 ID 保留快照，账号硬删除使用 RESTRICT。正常关闭只封口本进程登记的在途 ID；单实例、单 worker 启动恢复将持久任务／会话标记中断时，同事务将未终结对话台账及关联持久任务的未终结台账记为 unknown 和 EXECUTION_INTERRUPTED，不扫描无持久任务关联的参数化台账，字段与事务契约见 [运行台账基础](运维后台运行台账基础.md)。

批次存在时关联 `batch_id`；运行失败、取消或中断时保留已知事实。Redis 过期不改变 SQL 台账；明确观察到执行中断且无法确认终态时记录 `unknown`，不能推断为 `failed`。

## M3 后台查询

已实现管理员只读查询：平台概览、出题运行列表和基本详情。查询读取 M2 注册的正式 ORM，只返回运行摘要及已有业务标识，支持时间、账号、入口、状态和会话／任务／批次筛选及 limit/offset 分页。表尚未部署、列契约不兼容或读取失败返回 `503 OPS_DATA_UNAVAILABLE`；查询不刷新 `last_observed_at`，不推断或补写终态。

本模块不提供依赖监测、异常中心、告警恢复、质量覆盖、正文查看或 Phoenix 必需跳转。

## M4 后台前端

保留平台概览和出题运行页面，删除依赖状态、异常中心、告警通知和无数据来源的扩展展示。旧入口、类型及演示已清理。V2 数量空值、六状态、筛选、limit/offset、错误和基本详情已对接；未知数据保持未知。实际 HTTP 到页面联调和部署边界见[前端 V2 与页面联调](../implementation/运维后台前端V2适配与联调.md)。

## M5 Phoenix 可选扩展

Phoenix 通过 `phoenix_tracing.py` 的私有 provider、有界队列与手工 protobuf 导出实现，`MetadataClient` 观察当前普通 OpenAI 客户端，`@trace_run` 关联两类入口，线程池传递上下文。默认关闭，不引入 Agent SDK，不发送正文；导出故障不改变业务结果。实际出题的 `run_` 标识已关联运行台账，根 span OK 只说明函数返回。

详细设计见 [Phoenix 可选扩展](Phoenix可选扩展.md)。

## 已删除的模块范围

本方案不再建设 Agent SDK 追踪、依赖状态、异常聚合、告警通知、质量覆盖统计、复杂清理调度、运维链路自监控和正文访问审计。这些内容不得通过前端演示或占位接口继续对外宣称已实现。

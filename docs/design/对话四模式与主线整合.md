# 对话四模式与主线整合

状态：2026-11-11 四模式整合已验收；下文技能注册与流式生成说明按 2026-11-13 合并代码同步。文末验收记录属于原整合批次，本次增量验证见[主线整合记录](题目Word导出与公式呈现.md#2026-11-13-主线整合验证)。

## 目标与使用范围

将 `agent` 的四模式对话、图片附件和数据操作确认整合到当前 `main`，同时保留
账号权限、个人模型配置、共享提示和异步会话隔离。代码入口为
`backend/app/api/chat.py`、`backend/app/services/rag/` 和
`frontend/src/components/tabs/GenerateTab/`。

本说明补充《对话出题必填信息检查》和《出题审核中间件设计与实施记录》。总体 PRD
中的多资料选择、题目版本和组卷目标不由本次合并自动交付；当前会话仍绑定一个已入库
文档及其题库，创建和发送消息均需通过现有资源权限检查。

## 核心流程

| 模式 | 标识 | 当前用途 |
| --- | --- | --- |
| 快速出题 | `generate` | 累积题型、数量、范围和难度，补齐后检索与生成 |
| 创新命题 | `creative` | 在独立模式下收集命题要求，生成后继续经过统一审核 |
| 知识答疑 | `qa` | 检索当前资料并回答文字问题，引用文档及章节 |
| 数据管理 | `data` | 查询本人收藏、题目、试卷等数据；受支持的删除和改名先确认 |

输入框分段控制器显式选择模式。意图识别只提供切换建议，不替用户自动执行其他模式。
高置信度不匹配时保留待续文字及图片；用户紧接确认切换后接续处理。下一条普通请求会
替代旧待续内容，避免后续切换重新执行旧请求。普通显式切换清理旧槽位，
避免把上一模式参数带入新任务。

当前消息路由通过 `rag/skills.py` 的 `SKILLS` 注册表和 `get_skill()` 分发，
`ChatContext` 传入会话、当前用户、槽位、历史、图片、进度与取消检查等上下文。
四个执行入口分别为 `run_generate`、`run_creative`、`run_qa`、`run_data`，
内部延迟导入现有业务函数；这是代码内注册表，没有新增技能管理 HTTP 接口或动态插件发现。
`get_skill()` 对未知内部标识回退快速出题，外部请求仍沿用既有 `mode` 校验。
路由统一处理暂停、原题数量不足和模型错误；答疑技能另将内部异常转为可读回复。

按 `agent` 的当前知识点流水线，快速出题不再把题目来源作为必填追问；历史显式来源值
继续兼容，未提供时沿用 `variant_data`。数量仍须明确到各题型，不能用默认题量或截断
小数绕过完整性检查，构造生成参数时再次验证。

图片最多四张，后端仅接受 PNG、JPEG、WebP 的 base64 data URL，单张解码后不超过
5 MiB。快速出题与创新命题将图片用于要求抽取；知识答疑和数据管理目前按文字处理，
不将其描述为图片答疑或图片数据识别。纯图片请求与无内容请求须分别校验，不能只因
文字为空而拒绝有效图片，也不能将空白文字和空附件发送给模型。

出题结果经过现有查重、难度审核及独立解题再落库。独立解题使用同一次 JSON 输出中的
`answer` 和 `analysis`；两者必须同时为非空字符串，否则整体保留原答案和解析，且不计入
已解题数量。运行时配置继续遵循 `with_snapshot`，共享题库历史语料继续按当前用户隔离。

生成层通过 `llm.chat_stream()` 接收模型增量，在 `question_gen.py` 中滚动提取完整题目，
以 `Question` 校验并在必要时修复 JSON、反馈字段错误重试。审核通过后仍按原流程持久化；
消息接口返回整段结果，进度接口供前端轮询，没有新增 SSE、WebSocket 或逐 token 出题契约。
详细重试与公式规范见[出题审核说明](出题审核中间件设计与实施记录.md#流式生成与结构校验)。

## HTTP 与状态契约

保留现有创建、读取、发送、进度、暂停和清除会话接口，并增加：

| 方法 | 路径 | 请求 |
| --- | --- | --- |
| POST | `/api/chat/sessions/{session_id}/confirm` | `confirm_id` 与布尔值 `accepted` |

消息请求在 `message`、`existing_stems` 之外包含 `images`、`mode`、`switch_only`。
响应继续包含 `reply`、`questions`、`done`、`slot_state` 和 `batch_id`，并返回
`kind`、`mode`、`mode_changed`、`suggested_template`、`confirm`。
`kind` 的正常、模式不匹配及待澄清结果分别为 `reply`、`mode_mismatch`、`mode_confirm`。

数据操作预览的 `confirm` 包含确认 ID、操作及实体、影响数量和少量样本。确认有效期为
300 秒。预览和实际执行必须对应同一组目标，执行时再次校验归属，不能因重新扩大查询
而修改预览之外的记录。取消、过期和重复确认不得执行写操作。

确认绑定发起账号和会话，预览默认最多选中 50 条，显式 `limit` 上限为 200；只修改选中
目标，预览后新增记录不会被旧确认影响。当前写操作支持删除收藏，以及删除或改名本人
试卷；试卷新名称去除首尾空白后须为 1–128 字符，不支持的写操作不生成确认。
确认凭据使用 Redis Lua 原子比较并消费，跨账号和跨会话请求不消费原凭据；执行时仍按
当前归属筛选目标。Redis 与 SQL 没有跨存储事务，数据库执行失败后应重新预览确认。

数据统计的 `count/avg/max/min` 对完整归属、完整过滤集合计算，`limit` 仅限制明细和
写预览。收藏与题目支持按 `difficulty_score` 排序；未知排序字段返回 `DATA_ORDER/400`，
不适用的数值统计字段返回 `DATA_AGGREGATE/400`。当前过滤与聚合仍在内存中完成，
处理量随所属数据量增长。

OpenAPI 与 `docs/api.md` 按合并后的实际路由生成，保留当前账号登录、邮箱绑定、管理员
及模型检索接口，不恢复旧注册或密码登录路径。开发账号端点仅按现有受控环境条件挂载，
契约生成和测试使用隔离配置，不读取个人凭据。

## 前端状态与异常边界

- 保留 `agent` 的消息布局、四模式、图片和确认卡片；输入框动态行数与无障碍名称同时保留。
- 对话状态使用 `agent` 的新字段，提示使用 `main` 的共享提示机制，不恢复旧的局部提示状态。
- 发送前组合内容、资源选择、并发和当前登录会话检查。创建消息及轮询保留图片与当前请求标识。
- 收到响应后先判断请求是否仍有效，再更新模式、建议及确认状态，最后显示回复和题目。
- 图片读取和确认操作等异步回调同样遵循会话边界，清空或切换后不得把过期结果写回新对话。
- 上传及延迟返回的文档列表不能覆盖新对话的选择。确认写操作后刷新对应收藏或试卷缓存；
  确认已执行但刷新失败时明确提示，不恢复可重复执行的确认卡片。
- 清空会话同时清理进度、附件、模式建议与待确认操作；页面切换遵循已有未保存设置保护。
- 模型与检索故障使用现有错误反馈，不访问真实外部模型完成测试。

`main` 对历史用户消息的回退和编辑入口与 `agent` 仅操作最新消息的界面策略不同。
2026-11-11 整合时按用户决定保留 `agent` 策略；后续已恢复历史用户消息编辑与回退重发，
当前界面行为见[视觉恢复说明](登录视觉恢复与历史前端对照.md)。本次公式样式调整沿用当前消息操作。

## 验收标准

1. 当前账号、管理员、模型配置及资源归属检查保持生效，四模式可分别进入正确分支。
2. 图片数量、编码和大小非法时拒绝；有效纯图片与空消息边界有回归覆盖。
3. 数据确认预览和执行范围一致，新增记录不被旧确认影响；跨账号、跨会话、过期及重复确认受保护。
4. 退出、切换文档、清空对话、取消及重复点击后，过期请求不污染当前界面。
5. 运行后端全量测试、Ruff、Pyright 与前端类型、lint、构建及必要的离线回归；既有诊断单独记录。
6. 生成契约覆盖新增确认接口并保留主线接口，设计、目录入口与实际代码一致。

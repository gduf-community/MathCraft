# 运维后台运行手册（方案／待实现）

> 文档状态：方案／待实现
> 适用对象：负责本地部署、上线检查、日常值守、故障排查和交接的同事
> 当前边界：本文依据已确认的运维后台方案编写。新增前端及合成交互已完成，本次前端检查及独立复审已通过；真实授权审计和后端联调待完成。OpenAI Agents SDK 的真实出题链路、Phoenix 追踪接入、运行台账、告警后端和五个运维查询接口仍需按设计实现。本文中的部署命令、实际采集和作业结果不能当作当前已存在能力。

## 1. 运行目标与值守原则

运维后台在保留原管理员职责的基础上，负责观察参数化出题和对话出题的运行情况，帮助值守人员回答以下问题：

- 这次出题是否已经受理、实际开始、正常结束或失败。
- 是否存在已受理但迟迟未开始、执行过久、心跳失联或依赖调用超时。
- 模型、Redis、向量库、数据库和本地 Phoenix 是否可用。
- 是否出现题量不足、频繁重出、审核跳过、审核证据不完整或降级放行。
- 运行摘要、详细 trace、用户对话和模型调用是否能够相互关联。
- 运维采集链路自身是否积压、丢弃、导出失败、告警停止或清理失败。
- 某条异常是否已经恢复，恢复判断是否有足够证据。

值守时遵循以下原则：

1. 业务执行状态、交付质量状态和追踪可见状态分别判断，不能用其中一个状态替代另外两个。
2. Phoenix 的服务健康不等于某一条 trace 已经导出、持久化并可读。
3. 运行台账和告警摘要以 SQL 为查询来源；详细调用正文以受控访问的本地 Phoenix 为来源。
4. 采集、导出或告警失败不能阻断正常出题，也不能把运维记录失败伪造成业务失败。
5. 采集缺失、证据过期或无法关联时显示 `unknown`／`partial`，不能填写为零、正常或成功。
6. 首期只提供只读排障能力，不提供管理员代用户重试、强停运行、修改题目结果或修改业务终态的操作。
7. 阈值由配置文件或环境变量维护，后台只读展示实际生效值；首期不提供在线修改阈值接口。
8. 用户对话、题目正文、模型输入输出和工具参数默认隐藏；单条授权查看前必须经过权限检查，查看行为写入审计。

## 2. 系统组成和数据边界

运行链路按以下方式部署和检查：

```text
参数化／对话出题入口
        │
        ▼
OpenAI Agents SDK Agent
        ├── 原生 tracing
        │       ├── 本地有界导出
        │       └── 本地 Phoenix：详细 trace、允许查看的正文
        │
        ├── 业务事务：题目、批次、对话关联
        │
        └── 运维采集：运行事实、质量事实、依赖观测、告警摘要
                        └── SQL：运行台账、质量摘要、依赖状态、告警轮次、审计摘要
```

OpenAI Agents SDK 是出题 Agent 的执行基础。接入时必须使用本地 Phoenix 作为追踪出口，确认没有默认 OpenAI 追踪出口与本地出口双写，也不能在本地 Phoenix 不可用时静默回退云端。

SQL 只保存排障所需的运行和告警摘要、标识、计数、状态、原因码、时间和审计记录，不复制整套对话正文。Phoenix 保存详细调用链和经授权采集的正文，采集前必须删除凭据、密码、Cookie、认证令牌和私钥。认证、改密等敏感接口不进入追踪正文。

一个运行至少需要能关联：

- `run_id`：一次实际出题运行的唯一标识。
- `trace_id`：SDK 根 trace 或本地 Phoenix 映射标识。
- `entrypoint`：参数化出题或对话出题入口。
- `owner_user_id`：运行归属账号。
- `session_id`：可为空的会话标识；普通对话追问不自动算作新出题运行。
- `batch_id`：业务事务成功保存后形成的成果批次。
- 题目版本、审核范围、重出尝试和最终交付集合的摘要。

题目内容发生变化时必须产生新版本。审核结论绑定被审核版本和实际审核范围；只审核题干难度不能显示为答案、解析或全面数学正确性均已通过。没有证据保持未知，只有明确的跳过事件才记为跳过。

## 3. 启动前检查

每次首次部署、版本升级、机器重启后重新上线或切换配置前，按顺序执行以下检查。检查结果应记录到部署记录或交接记录中；当前功能尚未实现时，应明确标记为“待实现／无法检查”，不能用页面空数据代替通过。

2026-11-11 历史前端验收不覆盖 2026-11-12 补全；新增检查统一填写在[升级方案第 10.3 节](运维后台升级方案.md#103-2026-11-12-补全检查)。G0／G1／G3 均未通过，前端检查不作为部署就绪证据。

### 3.1 配置和版本检查

确认：

- OpenAI Agents SDK、追踪适配器、Phoenix 客户端或导出依赖使用已经锁定并验证过的兼容版本。
- MathCraft、SDK Agent、Phoenix、SQL 数据库和 Redis 的连接配置来自部署环境的配置文件或环境变量。
- Phoenix 只绑定到预期的本地或受控网络地址，不直接暴露到公网。
- Phoenix 访问控制已经开启；MathCraft 管理员登录不自动等价于第三方 Phoenix 已完成授权。
- 详细 trace 保留期的实际生效值已读取，默认目标为 3 天；SQL 摘要保留期的实际生效值默认目标为 14 天。
- 清理周期实际配置为每日或已记录的等效周期。
- 告警阈值、积压容量、重试上限和超时均有明确配置来源。
- 配置中没有真实密钥、Cookie、Token 或私钥被写入日志、样例或提交内容。
- 阈值只能通过配置文件或环境变量修改；后台只读显示生效值，不通过页面改写配置。

建议在部署日志中记录配置的名称、是否已设置和解析后的非敏感值。不要记录连接串、密钥、Token 或完整 Phoenix 访问凭据。

### 3.2 数据库和 Redis 检查

确认：

- SQL 数据库可连接，当前应用迁移版本与部署版本匹配。
- 业务数据库与运维摘要表的迁移顺序已完成；迁移失败时不启动真实运维采集。
- 运维摘要写入使用应用配置的数据库，不把测试库、临时库或个人本地库当作正式目标。
- Redis 可连接并能执行受控的健康检查命令。
- Redis 检查结果能区分“连接失败”“鉴权失败”“命令超时”和“服务异常”。
- Redis 键数量、客户端初始化成功或连接池创建成功不能单独当作出题队列长度或服务健康证据。
- SQL 不可用时，后台应显示摘要不可用；不能伪造无异常，也不能承诺站内告警继续正常运行。

### 3.3 Phoenix 检查

确认：

- Phoenix 进程或容器已经启动，监听地址和端口符合部署配置。
- Phoenix 存储目录存在，运行账号具备所需读写权限。
- Phoenix 的认证入口可访问，未授权访问被拒绝。
- MathCraft 到 Phoenix 的本地追踪出口可连通。
- Phoenix 能接收一条只包含假数据的合成 trace。
- 合成 trace 能查到根记录和预期子 span；查询结果不包含凭据和认证信息。
- 导出失败、Phoenix 暂停或网络短暂断开时，业务请求仍能完成，且导出缓冲有上限。
- Phoenix 的详细正文保留策略、清理方式和实际项目配置已经核对。
- 可以用隔离合成项目的缩短 TTL 或官方支持的过期样本验证删除，不需要等待真实三天；记录验证方法和限制。
- 不能把 Phoenix 健康检查成功当作某一条运行 trace 已经可查。

### 3.4 业务链路检查

用假模型、假服务和合成数据执行至少以下样例：

| 样例 | 需要确认 |
| --- | --- |
| 参数化出题成功 | 根 trace、必要子 span、run_id、账号和入口正确关联 |
| 对话出题成功 | session_id 与本次 run 正确关联，普通追问不被误计为新运行 |
| 业务失败 | 执行失败原因安全分类，trace 和运行摘要仍可定位 |
| 业务降级 | 降级阶段、原因和影响范围可见，不能按完整成功处理 |
| 同一会话多次运行 | 不串用前一次 run 的 trace、题目或批次 |
| 两个账号并发运行 | 账号、凭据范围、依赖观测和正文不串线 |
| 题目内容修补 | 版本变化后旧审核证据不自动套用到新版本 |
| 审核范围不完整 | 显示 unknown／incomplete，不显示全面通过 |
| 业务批次已提交但回复失败 | 批次提交和对话关联分别可见，不能把已提交成果抹成未发生 |
| Phoenix 暂时不可用 | 业务继续，trace 维度显示 pending／unavailable／unknown，不能无限积压 |

只有在上述证据可查并且敏感字段已脱敏后，才可以进入日常值守。

## 4. 日常巡检

日常巡检分为每班开始、值守期间和班次结束三次。巡检不应依赖管理员手动打开大量 trace；先看摘要和异常，再按单条运行进入受控正文。

### 4.1 每班开始

检查运维后台的以下区域：

1. **运维系统自监控与审计**

   - 最近一次事件采集时间。
   - 最近一次成功写入 SQL 时间。
   - 事件处理延迟和未处理数量。
   - 丢弃事件数量及原因。
   - Phoenix 导出失败、重试和丢弃数量。
   - 最近一次告警评估时间。
   - 最近一次清理时间、结果和失败原因。
   - 通知投递失败数量和当前积压。
   - run 与 trace 无法关联的数量。
   - 审计写入失败数量。

2. **出题运行**

   - 已受理未开始数量。
   - 执行中运行和心跳过期数量。
   - 失败、取消、降级和质量 attention 数量。
   - 题量不足、审核跳过、审核证据不完整和重出异常。
   - 最近运行的 trace 是否处于可查、等待、过期或不可用状态。

3. **依赖状态**

   - 模型的 platform 级和 account 级状态。
   - Redis、向量库、数据库和 Phoenix 的最近观测时间。
   - 连续失败次数、错误分类、影响运行数。
   - 观测是否已过期；过期状态必须显示 unknown，不能继续显示 healthy。

4. **异常中心**

   - 当前 firing 的 critical 和 warning 轮次。
   - 新发生、持续中、已恢复和重复发生的异常。
   - 是否出现同一故障大量新建告警，说明去重失效。
   - 通知失败本身是否生成运维异常。

### 4.2 值守期间

当系统有新运行或新告警时，优先查看：

- 运行的 accepted_at、started_at、heartbeat_at、finished_at。
- 当前阶段和最后一条权威事件。
- 执行终态与质量状态是否一致。
- 目标题量、实际最终交付题量、最终版本审核覆盖和降级原因。
- 重出尝试次数、失败次数、耗时和是否有未结束尝试。
- trace 的 export_status、availability、complete 和 verified_at。
- 依赖观测的 scope：平台共享故障与个人凭据故障要分开。
- 采集缺口、未知字段和最近一次成功观测时间。

后台的“正常结束”只表示执行终态，不自动表示题量满足、审核完整、无降级或 trace 完整。通知已读只表示管理员处理了通知，不表示故障已恢复。

### 4.3 班次结束

确认：

- 当前 firing 告警已有责任人或交接说明。
- 未恢复告警的最后证据时间和下一次检查时间已记录。
- Phoenix 正文查看审计已写入，异常查看没有使用共享账号。
- 当班发现的采集丢失、导出积压、通知失败和清理失败已记录。
- 没有把 unknown、partial 或 trace 过期误写成业务失败。
- 配置实际生效值没有被临时改动；如发生改动，记录变更来源、时间和回滚方式。
- 需要持续关注的 run_id、alert_id、trace_id 已列入交接清单。

## 5. 告警处理流程

告警处理只读排障，不直接改变业务状态。处理顺序为“确认范围 → 查看摘要 → 定位证据 → 判断影响 → 记录结果 → 等待恢复或升级”。

### 5.1 通用步骤

1. 打开异常中心，确认 `alert_id`、`rule_id`、级别、scope、首次发生时间、最近证据和影响运行数。
2. 检查告警是否为持续轮次、恢复后复发或状态 unknown。
3. 查看关联运行摘要，确认是业务运行故障、依赖故障、质量异常还是运维采集故障。
4. 检查最近一次有效事件和 trace 可见状态；不要仅依据 HTTP 状态、Redis 键数或 Phoenix 健康页。
5. 根据责任模块进入对应排查入口。
6. 记录处理人、确认时间、证据 ID、影响范围、当前判断和下一步。
7. 等待规则产生恢复证据；不能通过“标记已读”或手动关闭通知宣布恢复。

### 5.2 告警级别

- **warning**：有明确影响或趋势，但当前仍有可用路径；继续观察并记录。
- **critical**：核心出题能力、共享依赖、数据安全或运维观测可信度受到明显影响；按交接制度升级。

告警级别 `severity` 只有 `warning` 和 `critical`。`condition_state=unknown` 表示最近条件证据不足、不能判断恢复，应检查采集链路；它不是第三种严重级别，仍保留原 `severity` 和 `firing/resolved` 生命周期状态。

### 5.3 重点业务告警

| 告警 | 首先检查 | 处理记录 |
| --- | --- | --- |
| 已受理未开始过久 | run 是否实际进入执行、后台任务和 Redis 状态、是否存在大量同类 run | 记录受理时间、实际开始证据或缺失原因 |
| 执行过久 | 当前阶段、最后心跳、最近依赖调用、是否仍有活动 span | 不强停、不改终态，记录最后可信证据 |
| 心跳失联 | 应用进程、运行锁、worker 状态、最后事件写入时间 | 区分运行真的失联和采集器失效 |
| 题量不足 | 目标数、最终交付集合、候选数、重出失败和降级 | 不把候选数或 flush 数当最终交付数 |
| 频繁重出 | attempt_id、成功／失败比例、耗时和样本窗口 | 阈值未配置时显示未配置，不自行判异常 |
| 审核跳过 | 明确的 skip 事件、实际审核范围和最终版本 | 缺少证据是 unknown，不自动改成 skipped |
| 审核不完整 | 最终版本、要求范围、实际范围和证据 | 不自动追加模型复审来凑指标 |
| 降级后成功 | 降级原因、受影响题目／尝试和最终状态 | 成功终态与质量 attention 同时展示 |
| 运行失败 | 权威终态、safe reason code、依赖错误和 trace | 不能只看异常全文，也不能把导出失败算业务失败 |

### 5.4 运维链路自身告警

运维系统出现以下情况时，应将其作为独立异常处理：

- 运行台账写入延迟持续增加。
- Phoenix 导出缓冲达到 warning／critical 容量。
- 事件被丢弃或解析失败。
- 通知写入或投递失败。
- 告警评估任务停止或连续失败。
- 清理任务失败或超过预期周期未执行。
- run 与 trace 大量无法关联。
- SQL 读取不可用。
- 审计事件无法写入。

处理时先保护业务：采集和导出必须有界，不能无限重试、无限占用内存或阻塞出题。运行终态和质量摘要优先于详细正文；导出失败应保留失败计数和缺口信息。不得用“没有告警”证明系统健康，必须同时检查自监控指标的新鲜度。

## 6. Phoenix 启动、访问和故障恢复

### 6.1 启动顺序

部署方式和具体命令须在实现阶段依据锁定版本补齐。本节规定值守顺序：

1. 确认 Phoenix 存储目录和权限。
2. 启动 Phoenix 服务或容器。
3. 检查 Phoenix 健康端点、端口和认证入口。
4. 用合成数据确认写入和单条读取。
5. 启动 MathCraft 的追踪导出适配器。
6. 再启动或放行使用真实 SDK Agent 的业务服务。
7. 执行参数化和对话两类合成验收。
8. 保存本次根 trace、子 span、脱敏和导出结果的标识。

Phoenix 不可用时，是否允许 MathCraft 启动由实现阶段的部署配置决定，但业务请求不能因为追踪导出失败而无限等待。若继续提供业务服务，运维后台必须明确显示追踪不可用或待导出，并统计丢弃和缺口。

### 6.2 访问控制

- Phoenix 只能通过本地或受控网络入口访问。
- 管理员查看正文必须先通过单条权限检查。
- 普通教师、学生和无关账号不能获得 trace 正文。
- MathCraft 管理员身份与 Phoenix 访问凭据的映射必须明确，不能因为前端显示了“查看 trace”就跳过 Phoenix 授权。
- 默认列表、概览和通知只展示摘要、原因码、计数和时间。
- 用户对话、题目、模型输入输出和工具参数在单条详情中默认隐藏，用户主动进入并通过权限检查后才可展示。
- Phoenix 正文查看不能提供无审计的批量导出；下载能力如未来需要，必须另行设计权限和审计。

### 6.3 Phoenix 故障定位

| 现象 | 判断顺序 | 结果 |
| --- | --- | --- |
| Phoenix 健康但单条 trace 不可查 | 查 export_status、映射 ID、等待窗口、单条读取权限 | 可能是 pending、not_found、forbidden 或 unknown，不能直接判业务失败 |
| 大量 trace pending | 查导出缓冲、网络、Phoenix 写入和索引可见性 | 记录积压量和最早等待时间，防止无限重试 |
| Phoenix unavailable | 查进程、端口、存储目录和认证入口 | 业务摘要继续按实际能力显示，trace 维度标缺口 |
| trace 根可读但子 span 缺失 | 查导出截断、关闭顺序、采集器丢弃和 span 关联 | 显示 available + complete=false |
| 详细正文包含敏感信息 | 立即停止继续查看和导出，保留安全事件摘要 | 按安全流程处理，不在工单或聊天中复制正文 |
| Phoenix 存储满 | 查磁盘、保留策略、清理作业和写入量 | 先恢复容量和清理能力，不能无限扩容内存缓冲 |

Phoenix 清理后，SQL 运行摘要仍可按其保留期查询。trace 入口应显示 expired 或 unavailable 等原因，不把正文过期解释成业务运行失败。

## 7. SQL 故障和采集积压

### 7.1 SQL 读取或写入失败

SQL 故障时：

- 后台摘要接口返回“运维摘要暂不可用”或等价安全错误。
- 不伪造空列表、零失败率或 healthy 状态。
- 业务原有事务的成功或失败按业务结果处理，不因运维摘要写入失败而改写终态。
- 记录 SQL 连接失败、超时、迁移不匹配或约束错误的安全分类。
- 检查是否只有运维表不可用，还是业务数据库整体不可用。
- 恢复后不能凭空补写未观测的开始、心跳和结束事件；只能标明采集缺口。
- 若告警状态也依赖该 SQL，必须把告警评估停止或数据过期显示给值守人员。

### 7.2 积压和容量保护

运行台账、Phoenix 导出、事件处理和通知投递都必须有界。实现时应配置并展示：

- 当前待处理数量。
- 最早待处理时间。
- 当前处理延迟。
- 最大缓冲容量。
- 重试次数和下一次重试时间。
- 已丢弃数量及丢弃原因。
- 恢复后积压下降速度。

保护优先级：

1. 保留运行终态、业务结果关联、质量摘要和告警证据。
2. 保留根 trace 与必要的错误和阶段标识。
3. 在容量不足时丢弃详细正文或低优先级普通 span，并记录丢弃计数。
4. 脱敏必须发生在进入缓冲之前。
5. 不能因为写追踪、写通知或写摘要而无限等待业务请求。
6. 重试必须有次数、时间和容量上限；超过上限转为失败或 dropped 并可查询。

“Phoenix 在线”只说明服务级检查通过；“导出已提交”只说明本地端点受理，不能证明详细 trace 已持久化、全部 span 齐全或正文可读。

## 8. 数据清理和保留验证

### 8.1 保留目标

默认目标为：

- Phoenix 详细追踪正文：3 天。
- SQL 运行、质量、依赖和告警摘要：14 天。
- 清理任务：每日执行，具体时间由配置决定。
- 活动运行和仍需检测的故障：不能因普通 TTL 被无条件抹掉。
- 清理作业：可重入、有界，并记录开始、结束、删除范围、结果和错误分类。

实际值以后台只读显示的生效配置为准。后台不提供在线修改保留期或阈值的接口。

### 8.2 清理前检查

清理前确认：

- 当前没有迁移、恢复或数据库维护任务与清理冲突。
- Phoenix 与 SQL 的保留配置已读取。
- 活动 run、待处理告警和仍需检测的故障有保护规则。
- 清理任务只有一个调度来源，避免多实例重复执行。
- 上一次清理结果可读；上一次失败时已记录重试或人工处理。
- 清理不会删除当前班次仍在使用的审计证据。

### 8.3 清理后检查

清理完成后检查：

- 作业状态为 success，或明确显示 failed／partial。
- 过期的合成 trace 已删除或进入 Phoenix 的过期状态。
- 一个未到期的合成 trace仍可查，作为非过期对照。
- SQL 过期摘要已按策略处理；活动状态仍有保护。
- 删除计数、失败计数和执行耗时可查。
- 数据库文件体积没有立即缩小时，不把它当作清理失败；逻辑记录删除和磁盘回收是不同结果。
- 清理失败进入异常中心，通知失败也单独计入运维异常。
- Phoenix 物理清理、索引刷新和正文入口关闭的时间差有可解释记录。

不要求等待真实三天完成验收，也不能声称已经观察完整三天周期。必须记录使用的加速验证方式、适用版本和限制。若锁定版本无法验证约定的保留和删除能力，应阻塞对应验收，不能临时增加未经设计的应用调度器来掩盖平台能力不足。

## 9. 审计检查

审计用于回答“谁在什么时间查看了哪类运维数据，以及查看是否成功”。

至少记录以下动作：

- 查看运行详情。
- 查看单条 Phoenix trace。
- 展开用户对话正文。
- 展开题目、模型输入输出或工具参数。
- 查看异常详情和关联运行。
- 查看依赖详情。
- 查看清理作业结果。
- 查看审计记录或导出审计摘要。

每条审计记录至少包含：

- 管理员身份。
- 操作时间。
- 动作类型。
- 目标 `run_id`、`trace_id`、`alert_id` 或依赖标识。
- 结果：允许、拒绝、未找到、已过期、服务不可用或失败。
- 请求来源的安全标识。
- 关联的权限检查结果。

审计记录不得保存用户对话正文、题目全文、模型原始输入输出、凭据、Token 或异常全文。审计失败本身必须成为运维异常，不能静默放行正文查看。值守人员每天至少检查：

- 是否存在异常大量正文查看。
- 是否有同一账号连续被拒绝后仍尝试访问。
- 是否有共享账号查看 trace。
- 是否有查看成功但审计写入失败。
- 是否有已离职、禁用或权限变更账号仍然访问成功。
- 是否有批量导出或无法对应到单条目标的访问。

正文默认隐藏、单条权限和二次审计是首期约束。页面中显示“查看 trace”按钮不代表已经授权；真正展示正文前必须再次检查权限和到期状态。

## 10. 故障处理指引

运维后台提供排查信息和下一步建议，但不直接执行业务修复操作。建议每类告警在详情中显示：

- 现象和安全原因码。
- 影响范围和样本运行。
- 最近一次有效证据。
- 责任模块。
- 推荐排查入口。
- 是否需要人工处理。
- 当前未知项和采集缺口。
- 恢复条件。
- 升级对象。

首期值守人员不得在运维后台执行：

- 代用户重试出题。
- 强制停止运行。
- 修改运行终态。
- 修改最终题目或审核结果。
- 手动把 unknown 改成 success、failed 或 skipped。
- 通过标记通知已读来关闭告警。
- 在线修改阈值、保留期或调度配置。

如果业务需要这些动作，应回到已有业务管理流程或经过单独审批的发布、配置和故障处理流程，并在交接记录中保留关联编号。

## 11. 配置、阈值和变更管理

首期配置来源保持单一：

- 配置文件或环境变量定义阈值、保留期、清理周期、缓冲容量、超时和重试上限。
- 后台只读显示实际解析后的生效值、配置版本或加载时间。
- 页面不提供在线修改阈值、保留期、清理周期和容量上限的接口。
- 变更必须通过已有配置发布流程完成，记录变更人、时间、原因、旧值摘要、新值摘要和回滚方法。
- 敏感配置只记录名称和是否生效，不记录凭据内容。
- 配置变更后执行一次合成检查，确认页面显示与服务实际使用一致。
- 未配置的阈值显示 `unconfigured` 或等价状态，不能猜测默认值并生成告警。

重点阈值包括：

- 已受理未开始的等待阈值。
- 单次执行过久阈值。
- 心跳失联阈值。
- 质量异常窗口、最小样本数和比例。
- 连续失败和恢复次数。
- Phoenix 导出及通知积压 warning／critical 水位。
- 导出、SQL、通知和清理的有界重试次数。
- Phoenix 详细正文、SQL 摘要和审计记录保留期。

## 12. 交接清单

### 12.1 部署交接

交接人必须提供：

- MathCraft、OpenAI Agents SDK、Phoenix 和适配器的锁定版本。
- 启动顺序、停止顺序和重启方法。
- 配置文件／环境变量名称清单及非敏感样例。
- Phoenix 绑定地址、访问入口和权限负责人。
- Phoenix 存储目录、SQL 连接目标和备份边界。
- 健康检查方法和合成 trace 验证方法。
- 真实业务不能被追踪故障阻断的验证结果。
- 清理策略、实际生效值、每日调度方式和失败处理方式。
- 资源记录：内存、磁盘、写入量、导出缓冲和观测开销。
- 已知限制：当前未实现项、G0／G1／G3 状态和版本兼容风险。

### 12.2 日常值守交接

每次交接至少包含：

- 当前 firing 告警及 alert_id。
- 重点 run_id、trace_id、batch_id 和 session_id。
- 影响账号、入口和估计影响范围。
- 最近一次可信证据和下一次检查时间。
- Phoenix、SQL、Redis、向量库和模型的当前状态。
- 事件、导出、通知和清理积压。
- unknown／partial 的原因。
- 已经查看过的正文范围和对应审计记录。
- 已执行的配置变更、临时措施和回滚方式。
- 需要升级的责任模块和联系人。
- 下一班必须完成的检查。

### 12.3 故障恢复交接

故障恢复后，不要只记录“服务已恢复”。还应确认：

- 依赖连续成功达到恢复条件。
- 新运行能产生正确的根 trace 和子 span。
- SQL 摘要、告警状态和通知可以继续写入。
- 积压正在下降，没有超过容量上限。
- 丢弃、失败和无法关联的数量已记录。
- Phoenix 单条 trace 查询可用，正文权限和审计正常。
- 清理任务下一轮有明确计划。
- 旧告警已经有恢复证据；持续故障没有被误报恢复。
- 恢复前发生的 unknown、partial 和缺失事件仍保留解释。
- 交接记录包含恢复时间、验证 run_id、验证 trace_id 和剩余风险。

## 14. 本手册维护规则

本手册属于方案／待实现文档。实现过程中如果启动方式、配置来源、保留策略、权限模型、告警阈值、清理方式或故障恢复行为发生变化，应在同一功能变更中同步更新本手册，并保留实际验证证据。

新增运行状态、事件字段、题目版本、审核范围或审计动作时，应先更新契约和验收记录，再更新本手册中的值守步骤。任何页面显示都必须能够追溯到实际采集来源、时间窗口和数据新鲜度。

当前自监控解析器验证时间结构及 `fresh_until > observed_at`；依赖解析器验证时间格式及相关非空和 scope 条件，尚不在解析边界拒绝 `fresh_until <= checked_at`。两者均保留服务端状态，不按客户端 `Date.now()` 覆写；UI 要求观测不晚于快照，且有效期晚于服务端 `generated_at` 加页面经过时间，否则显示 unknown。依赖时钟保留在面板顶层，筛选重挂卡片或失败轮询不能延长证据有效期；自监控同样复核时间。

页面经过时间单调累加 `max(wallDelta, performanceDelta, 0)`，处理校时回拨及 Windows 休眠；新快照只向前校准，旧／空快照不回拨。概览父层及依赖面板顶层保留时钟；未来观测在原快照内持续 unknown，不随页面时间增长变 healthy。独立审查修复已复核关闭，完整离线回归已通过；结果仍不作为真实部署就绪结论。

## Phoenix 启停

1. 在 `backend/` 执行 `uv sync --extra phoenix`；使用根环境时在仓库根执行同一命令。
2. 在仓库根执行 `docker compose -f compose.phoenix.yaml up -d --wait phoenix`。
3. 默认配置保持关闭；启用时将 `PHOENIX_ENABLED=true`，使用 `http://127.0.0.1:6017/v1/traces` 并重启后端。
4. 本机访问 `http://127.0.0.1:6017`；仅限可信单机，默认无认证。远程须配置 HTTPS、独立认证和 API key。
5. 停用时将开关改回 `false` 并重启后端。容器可独立执行 `docker compose -f compose.phoenix.yaml stop phoenix`，保留 `phoenix_data` 卷。

完整配置、固定镜像和数据边界见 [Phoenix 可选扩展](Phoenix可选扩展.md)。不执行旧 `tools/ops_g0` 的启动或验收流程。

## 排障口径

- Phoenix 只收元数据，不查看对话、题目、模型输入输出或工具正文。
- 当前业务 `run_` 标识仍是追踪关联；台账写入支持复用，但实际入口尚未建立 SQL 对应记录。
- 根 span OK 只证明函数返回；LLM 错误独立判断，不能据此确认业务成功。
- Phoenix 不可用、队列满或导出失败时，元数据可能丢失；业务结果保持原有语义，不用空追踪推断失败。
- 台账使用 `accepted/running/completed/failed/canceled/unknown`；Redis 过期或终态缺失不能冒充失败，实际 unknown 触发留待入口接入。`completed` 只表示批次事务已提交保存，后续回复或进度失败不覆盖这一事实。

后台实现后再核对管理员权限、运行筛选分页及两条入口的终态关联，不恢复依赖探测、异常中心、质量覆盖、告警或复杂清理调度。

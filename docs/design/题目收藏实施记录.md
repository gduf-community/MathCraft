补充（同日第三轮）：

- **胶囊行被压扁的原因**：收藏夹胶囊行是内容区纵向 flex 的直接子项，`overflow-x-auto` 使其自动最小高度为 0；竖向空间不足时它先被压缩（实测 772×600 只剩 19px、772×500 只剩 4px）。页面本身没有整体滚动，`main` 已是 `overflow: hidden`，不是缺少页面级 overflow 约束。
- **修复**：给胶囊行、筛选面板与「加载更多」行加 `shrink-0`，只允许题目列表收缩。772×600 / 500 下胶囊行均保持 36px 完整高度。
- **题型胶囊行**：断点统一到 `min-[1440px]`：<1440 单行 `overflow-hidden + flex-nowrap`，超出部分直接截断（1024 下 `690 > 528`），不滚动、无滚动条、无遮罩；≥1440 恢复换行。胶囊加 `shrink-0 + whitespace-nowrap`，容器补 `min-w-0`。实测 1440 / 1200 / 1024 均单行，无换行跳变；1200 内容放得下（`690 = 690`），1024 被截断。
- 全局滚动条样式恢复原状（8px），本轮不再为组件覆盖滚动条尺寸。
- **最小宽度兜底**：根容器设 `min-width: 960px`，视口 <960 时整页横向滚动，不再做 <960 的逐级适配。772 宽下页面实际布局宽度为 960px。该改动位于 `App.tsx` 的 Shell 根容器，**影响全站所有页面**，不只是收藏页。

### 2.8 批量移出与快照撤销（2026-10-28）

## 3. 已知限制

- **数据为 mock**：`api/mock/favoritesMock.ts` 内置 10 道题、4 个收藏夹（未分类、导数与微分、线性代数、概率统计）。
- **刷新即重置**：收藏、收藏夹、排序与筛选状态不跨刷新保存；页面标题旁有「演示数据 · 刷新后重置」提示。
- **未接后端**：没有 `GET/POST/DELETE/PATCH /api/favorites` 等接口，也没有数据库或文件持久化。
- **组卷仅提示**：页面级、卡片级与批量条的「组卷」只累计 `pendingAssembleCount` 并提示，不打开 `AssembleModal`，不进入组卷流程。
- **编辑只读**：卡片「编辑」只提示「编辑能力待接入」，不进入编辑态，也未抽共享编辑组件。
- **导出仅提示**：Word / CSV 导出未实现。
- **部分可选增强未做**：URL query 还原筛选状态、知识点胶囊点击筛选、来源失效置灰。
- **异常态未覆盖**：mock 无加载失败、分页失败与网络重试状态。
- **响应式边界**：主验收宽度为 1280 / 1440 / 1680，下限为 1024；<1024 只按设计折叠为横向胶囊，不做手机布局，768 / 640 / 480 不在验收范围。
- **预览页星标手测前提**：当前后端未配置模型、没有知识库，无法真实生成题目；手测星标联动需先配置模型并建库，或临时把 `frontend/src/api/client.ts` 切到 `mockAdapter`（测完必须还原）。

## 5. 本地启动与验收

### 5.1 启动

```powershell
# 后端（仓库根目录）
.venv\Scripts\python.exe -m MathCraft --port 8000

# 前端（另开终端）
cd frontend
npm run dev
```

访问 **http://127.0.0.1:5173/**，左侧点击「题目收藏」。

依赖已安装在本机 `.venv` 与 `frontend/node_modules`；当前没有 `.env`，后端未配置模型与知识库。收藏页不依赖后端即可使用。

### 5.2 验收入口

按 [题目收藏页面设计](题目收藏页面设计.md) 的「验收标准」逐项执行，重点：

1. 进入收藏页，统计为 `10 / 10 / 5`，首屏 6 张卡片，加载更多后 10 题。
2. 切换收藏夹、题型、难度、知识点、来源、搜索与排序，列表与计数同步，已选清空。
3. 全选只作用于当前筛选结果；部分选中为中间态。
4. 勾选后批量条出现，合计分值正确；加入组卷提示计数。
5. 取消收藏后 5 秒内可撤销，题目与勾选恢复。
6. 新建、重命名、删除收藏夹；删除后题目回「未分类」。
7. 空收藏夹与筛选无结果两种空状态正确。
8. 紧凑视图隐藏选项与答案解析；卡片视图恢复。
9. 刷新页面恢复初始 mock 数据。
10. 预览页星标联动需先生成题目（见第 3 节前提）。

### 5.3 构建

```powershell
cd frontend
corepack pnpm build   # 或 npm run build
```

本机没有全局 pnpm，使用 corepack 提供的 pnpm；构建会生成 `pnpm-lock.yaml`，提交前应删除，项目仍使用 `package-lock.json`。

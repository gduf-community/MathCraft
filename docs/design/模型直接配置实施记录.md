## 已交付行为与最少配置流程

页面只展示语言模型、嵌入模型、任务模型，默认进入语言模型。每项独立维护提供方、地址、凭据、模型标识及高级参数，配置名称去首尾空白后跨三类全局唯一、区分大小写；模型标识可以重复。

已知模型标识：添加模型 → 同一表单填写配置名称、提供方、地址、凭据和模型标识 → 保存并启用。首项自动默认；后续新增保留既有默认，按需单独设为默认。任务默认跟随当前主模型，保存备用任务项不会擅自切换模式。

未知模型标识：填写提供方、地址、凭据 → 手动获取模型列表 → 选择结果或在失败后手填模型标识 → 保存并启用。保存不自动发现，不执行推理或嵌入。发现成功只证明列表接口有响应；失败显示原因及实际可用 HTTP 状态，允许继续手填保存。

环境变量只用于首次创建不存在的正式目录；初始化后的条目可在前端看到，凭据以掩码展示。正式目录存在后优先于环境变量，包括有意清空的目录；前端保存和重启不回写 `.env`。

## 设计、接口与异常边界

保留 `profile_id`、模型 `id` 和旧容器的内部兼容结构；每个模型的 `direct_config` 保存完整独立参数。公开运行时优先解析模型自身参数，明确清空不借用其他配置或旧共享来源的凭据。高级字段和未展示服务的扩展数据继续保留。

| 接口 | 行为 |
| --- | --- |
| `POST /api/settings/direct-model` | 锁内读取最新目录并只合并当前项；全局名称校验；首项默认；旧草稿恢复需明确版本与稳定 ID |
| `POST /api/settings/direct-model/default` | 单独设置默认，不保存表单的其他修改 |
| `POST /api/settings/direct-model/delete` | 保护真实引用；知识库绑定查询归属 `knowledge/model_references.py`，注册表异常时拒绝删除 |
| `POST /api/settings/direct-model/task-mode` | 跟随或独立两模式，切换不删除备用配置 |
| `GET /api/settings/direct-model/draft` | 返回迁移后掩码预览；保留原草稿文件和版本，用户逐项明确恢复 |
| `/api/settings/test-provider`、`/api/settings/fetch-models` | 使用未保存表单进行相同语义的列表发现；不透传上游正文、不假造 HTTP 状态 |

原正式共享连接按实际有效参数原子展开，旧任务引用复制原先选中的目标；保留默认、稳定 ID、知识库绑定及嵌入签名。名称去重预留原有后缀，输出稳定的改名前后对应关系。已有独立配置不再受遗留共享字段影响。旧草稿不会因读取、迁移或普通单项保存而被应用；恢复掩码只能使用当前项对应的正式来源或明确选中的旧草稿版本。

未落盘的失败保留正式状态、输入及原有客户端。写入已完成但服务端读回失败时，返回 HTTP 503 和受控代码 `model_write_committed_readback_failed`，刷新必要缓存；页面显示待核实并保留输入。成功响应后的前端读回失败同样显示待核实。读取、发现和无变化保存不应无故重置客户端。

旧嵌入配置迁移在解析完继承来源后再规范化完整端点，保留原加载行为：例如旧本地 `/v1` 转为 `/v1/embeddings`。不能先用默认端点覆盖继承地址，也不能把这一迁移规则扩展成对新表单的隐式地址改写。

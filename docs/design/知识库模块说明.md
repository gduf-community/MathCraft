> 状态：已实现，实际迁移／存储与运行设置服务恢复已核验；完整后端全量基线已通过，末轮定向验证与独立审查已完成。日期：2026-11-10，按 `main` 当前实现同步。事实来源为 `backend/app/`、`frontend/src/` 与根 [openapi.json](../../openapi.json)。原 PDF 仍 failed、chunks=0，不能将恢复写成已入库。历史测试数字原样保留，本次最终检查见末轮收尾记录，验收清单不代表已经执行或通过。

## 1. 目标、范围与当前架构

当前知识库以题库 `Bank` 为资源边界，供启用的教师、学生按成员权限上传材料、轮询状态、下载、检索并基于单个文档出题。平台身份与题库角色分别判断，平台管理员没有教学资源权限豁免。

~~~text
/api/banks → 成员鉴权 → 上传 Document → 进程内 BackgroundTasks
  → 按格式解析（扫描 PDF：MinerU 云 OCR → 知识点简化 MD）
  → 切片、jieba 分词 → SQL document_chunks + SQLite FTS5
  → 平台活动嵌入模型 → 活动 generation 的题库级 Chroma collection → ready
  → 单文档 HyDE/混合检索/重排 → 出题与审核 → 批次/题目
~~~

历史 `backend/src/`、单租户 `kb_config.json`、LlamaIndex/provider 切换、`/api/knowledge-bases/*`、`/api/settings`、知识库进度 WebSocket 和旧解析版本方案均不是当前应用入口。本文不据历史文件宣称这些能力已经实现；平台模型变更的索引 generation 切换见第 4.1 节，不等于单文档解析版本发布；`kb_id/doc_id` 仅在当前出题请求中作为兼容字段保留。

## 3. 三档成员权限、教师新建与管理员排除

| 能力 | creator（创建者） | editor（可编辑成员） | readonly（只读成员） |
| --- | --- | --- | --- |
| 详情、成员列表、文档列表/状态、下载/查看、检索 | 允许 | 允许 | 允许 |
| 基于 ready 文档出题 | 允许 | 允许 | 允许 |
| 上传、删除文档、重新解析 | 允许 | 允许 | 禁止 |
| 修改题库、管理成员、转让、删除题库 | 允许 | 禁止 | 禁止 |
| 退出题库 | 需先转让或删除 | 允许 | 允许 |

`BankAccess.my_role` 使用 `creator/editor/readonly`；历史角色兼容映射为 `owner → creator`、`admin → readonly`、`member → readonly`。历史 `Bank.admin_level` 不参与当前成员权限判断。`require_bank_admin` 指创建者或编辑者，不能等同于平台 `admin`。

仅平台 `teacher` 可新建题库及组合创建上传。教师、学生均可由创建者添加为 `editor/readonly`，目标账号须启用，不能添加平台管理员。转让目标须为已加入题库的启用教师；原创建者降为 `editor`，同步转移 `creator_id`。

`resolve_bank_access` 将教学资源访问限制为教师或学生，平台管理员返回 403；非成员、非活动题库返回 404，避免暴露他人资源存在性。题库列表只列出调用者的活动成员关系，不提供管理员全局教学资源列表。文档还须属于路径中的题库，否则 404。

### 3.1 题库与成员接口

| 方法与路径 | 输入与实际成功行为 |
| --- | --- |
| `GET /api/banks` | 查询 `scope=all/owned/joined`，默认 all；keyword 默认空串，按去空白后的名称子串过滤；200 题库数组 |
| `POST /api/banks` | JSON 必填 name，长度 1–64；仅教师，201 |
| `POST /api/banks/with-document` | multipart 必填 name、单个 file；仅教师，201，返回 bank 与 document |
| `GET /api/banks/{bank_id}` | 成员读取详情，200 |
| `PUT /api/banks/{bank_id}` | JSON 可选 name，非 null 时长度 1–64；创建者，200 |
| `DELETE /api/banks/{bank_id}` | 创建者删除，204 |
| `POST /api/banks/{bank_id}/quit` | 非创建者退出，204；创建者 403 |
| `GET /api/banks/{bank_id}/members` | 活动成员可读，200 |
| `POST /api/banks/{bank_id}/members` | 创建者；account 长度 1–64，role=editor/readonly，默认 readonly，201 |
| `PUT /api/banks/{bank_id}/members/{member_id}/role` | 创建者；必填 role=editor/readonly，204；不能修改创建者角色 |
| `DELETE /api/banks/{bank_id}/members/{member_id}` | 创建者移除成员，204；不能移出自己 |
| `POST /api/banks/{bank_id}/transfer` | 创建者；必填 target_user_id，长度 1–40，204 |
| `POST /api/banks/join` | 已禁用；实际始终 404 BANK_JOIN_DISABLED，不能按编号加入；OpenAPI 默认 200 不是实际成功行为 |

`member_id` 路径由服务兼容接受成员行 ID 或用户 ID。默认容量 200；重复添加为 409 `ALREADY_IN_BANK`，超员为 409 `BANK_FULL`。普通创建/更新 JSON 的名称长度来自 schema；组合上传的 name 是 Form 字符串，不应宣称具有相同的 1–64 长度校验。

题库载荷为 `id/name/code/creator/member_count/capacity/source/quitted/my_role`，以及 `can_upload_document/can_download_document/can_delete_document/can_manage_members/can_edit_bank/can_transfer_bank/can_delete_bank`。creator 为 `id/display_name` 或 null，source 为 owned/joined。成员载荷为 `id/user/role/is_creator/is_me/joined_at`，user 含 `id/display_name/account`。

组合接口先读取文件，再取得与重建共用的资料变更门禁，`create_bank(commit=False)` 创建题库与成员但不提前提交，由 `queue_upload` 在同一 SQL 事务提交题库、成员和首文档，避免重建竞态或上传校验失败留下已提交空库。文件保存与后续后台解析不属于 SQL／文件／向量全流程原子事务，后台入库失败仍会保留题库及失败文档。

## 4. 模型配置来源：各阶段分别解析

个人配置存于 `UserModelSetting`，入口为应用设置“模型与服务”和 `GET/PUT /api/users/me/model-settings`，不是历史 `/api/settings`。个人中心只保留资料与安全；普通设置已移除旧知识库连接、引擎与解析分区，题库配置从题库管理进入。平台配置由管理员左侧导航／右侧内容后台的“模型与检索”维护。

跨模型与资料入库的完整配置优先级见 [模型配置来源与普通知识库流程](模型配置来源与普通知识库流程.md)，个人页面的保存、清除、读回与测试规则见 [模型配置功能规格](模型直接配置功能规格.md)。

| 使用阶段 | 当前配置来源 |
| --- | --- |
| 上传/重解析的 MinerU OCR | 本次操作者的 UserModelSetting.mineru_token 优先，无个人值时取系统 MINERU_DEFAULT_TOKEN；Token 传入后台任务，重解析使用发起者而非固定原上传者 |
| 扫描 PDF 知识点简化 | 在请求受理时解析本次上传／重解析操作者的个人 DeepSeek Key，无个人值时使用 settings.deepseek_api_key；显式传入目录提取、并发概括和补写，模型与地址用 settings.deepseek_model/deepseek_base_url |
| 参数出题与 HyDE | 调用者的个人 deepseek_api_key 优先，否则 settings.deepseek_api_key；两者均无则 400 DEEPSEEK_KEY_MISSING |
| 向量与重排 | 平台活动配置优先；未覆盖时默认 BAAI/bge-m3（默认模型 1024 维）和 BAAI/bge-reranker-v2-m3，基址取 settings.siliconflow_base_url，凭据用既有 SILICONFLOW_API_KEY 兜底；管理员可编辑模型、URL、凭据，个人只读 |

扫描简化与个人 DeepSeek 连接测试均遵守个人 Key 优先、服务端兜底的规则；连接测试成功仍不等于整份扫描文档已完成简化和索引。服务端默认模型为 `deepseek-flash`、显示名 `DeepSeek Flash`；个人接口不能选择模型、基址或向量模型。

PUT 接受 `deepseek_api_key/mineru_token`，各最长 128；省略或 null 保留，空串/纯空白清除个人值，返回 `{"saved": true}`。GET 返回：

~~~text
deepseek_model, deepseek_model_id, deepseek_key_configured, deepseek_key_masked,
mineru_token_configured, mineru_token_masked, mineru_using_default, mineru_limits,
embedding_model, rerank_model, embedding_configurable, rerank_configurable
~~~

configured 只表示个人行有值，`mineru_using_default=true` 不证明系统默认 Token 存在或有效。`mineru_limits` 为 `max_file_mb=200/max_pages=200`，超页扫描 PDF 的当前分片行为见 OCR 策略。

`POST /api/users/me/model-settings/test-deepseek` 使用个人优先的有效 Key，成功返回 `ok/model/reply`；`POST /api/users/me/model-settings/test-mineru` 测试有效 Token，返回 `ok/limits`。两者会调用外部服务；MinerU 探测主要将 401 视为无效，不等于完整 OCR 可用性验收。

配置定义以 config.py 为准，其 env_file 指向 `backend/.env`。本文只核对配置代码与调用位置，未读取任何 .env 或 local_secrets.py，不确认本机真实凭据或部署覆盖值。

### 4.1 平台模型保存、索引重建与版本切换

管理员通过 `GET/PUT /api/admin/rag-settings` 读取／保存平台配置，响应包含 `active/pending/vector_store/rebuild/revision`；`POST .../test` 测试当前嵌入或重排草稿但不保存，`POST .../rebuild` 携带 revision 显式提交重建并返回 202，完成须读取终态。接口仅管理员可用，不授予读取私有教学内容的权限，Chroma 类型、路径和 heartbeat 可用状态只读。详见 [设置拆分与保存反馈设计](设置拆分与保存反馈设计.md) 及 [API 入口](../api.md)。

响应无明文凭据，仅配置状态与掩码；管理员 API Key 省略、null、空串或纯空白均保留，首版没有清除接口。URL 限 HTTP(S)，禁止内嵌凭据、查询参数和片段。保存／重建携带 revision，过期返回 409 `RAG_SETTINGS_CONFLICT`；前端保留草稿，要求载入最新已保存配置后重新编辑。

1. 嵌入模型或 URL 改变先保存为 pending，不自动重建或生效；同次输入的嵌入凭据跟随 pending，活动嵌入配置继续使用旧值。仅更新活动嵌入凭据或重排模型／URL／凭据用于后续请求，无需重建。
2. 管理员确认重建；若活动题库仍有非 ready/failed 文档，返回 409 `RAG_INGESTION_BUSY`。没有 pending 返回 409 `RAG_NO_PENDING_CONFIG`。queued/running 阶段拒绝配置保存、重复重建、上传、重解析、删除文档和整库删除（409 `RAG_REBUILD_BUSY`）；名称、成员等不写索引的操作仍按原权限执行。
3. 后台读取活动题库 ready 文档的 SQL document_chunks，保留 chunk ID、chunk_index（跨批次不重置）、章节与类型，分批生成向量写入新 generation 集合；校验切片数量和向量维度。不重新解析或 OCR，不改写 SQL/FTS 文本；即使无文档也先探测模型。
4. 旧配置和旧索引继续支持读取、查询与出题，一次检索使用固定配置与 generation 快照。全部成功后一次 SQL 提交切换活动配置和 generation，清空 pending；在途检索仍可读取旧集合。
5. 失败不切换，保留旧活动配置、旧索引和 pending，错误脱敏并允许重试；重启将中断 queued/running 重建标记 failed，不自动续跑。改回活动嵌入模型与 URL 后保存可取消 pending。

保存、连接测试及重建结果使用全局顶部居中 toast：成功绿色约 3 秒、错误红色约 6 秒，支持关闭和辅助技术播报，字段错误保留在表单附近，会话失效清除提示并拒绝旧反馈。本轮验证记录见文末。

## 5. 上传、解析、存储与进度

### 5.1 文档接口与字段

| 方法与路径 | 权限、输入与响应 |
| --- | --- |
| `POST /api/banks/{bank_id}/documents` | creator/editor；multipart 单个 file，202 |
| `GET /api/banks/{bank_id}/documents` | 成员读取，200，按创建时间倒序的文档数组 |
| `GET /api/banks/{bank_id}/documents/{document_id}` | 成员读取，200，用于轮询 |
| `POST /api/banks/{bank_id}/documents/{document_id}/reprocess` | creator/editor；无请求体，仅 failed/ready 可用，202；其他状态 400 BAD_STATE |
| `GET /api/banks/{bank_id}/documents/{document_id}/download` | 成员读取；inline 为布尔值，默认 false；200 文件响应，文件不存在 404 |
| `DELETE /api/banks/{bank_id}/documents/{document_id}` | creator/editor，204 |

上传返回 `document_id/name/status/stage/progress/eta_minutes`，重解析返回 `document_id/status/stage/progress`。返回排队状态不等于入库完成；eta_minutes 仅按体积/PDF 页数粗估。

文档列表和详情的实际字段为：

~~~text
id, bank_id, name, format, size_bytes, page_count, is_scanned,
status, stage, progress, chunk_count, ocr_status, error_message, created_at
~~~

内部 `storage_path/text_source/ocr_task_id/ocr_result_path/ocr_error/uploader_id` 未由上述接口直接公开。当前没有文档重命名路由，不能因存在 DocumentRenameBody 就宣称支持。

### 5.2 格式和存储

| 扩展名 | 展示格式 | 当前解析 |
| --- | --- | --- |
| .pdf | PDF | 先检测扫描件；普通 PDF 用 PyMuPDF 提文字层，扫描件走云 OCR 与简化 |
| .docx | DOCX | 正文段落、表格逐行 |
| .xlsx | XLSX | openpyxl，各工作表按行转文本，优先首行作表头，读取缓存值 |
| .md、.markdown | MD | UTF-8 读取，按标题维护章节上下文 |
| .txt | TXT | UTF-8 读取，空行分段、长段按行处理 |

不支持旧 .xls、.doc、图片、ZIP、PPTX、EPUB、网页/GitHub 来源导入。上传按扩展名判断，不等于已做完整内容真实性校验。默认 `settings.max_upload_mb=200` MiB；不支持格式为 400 `UNSUPPORTED_FORMAT`，空文件为 400 `EMPTY_FILE`，超限为 422 `DOCUMENT_TOO_LARGE`。

文件保存到 `settings.upload_path()/{bank_id}/{document_id}{suffix}`。每次上传生成独立文档 ID，没有按文件哈希去重或同名覆盖契约。路径在 BASE_DIR（backend）内时存相对路径，否则存绝对路径。

前端新建、编辑、查看题库的上传入口共用 `uploadFiles.ts`：扩展名不区分大小写，`.markdown` 统一显示为 MD；拒绝不支持的格式和零字节文件，按文件名称、`size`、`lastModified` 三项完全相同判为重复。同名但大小或修改时间不同的文件允许加入；此校验不是内容哈希，也不是服务端去重。前端不另设上传大小上限，以服务端 `max_upload_mb` 的拒绝结果为准。

文件选择支持 `multiple`，拖放接收虚线区内的全部文件；按钮可用 Enter／空格选择，键盘焦点和拖入有高亮，提示明确只有虚线区接受拖放。有效文件按顺序串行提交；校验未通过的文件显示红色详情，其余有效文件仍可处理。编辑／查看上传过程中再次加入文件会明确提示等待本批完成，不静默丢弃新输入；已受理文件在本弹窗内防止重复提交，失败文件可重新选择。

新建弹窗在首个写请求受理前保留名称与文件，首个请求失败（包括大小拒绝）不关闭、不清空草稿。首文件经 `POST /api/banks/with-document` 成功返回后立即记录 `bankId`，后续调用该题库的上传接口；每个成功受理的文件从待提交列表移除。部分失败时保留已创建题库及剩余草稿，继续处理后续文件，重试仅提交尚未受理的文件，不重复建库或重传已成功文件。批量提交期间禁止通过关闭按钮、遮罩、取消或 Escape 关闭弹窗；新建全部请求受理成功才关闭并显示绿色提示，部分失败保留弹窗和红色错误。受理成功不代表后台已经 `ready`，前端保留轮询展示解析状态。

### 5.3 后台任务、进度和重启

状态集合为 `uploaded/parsing/ocr/chunking/embedding/ready/failed`，普通文档跳过 ocr。进度大致为 parsing 10、ocr 20–45、chunking 40–57、embedding 60、ready 100；失败也写 100，成功须看 status=ready。

FastAPI BackgroundTasks 在当前进程执行，不是持久化队列。`_set_stage` 先提交 SQL 文档行，再写 Redis `ingest:task:{document_id}`，默认 TTL 7200 秒；HTTP 详情实际读 SQL。末轮修复已在此捕获 `RedisError`，仅记录异常类型及 `PROGRESS_CACHE_UNAVAILABLE`，进度缓存故障不再阻断后续调度／处理；定向验证通过，详见末轮收尾记录。SQL、缓存、Chroma 没有统一事务。

启动时将 uploaded/parsing/ocr/chunking/embedding 文档标为 failed，提示重启中断、请重新解析；包含已排队尚未开始的 uploaded，避免遗留状态永久阻塞平台重建。不会自动续跑，不同步重写 Redis。没有当前知识库任务日志流、取消接口、跨进程租约或知识库进度 WebSocket；平台重建与资料变更门禁不等于单文档重解析已有完整互斥。

重解析通过 `requeue_document` 将 SQL 和 Redis 进度重置为 `uploaded`、0，清空上一轮 `error_message/chunk_count/ocr_status/ocr_error/ocr_task_id/ocr_result_path/text_source/page_count/is_scanned`。简化稿可找到原 PDF 时恢复其文件属性。磁盘 OCR 缓存仍保留供后续复用；这不是强制重新 OCR 或解析版本回滚。

### 5.4 先删旧索引与异常边界

后台先确认当前源文件存在，再 `_purge_chunks`：先删除 Chroma 中该文档的活动向量，成功后删除 SQL chunks 与 FTS 并提交，之后才解析。向量初始化／删除失败会通过 `VectorStoreError` 上抛，尚未进入 SQL 清理时保留原 SQL/FTS；首次上传也执行清理，Chroma 初始化失败可能在扫描检测前终止任务。

单文档重解析清理当前活动版本的旧切片与向量后再重建，没有文档级版本切换或失败回滚；后续 OCR、简化、嵌入失败不会恢复已清理的旧索引，不适用第 4.1 节平台模型重建的回退保证。新 SQL/FTS 也在向量写入前提交，可能留下有切片但无完整向量的状态。检索测试没有统一 ready 过滤，出题入口则要求所选文档 ready。

当前没有完整的重解析互斥、取消或任务 ID 防旧写保障；不能将“重新解析”描述成安全续跑旧发布版本。

### 5.5 失败详情与错误分类

文档列表将原始 `error_message/ocr_status` 映射为 `BankDoc.errorMessage/ocrStatus`。编辑／查看弹窗的失败行用按钮展开，暴露 `aria-expanded/aria-controls`，正文是可选择复制的只读文本，附处理阶段及 OCR 状态；未返回具体错误时显示明确的后备提示。创建者／可编辑成员可重新解析，只读成员仅查看详情。重试成功表示重新排队，绿色反馈后刷新列表；失败为红色。进行中消息使用信息色，不能将 `failed` 的 progress=100 当作成功。

| 错误边界 | 当前分类与对外行为 |
| --- | --- |
| 上传输入 | `UNSUPPORTED_FORMAT`、`EMPTY_FILE` 为 400；`DOCUMENT_TOO_LARGE` 为 422。前端预检不代替后端鉴权或大小校验 |
| 向量服务 | `EmbeddingError.category` 区分 `authentication/rate_limit/timeout/connection/server/request/invalid_response`；缺凭据、HTTP 401/403、429、408/504、其他 5xx、请求／响应异常分别给出安全中文提示，日志只记类别、异常类型与 HTTP 状态 |
| Chroma 存储 | `VectorStoreError.operation` 区分 `init/access/write/query/read/delete/health`；仅原生 `NotFoundError` 表示集合不存在，其他故障不会当作空库成功。日志保留操作、异常类型和可提取的数值原生码，不写底层异常全文、路径、请求头或凭据 |
| HTTP 检索／删除 | 路由捕获向量异常返回 503 `VECTOR_STORE_UNAVAILABLE`；检索直接暴露的嵌入异常返回 503 `EMBEDDING_UNAVAILABLE`。混合检索内已有降级路径仍按第 7 节处理，不能承诺任意故障均可降级 |
| 后台入库 | 嵌入／向量存储异常以安全消息写入文档失败状态与 `error_message`；其他解析／OCR 异常按现有后台边界标记 failed。列表失败详情不是额外公开内部凭据或服务响应的入口 |

末轮独立审查后，Redis 进度故障的非阻断处理已落地，排队边界四项定向验证通过；OCR／未知异常安全消息映射已实现并经独立复核，不能将这些后续修复计入此前全量基线。SQL 状态更新仍不等于持久化任务队列确认，最终实现与定向验证已完成。

## 6. 扫描 PDF、简化稿替换与原件预览缺口

扫描检测为 `total_chars < 50` 或平均每页字符数 `< 30`；零页返回非扫描。不要求页面图像，也不是“全文完全无文字”。详见 [扫描 PDF 云端 OCR 策略](扫描PDF云端OCR策略.md)。

OCR 后尝试清洗、提目录、定位章节、按章概括，生成保留核心公式而排除例题习题的知识点 MD。成功时保持 Document ID，把 name 改为 `<原名>_知识点简化版.md`、format 改 MD、size_bytes/storage_path 指向 `uploads/{bank_id}/{document_id}_simplified.md`；原 PDF 通常仍在 `uploads/{bank_id}/{document_id}.pdf`，但不是独立公开文档。检索、向量化、出题参考实际为简化内容，不保证保留原题或 PDF 页码溯源。

下载只读当前 storage_path，简化成功后下载/查看返回 MD；inline=true 为 `text/plain; charset=utf-8`，不做 Markdown 富文本渲染。即使路由注释写“下载原件”，也没有选择 original/simplified 的参数或独立原 PDF 预览通道。

### 6.1 前端预览上限、分页、超时与取消

查看文档按当前 `format` 分流：PDF 点击时同步预开独立窗口，经现有会话认证获取 `/download?inline=1` 的二进制 Blob，校验 `application/pdf` 后用对象 URL 和 iframe 显示，不进行文本解码。窗口提供重试和下载；弹窗被拦截时提示允许弹出窗口或下载。扫描简化后的当前文档格式为 MD，不会因此自动恢复原 PDF 入口。

MD／TXT 使用 `DocPreviewModal` 并传递 `docFormat`。MD 支持受限标题、段落、列表、引用和数学公式；TXT 按纯文本保留原始换行与符号，不按 Markdown／公式解释，也不执行原文 HTML。DOCX／XLSX 明确提示暂不支持内联预览，提供下载，不能走文本解码或假装解析失败。

| 限制 | 当前行为 |
| --- | --- |
| 文本体积 | 最多 2 MiB，按字节检查 `Content-Length` 并再次统计流式响应体，缺失或不可信长度头不能绕过；超过上限拒绝预览并提供下载，不截成“完整内容” |
| 文本类型／编码 | TXT 仅接收 `text/plain`；MD 接收 `text/plain`、`text/markdown`、`text/x-markdown`。声明字符集须为 UTF-8／UTF8，使用严格 UTF-8 解码，类型或编码错误显示失败 |
| 文本分页 | 每页至多 40 块、2 万个 UTF-16 字符单位，公式只挂载当前页；TXT 连续切页保留源文本。MD 超长单块退化为截断纯文本并明确提示下载全文，切分避免截断代理对 |
| 超时 | 文本预览 60 秒；PDF 和下载 180 秒，覆盖认证、响应头及响应体读取。超时显示可重试／下载错误，不记为用户主动取消；这些值不是后台 OCR／入库超时 |
| 生命周期 | 关闭弹窗、切换文档、关闭 PDF 窗口或会话失效时取消请求，抑制旧结果和主动取消提示；结束或替换 PDF 时释放对象 URL。已有 Blob 在浏览器内显示不等于持久化本地认证凭据 |

前端预览错误码为 `DOCUMENT_TIMEOUT/DOCUMENT_HTTP_ERROR/DOCUMENT_CONTENT_TYPE/DOCUMENT_TOO_LARGE/DOCUMENT_POPUP_BLOCKED`，属于客户端传输／显示边界，不新增后端预览路由。预览的 `DOCUMENT_TOO_LARGE` 指 2 MiB 文本限制，与上传接口的同名错误码及服务端上传上限须结合所在环节区分。

重解析按命名与固定路径找原 PDF，存在时恢复 PDF 属性再跑，可复用 OCR/简化缓存；丢失时按当前 MD 重解析，不必然报原 PDF 缺失。简化服务错误 SimplifyServiceError 导致 failed；目录/内容类一般异常回退 OCR 全文索引，保留 PDF 条目及下载行为。不能概称所有简化失败都回退原文。

## 7. SQL、FTS5、Chroma 与 Redis 检索

SQL 保存题库、成员、文档、切片及出题数据。DocumentChunk 以 `(document_id, chunk_index)` 唯一，保存正文、分词、章节和 question/general/answer 类型。FTS5 表 `document_chunks_fts` 保存 `chunk_id/bank_id/document_id/tokens`，服务层与 SQL chunk 在同一事务增删。

默认 chunk_size=500、chunk_overlap=100；至少 5 个题号行命中时走练习卷题号切片，否则顺序聚合、保留章节/页码文本前缀。通用聚合不是严格 token 限额，也不保证每块都不超过 500 字符。

Chroma 用 PersistentClient，按题库和 generation 建 collection，使用 cosine 距离；初始空 generation 沿用 `kb_` 加规范化 bank ID，重建后追加 generation 后缀。活动指针决定当前请求使用哪一版，旧／失败集合保留。向量 ID 与 SQL chunk ID 一致，元数据含 `bank_id/doc_id/doc_name/chunk_index/chunk_type/section`，平台重建保留 SQL chunk_index，跨批次不重置。FTS 按 bank_id 和可选 document_id 过滤；Chroma 在活动题库 collection 内按 doc_id 过滤。

`POST /api/banks/{bank_id}/search` 对全体成员开放，请求 JSON：

| 字段 | 契约 |
| --- | --- |
| query | 必填字符串，长度 1–512 |
| document_id | 可选字符串或 null；检索测试不另行校验文档存在/ready，但仍限于本题库索引 |
| mode | dense/sparse/hybrid/hybrid_rerank，默认 hybrid_rerank |
| top_k | 整数 1–50，默认 6 |

模式行为：

- dense：活动嵌入模型（默认 bge-m3）→ 活动 Chroma 集合，返回 `{"mode":"dense","results":[...]}`；命中含 chunk_id/text/doc_id/doc_name/chunk_index/chunk_type/section/distance。
- sparse：jieba 后按 OR 构造 FTS MATCH，BM25 取反为正向得分；返回 `{"mode":"sparse","results":[{"chunk_id":"...","bm25":0.0}]}`。
- 混合：返回 hyde/dense/sparse/fused/reranked。默认 dense 20、sparse 20，RRF k=60，融合最多 12，重排默认 6，回 SQL 取正文与章节。混合接口 dense 数组仅保留 chunk_id/doc_name/chunk_index/distance/text。
- hybrid_rerank 的 top_k 控制重排数量，仍受融合候选数限制；hybrid 请求的 top_k 不控制候选数，当前仍调用完整重排链路，再清空返回的 reranked，不能宣称省去了重排请求。

混合检索捕获 EmbeddingError 后可走稀疏路径，稀疏异常按空列表处理，RerankError 时回退融合顺序。重排响应的越界／重复／非整数下标和非有限分数（含 NaN）均转换为 RerankError，遵循同一回退边界。Chroma 初始化等其他异常未被嵌入异常分支统一捕获，不能宣称任意向量故障均可成功降级。

Redis 用于任务进度、出题锁和 HyDE 缓存，不是 FTS/向量主索引。HyDE 在出题有非空 scope 和有效 Key 时启用，按 bank+document+scope+difficulty 摘要缓存 3600 秒；失败退回原查询。稠密可用 HyDE 文本，稀疏始终用原查询。

## 8. 单文档出题接口与边界

`POST /api/generate/start` 返回 202 `{"task_id":"..."}`；`POST /api/generate` 为同步入口，成功返回题目数组。均校验成员身份、文档归属和 status=ready，只读成员也可调用。

| GenerateStartBody 字段 | 当前约束 |
| --- | --- |
| bank_id、document_id | 默认空串、最大 40；业务层必须能解析出一个题库和一个文档 |
| kb_id、doc_id | 兼容字段；优先非空 bank_id/document_id；doc ID 是数据库 ID，不是 raw 相对路径 |
| types | 必填、至少一项；每项 type=single/multiple/judge/blank/compute/essay，count 为 1–20 |
| difficulty | 低/中/高/地狱，默认中 |
| scope | 默认空串、最大 512 |
| source_mode | original/variant_data/variant_context/new，默认 variant_data |
| existing_stems | 默认空数组、最多 200 |
| doc_name | 默认空串、最大 255；归属和检索范围由文档 ID 决定 |

所选文档 ID 同时传入向量、FTS 路径。不存在/不属题库为 404 DOCUMENT_NOT_FOUND，未 ready 为 400 DOCUMENT_NOT_READY。原题模式数量不足：同步返回 422 NEED_CONFIRM，带 kind=need_confirm/available/requested；异步写入任务 error。简化稿不保证保留原题，无题号结构时原题计数检查也可能跳过。

`GET /api/generate/progress/{task_id}` 仅任务所属用户可读，返回 `progress/stage/review/done/batch_id/questions/error`；过期或他人任务为 404 TASK_NOT_FOUND。异步出题仍是 Redis 进度加进程内任务，不承诺重启续跑。启动锁 `gen:lock:{user_id}` 冲突为 409 GENERATION_BUSY；当前锁 TTL 60 秒且无持续续期，长任务期间不能保证全程互斥。进度默认 TTL 1800 秒。

审核后将批次和题目写 SQL。`GET /api/generate/batches/latest` 可按 bank_id/document_id 筛选当前用户最近 done 批次，返回 batch_id/questions；无结果为 null、空数组。恢复批次不等于恢复后台任务。

## 9. 数据布局、删除与待实现目标

路径由 Settings 解析；默认上传/OCR/Chroma 位于 backend 下 `data/uploads`、`data/ocr`、`data/chroma`，数据库由 database_url 决定。既有 storage_path 可为相对/绝对路径，移动数据须同时核对数据库与文件位置，没有旧 runtime-home 自动迁移机制。

部署本轮平台模型配置前须备份 SQL 与 Chroma、在受控副本核对，并从 backend 执行 `uv run alembic upgrade head`，包含新增 `i4d5e6f7a890`（前序 `h3c4d5e6f789`）。迁移初始化空平台覆盖及空 generation，沿用原集合，不复制本地敏感配置。线上部署仍须独立完成迁移。当前必须使用单 worker 进程（`--workers 1`）；进程内任务与启动收尾不提供多 worker 协调。已切换 generation 或 queued/running 时 downgrade 会拒绝，须先恢复兼容旧模型和索引。

旧索引及失败重建残留集合保留并占用磁盘，没有自动回收或清理接口，需要运维清理。清理前核对活动 generation、正在重建的 generation 及仍被在途检索快照引用的旧版本，不得误删活动／在途索引，不能只按前缀或集合年龄删除。

`banks.purge_document` 在 SQL 事务内清理文档的 FTS、SQL chunks、题目／收藏、生成批次和文档行；`banks.purge_bank` 在事务内清理相关题目／收藏、FTS、文档、成员，并将题库置为 deleted。两者均先保持 SQL 修改未提交，删除对应活动向量／collection，向量删除成功后才提交 SQL，最后删除各文档当前 `storage_path` 文件。向量删除失败时回滚 SQL，保留文档记录与文件，允许重试。

SQL、Chroma 与文件系统仍不具备跨存储原子性：若向量已删除而 SQL commit 失败，SQL 回滚、文件保留，但需要重新解析恢复向量；若提交后文件 unlink 失败，SQL／向量删除不会回滚，可能留下残留文件，当前实现捕获该文件清理异常。只清理当前 `storage_path`，不能保证同步回收原 PDF、OCR 目录、Redis 入库／HyDE 记录及全部派生产物；历史试卷快照不在单文档删除清理范围内。

上传受理与重新解析受理后，前端经 `onChanged() → refreshKbs` 同步题库和当前选中题库的 docs。删除成功后，编辑／查看弹窗先移除本地行，再调用 `onChanged(documentId)`；`BankTab/index.tsx` 先调用 `AppContext.invalidateDocument(bankId, documentId)`，立即从当前题库 docs 移除该项、清空对应文档选择并递增请求版本，随后启动异步刷新。即使刷新失败，已清理的文档也不会因删除前的旧响应恢复。刷新另用会话、题库 ID 与请求版本校验抑制迟到结果；题库消失时清空所选题库／文档及 docs。刷新失败显示错误，不等于服务端删除回滚；前端缓存失效也不代表服务端 OCR／Redis／派生文件已回收。

### 备份与本机运行恢复（2026-11-10，已核验）

SQLite 使用 WAL。文件级 SQL 备份必须在停止写入并保证同一快照后，保存主库及仍存在的 `-wal`（并同步保存 `-shm` 供核对）；不能只复制 `.db` 而漏掉尚未 checkpoint 的已提交数据。也可用 SQLite backup API 生成包含已提交 WAL 内容的完整快照。SQL、Chroma、上传与 OCR 目录分别按实际配置备份，不混用不同时点的数据或为排错重置账号与索引。

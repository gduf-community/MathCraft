# 后端包统一与接口对齐

## 1. 目标与范围

本轮将 `backend/math_q_agent/` 与 `backend/MathCraft/` 的 Python 实现真正统一到 `backend/MathCraft/`。知识库、模型配置、教师资料和出题编排在同一个 FastAPI 应用中运行，Python import 统一使用 `MathCraft`。

远端更新已合并，合并提交为 `6045b32`，保留本地既有提交及远端收藏页更新。本文记录本轮包迁移、接口对齐与实际验收结果；第 10 节补充隔离文档解析恢复实现与真实子进程验收记录。

- 唯一主实现包：`backend/MathCraft/`，包含原实现包的领域模块、业务服务、运行时和路由。
- 统一入口：`MathCraft.app`、`MathCraft.api.main:app`、`python -m MathCraft`。
- 旧 `math_q_agent` import 与启动命令停止支持；删除旧目录，不创建兼容壳或模块别名。
- 保留已有 HTTP、WebSocket 契约和 `data/` 运行时布局；数据根环境变量现统一为 `MATHCRAFT_HOME`，不提供旧名回退。
- 检查前端真实服务调用对齐；收藏页保留远端已有 mock，不新增未实现的后端能力。

## 3. 迁移与启动流程

1. 以已完成的远端合并 `6045b32` 为基础，保留远端收藏 mock 及已有本地改动；后续实现冲突由根任务处理。
2. 将旧实现包内容迁入 `MathCraft`，处理同名入口冲突，保留原有模块职责和单租户行为。
3. 将原实现包 `api/main.py` 的 lifespan、中间件与运行时初始化移至 `MathCraft/api/runtime.py`。`MathCraft.app` 引用该运行时模块并装配出题与正式业务路由；公开 `MathCraft/api/main.py` 仅导出统一 app，避免循环导入或形成第二套应用。
4. 将原 `api/routers/` 迁入 `MathCraft/api/routers/`，更新 Python import、动态导入字符串、worker 子进程模块名与启动脚本。
5. 同步打包配置、开发入口与本轮维护文档；移除旧包目录，不保留旧 import 或兼容命令。
6. 前端任务审计 HTTP 与 WebSocket 基址、代理、路径与字段；根任务同步 OpenAPI、API 文档并完成集成验收。

启动路径：`python -m MathCraft` → 启动器读取 `.env` 并解析监听参数 → 加载 `MathCraft.app` → ASGI lifespan 初始化设置、日志与运行时服务 → 同一应用提供 HTTP 和 WebSocket。

ASGI 导出路径：`MathCraft.api.main:app` → `MathCraft.app.app`。直接运行 Uvicorn 时，监听地址和端口由 Uvicorn 参数确定；lifespan 加载环境不会改变已经解析的监听参数。

## 10. 隔离文档解析恢复方案与验收

### 10.1 目标与恢复范围

2026-10-31：补齐 `runtime/worker_process.py` 和 `runtime/worker_tasks.py`，让现有隔离文本预览与 text-only 解析可以执行实际文档任务。新增真实子进程回归 25 项通过，完整后端套件 322 项通过、1 项跳过；具体命令和验证边界见第 10.5 节。

恢复仅涉及固定子进程入口、内部请求/结果协议和文档任务包装，复用 `MathCraft.utils.document_extractor.extract_text_from_path`。不增加依赖，不恢复认证、工作区或多租户行为，不新增 HTTP 端点、请求字段或响应字段。运行时数据根与本次恢复无关，沿用当前路径服务；不搬迁、重建或清空设置、知识库、索引和教师资料。

### 10.2 核心流程与职责

1. 现有异步 `extract_text_from_path_isolated()` 或同步 `TextOnlyParser.parse()` 调用 `isolated_worker.py`；父进程取得并发槽位并创建临时请求和结果路径。
2. 父进程使用 `sys.executable -m MathCraft.runtime.worker_process <request_path> <result_path>` 启动固定入口，使用参数列表且不经过 shell。子进程模块导入不应提前加载可选解析器或初始化应用服务。
3. 子进程读取请求，按 `module:callable` 导入并执行同步任务，将成功结果或错误封套写入结果文件。父进程从文件读取封套，标准输出不承载协议。
4. `extract_document_text` 在任务执行时惰性调用现有 `extract_text_from_path`，透传 `filename_hint`、`max_bytes` 和 `max_chars`，返回 `str`。逻辑文件名用于格式识别与异常中的文件名；显式 `None` 继续遵循现有提取器限制语义。
5. `extract_document_to_markdown` 先提取文本，再创建输出路径的父目录，以 UTF-8 写入 `.md` 并返回 `None`。text-only 调用继续传入文件大小限制及 `max_chars=None`。提取阶段失败不创建输出目录或文件；目录创建、文件写入失败仍是任务失败，不承诺新增写入事务或回滚机制。
6. 父进程沿用现有同步/异步超时、并发限制、取消处理与临时目录生命周期。异步取消终止并等待子进程回收后重新抛出取消；不改为线程提取或静默回退。

### 10.3 内部数据协议

父进程创建的可信临时文件使用 pickle 编解码；该协议不接受 HTTP 上传的 pickle，也不作为网络或多租户隔离协议。请求和结果的字段如下：

| 方向 | 字段 | 约定 |
| --- | --- | --- |
| 请求 | `callable_path` | 可导入同步任务的 `module:callable` 路径；文档任务位于 `MathCraft.runtime.worker_tasks` |
| 请求 | `args` | 位置参数元组，包含源文件路径及需要时的输出路径 |
| 请求 | `kwargs` | 关键字参数字典，沿用调用方的文件名提示与提取限制 |
| 成功结果 | `ok`, `result` | `ok=True`；文本任务返回字符串，Markdown 任务返回 `None` |
| 失败结果 | `ok`, `message` | `ok=False`；`message` 为异常消息 |
| 失败结果 | `module`, `type`, `traceback` | 异常类模块、类名和子进程 traceback 文本，供父进程诊断与现有异常转换 |
| 失败结果 | `attrs` | 可 pickle 的异常属性字典，至少保留存在的 `filename`；不可序列化属性忽略，不能掩盖原异常 |

成功结果本身须可序列化。任务定位、执行或结果序列化失败应进入失败封套；未能写出有效结果文件时，父进程继续按无结果或损坏结果处理。内部 traceback 和属性不新增为公开 HTTP 字段。

### 10.4 异常与 HTTP 边界

| 场景 | 保持的调用方行为 |
| --- | --- |
| 子进程返回失败封套 | `isolated_worker.py` 抛出 `IsolatedWorkerError`，保留 `remote_module`、`remote_type`、`remote_traceback`、`remote_attrs` |
| 已知文档提取错误 | 公开隔离提取入口恢复 `DocumentExtractionError`、`UnsupportedDocumentError`、`CorruptDocumentError`、`EmptyDocumentError` 或 `DocumentTooLargeError`，保留 `filename`；缺省时沿用逻辑文件名/源路径文件名 |
| 子进程内置文件错误 | 既有 `OSError`、`FileNotFoundError`、`PermissionError` 映射为公开 `OSError`，不增加异常类动态重建机制 |
| 无结果、不可读或非法封套 | 沿用父进程 `IsolatedWorkerCrashed` / `IsolatedWorkerError` 处理，不伪造空字符串或成功结果 |
| 超时 | 父进程终止并回收 worker，抛出 `IsolatedWorkerTimeout`；保持现有超时边界，不新增 HTTP 状态映射 |
| 异步取消 | 终止并等待 worker，清理临时目录并释放槽位，重新抛出 `CancelledError` |
| text-only 解析失败 | 继续由 `TextOnlyParser.parse()` 将既有 `IsolatedWorkerError` / `OSError` 包装为 `ParserError`；其他异常沿用现有传播边界 |
| HTTP 预览 | `GET /api/knowledge-bases/{kb_name}/file-preview-text/{filename:path}` 成功为纯文本；文档错误为 422，文件缺失为 404；已有路径校验及其他错误行为保持有效 |

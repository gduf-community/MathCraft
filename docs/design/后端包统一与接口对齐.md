# 后端包统一与接口对齐

## 1. 目标与范围

本轮将 `backend/math_q_agent/` 与 `backend/MathCraft/` 的 Python 实现真正统一到 `backend/MathCraft/`。知识库、模型配置、教师资料和出题编排在同一个 FastAPI 应用中运行，Python import 统一使用 `MathCraft`。

远端更新已合并，合并提交为 `6045b32`，保留本地既有提交及远端收藏页更新。本文记录本轮包迁移、接口对齐与实际验收结果。

- 唯一主实现包：`backend/MathCraft/`，包含原实现包的领域模块、业务服务、运行时和路由。
- 统一入口：`MathCraft.app`、`MathCraft.api.main:app`、`python -m MathCraft`。
- 旧 `math_q_agent` import 与启动命令停止支持；删除旧目录，不创建兼容壳或模块别名。
- 保留已有 HTTP、WebSocket 契约，以及 `MATH_Q_HOME` 和 `data/` 运行时布局。
- 检查前端真实服务调用对齐；收藏页保留远端已有 mock，不新增未实现的后端能力。

## 2. 目标目录与职责

```text
backend/
├── MathCraft/                 # 唯一 Python 主实现包
│   ├── __main__.py            # python -m MathCraft 启动入口
│   ├── app.py                 # 统一 FastAPI app 与路由装配
│   ├── api/
│   │   ├── main.py            # 导出 MathCraft.app 中的同一个 app
│   │   ├── runtime.py         # 原 api/main.py 的 lifespan、运行时初始化和中间件
│   │   └── routers/           # 原 math_q_agent/api/routers 的正式路由
│   ├── capabilities/          # 外部能力与连接器
│   ├── config/                # 进程配置
│   ├── core/                  # 协议、工具与事件
│   ├── knowledge/             # 知识库领域与索引生命周期
│   ├── logging/               # 日志与统计
│   ├── multi_user/            # 保留原名称，继续执行单租户替身语义
│   ├── runtime/               # 环境、数据根与隔离 worker
│   ├── services/              # 模型、RAG、解析、设置与教师资料
│   ├── tools/                 # 检索与抓取工具
│   └── utils/                 # 通用工具
├── api/                       # 既有出题编排路由
├── services/                  # 既有出题编排服务与 MathCraft 适配器
├── schemas/                   # 出题与资料请求、响应模型
└── tests/                     # 后端验证用例
```

`backend/api/`、`backend/services/` 和 `backend/schemas/` 保持现有出题编排职责；本轮聚焦两个主包的统一，不扩展为无关目录重构。包内文档引用同步迁移。

## 3. 迁移与启动流程

1. 以已完成的远端合并 `6045b32` 为基础，保留远端收藏 mock 及已有本地改动；后续实现冲突由根任务处理。
2. 将旧实现包内容迁入 `MathCraft`，处理同名入口冲突，保留原有模块职责和单租户行为。
3. 将原实现包 `api/main.py` 的 lifespan、中间件与运行时初始化移至 `MathCraft/api/runtime.py`。`MathCraft.app` 引用该运行时模块并装配出题与正式业务路由；公开 `MathCraft/api/main.py` 仅导出统一 app，避免循环导入或形成第二套应用。
4. 将原 `api/routers/` 迁入 `MathCraft/api/routers/`，更新 Python import、动态导入字符串、worker 子进程模块名与启动脚本。
5. 同步打包配置、开发入口与本轮维护文档；移除旧包目录，不保留旧 import 或兼容命令。
6. 前端任务审计 HTTP 与 WebSocket 基址、代理、路径与字段；根任务同步 OpenAPI、API 文档并完成集成验收。

启动路径：`python -m MathCraft` → 启动器读取 `.env` 并解析监听参数 → 加载 `MathCraft.app` → ASGI lifespan 初始化设置、日志与运行时服务 → 同一应用提供 HTTP 和 WebSocket。

ASGI 导出路径：`MathCraft.api.main:app` → `MathCraft.app.app`。直接运行 Uvicorn 时，监听地址和端口由 Uvicorn 参数确定；lifespan 加载环境不会改变已经解析的监听参数。

## 4. 保持不变的契约

| 契约 | 本轮要求 |
| --- | --- |
| HTTP 路径与方法 | 保留 `/healthz`、`/api/health`、`/api/generate`、`/api/chat`、`/api/auth/*`、`/api/knowledge-bases/*`、`/api/settings/*`、`/api/user-profile` 及头像接口、`/api/system/*` 等已有路径和方法；完整清单以实际导出契约为准 |
| WebSocket | 保留 `/ws/knowledge-bases/*` 的路径、消息结构与进度事件含义 |
| 请求和响应 | 保持出题槽位、各题型数量、错误状态、模型配置及知识库字段和默认行为 |
| 文档标识 | `doc_id` 仍为 `raw/` 下的 POSIX 相对路径，检索继续使用 `document_keys` 限定范围 |
| 数据根 | 保留 `MATH_Q_HOME`、默认数据根解析及已有 `data/` 相对路径；在仓库根启动时默认使用仓库根，不因包名改变而另建数据根 |
| 已保存数据 | 继续读取原设置、知识库注册表、索引与教师资料；不复制、清空、重建或自动迁移数据 |
| 启动配置 | 保留 host/port 参数、环境变量与已保存端口设置的既有优先级，以及 CORS 配置语义 |
| 单租户与依赖 | 认证和工作空间替身继续有效；可选解析器与 RAG 引擎继续惰性加载 |

Python import 与启动模块名是本轮有意改变的开发契约。调用方需要将 `math_q_agent.*` 更新为 `MathCraft.*`，不能依赖旧目录、模块别名或兼容命令。保留 `multi_user` 等内部目录名称不代表恢复上游多用户行为。

## 5. 前端对齐与收藏边界

- 对照统一后端检查 HTTP 基址、Vite `/api` 代理和 WebSocket URL，使环境配置与实际监听端口一致。
- 知识库、模型设置、教师资料与出题调用沿用既有契约；Python 包名更改不要求浏览器请求路径改名。
- 收藏页使用远端已有的前端内存 mock，刷新后重置；收藏与收藏夹操作不代表已有后端持久化。
- 本轮不新增收藏 HTTP 接口、数据库、磁盘存储或迁移，也不将 mock 行为描述为已实现后端能力。

## 6. 异常与协作边界

- 入口重名：原运行时实现落到 `api/runtime.py`；公开 `api/main.py` 始终导出统一 app。
- 路由冲突：核对已有路径、方法与依赖装配，避免重复注册或遗漏正式路由。
- import 与 worker：同时检查静态和动态引用，避免旧包路径只在子进程或可选分支触发。
- 数据路径：包位置改变不能导致另建用户数据根；保留原文件和失败处理，不能以空配置覆盖已有数据。
- 可选依赖缺失：仅影响对应能力并继续报告 unavailable，不能导致基础应用导入或启动失败。
- 仓库约定：`AGENTS.md` 已按用户授权更新，唯一主包、import、启动入口和目录约定统一为 `MathCraft`。

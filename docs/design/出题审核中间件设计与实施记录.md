# 出题审核中间件设计与实施记录

本文记录 `backend/app/services/question_review.py` 的目标、使用范围、核心流程、数据契约、异常边界与验收结果。对应提交 `feat(generation): 出题中间件、盲评校准与模型超时修复`。

## 目标

命题模型一次给出的题目不能直接用。实测并发出题时十道题里有五题撞到同一考点，地狱难度题里约七成达不到目标档，答案与解析还会互相矛盾。中间件把查重、难度盲评、缺陷修补、独立解题收敛成一条固定流水线，题目通过后才写入题目预览。

另一个目标是修掉模型响应超时。生成阶段开启思考模式时，单题跑 3 分 19 秒仍无返回，十题并发会一起撞上 300 秒超时线。

## 使用范围

对话出题与参数化出题两条链路都经过中间件，入口分别是 `app/api/chat.py` 与 `app/services/generation.py`。知识点检索、HyDE、混合检索、题型编排仍在 `app/services/rag/`，不在本模块内重复实现。

## 核心流程

| 阶段 | 处理内容 | 并发方式 |
| --- | --- | --- |
| 考点规划 | 出题前让模型列出互不重复的细分考点，再按考点拆给单题批次 | 一次调用 |
| 生成 | 单题流式调用，关闭思考模式，单题预算 3000 token 加结构开销 400；完整对象即校验 | 六路 |
| 查重 | 与收藏、组卷记录、同题库历史题目做 bge-m3 语义比对，余弦 0.92 以上丢弃，批内同样互查 | 本地计算 |
| 盲评 | 不告知命题时标注的难度，独立解题后按六个维度打分，两次评分差超过 0.7 时第三人仲裁 | 每题两到三次调用 |
| 修补 | 按缺陷码做最小修补，只改必要字段，保持题型与考点不变 | 六路 |
| 换模板重出 | 修补未通过或数量不足时换难度模板重出，最多一轮 | 六路 |
| 补齐 | 仍不达标时按距离目标档中心最近的顺序补足数量 | 本地计算 |
| 解析 | 另起对话独立解题，覆盖命题阶段自带的答案与解析 | 六路 |

六维权重为知识点匹配 0.20、步骤综合 0.20、概念抽象 0.20、计算复杂度 0.15、陷阱非常规 0.15、可解唯一 0.10。加权总分 1 到 2 为低，2 到 3 为中，3 到 4 为高，4 到 5 为地狱，边界留 0.5 容差。可解唯一性过低、超纲、答案有问题时一票否决。加权总分由本地重算，不采信模型算术。

## 流式生成与结构校验

本节按 2026-11-13 合并代码同步，范围为 `rag/llm.py`、`rag/question_gen.py`、
`rag/prompts.py` 和 `schemas/question.py`；后文原有实测数据仍为历史批次。

1. 提示词提供字段结构与示例，要求输出 `<questions>{"questions": [...]}</questions>`，
   公式采用 `$...$` 或 `$$...$$`。标签是模型输出约定，不是新的 HTTP 消息格式。
2. `chat_stream()` 仅累积有效内容增量。滚动解析器找到 `questions` 数组后，
   每个完整对象立即交给 `Question.model_validate()`；字段校验失败中断当前批次解析。
3. 流结束后对剩余可恢复内容使用 `json-repair`，修复所得对象仍须通过相同校验。
   无有效题目或字段不合法时，最多附带一次错误摘要与输出片段重新请求，预算保持不变。
4. 返回前丢弃不匹配的题型，补充题目 ID、默认分值、目标难度及文档名称；
   仍无有效题目则抛出生成错误，由原有批次及审核流程处理。

Pydantic 使用现有 `Question` 的默认字段和兼容转换，并非提示词中“禁止增删字段”的
逐字强制实现，不能据提示词宣称所有缺省或额外字段均会拒绝。题干、选项、答案和解析
会去掉代码栅栏，将 `\(...\)`、`\[...\]` 统一为美元定界；这只处理格式，不验证数学正确性。
格式通过后仍须经过查重、盲评、修补与独立解题，不向浏览器提前交付未审核对象。

`json-repair` 同时用于审核低温 JSON 调用的解析兜底；它只修复结构，审核内容仍由
各阶段解析规则处理。审核初始预算失败后最多再用 1.4 倍预算调用一次。

## 接口与数据契约

新增两个 HTTP 入口，完整契约见根目录 `openapi.json` 与 `docs/api.md`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/chat/sessions/{session_id}/progress` | 前端每 1.5 秒轮询阶段百分比与文案 |
| POST | `/api/chat/sessions/{session_id}/cancel` | 暂停生成，后台在检查点停下且不落库 |

生成任务结果新增 `review` 字段，含 `duplicates`、`repaired`、`regenerated`、`solved` 四个计数。题目新增 `difficulty_score`、`blueprint`、`difficulty_review`，落库列对应 `difficulty_score`、`blueprint_json`、`review_json`，由两条 Alembic 迁移 `d9f4a2c7e815` 与 `e3b7c1d94a62` 引入。迁移链从 `c3e8a1f5b279` 起，升级前需确认该版本已存在。

## 异常边界

- 向量服务不可用时跳过查重，不阻断出题。
- 盲评、修补、解析任一环节的服务异常只降级并写日志，保留原题与原有答案，不让整批失败。
- 单批生成失败只丢该批，由补齐轮补上；一道都没出时才把真实异常抛给前端。
- 生成端 JSON 截断或结构异常按上述滚动解析与修复流程处理；字段校验失败或未解析出题目时最多反馈一次错误重试，不再使用旧的生成预算递增流程。流式传输异常不作为结构错误重试。审核 JSON 调用的修复与预算重试遵循本节上方说明。
- 接口不认关闭思考模式的参数时退回默认调用，保证 DeepSeek 官方实现可以直接使用。
- 对话与出题模型配置只保留 DeepSeek 官方地址与模型名，个人密钥通过现有用户模型设置接口保存，不写入仓库。

## 验收标准与实测

流式增量验收应覆盖任意内容分片、标签／代码栅栏、截断 JSON 修复、字段错误反馈重试、
无有效题目、错误题型过滤和公式定界规范化；验证使用模型替身，不连接真实服务。
下表保留原审核中间件实测，不能作为本次流解析增量的测试结果。

| 项目 | 结果 |
| --- | --- |
| 后端接口测试 | 191 项通过 |
| 前端类型检查与 lint | 无错误 |
| 十道地狱难度选择题端到端 | 376 秒返回，落库 10 道，平均难度 4.0 |
| 题目覆盖面 | 数列、反常积分、欧拉方程、无穷小比较等不同考点，不再扎堆同一模板 |
| 两道判断题冒烟 | 29 秒，正常入库 |
| 超时与截断 | 关闭思考后单题 7 到 12 秒，半截 JSON 自动放大预算重试成功 |

剩余瓶颈是盲评与修补占一半以上耗时，修补一道要整题重写 JSON，单次约 30 秒。要继续压缩等待时间，可考虑修补只返回差异字段再本地合并、放宽难度判定，或加强前端等待反馈。三者分别对应实现复杂度、质量门槛与体验取舍。


### 2026-11-10 共享题库审核语料隔离

远端整合审查发现：历史题目查重原先只按题库查询，重出时可能将其他成员的个人题干送入当前用户的模型请求。现已同时按 `bank_id` 与 `created_by=user_id` 限定历史语料；收藏和组卷记录继续按本人账号查询，不改变既有个人记录归属。共享资源成员身份不授予他人个人题目的读取或模型处理权限。

跨账号合成数据库回归在修复前复现该问题；修复后两个文件专项共 16 项通过，确认双方仅取得本人历史题干，并保留出题审核既有回归。本次不新增接口或数据库字段。

### 2026-11-11 独立解题 JSON 与运行时配置整合

独立求解改为使用 `rag.prompts.SOLVE_SYSTEM`，同一次调用输出 `answer`、`analysis`
及 `confidence`，避免分别生成答案和解析造成结论不一致。答案继续按题型规范化，
低置信度写入题目自检说明；求解失败继续遵循已有降级边界。

保留 `with_snapshot` 和当前用户语料过滤，使用主线模型配置及隔离规则。四模式对话
生成的题目也经过同一审核入口，接口整合及验证记录见[四模式说明](对话四模式与主线整合.md)。

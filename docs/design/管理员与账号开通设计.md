# 管理员与账号开通设计

2026-11-12 自身邮箱绑定契约同步：管理员与教师、学生共用免密码绑定规则，有效登录态且无已验证邮箱时提交新邮箱 `email_bind` 验证码即可。历史未验证邮箱同样适用；不开放替他人绑定或覆盖已验证邮箱的能力。换绑双验证码、解绑当前密码及成功全会话撤销保持既有规则。

状态：已批准的账号、管理员与可选邮箱规则已实现；实际验证批次、环境失败和历史证据统一见[账号系统整合与审查修复](../implementation/账号系统整合与审查修复.md)。本文保留现行业务规则、异常边界及验收标准，不据历史批次推断当前远端或部署状态。

## 当前目标与范围

管理员专用于账号运维和平台汇总查看；教师、学生使用自己的教学身份。账号由管理员开通，公开自助注册删除；三角色均以 account 密码为默认登录方式，可在自身安全区域选配邮箱。邮箱可绑定、换绑或解绑，用户 ID、历史密码和资源归属保持稳定。实现入口为 [管理员路由](../../backend/app/api/admin.py)、[管理员 schema](../../backend/app/schemas/admin.py)、[认证路由](../../backend/app/api/auth.py)、[权限依赖](../../backend/app/deps.py) 和 [管理员页面](../../frontend/src/components/admin/AdminPanel.tsx)。完整认证、资料及 Cookie 契约见 [用户系统实施规格](用户系统实施规格.md)，业务规则见 [用户系统功能规格](用户系统功能规格.md)，迁移与跨模块边界见 [账号系统整合与审查修复](../implementation/账号系统整合与审查修复.md)。

## 当前规则与原方案差异

| 范围 | 本地 main 当前实现 |
| --- | --- |
| 账号来源 | 管理员创建 admin/teacher/student 账号；首个管理员由运维交互创建。公开注册页面、POST /api/auth/register 与发码 purpose=register 删除，邮箱登录不建号 |
| 登录入口 | 仅“密码登录”“邮箱登录”两种登录入口，默认密码登录，不选择教师/学生/管理员身份，服务端识别角色；学工号登录删除，学工号资料及维护接口保留 |
| 账号密码登录 | POST /api/auth/login/account 的 account、password、turnstile_token 保持不变；按 account 精确匹配启用账号，不受邮箱缺失/未验证/已验证状态限制。POST /api/auth/login/email 删除 role，仅已验证邮箱可用，服务端识别三角色 |
| 首个管理员 | 运维在完成迁移后显式运行交互 create_admin.py，账号与显示名交互输入，密码 getpass 隐藏输入两次；无默认密码、不接受账号/密码命令行参数、不覆盖已有账号，也不自动修复或启用账号 |
| 开发初始化 | seed.py 只在 development＋显式开关下创建教师/学生开发账号；生产禁止开发种子能力，日常启动不自动建号。没有从 .env 同时初始化三角色的当前流程 |
| 账号创建 | account、display_name、role、password 必填；新账号 1–64 字符、去首尾空白，仅 ASCII 字母/数字/下划线/点/短横线，按原文匹配，区别于旧方案允许中文。登录兼容历史账号字符，不套新建正则；新密码 8–64 字符且 UTF-8 ≤72 字节 |
| 维护操作 | 查询/筛选，创建三类账号，编辑显示名，专用重置密码及禁用/恢复；无改角色、改 account 或永久删除接口。基础资料与认证标识由现有用户专用接口维护 |
| 会话 | 认证为短期 HS256 JWT＋SQL 设备会话/认证版本，默认 access 15 分钟、refresh 绝对 7 天并逐次轮换；Redis 用于验证码、限流和任务/缓存，不承载当前登录会话 |
| 撤销与并发 | 普通退出按本标签 Bearer 的 sid 撤销；自行改密、邮箱恢复/绑定/换绑/解绑、管理员重置/禁用使目标用户全部旧会话失效。邮箱变更成功均 204，回默认密码登录页。管理员写操作用数据库锁重新校验操作人并保护最后一个启用管理员，恢复不会复活旧会话 |
| 密码与提醒 | 管理员手动设置初始/重置密码，通过受控既有渠道交付，页面不能读取原密码。创建/重置及交互管理员创建设置 password_change_recommended；自行改密或邮箱恢复清除。提醒持久化且非强制 |
| 密码恢复 | 有已验证邮箱可自助验证码恢复；无已验证邮箱时联系管理员重置。已登录三类账号自行改密需 Bearer、旧密码及两次新密码；不存在公开 account＋旧密码改密旁路 |
| 联系指引与配置 | GET /api/auth/config 公开 admin_contact，说明开户及无法恢复时联系管理员；methods 严格顺序 account_password、email_code。开发填充返回 account、password、role，role 只选开发样例，不是登录身份 |
| 自身邮箱配置 | UserPayload 必含 email_verified；管理员在管理面板自己的安全区域，与教师/学生共用绑定、换绑、解绑契约；不能通过该入口替他人绑定邮箱，也不因此获得教学权限 |
| 资料与模型设置 | 普通资料接口不能改邮箱、学工号、角色；性别/手机省略保留、null 清空。个人模型设置按用户保存、只返回状态与掩码；留空保留、显式清除、测试已保存配置，默认配置可用性需另验证 |
| 平台信息 | 返回账号角色/状态数量、启用题库数、文档数、试卷数；任务总数和状态数为全部已持久化 GenerationBatch，列表仅最近 50 项。task_scope=persisted_generation_batches，completed_at=null，不虚构全平台任务覆盖或完成时间 |
| 管理员权限 | 管理面板不额外授予用户题库正文、对话、作答或个人模型凭据访问权限；教学资源权限解析拒绝 admin，管理员需要教学功能时使用独立教学账号 |
| 题库创建与成员 | 仅教师可创建，学生前端隐藏入口、直接 POST 也拒绝；creator/editor/readonly 三档，创建者按 account 添加启用教师/学生。编号加入关闭；历史学生创建库保留归属与访问，转让仅给启用教师，原创建者降为 editor |
| 个人记录与文件 | 题目、收藏、聊天、组卷按账号归属；成员共享不公开他人个人记录。文档按题库和文档 ID 存储，授权不靠个人磁盘目录；历史聊天重新校验题库成员资格 |
| 学习空间 | 教师创建管理，学生凭随机加入码（SP＋8 位随机字符，共 10 位，2026-11-18 起）加入；旧顺序码迁移轮换，removed 成员不能凭码重新加入。题库成员权限不自动获得空间资源 |
| 迁移与隔离测试 | 沿用既有认证、随机空间码及改密提醒迁移，本轮不新增模型或迁移，保留 account、密码、用户 ID 和外键；邮箱缺失/未验证审计仅为信息项。测试用临时 SQLite、独立 fakeredis、假外部服务，不清空本机 Redis |

## 当前核心流程与接口

首次受控开通：备份并完成既有数据库迁移 → 操作者在服务器本地交互运行 [create_admin.py](../../backend/scripts/create_admin.py) → 通过默认“密码登录”完成 Turnstile 和 account 密码验证 → 进入管理员面板 → 创建后续管理员或教学账号。使用已有服务器时由 SSH 连接，本次实施未执行服务器初始化。密码不得放在命令行或输出到共享日志。

已有管理员通过面板创建账号或重置密码后，向使用者交付凭据并提示自行改密；管理员自行重置或禁用自身时，旧会话同样撤销，页面反馈结果并要求重新登录。使用者可直接以 account 密码登录，再自愿配置邮箱；开户不要求邮箱或学工号，也不自动验证历史邮箱。

管理员自身邮箱流程：打开管理面板安全区域 → 无已验证邮箱时申请 email_bind 码并以有效登录态提交绑定，已有已验证邮箱时沿用旧、新邮箱双码换绑，解绑时仅提交当前密码 → 成功 204、撤销全部设备会话 → 返回默认“密码登录”。界面以 email_verified 判断绑定状态，历史未验证邮箱允许按绑定流程重新验证新邮箱。

| 方法与路径 | 输入和结果 |
| --- | --- |
| GET /api/admin/accounts | 管理员 Bearer；query 搜索 account/显示名，可按 role、status 筛选，返回基础账号列表与改密提醒，不返回密码/模型凭据 |
| POST /api/admin/accounts | account、display_name、role、password；201 创建启用无邮箱账号及其模型设置，唯一冲突 409 |
| PATCH /api/admin/accounts/{user_id} | display_name；更新显示名，不改 account、role 或认证标识 |
| POST /api/admin/accounts/{user_id}/reset-password | password；204，同事务更新哈希、认证版本和全部会话撤销，设置改密提醒；允许为禁用账号重置但不自动启用 |
| POST /api/admin/accounts/{user_id}/disable | 204，保留数据并撤销旧会话；最后一个启用管理员返回 LAST_ADMIN/409 |
| POST /api/admin/accounts/{user_id}/restore | 204，恢复 active，不降低认证版本或恢复旧会话 |
| GET /api/admin/overview | 账号数量、资源统计、持久化批次统计与最近 50 项，不返回私有业务内容 |
| POST /api/auth/email-code | 自身 Bearer；email、purpose=email_bind、turnstile_token；仅无已验证邮箱可用，挑战绑定 user_id、auth_version、原邮箱快照及目标邮箱 |
| PUT /api/users/me/email-binding | 自身 Bearer；email、challenge_id、code；204，验证有效登录态与专用 proof 后绑定、全部撤销；不接受 current_password |
| POST /api/users/me/email-change；PUT /api/users/me/email | 自身 Bearer；沿用已验证旧邮箱与新邮箱双码契约；换绑成功 204、全部撤销 |
| DELETE /api/users/me/email | 自身 Bearer；JSON {current_password}；204，清空 email/email_normalized/email_verified_at，email_verified=false，全部撤销 |

## 当前异常边界与验收限制

公开 login/reset_password 挑战须绑定用途、规范化邮箱、用户 ID、认证版本，发码/登录/重置三处保持一致；补用户 ID 绑定的安全修复已通过相关回归。邮箱解绑转给另一账号后，即使认证版本相同，旧登录/重置码不能作用新账号；部署后旧未消费挑战需重发，无数据库迁移。管理员同样适用，最终后端验收必须覆盖。

历史邮箱不自动标记可信；未验证邮箱不提供邮箱码登录或恢复，但原 account 密码仍可登录，再取得有效登录态完成自助绑定。email_bind 只允许无已验证邮箱，绑定提交校验有效登录态、用户、认证版本、原邮箱快照、目标邮箱和唯一性；已验证邮箱走双码换绑或明确当前密码解绑。错误或并发条件不符不修改邮箱。邮箱缺失/未验证只作为只读审计信息；标识冲突、角色/身份、开发来源或结构异常等独立门禁仍可阻断发布。seed/create_admin 不覆盖密码或状态，全部管理员不可用仍由运维受控处理。

认证会话状态以 SQL 为准，浏览器 access 只在内存，refresh 使用 HttpOnly Cookie；refresh/logout 的 Origin、JSON、CSRF，以及普通退出同 sid 清 Cookie、安全操作目标用户清 Cookie 规则均见实施规格。退出网络失败不能宣称服务端已撤销。公开登录/恢复发码统一 202、后台失败不激活码；绑定与换绑同步投递失败 503，失败不清限额，202 不等于投递完成。

验收需覆盖管理员与教学身份隔离、最后管理员并发保护、三角色两种登录、管理员开户、管理员自身邮箱绑定/换绑/解绑、204 后全会话撤销并回默认密码登录、旧账号与资源归属保留、初始化不覆盖及邮箱审计信息化。实际实施与检查结果见[账号系统整合与审查修复](../implementation/账号系统整合与审查修复.md)；历史分支数量与旧 PR 状态不作为当前结果。

## 1. 目标与使用范围

初版由平台管理员创建账号，普通使用者通过登录进入平台；登录界面提示“获取账号请联系管理员”。新增管理员面板，承担账号管理与平台信息查看。

本轮要求优先于 2026-11-04 的自助注册方案。旧功能规格、实施规格及关联 Issue 中的自助注册、排除管理员等冲突要求不再作为本轮实施依据；未冲突的历史技术方案是否保留，仍需逐项确认。

## 3. 当前源码基线

本轮静态核查，未读取真实配置或数据库：

### 3.2 成员授权与统一权限的现状差距（2026-11-06）

- backend/app/api/banks.py 的 join 路由当前凭编号直接建立有效成员关系，已有非活跃成员也可重新激活，无创建者批准步骤。成员管理现有列表、改角色和移除操作，尚无创建者主动添加成员或审批加入接口。
- 现有 backend/app/deps.py 中的 resolve_bank_access、require_bank_admin／super_admin／owner 和 BankAccess.capabilities 可作为权限收敛基础；本轮不会将现有题库管理员直接等同于平台管理员。
- 当前文档关联 Bank，生成接口的 bank_id 与兼容 kb_id 使用同一资源权限解析器；题目仍保留 created_by 个人归属。可复用该资源授权基础，无需因此合并知识库和题库的产品概念。
- 已确认改为创建者按登录账号添加成员、分配权限或移除，取消知识库／题库的凭编号直接加入及被移除后自行恢复成员资格；实施时需同步调整成员接口、页面入口与对应契约。学习空间的加入机制不在此变更范围。

### 3.3 学习空间现状与本轮边界

以下为当前源码行为核查，仅用于说明现状，不构成新增需求：

- 教师创建和管理自己的学习空间，填写名称及人数上限；学生通过空间编号加入，学生不能创建空间，教师不能以学生方式加入。
- 教师可调整自己空间的信息、查看和移除成员、解散空间；学生可查看所属空间及成员并退出。后端按创建者或有效成员身份校验访问。
- 教师将自己的试卷发布到自己的空间，学生查看发布的试卷并作答；页面提供催交、停止／恢复及相关试卷操作，具体行为沿用现有实现。
- 当前空间加入接口允许非活跃成员凭有效编号重新加入（受容量等现有校验约束）；本轮取消知识库／题库凭编号加入不作用于学习空间。
- 源码依据：backend/app/api/spaces.py、backend/app/services/spaces.py、backend/app/deps.py、backend/app/services/papers.py 与 frontend/src/components/tabs/SpaceTab/index.tsx；本轮未运行服务或修改这些代码。

本轮只实施明确约定的账号与资源权限变更，不借权限统一扩展或重写学习空间业务。

## 4. 核心流程

已确定的产品流程：部署者在 .env 配置首个管理员的账号和初始密码 → 首次初始化保存到数据库 → 管理员登录 → 在管理面板创建教师、学生及其他管理员账号 → 使用者联系管理员获取账号 → 使用者登录。

初始化完成后，管理员账号由数据库和管理面板维护；服务重启或修改 .env 不覆盖既有账号信息及密码。初始化由部署者显式执行命令触发，日常启动服务不自动建号；命令执行前检查配置完整性和账号重复，角色冲突直接报错；初始化不承担账号恢复。

三类账号使用统一登录页，仅填写登录账号和密码，由后端识别角色并进入对应界面；取消教师／学生身份选择。管理员登录后进入管理面板，不以管理员账号进入教师或学生工作台；同一人员需要教学功能时使用另外的教师或学生账号。登录页统一展示获取账号联系管理员的提示。

首次初始化同时准备首个管理员、一名教师和一名学生，三者的登录账号和密码均由 .env 提供，开发环境与正式部署采用同一规则。只创建缺失账号，不覆盖已有资料、密码或启用状态；初始教师和学生创建后按普通账号维护。部署时显式执行一次初始化命令；日常启动服务不自动建号。重复执行同一初始化命令时，仅补建缺失账号，保留已有账号的资料、密码、角色及启用状态。

## 5. 接口与数据契约

当前以 backend/app/ 和根 openapi.json 为实现基线。用户 ID、既有教师／学生账号及其资源归属需要保持不变；当前表结构已支持管理员角色和账号状态。

认证方式已确定为全平台唯一的登录账号＋密码，登录账号与显示名称分离；邮箱验证码登录、邮箱验证和自助密码找回不在初版范围。创建账号的必填字段为登录账号、显示名称、角色与初始密码；登录账号和角色创建后固定，管理员可编辑显示名称，密码使用专门的重置操作修改。登录账号格式、管理员身份建模、账号状态及账号管理接口已确定；本阶段不把候选路径写入正式 API 契约。

管理员配置仅用于显式初始化命令，不在每次启动时同步覆盖数据库账号；修改 .env 本身不修改已有账号或撤销其会话。已有账号角色冲突时初始化直接报错；管理员全部无法登录时由服务器运维人工处理。

### 5.1 统一用户权限边界

| 权限范围 | 已确认规则 |

## 7. 异常边界

已确定的保护：账号禁用后停止访问且保留业务数据，最后一个可用管理员不得禁用；初版不提供永久删除与角色变更。

会话边界：普通退出仅撤销当前登录；修改密码、管理员重置密码及禁用账号撤销该账号全部已有登录，恢复账号不会恢复旧会话；同一账号不同设备使用同一份数据。

初始化边界：仅补建缺失账号，不覆盖已有资料、密码或启用状态；默认教师与学生并非特殊免管理账号。命令执行前检查配置完整性和账号重复，已有账号角色冲突直接报错；初始化不承担账号恢复。

数据查看边界：管理员权限不绕过用户私有业务资源的归属校验；平台信息接口仅返回已确认的基础资料、状态和统计，以及任务类型、状态、创建时间、完成时间和状态数量；不返回题库正文、出题对话、作答内容、用户输入、生成内容、原始错误堆栈或个人模型密钥。

实现约束：沿用既有用户、权限和会话模块，保留必要的服务端授权、输入校验及已确认的账号保护。围绕实际需求做小范围修改，不为假设场景增加权限框架、通用状态机制或重复校验；不编写复述实现的低价值测试。

不读取或写入真实凭据；正式环境和本地开发均由操作者显式执行初始化命令，日常启动不自动建号。测试使用隔离数据库与 Redis 15。

## 8. 验收标准

已确定的产品验收：无公开注册入口；账号由管理员创建；登录页展示联系管理员提示；管理员面板提供账号管理与平台信息查看；初版提供教师与学生初始账号；管理员凭据从部署配置取得；支持最终确认的多人登录语义。

管理员身份验收：管理员登录后进入管理面板，不兼任教师或学生；需要教学功能时使用独立的教师或学生账号。所有平台管理员具有相同的管理权限，不存在超级管理员与普通管理员分级。

初始账号与维护验收：开发及正式部署均通过显式初始化命令准备一个管理员、一个教师与一个学生，登录账号和初始密码来自 .env；日常启动服务不自动创建账号；重复初始化仅创建缺失账号，不改变已有资料、密码或启用状态；初始教师与学生可按普通账号改密、禁用和恢复；已有管理员可在面板中创建其他管理员，账号信息保存到数据库，服务重启或修改 .env 不覆盖已维护的账号及密码。

账号管理验收：支持按账号标识和显示名称搜索、按角色和启用状态筛选；创建三类账号仅必填登录账号、显示名称、角色与创建者设置的初始密码，邮箱、手机号、学校及学工号非必填；创建后登录账号与角色固定，支持编辑显示名称、专门重置密码及禁用／恢复；禁用停止访问但保留数据；不能禁用最后一个可用管理员；初版不提供永久删除或角色变更。

平台信息验收：管理员能查看账号基础资料、启用状态与约定的平台统计和任务运行情况；相关页面和接口不额外开放用户题库正文、出题对话、作答内容或个人模型密钥。

登录验收：三类账号共用登录页，以全平台唯一的登录账号＋密码认证，不需选择身份；后端识别实际角色，管理员进入管理面板，教师和学生进入各自工作台；页面展示获取账号联系管理员的提示；修改显示名称不改变登录账号；忘记密码引导联系管理员重置，初版不提供邮箱验证码登录、邮箱验证或自助密码找回。

会话验收：三类账号均可多设备同时登录，新登录不踢出旧登录；各设备使用同一账号的数据；普通退出仅影响当前登录；修改密码、管理员重置密码或禁用账号后旧会话全部失效；恢复账号后需重新认证。

密码交付与修改验收：管理员可手动设置初始或重置密码并自行告知使用者；三类账号登录后均能自行改密，首次登录或重置后可见非强制改密提示；管理面板不能查看已有密码。

资源权限验收：未获授权的教师不能通过页面或直接调用接口读取其他教师的知识库、题库及其受保护内容；创建者可按登录账号添加成员、分配权限和移除成员；知道编号不足以自行加入，被移除成员不能凭编号恢复资格；资源授权不自动开放个人题目、收藏、聊天和组卷记录；目录布局不作为访问授权依据。按已确认矩阵验收：只读成员可查看、下载和使用资料检索出题，但不能上传或删除资料；可编辑成员可上传、删除资料，但不能管理成员、库设置或删除整个库；创建者可管理上述操作；各成员生成的题目分别归本人账号。

学生创建权限验收：学生页面不提供知识库／题库创建操作，直接调用创建接口也被拒绝；其他学生能力不因权限统一而扩展，不能仅凭代码当前存在入口认定为已约定功能。

最终验收需要补齐管理员权限隔离、教师与学生权限边界、普通账号越权拒绝、已有账号与数据归属迁移、初始化幂等及会话撤销场景。具体断言随决策补充。

## 目标、范围与最终规则

- 账号由管理员开通，首个管理员由运维交互创建；平台角色为 admin/teacher/student。公开注册页面、POST /api/auth/register 与发码 purpose=register 删除；邮箱登录和发码不建号。
- 登录仅有“密码登录”“邮箱登录”两种入口，默认密码模式，无身份选择；两种登录均由服务端识别三角色。删除 POST /api/auth/login/password 学工号登录；学工号资料及专用维护接口保留。
- POST /api/auth/login/account 沿用 account、password；turnstile_token 可缺省或为空字符串，有效启用时仍拒绝空票据。按 account 精确匹配启用账号；邮箱缺失、未验证或已验证均可原 account 密码登录。不混用邮箱/学工号/手机号查询，不套新建账号正则或新密码最小长度限制。
- POST /api/auth/login/email 仅 email、challenge_id、code，删除 role；仅已验证邮箱可用。GET /api/auth/config 的 methods 严格为 [account_password, email_code]，AuthConfig.turnstile_enabled 为当前请求的有效 boolean；开发填充接口返回 account、password、role，按钮填充 account，role 只选择开发样例。
- 邮箱是可选个人安全配置，UserPayload 新增必填布尔字段 email_verified。三角色均可自助绑定、换绑、解绑；管理员通过管理面板自身安全区域操作，不必进入教学工作台，也不借此配置他人邮箱。
- JWT + SQL 会话、内存 access、HttpOnly refresh Cookie 沿用；Redis 用于验证码、限流和任务/缓存。refresh/logout 校验 Origin、JSON 与双提交 CSRF，其他安全操作按 Bearer 或邮箱 proof 契约校验。
- 首个管理员通过受控本地 create_admin.py 交互创建，无默认密码或密码命令行参数。管理员创建/重置设置 password_change_recommended，自行改密或密码恢复清除；提醒非强制。
- 公开 config 保留 admin_contact 开户及恢复指引；密码恢复仅限已验证邮箱，无已验证邮箱时联系管理员。不恢复旧 Redis token 或公开 account＋旧密码改密旁路。

## 核心流程与契约

管理员开户 → 用户默认 account 密码登录 → 按需进入自身安全设置配置邮箱 → 已验证邮箱可用于“邮箱登录”及密码恢复。已有历史未验证邮箱的用户仍可密码登录，绑定时验证目标邮箱，不自动信任旧值。

| 邮箱流程 | 契约与提交条件 | 成功结果与异常边界 |
| --- | --- | --- |
| 绑定发码 | POST /api/auth/email-code：Bearer、email、purpose=email_bind；turnstile_token 可缺省或为空，有效启用时仍需有效票据 | 仅无已验证邮箱可用；challenge 绑定 user_id、auth_version、原邮箱快照与目标邮箱；同步 SMTP 失败 503 |
| 绑定提交 | PUT /api/users/me/email-binding：Bearer；email、current_password、challenge_id、code | 验证当前密码、用途/主体/版本/快照及目标邮箱唯一性，写入已验证邮箱，204 |
| 换绑 | POST /api/users/me/email-change；分别发送 email_change_old/email_change_new 码；PUT /api/users/me/email 提交 change_id 和旧、新 challenge_id/code | 沿用已验证旧邮箱与新邮箱双 proof，绑定事务、用户、邮箱快照、版本；不能用 email_bind 代替，204 |
| 解绑 | DELETE /api/users/me/email：Bearer；JSON {current_password} | 校验当前密码及版本，清空 email、email_normalized、email_verified_at；响应用户状态 email_verified=false，204 |

三类邮箱变更在同一 SQL 事务内消费适用 proof、更新邮箱及认证版本、撤销全部设备会话；清目标用户 Cookie，前端回默认“密码登录”，不自动签发新会话。解绑后仍可用原 account 密码登录。错密码、邮箱占用、错码/过期/重放、跨用户/用途或版本/原邮箱快照变化时不改变邮箱及资源归属；提交时再次校验版本和唯一性，不把 Redis/SQL 独立提交误称为跨存储原子事务。

登录、发会话和刷新复核原验证版本；管理员写操作在数据库锁内重新校验操作人并保护最后一个启用管理员，恢复不复活旧会话。平台任务统计为已持久化 GenerationBatch，最近 50 项仅为列表，没有真实完成时间返回 null。

## 发码安全与部署兼容

公开 login/reset_password 发码在有效启用时经 Turnstile、始终经限流后统一 202、响应后投递；不适用收件人不投递，SMTP 失败不激活 challenge，响应不泄露邮箱存在性。邮件成功且挑战仍为最新才激活；后台任务非持久队列，202 不代表已送达。email_bind 及换绑发码要求有效 Bearer，同步失败返回 EMAIL_SERVICE_UNAVAILABLE/503，失败不清限额。

安全复核补充（已修复，127 项认证相关回归通过）：公开 login/reset_password 挑战必须绑定用途、规范化邮箱、用户 ID、认证版本。发码、邮箱登录验码、密码重置验码三处使用同一绑定规则，不再仅依赖 purpose/email/version。邮箱解绑后转给另一用户，即使双方认证版本相同，旧挑战也不能登录或重置新账号。部署后旧未消费 login/reset 挑战因绑定变化失效，用户需重新发码；无数据库迁移。

验证码默认 6 位、300 秒、最多 5 次错误；60 秒冷却、每邮箱用途每小时 5 次、来源 IP 每小时 30 次，按配置调整。Redis 控制最新挑战和尝试，SQL AuthProof 唯一消费与版本校验防重放。刷新旧摘要保留到到期，proof 仅在 Redis 挑战消失后清理，错误和日志不含秘密。

## 会话、资料与资源边界

普通退出按本标签签名 Bearer 的 sid 撤销，仅注销允许 access 过期，仅清同 sid Cookie；无效 Bearer 不清共享 Cookie。改密、恢复、邮箱绑定/换绑/解绑清目标用户 Cookie，并与登录、刷新、退出共用 Web Lock，避免延迟响应覆盖另一账号 Cookie。需要续期先在锁外完成，锁内不重放安全写操作。失效通知按用户或会话定向；身份约束、会话代次与下载检查防旧响应回填。退出网络失败保留原页面内存撤销凭据和重载恢复阻断意图，不宣称服务端撤销成功。

普通资料接口不改邮箱、学工号、身份或密码。gender/phone 省略保留、null 清空；显示名空白拒绝、null 保留，school 空串清除、null 保留，保存等待服务端确认。学工号以当前密码维护，保留前导零、大小写敏感，仅为资料。头像仍限量读取，前端显示昵称首字。

个人中心和设置页共用 PersonalModelSettings；用户 Key/Token 省略/null 保留、空串清除，界面显式清除，仅测试已保存配置及其系统兜底，未保存输入时禁用测试。状态与掩码不证明默认配置可用。

- 题库仅教师可创建，创建者按 account 添加启用教师/学生，creator/editor/readonly 三档。管理员不参与教学授权；历史学生资源保留，转让仅给启用教师，原创建者降为 editor。
- 题库编号自助加入关闭，历史聊天重新校验成员资格，成员授权不公开他人题目、收藏、对话、作答或模型凭据。
- 学习空间采用 SP 加 96 位随机加入码，旧顺序码经既有迁移轮换；原资源外键不变，被移除成员不能凭码恢复。
- 试卷拥有者可访问自己的答案，其他学生仅已交卷且 allow_review=true 时取得答案与解析。

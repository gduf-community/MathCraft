# 个人中心与应用设置功能规格

- **状态**：已实现并完成本地验收（2026-10-26）；结果与验证边界见[实施记录](个人中心与应用设置实施记录.md)。
- **日期**：2026-10-26。
- **产品**：MathCraft，当前单租户教师端。
- **依据**：已确认的需求对齐与《个人中心与模型配置页面设计》。不重新访谈，不扩大已确认范围。
- **交付形式**：本地 Markdown；不发布 GitHub Issue，不初始化工单跟踪器或标签。
- **阶段边界**：规格阶段已结束；本轮按用户明确调用进入实施，使用本地任务记录与集成分支，不发布远端工单或 PR。

## Problem Statement

教师需要在 MathCraft 中维护自己的基本资料，并实际配置出题、辅助任务、嵌入、知识库引擎与文档解析能力。当前个人中心和学习空间仍为占位，前端缺少与现有后端设置能力对应的完整可操作页面；如果把系统级模型与引擎配置混入个人中心，会让个人资料与应用配置的职责不清。

后端各类设置的生效边界不同：模型有独立草稿与正式应用，引擎配置和解析配置单独保存，安装与模型下载是独立任务。页面若只展示介绍卡片、统一一个“保存全部”按钮，或把连接测试成功表述为推理成功，就会误导使用者。

教师还需要知道配置变更对后续出题、解析、检索和已有索引的实际影响，避免因默认模型切换、依赖缺失或错误的成功提示而误判系统可用性。个人资料必须真正持久化，但不能以此次改动为由恢复多用户认证或学生端能力。

## Solution

### 入口与页面范围

| 入口 | 页面内容 | 本期交付 |
| --- | --- | --- |
| 左侧主导航底部「设置」 | 模型与服务、知识库引擎、文档解析 | 新增真实配置页面；默认进入「模型与服务 → 主语言模型」 |
| 现有个人中心入口 | 头像、昵称、教师身份、任教学段、年级 | 教师身份只读，其余可编辑；独立保存及头像持久化 |
| 知识库／题库中的「配置引擎」 | 前往设置中的对应引擎配置 | 保留快捷入口；建库时选择本次使用的引擎 |
| 学习空间 | 学生查看教师发布内容及做题的未来入口 | 仅保留现有导航和明确的演示／未开放说明，不开发学生端前端 |
| 现有组卷页面 | 现有组卷结构、数据和占位流程 | 保留；不能把占位发布反馈表述为学生已收到或可以作答 |

模型与服务只包含「提供方与连接管理」「主语言模型」「辅助任务模型」「嵌入模型」。辅助任务模型明确提供「跟随主模型」，不扩展搜索、语音、图片或视频设置。

### 保存与生效概览

| 区域 | 操作 | 成功的含义 | 不意味着 |
| --- | --- | --- | --- |
| 模型与服务 | 保存草稿 | 草稿持久化，正式目录不变 | 正式模型已经切换 |
| 模型与服务 | 应用更改 | 已保存草稿的模型目录正式生效，并清除草稿 | 引擎、解析器或个人资料同时应用 |
| 模型与服务 | 丢弃草稿 | 删除草稿并回到正式配置 | 删除正式目录或清空正式凭据 |
| 知识库引擎 | 保存配置／预检或专用连接测试 | 配置已保存／该次检查成功，分别反馈 | 依赖必然齐全、索引迁移或全局默认引擎已切换 |
| 文档解析 | 保存配置 | 后续解析使用已保存配置 | 自动重新解析已有文档 |
| 安装／模型下载 | 开始／查看状态／取消 | 当前任务的真实状态 | 持久化任务历史、跨重启续传或取消后回滚 |
| 个人中心 | 保存资料 | 资料及已确认头像可读回、刷新和服务重启后保留 | 新建账号、角色切换或模型配置变更 |

### 交付判定

功能完成以真实后端往返、外部行为验收及页面操作验证为准，不以页面渲染、按钮出现、HTTP 200 或静态演示截图单独作为完成依据。详细验收见 Testing Decisions。

## User Stories

1. 作为教师，我希望在左侧主导航底部找到独立的设置入口，以便不必进入个人中心寻找系统配置。
2. 作为教师，我希望首次进入设置时默认打开主语言模型，以便先配置出题所需的核心能力。
3. 作为教师，我希望在模型与服务、知识库引擎、文档解析之间清晰切换，以便理解各类配置的职责。
4. 作为教师，我希望设置页面延续现有蓝白配色和卡片布局，以便不需要适应另一套界面。
5. 作为教师，我希望窄屏上仍能阅读表单和操作保存按钮，以便正常完成配置。
6. 作为教师，我希望查看并维护后端支持的提供方和共享连接，以便复用连接而不是重复填写。
7. 作为教师，我希望编辑提供方支持的连接字段并看到字段错误，以便修正配置而不是依赖通用失败提示。
8. 作为教师，我希望凭据脱敏展示，未改动的凭据保存后保持原值，以便不会因保存掩码而破坏连接。
9. 作为教师，我希望单独测试连接并了解测试范围，以便不把模型发现接口可达误认为推理或嵌入成功。
10. 作为教师，我希望在支持的语言模型用途上获取可用模型列表，并在后端允许时填写模型标识，以便不受不完整的发现结果限制。
11. 作为教师，我希望配置并选择主语言模型，以便后续出题使用正式生效的配置。
12. 作为教师，我希望辅助任务模型明显提供“跟随主模型”选项，以便无需重复维护同一模型。
13. 作为教师，我希望辅助任务模型也能按现有引用或独立配置方式选择模型，以便在需要时使用不同的任务能力。
14. 作为教师，我希望配置嵌入模型及其支持的维度信息，以便满足知识库索引的实际要求。
15. 作为教师，我希望页面未展示的既有服务配置在编辑后保持不变，以便本期界面范围不会破坏其他配置。
16. 作为教师，我希望保存模型草稿而不影响当前正式配置，以便安全地准备变更。
17. 作为教师，我希望刷新或再次打开页面能恢复已保存草稿，以便继续编辑尚未应用的配置。
18. 作为教师，我希望看到未保存编辑、已保存草稿与正式生效的区别，以便知道当前操作是否已影响运行时。
19. 作为教师，我希望应用已保存的模型草稿并看到真实结果，以便确认正式配置已经更新。
20. 作为教师，我希望丢弃模型草稿后正式配置不变，以便撤销尚未生效的编辑。
21. 作为教师，我希望应用失败后保留可恢复的草稿和错误说明，以便修正后重试。
22. 作为教师，我希望离开存在未保存修改的页面时得到提醒，以便不会意外丢失编辑。
23. 作为教师，我希望查看知识库引擎的实际可用性及配置详情，以便区分未配置、缺依赖与连接失败。
24. 作为教师，我希望按引擎实际支持的字段编辑和保存参数，以便配置不是仅供浏览的介绍卡片。
25. 作为教师，我希望独立执行通用引擎预检或专用服务连接测试，以便在使用前了解实际问题。
26. 作为教师，我希望在知识库或题库通过快捷入口进入对应引擎设置，以便不必重新寻找配置页面。
27. 作为教师，我希望建库时选择本次使用的引擎，以便为不同知识库使用适合的后端能力。
28. 作为教师，我希望已有就绪索引的知识库更换引擎时看到真实限制，以便不会误以为系统已完成迁移。
29. 作为教师，我希望选择后端支持的文档解析器并维护参数，以便后续文档采用适合的解析方式。
30. 作为教师，我希望仅对后端确实支持的解析器发起安装或模型下载，以便不会遇到没有实际能力的按钮。
31. 作为教师，我希望看到安装或下载的进度、日志及失败原因，以便判断是否需要重试或人工处理。
32. 作为教师，我希望在同一后端进程内刷新或切页后继续查看当前任务，以便不因页面离开而丢失观察入口。
33. 作为教师，我希望可以取消后端支持取消的当前任务，并了解已完成内容不会回滚，以便做出正确操作。
34. 作为教师，我希望知道扫描 PDF 仍可能使用 MinerU Cloud OCR，以便不会把本地解析器选择误解为所有处理都在本地完成。
35. 作为教师，我希望在个人中心看到头像、昵称、教师身份、任教学段、年级，以便维护必要的个人资料。
36. 作为教师，我希望教师身份只读，以便不会把资料编辑误认为账号角色管理。
37. 作为教师，我希望修改昵称、任教学段与年级并单独保存，以便资料编辑不影响模型或知识库设置。
38. 作为教师，我希望上传并预览头像，保存后可再次读取，以便头像不依赖临时浏览器地址。
39. 作为教师，我希望资料和头像在页面刷新及服务重启后仍然保留，以便不必重复填写。
40. 作为教师，我希望资料保存失败时保留原资料且不上传头像；头像上传失败时保留已成功的新资料、旧头像及待重试选择，并看到分别反馈的原因，以便可以安全重试。
41. 作为教师，我希望在嵌入配置变更可能影响现有绑定时看到准确的风险说明，以便知道何时需要到知识库页面重建。
42. 作为教师，我希望仅更换凭据时不会收到不必要的嵌入重建要求，以便正常维护访问凭据。
43. 作为教师，我希望“跟随主模型”会使用当前正式主语言模型，以便辅助任务不会停留在旧模型的复制配置上。
44. 作为教师，我希望学习空间和组卷占位明确标识未开放边界，以便不会向学生承诺尚不存在的接收与作答功能。
45. 作为维护者，我希望此次改动保留正式知识库唯一入口与单租户边界，以便不会重新引入旧的并行链路或多用户系统。
46. 作为维护者，我希望新资料能力和任何真实接口变化同步类型、契约与文档，以便前后端具有一致的可验证行为。

## Implementation Decisions

### 1. 模块边界与导航

- 延伸当前 React 应用外壳、导航机制、API 适配层与公共状态，不另建独立风格的管理后台。
- 设置中心负责应用级配置；个人中心仅负责单租户教师的个人资料。保留教师／学生的领域概念，但本期不开放学生入口、登录、角色切换或成员权限。
- 默认设置页是「模型与服务 → 主语言模型」。知识库／题库的配置引擎快捷入口可定位对应引擎详情，不更改知识库绑定。
- 继续遵守正式知识库作为唯一知识库入口的架构决定；不恢复旧轻量知识库接口或另一套模型、索引事实来源。
- 模型配置、引擎配置、解析配置、个人资料、安装下载任务具有各自独立的保存及状态边界，不提供跨区域原子应用。

### 2. 模型目录、提供方与共享连接

- 领域上区分提供方、连接、服务 Profile、模型与活动选择；共享连接引用与后端既有语义一致，不将连接与模型混为一个只能整体覆盖的表单对象。
- 界面命名固定为「主语言模型」「辅助任务模型」「嵌入模型」；主语言模型对应 llm，辅助任务模型对应 task，嵌入模型使用现有后端模型用途和字段，不创建第四种用途。
- 辅助任务模型显著提供「跟随主模型」并可查看当前解析结果；保留 inherit、reference、profiles 的现有含义，不把继承实现为复制主模型参数。
- 继承在运行时解析当前正式主语言模型。正式主模型改变后，继承任务随之改变；独立任务配置不被无意重置。
- 嵌入模型保留后端支持的模型标识、连接、维度及其他现有配置字段。模型列表发现不是嵌入实测，也不能承诺所有提供方都支持自动发现。
- 对未展示用途及额外字段实行无损读改写，保留目录中的连接、服务、Profile、模型、引用和活动选择；不得按本期可见字段重新构造并覆盖整个正式目录。
- 凭据为密码输入并按后端规则脱敏；读取掩码不等于获得明文，也不允许以脱敏内容覆盖原值。新增或更改凭据只传给相应后端能力，不写入日志、静态资源或浏览器长期明文缓存。
- 删除被引用连接或模型时尊重现有验证约束；显示可识别的引用或后端错误，不生成悬空引用、不静默清空选择。

### 3. 草稿、应用与连接测试契约

| 现有 API | 规格要求 |
| --- | --- |
| GET /api/settings；GET /api/settings/catalog | 读取正式配置；以脱敏结果和既有结构建立编辑基线 |
| GET /api/settings/draft | 独立加载已保存草稿；无草稿不是请求失败 |
| PUT /api/settings/draft | 只保存模型草稿，不修改正式配置 |
| DELETE /api/settings/draft | 只删除草稿，恢复正式配置视图 |
| POST /api/settings/apply，无请求体 | 首版优先应用已保存草稿中的 catalog，成功后清空草稿 |
| POST /api/settings/apply，携带 catalog | 保留已有接口；掩码凭据从正式配置恢复，不要求首版另建一条应用流程 |
| PUT /api/settings/catalog | 直接修改正式目录；不能作为「保存草稿」的实现 |
| POST /api/settings/test-provider | 只证明该次模型发现连接测试覆盖的能力，不标记推理或嵌入成功 |
| POST /api/settings/fetch-models | 使用现有 llm/task 能力；掩码凭据恢复基于正式 Profile，不等同于任意草稿测试 |

- 页面分别维护正式基线、已保存草稿、未保存编辑、请求进行中及失败状态。进入时优先恢复已保存草稿，并始终可辨认其未正式生效。
- 「保存草稿」成功才更新草稿基线；「应用更改」针对已保存草稿。存在未保存编辑时先提示保存，不悄悄应用旧草稿并声称页面内容全部生效。
- 应用成功后重新读取正式配置并核实草稿已清空；失败时不显示成功，不丢弃可恢复的编辑。后端错误若涉及部分副作用，不假称跨服务事务已经回滚，需重新读取真实状态。
- 丢弃操作明确告知会移除草稿及当前未保存编辑；不删除正式模型、连接或凭据。无草稿时不伪造删除结果。
- 草稿 extensions 仅为不透明页面状态；apply 只应用 catalog，不包含引擎、解析器或个人资料。成功后清空整份草稿，包括 extensions；无草稿 catalog 时，现有后端会重新应用正式 catalog，而不是必然拒绝。页面无可应用草稿时不诱导执行无意义的应用操作。
- 草稿中的新增连接或改动凭据如需模型发现，使用既有接口真实支持的请求字段；不能仅靠正式 Profile 的掩码恢复去测试另一套草稿凭据。能力不满足时明确说明，而不是假装已验证。
- 同一区域提交期间阻止重复操作；离开未保存编辑时提醒。已保存草稿不与未保存编辑混为一谈，也不阻止其他独立区域正常保存。

### 4. 知识库引擎配置

- 提供引擎列表与真实详情表单。通用配置按 LlamaIndex、PageIndex、IMA、GraphRAG、LightRAG、LightRAG Server 六类组织。PageIndex 包含 Cloud（pageindex）与 OSS（pageindex-oss）两个目录项，分别使用其实际字段和能力，不把云服务配置套给本地模式。目录使用 GET /api/knowledge-bases/rag-providers 的实际结果，不能将六类分组误解为只有六个 provider。
- WeKnora 与 Kiwix 均采用各自专用 probe/connect 行为，均不调用通用 preflight。WeKnora 在 provider 目录中，Kiwix 不在该目录中；不能据此将二者视为同一种配置能力。WeKnora 的 POST /api/knowledge-bases/probe-weknora 用于检查，POST /api/knowledge-bases/connect-weknora 用于注册／连接远端知识库供检索，二者都不是全局引擎配置保存。设置中的连接测试不隐式 connect；连接知识库沿用已有知识库工作流。
- 单独区分已配置、依赖可用、连接可达与预检结果。configured 不能作为依赖、权限或服务正常的证明；未检查不能标记为已就绪。
- 详情修改独立保存，预检独立执行；预检操作是否包含配置写入以其现有契约为准，页面必须告知，不以模型草稿包装这些行为。
- 检索参数用于后续查询；索引参数影响后续处理或重建，不自动重写已处理文档。显示后续生效范围，不承诺无重建迁移。
- 当前全局默认引擎保持 LlamaIndex。本期不引入不存在的全局切换 API；建库选择是该知识库的引擎选择，不是修改全局默认。
- 已有就绪索引时更换绑定引擎，展示后端实际 409 冲突及说明；不自动删除旧索引、复制数据或实施跨引擎迁移。
- 可选依赖继续惰性加载，缺失时报告 unavailable 或真实错误，不允许因打开设置页面导致应用无法启动。

### 5. 文档解析与后台任务

| 能力 | 支持范围与边界 |
| --- | --- |
| 解析器选择 | text_only、mineru、docling、markitdown、pymupdf4llm、liteparse、tika |
| 一键安装 | 仅 Docling、MarkItDown、PyMuPDF4LLM、LiteParse 的已有后端安装能力 |
| 模型下载 | 仅现有 Docling、MinerU 下载能力 |
| 引擎安装 | 不提供通用知识库引擎一键安装 |
| 通用任务状态 | GET /api/settings/document-parsing/job/status?cursor=0，覆盖现有通用安装与 Docling 下载单例 |
| MinerU 下载状态 | GET /api/settings/mineru/models/download/status?cursor=0，独立单例 |

- 解析配置直接保存，后续解析读取；不写入模型草稿，不通过模型 apply 生效，不自动重解析现有资料。
- 安装和下载是独立操作，明确展示进行中、完成、失败、取消、当前日志及后端实际提供的进度；后端没有可靠百分比时只展示阶段，不编造进度。
- 状态为后端进程内单例，没有任务 ID、历史列表或持久化调度；并发开始的处理方式尊重后端当前契约，不能将互斥任务伪装为队列。
- 同一后端进程内刷新或切页后可重新获取当前任务并继续 cursor 轮询；重复响应不重复追加日志。后端重启、游标失效或网络中断时重新对齐真实状态，不永久显示旧任务进行中。
- 通用任务与 MinerU 下载分别观察和取消；取消针对当前子进程，不接收虚构的任务 ID，不承诺回滚已经安装或下载的内容。
- 保留扫描 PDF 当前 MinerU Cloud OCR 策略及数据可能发往云端的说明；选择某个本地解析器不代表所有处理都转为本地。

### 6. 个人资料数据与头像

| 用户可见字段 | 语义 | 编辑边界 |
| --- | --- | --- |
| 头像 | 当前教师的持久化头像资源 | 可上传、预览并随资料保存确认；临时预览不等于保存成功 |
| 昵称 | 个人展示名称 | 可编辑，验证必填与长度等明确规则 |
| 教师身份 | 当前开放身份的展示 | 只读；不能通过资料请求变更身份 |
| 任教学段 | 教师当前教学阶段 | 可编辑，优先使用已有领域枚举 |
| 年级 | 教师当前任教年级 | 可编辑，与任教学段组合合法，不新增班级或学科字段 |

- 独立资料服务已提供 GET／PUT /api/user-profile 和 POST／GET /api/user-profile/avatar，并同步前后端类型、OpenAPI 与 API 文档。头像在前端选择后仅本地预览，点击「保存资料」后先保存资料、成功后再提交待确认头像；各请求分别反馈真实结果。
- 请求和响应的业务字段仅服务于上述五项；内部资源标识不展示为额外资料项，不引入账号 ID 选择、多用户目录或成员关系。
- 教师身份由服务端确定且不可由客户端修改。旧数据缺少学段或年级时可呈现未填写，不伪造教师姓名、任教信息或账号资料。
- 资料与头像使用独立持久化，不借用模型 catalog、draft 或 extensions；既有 /api/settings/profile 是配置导出，不可改解释为个人资料接口。
- 头像只允许后端明确支持并校验的安全位图格式，校验内容、大小与类型；拒绝伪装扩展名、路径穿越与可执行内容。资源路径由服务端生成，禁止客户端指定任意磁盘路径。
- 资料保存失败不提交待确认头像；头像上传失败保留旧头像和可重试选择。资料先保存成功而头像随后失败时，明确报告两项结果，不声称跨请求原子回滚。未确认的本地预览可以放弃，不能被当作资料已保存。
- 头像地址必须可由后端稳定读取，不以 blob URL 或浏览器内存作为最终存储。页面刷新和服务进程重启后资料及头像仍可访问。
- 保存资料不修改模型、引擎、解析配置或认证体系；头像与资料同样不能向日志和导出泄露非必要个人信息。

### 7. 配置影响与风险确认

| 变更 | 页面应说明的实际影响 |
| --- | --- |
| 主语言模型变化 | 影响后续按正式配置解析的调用；对已有知识库的影响取决于引擎与绑定策略，不作一刀切承诺 |
| 辅助任务模型使用 inherit | 运行时跟随当前正式 llm，不复制旧参数，不因此触发嵌入重建 |
| 切换全局默认嵌入模型 | 不遍历重建所有旧库；本地 LlamaIndex／GraphRAG／LightRAG 通常保留既有绑定，但有 legacy 分支 |
| 修改已绑定嵌入模型的名称、维度、endpoint 等身份属性 | 可能触发 changed／needs_reindex 或不可用；应用前提示绑定风险并要求确认 |
| 删除已绑定嵌入模型 | 可能阻断原库使用；尊重后端约束，明确风险，不能静默替换 |
| 仅更换 API Key | 凭据不是嵌入签名，不能仅因该变更要求重建索引 |
| 引擎检索／索引参数变化 | 分别影响后续查询／处理或重建，不追溯改写已有内容 |
| 解析参数变化 | 影响后续解析，不自动重新解析现有文档 |

不能可靠枚举全部受影响库时，应说明范围无法完全确定，不展示伪精确数量。风险确认与真实后端校验都不能省略；重建留在知识库页面处理，设置页不自动启动重建、迁移或删除数据。

### 8. 页面状态、视觉与兼容

- 沿用当前蓝白体系：背景 #f3f6fb、主色 #1e6fff、白色圆角卡片、细边框、轻阴影、线性图标、浅蓝选中态；复用已有字体、间距与组件，不以本规格重新设计整站。
- 设置页采用分区导航和表单内容区，必要时折叠次级参数；关键保存动作和当前编辑范围始终可辨认。窄屏允许导航收拢或纵向排布，不挤压输入控件。
- 对加载、未配置、不可用、编辑中、已保存草稿、正式生效、提交中和失败分别反馈；保存／测试／应用按钮对应自己的结果，不共用一个“全部成功”状态。
- 表单有可访问标签、可见键盘焦点、行内错误说明；颜色不是唯一状态信号。失败保留输入并支持重试，不静默回退为空目录或默认成功状态。
- 学习空间不扩展新前端流程；保留现有入口，显示演示／未开放边界。组卷仍保留既有 UI、结构和占位流程，但不使用会让人误解为真实发布成功的反馈。

## Testing Decisions

### 验收边界与执行原则

以下是依据现有架构整理的实施建议，不将其表述为用户逐项另行确认的测试方案，也不再为此阻塞本地规格交付。

- **主要 seam**：现有 TestClient → 真实 HTTP／ASGI 路由 → 后续 GET 或实际业务操作。优先通过一个高层外部行为边界验证持久化与生效，不以内部类方法调用次数替代验收。
- **必要补充**：辅助任务运行时继承、知识库绑定和重建限制由现有出题／知识库外部行为覆盖；只有 HTTP 边界无法表达的风险才增加最小内部验证边界。
- **隔离**：设置根、资料和头像目录使用临时隔离数据；模型与嵌入使用本地假服务、假凭据，不访问真实账号、生产配置或真实第三方服务。
- **任务替身**：安装／下载使用假子进程或任务替身，不实际安装依赖、下载模型或访问云端；测试验证开始／状态／取消的外部契约，不测试线程或实现细节。
- **前端**：执行类型检查、生产构建和关键交互验收；复用已有测试框架，不为纯样式、静态标签和可逆布局编写与实现同构的低价值测试。
- **运行范围**：实施触及设置写入、索引或解析核心路径后，按仓库要求完成后端全套测试；检查通过后仅因新增变更、失败或未解决风险扩大测试。实施验收结果见实施记录。

### 行为验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 | 导航与默认页 | 独立设置入口位于主导航底部；默认主语言模型；个人中心没有系统配置混入 |
| AC-02 | 提供方、连接、目录往返 | 支持字段正确保存；共享引用有效；未展示用途与未知既有字段不丢失；读取不泄露明文凭据 |
| AC-03 | 草稿隔离与恢复 | 保存草稿后正式 GET 与运行调用仍保持原配置；重新加载可恢复已保存草稿 |
| AC-04 | 应用与丢弃 | 应用已保存草稿后正式 GET 及后续调用体现新配置，草稿消失；丢弃仅删除草稿；未保存编辑不能被误报已应用 |
| AC-05 | 失败与凭据 | 保存／应用失败不报成功，可恢复输入；未改掩码不覆盖真实值；更改草稿凭据的测试不误用旧正式凭据 |
| AC-06 | 辅助任务模式 | inherit 随正式 llm 改变；reference／profiles 保持现有语义；独立配置不会被错误覆盖 |
| AC-07 | 连接与模型发现 | 成功文案只声明实际覆盖能力；发现失败可纠正或重试；不声称完成真实推理／嵌入验证 |
| AC-08 | 引擎配置与专用检查 | 六类引擎按实际后端能力展示，支持写入的配置按字段往返；PageIndex Cloud／OSS 分别映射，OSS 无配置写 API，仅展示说明和检查，不计作配置保存成功；WeKnora／Kiwix 使用专用检查而非通用预检，测试不隐式注册知识库；缺依赖和失败真实呈现 |
| AC-09 | 引擎绑定限制 | 建库的引擎选择不改全局默认；已有就绪索引换引擎返回真实 409；不启动隐式迁移或删除 |
| AC-10 | 解析配置 | 七种解析器及支持参数能读写；仅影响后续解析；不能因保存而意外安装、下载或重解析 |
| AC-11 | 任务状态与取消 | 仅支持能力有入口；使用假任务验证 start/status/cancel；cursor 日志无重复；同进程刷新恢复当前观察；重启不伪称恢复历史 |
| AC-12 | 个人资料持久化 | 仅五项资料；身份不可写；资料更新后 GET 可读回；刷新及重新创建服务实例后仍保留，其他设置不变 |
| AC-13 | 头像可靠性与安全 | 上传、保存、再次获取有效；服务重启后仍可读；非法格式、超限或恶意路径被拒绝；失败保留旧头像 |
| AC-14 | 嵌入变更风险 | 默认切换不自动重建所有库；有绑定的身份属性变更准确提示；仅换 Key 不触发重建；风险确认后仍执行真实后端验证 |
| AC-15 | 未保存与独立保存 | 离开编辑有提醒；提交期间防重复；模型、引擎、解析、资料的保存与结果互不冒用 |
| AC-16 | 学习空间与组卷 | 不新增学生前端或真实发布闭环；既有流程保留；占位反馈明确演示／未开放 |
| AC-17 | 视觉与可访问性 | 与现有蓝白风格一致；桌面和窄屏表单可用；键盘可达、焦点清晰、错误可定位 |
| AC-18 | 契约、类型与回归 | 实际新增或修改的接口与 OpenAPI／API 文档／前后端类型一致；要求的测试、类型检查与构建通过 |

### 可复用的测试先例与已知缺口

- 现有设置草稿、设置写入、HTTP 契约、文档解析和引擎配置测试，以及隔离设置根和本地假嵌入服务，可作为外部行为测试先例。
- 现有 apply 用例仅断言成功状态码时，不足以证明草稿真的应用或运行调用已切换；必须补正式 GET、草稿状态与业务行为断言。
- 引擎配置用例遇 400／422 而跳过时，不能计作成功配置往返；应提供满足前置条件的假服务与有效参数，成功和拒绝分别验证。
- 安装下载当前没有现成 fake job manager；实施时补最小任务替身，不据此扩建持久化任务系统。
- 页面状态验证覆盖首次进入、已有草稿、空配置、失败、提交中、离开提醒和刷新恢复，不以快照或仅测试组件内部状态代替关键操作验收。

## Out of Scope

- 学习空间学生端前端、教师发布—学生接收—作答闭环，以及课程、班级、作业、成绩功能。
- 新增个人资料字段、出题偏好、成员管理、角色切换、多人认证、权限系统或多租户恢复。
- 扩展到搜索、语音、图像、视频等模型服务；上游 DeepTutor 未在本规格列出的全部能力。
- 重做现有组卷 UI、改变组卷数据结构，或把占位操作接成真实发布服务。
- 跨区域统一草稿或原子 apply、任务队列、任务 ID、持久化历史、后端重启后任务续传。
- 全局默认引擎切换、跨引擎迁移、配置页自动重建所有知识库、自动重解析旧文档。
- 新增后端尚未支持的解析器安装器、任意知识库引擎一键安装，或承诺扫描 PDF 全程本地运行。
- 重构既有大型路由、恢复废弃知识库链路、引入与本期能力无关的新依赖或设计体系。
- 修改 AGENTS.md、自动初始化远端工单或发布 Issue、PR；规格阶段不主动实施的限制已由本轮用户手动调用 implement-spec 解除。

## 最小台账接点

查询服务只读取 `app.db.Base.registry` 中已注册、表名为 `ops_runs` 的正式 ORM 映射。
模型应由甲按现有 `app/models/__init__.py` 机制加载，`run_id` 必须是唯一主键。
ORM 列类型须提供相应的字符串、整数、datetime Python 类型；将时间或数量误存为字符串时拒绝查询，避免产生看似有效的空结果。
不反射数据库、不自动建表、不从 GenerationBatch、Redis、Phoenix 或演示数据补齐记录。
若甲交付的正式模型不满足以下列契约，应先协调差异，不新增第二套表绕过。

| 字段 | 查询契约 | 来源与语义 |
| --- | --- | --- |
| `run_id` | 非空标识 | 甲生成、稳定不变；需要时复用追踪上下文 ID |
| `entrypoint` | `parameterized` / `conversation` | 两类实际出题入口，不以普通聊天消息替代出题运行 |
| `owner_user_id` | 非空标识 | 甲记录受理账号；查询不关联或披露个人配置 |
| `session_id`, `task_id` | 标识或 null | 分别保留会话、异步任务关联，不混用 |
| `bank_id`, `document_id`, `batch_id` | 标识或 null | 当时能确认的关联；没有证据保留 null |
| `status` | `accepted`, `running`, `completed`, `failed`, `canceled`, `unknown` | 只读甲的事实；Redis 过期不推断 failed |
| `requested_count` | 正整数或 null | 已知请求数量；未知不转成 0 |
| `delivered_count` | 非负整数或 null | 甲保存的历史交付快照；不重算现存题目 |
| `error_code` | 安全分类或 null | 不允许原始异常文本；查询再做白名单收口 |
| `accepted_at` | 必填 UTC 时间 | 受理时间，所有时间筛选的唯一基准 |
| `started_at`, `finished_at`, `last_observed_at` | UTC 时间或 null | 未发生或未确认保留 null，不用 generated_at 补值 |

`completed` 表示批次已成功保存，不等同于函数返回、HTTP 200、题目数学质量或数量达标。
查询不会补写终态、心跳、结束时间或丢失的关联。未识别的状态值属于契约错误，返回 503；
有效的 `unknown` 单独计数，不归入成功或失败。

标识按不透明值处理，边界允许 1–128 个英文字母、数字、`_ . : -`，无前缀强制要求。
当前展示允许的非空错误分类为 `MODEL_CALL_FAILED`、`TOOL_FAILED`、`DEPENDENCY_FAILED`、
`PERSIST_FAILED`、`USER_CANCELED`、`INTERNAL_ERROR`、`UNKNOWN`。其他非空值一律显示 `UNKNOWN`；
这是防止正文泄露的输出规则，不是要求甲恢复旧版错误字段。甲提供其他安全分类时应显式评审映射。

## HTTP 与查询语义

全部路由复用 `require_admin` 的现有账号、会话、撤销和角色检查。成功响应及业务错误禁用缓存。
生成时间使用单次请求的 UTC 时钟；SQLite 无时区返回值按台账必须存储 UTC 的约定解释。

| 方法与路径 | 成功结构 |
| --- | --- |
| `GET /api/admin/ops/overview` | `schema_version, generated_at, window, total_runs, status_counts, recent_runs` |
| `GET /api/admin/ops/runs` | `schema_version, generated_at, window, items, page` |
| `GET /api/admin/ops/runs/{run_id}` | `schema_version, generated_at, run` |

- `schema_version` 固定 `v2`；时间以带时区 ISO 8601 返回，规范化到 UTC。
- 概览与列表共用 `from`、`to`、`owner_user_id`、`entrypoint`、`status`、`session_id`、`task_id`、`batch_id`。
- 时间输入必须带时区。`to` 默认当前时间；`from` 默认已解析 `to` 前 24 小时。
  区间为 `accepted_at >= from AND accepted_at < to`，必须 `from < to`。
  `window` 返回实际生效的 `from`、`to`、`time_basis: accepted_at`。
- 其他筛选均为精确匹配，组合使用 AND。查询使用绑定参数，不拼接用户 SQL。
- 列表 `limit` 默认 20，范围 1–100；`offset` 默认 0，范围 0–2147483647。
  按 `accepted_at DESC, run_id DESC` 稳定排序，读取 `limit + 1` 判断 `has_more`。
  `page` 为 `{limit, offset, has_more}`，没有 cursor、令牌或跨请求冻结快照。
  并发新增/状态改变可能移动 offset 页边界；前端换筛选时从 offset 0 重新查询。
- 概览与列表使用同一条件。概览单条 SQL 返回六状态计数及最近 10 条记录，避免分开读取引起的计数漂移。
  空的有效台账返回 0 与空数组；无法读取不能显示成空数据。总数只代表已记录行，不宣称历史采集完整。
- 详情不套用默认 24 小时窗口。三处运行对象共享 `OpsRun`，没有正文、质量、追踪链接或配置字段。

统一错误为 `{"detail":{"code":"...","message":"..."}}`：

| HTTP | 错误 | 边界 |
| --- | --- | --- |
| 401 / 403 | 沿用认证错误 / `FORBIDDEN` | 在获取台账依赖前完成管理员鉴权 |
| 422 | `VALIDATION_ERROR` | 无效时间、标识、状态、分页或列表/概览额外参数；固定文案，不回显输入 |
| 404 | `OPS_RUN_NOT_FOUND` | 有效台账中没有该主键，不宣称记录已过期 |
| 503 | `OPS_DATA_UNAVAILABLE` | 台账模型/列缺失、表未部署、读取失败或不兼容行；固定文案 |

认证数据库自身失败仍沿用已有认证错误处理，不能假装是台账为空。

# 个人中心与模型配置页面设计

**状态**：已按[本地功能规格](个人中心与应用设置功能规格.md)实现；本地验收结果见[实施记录](个人中心与应用设置实施记录.md)。
**确认日期**：2026-10-26
**适用范围**：当前单租户教师端；学生端与学习空间前端延后开发。
**阶段约束**：用户已手动调用 implement-spec；本轮仅落实已确认范围，使用本地 Markdown 记录实施与验收。

## 目标

沿用 MathCraft 当前页面样式，补齐教师个人中心和真实可操作的应用设置页面。个人中心只管理个人资料；提供方、模型、知识库引擎与文档解析归属独立的设置中心。以本地 DeepTutor 的实际能力为参照，不把上游所有功能都视为本期移植承诺。

## 已确认的范围与导航

| 区域 | 内容与职责 | 本期边界 |
| --- | --- | --- |
| 设置入口 | 左侧主导航底部独立「设置」 | 默认打开「模型与服务 → 主语言模型」 |
| 模型与服务 | 提供方与连接管理、主语言模型、辅助任务模型、嵌入模型 | 只覆盖三种模型用途；不做搜索、语音、图像与视频生成设置 |
| 知识库引擎 | 引擎列表、详情参数、通用预检或专用服务连接测试 | 真实配置表单；知识库/题库保留「配置引擎」快捷入口，建库时选择本次引擎 |
| 文档解析 | 解析器选择、参数及后端已支持的安装、模型下载、进度与取消 | 不虚构未支持的安装器或下载操作 |
| 个人中心 | 头像、昵称、教师身份、任教学段、年级 | 概念兼容教师与学生，本期只向教师提供；教师身份只读，其余可编辑并独立持久化 |
| 学习空间 | 学生查看教师发布内容并做题的地方 | 保留导航和明确的演示/未开放提示，不开发学生端前端与发布接收作答闭环 |

个人中心不加入出题偏好、成员管理、成绩统计或其他资料字段。保留现有组卷界面、数据结构及占位流程；现有发布成功反馈不能被解释为学生已可接收或作答，必须说明演示/未开放边界。本期不恢复多用户认证、角色切换或成员权限。

## 视觉与交互基线

- 继承现有应用外壳和题库管理样式：蓝白配色、淡灰蓝背景（#f3f6fb）、蓝色主色（#1e6fff）、白色圆角面板、细边框、轻阴影、线性图标、浅蓝选中态。
- 设置使用清晰的分区导航与表单内容区；个人资料与应用配置不混放。窄屏保持表单可读、操作可达，避免横向挤压。
- 明确区分加载、未配置、不可用、编辑中、已保存草稿、正式生效与失败；显示真实错误，失败时保留可恢复的输入，不以静默回退或假成功代替。
- 未保存编辑离开时提醒；已保存草稿与尚未保存的页面编辑分开呈现。各区域独立保存，不提供伪装成统一原子提交的全局按钮。
- 凭据保持脱敏，不因读取或保存掩码而覆盖真实值；字段错误有对应说明，键盘焦点和操作反馈清晰。

## 设计时基线与上游参照

以下记录设计时的源码基线，保留作为方案依据；实施后的页面、资料端点和已执行验证见实施记录。

- MathCraft 已有 generate / preview / bank 实际页面；个人中心与学习空间是占位，尚无应用设置实际页面。学习空间类型仅含 ID/名称，适配器返回固定列表，不构成真实学生能力。
- 模型服务已有目录、独立草稿、应用与连接测试接口；个人资料没有对应的独立读写与头像上传接口，需要在实施阶段补充。
- DeepTutor 的模型与服务、文档解析在设置中心，知识库引擎配置在知识库模块内。本项目将三者集中到设置，是已确认的 MathCraft 设计选择，不是上游原样组织。
- 上游模型服务范围更广；MathCraft 仅采用本期确认的三种模型用途及提供方、连接管理。

功能参考：本地 DeepTutor 的 settings-pages、ProvidersWorkspace、ModelsWorkspace、SettingsToolbar、DocumentParsingSettingsSection、EngineDetail 和 CreateKbModal。具体支持边界以 MathCraft 后端为准。

## 核心流程与保存语义

### 模型与服务

1. 读取正式目录与已保存草稿，呈现草稿/正式配置差异；编辑提供方、共享连接、模型与活动选择。
2. 使用用户命名「主语言模型」「辅助任务模型」「嵌入模型」，分别对应现有 llm、task、embedding 用途。
3. 辅助任务模型明显提供「跟随主模型」；保持 inherit、reference、profiles 的既有语义，不创建与后端不一致的第四种模式。
4. 测试连接与获取模型列表是独立操作；测试通过只说明该测试验证的能力，不代表推理、嵌入或索引全部可用。
5. 「保存草稿」只保存草稿；「应用更改」应用已保存的模型目录，成功后清空草稿；「丢弃草稿」删除草稿，不修改正式配置。尚未保存的编辑不得被无提示遗漏。
6. 首版采用整份模型目录的草稿/应用流程，不额外引入局部应用交互；保留本期未展示服务的原有配置，不因页面只支持三种用途而删掉其他目录数据。

### 知识库引擎

- 进入引擎列表与详情，查看实际能力；支持配置写入的引擎可编辑参数并独立保存，预检另行执行。PageIndex OSS 无配置写 API，仅展示能力说明和检查，不参与配置保存成功验收。configured 不等于依赖完整或连接正常。
- 通用配置表单按 LlamaIndex、PageIndex、IMA、GraphRAG、LightRAG、LightRAG Server 六类组织；PageIndex 的 Cloud（pageindex）与 OSS（pageindex-oss）分别使用实际支持字段与能力；OSS 不提供配置保存表单，不将分类数量视为 provider 目录项数量。
- WeKnora、Kiwix 均使用专用 probe/connect 能力，均不能调用通用预检；Kiwix 不在 provider 目录中。WeKnora 的 probe 是连接检查，connect 是注册／连接远端知识库供检索，不是全局引擎配置保存；设置连接测试不隐式注册知识库。
- 检索参数保存后由后续查询读取；索引参数影响后续处理或重建，不追溯重写已处理文档。
- 当前全局默认引擎固定为 LlamaIndex，本期不新增全局默认引擎切换或跨引擎迁移。已有就绪索引的库更换绑定引擎时，显示后端真实 409 冲突。

### 文档解析

- 覆盖 text_only、mineru、docling、markitdown、pymupdf4llm、liteparse、tika 的选择与支持参数，配置保存直接写设置，后续解析读取，不自动重解析已有文档。
- 一键安装只开放已支持的 Docling、MarkItDown、PyMuPDF4LLM、LiteParse；模型下载仅开放后端已有的 Docling、MinerU 操作。知识库引擎没有通用一键安装能力。
- 安装/下载是独立任务操作，不进入模型草稿或统一 apply。通用安装/Docling 下载与 MinerU 下载各有进程内单例状态；没有任务 ID 或历史任务列表。
- 同一后端进程内切页或刷新可重新轮询当前状态；后端重启后不承诺恢复任务记录。取消针对当前子进程，不是按 ID 取消，也不回滚已安装或下载内容。
- 保留扫描 PDF 当前使用 MinerU Cloud OCR 的事实说明，不能宣称选择本地解析器后所有处理均在本地完成。

### 个人资料

- 独立读取资料、编辑头像/昵称/任教学段/年级，教师身份只读；使用「保存资料」提交并显示真实结果。
- 新增独立的后端资料读写与头像上传能力；页面刷新、服务重启后资料仍保留。头像存储不得仅依赖浏览器内存或临时预览地址。
- 不将资料塞入模型目录或模型草稿 extensions；不误用配置导出的 /api/settings/profile，也不恢复多用户认证。
- 已提供 /api/user-profile 与 /api/user-profile/avatar 契约，并同步 OpenAPI、API 文档及前后端类型。头像先本地预览，随「保存资料」确认；先保存资料，再上传头像，部分失败分别报告，不伪称原子回滚。

## 接口与数据契约

复用现有正式设置和知识库能力。参考[模型配置来源与普通知识库流程](模型配置来源与普通知识库流程.md)、[API 文档](../api.md)和[正式知识库 ADR](../adr/0001-正式知识库作为唯一知识库入口.md)。

| 现有接口 | 已核实语义与页面约束 |
| --- | --- |
| GET /api/settings、GET /api/settings/catalog | 读取正式配置，凭据脱敏 |
| GET /api/settings/draft | 读取独立草稿 |
| PUT /api/settings/draft | 保存草稿，不改变正式配置 |
| DELETE /api/settings/draft | 丢弃草稿 |
| POST /api/settings/apply（无请求体） | 应用已保存草稿中的 catalog，成功清空草稿，首版优先使用 |
| POST /api/settings/apply（携带 catalog） | 应用请求中的目录，掩码凭据按正式配置恢复 |
| PUT /api/settings/catalog | 直接写正式配置，不能当作保存草稿 |
| POST /api/settings/test-provider | 验证模型发现接口可达，不证明模型推理成功 |
| POST /api/settings/fetch-models | 支持 llm/task；掩码凭据从正式 Profile 恢复，与草稿连接测试行为不同 |
| /api/settings/document-parsing/job/status?cursor=0 | 通用安装/Docling 下载当前单例状态，不是任务历史查询 |
| /api/settings/mineru/models/download/status?cursor=0 | MinerU 下载当前单例状态，不是持久化任务查询 |

模型目录保留 connections、services/profiles/models、活动选择及共享连接引用。嵌入模型保留维度信息。草稿 extensions 只是 opaque 页面状态，apply 只应用 catalog 并清空整份草稿（包括 extensions）；无草稿 catalog 时会重新应用正式目录；不应用引擎、解析器、个人资料，不能借此实现跨区原子提交。身份类型存在 teacher/student 不意味着已实现相应账号体系。

代码依据：[设置路由](../../backend/math_q_agent/api/routers/settings.py)、[模型目录](../../backend/math_q_agent/services/config/model_catalog.py)、[身份路由](../../backend/math_q_agent/api/routers/auth.py)、[知识库路由](../../backend/math_q_agent/api/routers/knowledge.py)、[RAG 工厂](../../backend/math_q_agent/services/rag/factory.py)、[引擎预检](../../backend/math_q_agent/services/rag/preflight.py)、[解析器注册](../../backend/math_q_agent/services/parsing/engines/factory.py)。

## 配置影响与异常边界

- 「跟随主模型」在运行时解析为当前主语言模型；调整辅助任务模型不触发嵌入索引重建。
- 切换全局默认嵌入模型不会遍历或自动重建全部知识库；LlamaIndex、GraphRAG、LightRAG 本地库通常保存既有嵌入绑定，不自动跟随全局切换。历史库有 legacy 分支，不能宣称所有旧库都已固定绑定。
- 修改已绑定嵌入模型的名称、维度、endpoint 等身份属性可能导致 changed/needs_reindex；删除绑定可能阻断使用。API Key 不属于嵌入签名，不能仅因换密钥要求重建。
- 应用可能影响已有绑定/索引的变更前，明确说明影响并要求确认；无法可靠确定范围时不假称已精确识别所有受影响库。配置页不自动重建，重建在知识库页面处理。
- 主语言模型对旧库的影响依引擎与模型绑定策略而异；不概括为全部旧库立即跟随，也不概括为全部需要重建。
- 状态来源、测试范围、后端限制及失败原因必须真实；引擎预检、连接发现、保存、正式生效是不同结果。服务端失败时不显示已应用/已保存成功。
- 凭据不写入文档、静态页面、日志或测试；测试只使用假服务与假值，不访问真实账号。

嵌入绑定代码依据：[embedding_binding](../../backend/math_q_agent/services/rag/embedding_binding.py)、[embedding_signature](../../backend/math_q_agent/services/rag/embedding_signature.py)。

## 验收标准

1. 导航、默认页、个人中心和设置归属符合本方案；延续当前样式，不用介绍卡片替代实际配置表单。
2. 提供方/连接与三种模型用途可按后端能力维护，辅助任务模型「跟随主模型」可见且语义正确，未展示服务配置不丢失。
3. 草稿隔离、正式应用、丢弃和失败反馈正确；引擎、解析器及资料独立保存，不误报统一 apply。
4. 六类引擎表单、专用知识服务连接和七种解析器遵守真实能力；不虚构通用预检、安装、迁移或持久化任务历史。
5. 个人中心仅五项资料，教师身份只读，其余可编辑；头像上传与资料保存可读回，刷新及服务重启后保留，不引入多人认证。
6. 嵌入变更按实际绑定风险提示，不将全局默认切换等同于所有旧库必须重建；已有索引换引擎显示真实限制。
7. 学习空间与组卷发布占位明确说明演示/未开放，不被计入真实学生闭环交付。
8. 实施阶段同步设计、README、前后端类型与实际变更的 API 契约，不修改 AGENTS.md；只做文档时持续标明待实现。

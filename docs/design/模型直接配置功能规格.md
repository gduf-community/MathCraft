## Problem Statement

教师配置模型时需要先建立提供方连接，再创建模型并理解连接、Profile、模型和默认选择之间的关系。一个连接被多个模型共用时，修改地址或凭据可能同时改变其他模型，难以判断影响范围。配置名称又缺少明确的唯一性规则，选择模型时容易混淆。

教师希望直接维护语言模型、嵌入模型和任务模型，每个配置项包含完整信息，填写完成后一次保存即可生效。保留多个模型及明确的默认选择，同时避免保存某个模型时顺带应用其他未完成编辑。

模型发现目前存在失败反馈不清的问题。用户使用 DeepSeek 官方 API 时遇到 auth_error；代码将上游 401 和 403 都归入这一分类，前端又缺少对应中文说明。该请求的实际拒绝原因尚未复现确认，不能预先归因为密钥错误，也不能把获取列表失败当成模型推理一定不可用。

## Solution

### 三类直接配置

模型与服务只保留面向本轮用途的语言模型、嵌入模型、任务模型入口，默认进入语言模型。移除独立提供方连接管理入口和先建立连接的前置步骤；提供方仍是直接配置表单中的字段，用于决定适用参数和可编辑的合理默认值。

语言模型、嵌入模型继续采用可搜索的配置列表与详情表单。每个配置项独立维护提供方、地址、凭据、模型标识及适用参数；编辑配置 A 不改变配置 B，即使二者属于同一提供方。选中配置只切换编辑对象，设为默认为独立操作。

延续现有 MathCraft 的视觉、响应式布局、键盘可达性、加载与空态反馈。高级字段折叠，不用新视觉皮肤替代功能简化；本轮不影响知识库连接、引擎、解析器和个人中心。

### 名称与必要字段

统一使用“配置名称”称呼使用者起的名字，使用“模型标识”称呼提供方要求的调用标识。语言模型、嵌入模型及独立任务模型的配置名称全局唯一，区分大小写；同一模型标识可以出现在多个配置项中。

配置名称去除首尾输入空白后不能为空，唯一性比较保持大小写敏感；编辑时排除当前项本身。前后端遵守相同规则，不能通过其他写入入口创建冲突。内部稳定标识与可修改名称分离，改名不重建引用。

直接配置的必要信息如下：

| 信息 | 行为 |
| --- | --- |
| 配置名称 | 必填；全局唯一，区分大小写 |
| 提供方 | 必选；保留现有可用提供方及适配能力，不引入新的账号体系 |
| 服务地址 | 按提供方预填并允许修改；不能重复拼接 API 版本或模型列表路径 |
| 凭据 | 按提供方实际要求填写或保留既有授权；允许无鉴权的提供方不强制密钥 |
| 模型标识 | 启用前必填；允许手动输入，不要求先发现成功或必须存在于发现结果中 |
| 嵌入与高级参数 | 维度、上下文、协议、版本、请求头等按既有能力保留；不新增全局强制探测 |

### 最少操作流程

已知模型标识：添加模型 → 同一表单填写必要信息 → 保存并启用。用户只需一次保存，不再分别执行保存草稿与应用更改。

未知模型标识：填写提供方、地址、凭据 → 点击“获取模型列表” → 选择结果或在失败后手动填写模型标识 → 补齐配置名称 → 保存并启用。获取模型列表使用当前表单，不要求先保存。保存不会自动获取列表，也不会自动执行推理或嵌入。

每类第一个配置保存成功后自动成为该类默认配置；后续新增保留既有默认。任务模型初始跟随主语言模型；独立任务配置的默认选择只有在独立模式下参与调用，不得仅因保存一个备用配置就切换任务模式。

### 任务模型

只展示“跟随主模型”和“独立配置”。跟随始终解析当前主语言模型，不复制某次主模型快照；它不产生额外命名配置。独立配置使用直接表单，保留已有独立任务配置及高级参数。切换到跟随模式不删除独立配置，便于恢复。

旧的“引用指定主模型”模式不再作为新建入口；迁移时以原来引用的具体模型为依据，展开为独立任务配置，不能改为当前主模型默认值。迁移后该独立配置不再随原引用目标的地址或凭据变化。

### 手动获取与错误反馈

用户主动点击后才调用模型列表接口，使用当前项的有效字段及对应凭据。获取结果只辅助填写，不改变正式配置、默认选择或其他表单。修改提供方、地址或凭据后，旧结果应失效或标明过期；迟到响应不得覆盖新的表单状态。

成功时展示列表数量，并说明未验证推理或嵌入能力。失败时显示易理解的类别及可用的 HTTP 状态；没有上游 HTTP 响应时不编造状态码。至少区分输入/凭据不足、鉴权失败或访问被拒绝、限流、超时、无法连接、不支持或未提供发现接口、其他 HTTP 失败。

401/403 可以表达为“鉴权失败或访问被拒绝”，不能仅凭这一分类断言密钥错误。获取失败不能清空输入、禁止手动输入模型标识、阻止保存，或被包装成“成功获取零个模型”。上游错误正文与请求头不得直接透传为含凭据的文案。

### 当前项保存与旧配置迁移

“保存并启用”只保存当前配置项及其必要的默认选择，不能应用其他配置的本地编辑或旧草稿。启用表示进入正式配置并可被选择，不等于设为默认。成功后读回正式状态，确认对应项已经生效；失败保留输入，准确区分校验、写入及正式状态核实失败，不误报全部成功。

旧共享连接自动展开到各模型配置项，保留有效字段、模型标识、稳定引用标识、默认选择与知识库绑定。重复配置名称按稳定顺序生成唯一后缀，展示改名前后的对应关系；大小写不同本身不构成重复。旧任务引用按原目标转为独立配置。

迁移须先校验、保留可恢复的原状态并原子提交；失败不留下部分迁移结果。重复执行不能继续复制配置或追加后缀。不能无提示应用旧草稿；旧草稿需独立保留、转换并等待用户明确保存相应配置，或保留为可恢复旧版本。新增后台恢复机制不得把凭据写入仓库或日志。

3. 作为教师，我希望在同一表单填写完整信息，以便无需先建立共享连接。

5. 作为教师，我希望能修改预填地址，以便使用自定义兼容服务。

## Implementation Decisions

1. **边界**：本轮调整模型设置的交互、当前项保存、运行时独立凭据解析和历史配置迁移。知识库配置仍由正式知识库领域负责，不引入第二套模型或索引来源。
2. **独立配置单位**：每个可编辑模型配置项具有稳定内部标识、配置名称、用途、提供方信息、模型标识及完整有效调用参数。使用现有存储结构或版本化扩展均可，但必须从行为上保证不再因共享连接写入影响其他项，不允许用隐藏连接编辑伪装独立配置。
3. **名称契约**：去首尾空白、非空、跨三类配置全局唯一、大小写敏感。模型标识不参与唯一约束；编辑当前项排除自己。旧名称迁移先保留不冲突名称，再以稳定顺序分配不冲突后缀，包含用户原本已使用后缀的场景。
4. **当前项写契约**：在现有设置 API 分组中提供或复用足以表达当前项完整保存与默认选择的原子操作；不能直接以整服务或整草稿覆盖代替当前项合并。以服务端最新正式目录为基础合并，序列化唯一性校验与写入，避免并发同名或覆盖其他项。具体 URL、字段版本在实现阶段依据真实接口确定并同步机器契约。
5. **成功与失败**：响应能标识已保存项及正式选择，前端按正式状态核实成功；持久化失败不重置客户端、不清理其他编辑。写入已经完成但读回失败时说明正式状态待核实，不能谎称未保存或已完全成功。
6. **默认选择与任务模式**：首个有效配置自动默认，新增不切换已有默认；任务初始跟随。任务模式为显式设置，保存备用独立配置不自动退出跟随。切换跟随后保留独立配置，不能通过删除旧模式数据简化 UI。
7. **凭据与协议**：掩码恢复必须按当前配置稳定标识定位对应正式值或用户明确选中的当前项草稿，不能优先借用无关旧草稿、共享连接或同提供方其他配置的密钥。缺省、保留和显式清除语义需可区分；无鉴权提供方继续允许空凭据。已有协议、授权方式、请求头与版本等有效字段保留。
8. **发现契约**：使用当前项表单并显式发起只读发现；能区分成功空列表与上游失败。多条现有发现通路如继续存在，须对外提供一致的成功/失败语义。结果至少包含状态、模型列表及实际存在的上游 HTTP 状态，不回传真实凭据或未清理的上游错误正文。保存和默认选择不依赖发现结果。
9. **异步状态**：发现、保存和迁移分别有忙碌/失败状态，防止重复提交；发现响应应与当前表单版本或身份匹配。失败保留输入；重新读取、切换与离开时维持已有未保存提醒，不借机静默丢弃其他项编辑。
10. **迁移契约**：以版本标识或等效可判定方式识别迁移；先解析所有正式配置的有效值、校验引用，再生成独立配置及稳定映射。原有稳定 ID 尽量不变；必须变更时提供兼容映射，不按可修改名称或模型标识猜测引用。旧任务引用展开为原目标的独立配置，保持原有效参数；失效引用应报告并整体停止迁移，不能自动选择其他模型。
11. **迁移恢复与隔离**：先完整验证再原子提交，持有配置写入边界，避免与普通保存交错；迁移失败保留原正式目录、引用和默认选择。恢复材料只在受保护运行时设置区域保存，不进入版本库、普通日志或 API 响应。重复迁移无额外副作用。正式目录与旧草稿分开处理，旧草稿不因访问页面、重启或迁移而启用。
12. **嵌入身份**：纯结构迁移及名称去重不得改变有效嵌入地址、模型、维度、协议和已有知识库绑定意义；必要时同步迁移引用映射与兼容签名，不能仅改目录引用后让旧索引变为不可用。实际更换嵌入身份仍遵循知识库风险提示及既有重建流程，本页不自动重建或调用嵌入探测。
13. **生效与环境来源**：只有有效正式写入后更新必要运行时缓存；读取、发现或无变化保存不无故重置正在使用的客户端。继续遵循已保存模型目录优先、环境仅初始化的规则，不把配置写回环境文件。
14. **文档与实现同步**：实现时同步设计、目录说明、前后端类型和实际改动的 API 契约；不能只改前端隐藏入口而遗漏后端隔离及迁移。规格生成阶段未改变 HTTP 行为，实施阶段同步更新机器契约及生成文档。

## Testing Decisions

### 主测试边界与先例

主边界采用设置 HTTP API 加公共运行时配置解析，后接本地假服务，观察真实持久化、掩码恢复、模型发现及选模结果。优先复用已有测试设施，不围绕每个前端字段新增镜像测试，也不为本轮文档变更新增测试。

### DeepSeek 问题的验证边界

已有事实仅能说明错误分类与前端文案缺口。实施时应先使用假服务构造可重复的模型发现反馈回路，核对有效请求地址、鉴权字段、掩码恢复和多发现通路语义，再针对已证实问题修复。没有真实失败证据时不得宣称已修复用户账号的 401/403 根因。验收通过表示发现流程与错误表达符合契约，不表示真实账号具备推理权限。

## Out of Scope

- 新增模型提供方、新的模型协议或新的 OAuth/账号接入流程。
- 恢复多用户、账号权限管理或变更当前单租户边界。
- 新增搜索、语音、图像、视频服务配置及逐任务路由编辑。
- 自动获取模型列表、保存前强制发现、强制列表包含模型标识、自动推理或自动嵌入探测。
- 本轮页面中保留独立共享连接配置入口，或新增任务“引用指定主模型”入口。
- 自动重建知识库、改换知识库引擎或将全局默认变更强制同步给全部旧知识库。
- 将未确认旧草稿自动应用、批量启用其他未完成配置，或向环境文件回写模型设置。
- 在缺少复现证据时承诺解决真实 DeepSeek 账号鉴权，或在测试中访问真实账号。
- 本轮规格生成期间实施功能、迁移真实运行时数据、发布远端工单或提交代码。

## 目标与范围

教师和学生仅在应用设置“模型与服务”维护自己的 DeepSeek API Key 与 MinerU Token，保存后用于对应业务。个人中心只保留个人资料与账号安全，不展示模型编辑或模型状态摘要。界面明确区分个人配置、系统默认与实际连通性，避免未保存表单被误认为已经生效。

普通设置只提供个人凭据编辑，`ModelSettings` 挂载 `settings/PersonalModelSettings.tsx`。DeepSeek 模型与地址由部署配置管理，嵌入与重排展示平台当前活动模型，普通用户不可编辑。当前不提供多提供方模型目录、配置命名、逐项默认选择、任务模型跟随／独立模式、模型列表发现或逐知识库嵌入绑定；旧目录编辑器及其孤立 API／类型已清理，不属于当前页面。

平台管理员在左侧导航、右侧内容的后台“模型与检索”维护系统嵌入／重排的模型标识、服务 URL 与凭据，Chroma 类型、路径和状态只读。嵌入模型／URL 保存为 pending，显式重建才应用；仅更新活动嵌入凭据或重排配置用于后续请求。详细流程、API、权限和运维边界以[设置拆分与保存反馈设计](设置拆分与保存反馈设计.md)为准。

## 使用流程与交互

1. 进入设置“模型与服务”后读取当前账号设置。加载中禁用修改；读取失败提供重新读取。
2. DeepSeek 与 MinerU 各自展示个人配置状态及掩码，输入新凭据可替换。输入留空保留原值，清除必须显式勾选并保存。
3. 保存当前两项发生变化的字段；未改字段不提交。保存失败保留输入；成功后读回正式状态。
4. 写入成功但读回失败时明确提示“保存已完成”，清空可测试状态，允许重新读取。
5. 只在没有未保存修改且设置读取成功时测试已保存配置。测试包含服务端默认兜底，不接收未保存凭据，不自动获取模型列表。

输入有 label，凭据使用 password 控件，加载、错误与成功状态分别展示。保存和模型测试使用顶部居中 toast，成功绿色约 3 秒、错误红色约 6 秒，带图标、文字、关闭按钮及辅助技术播报，字段错误在表单附近保留。

## 配置与接口契约

实现依据为 `backend/app/api/users.py`、`backend/app/schemas/auth.py`、`backend/app/services/model_settings.py` 和 `frontend/src/components/settings/PersonalModelSettings.tsx`。完整字段与调用流程见[配置来源与知识库流程](模型配置来源与普通知识库流程.md)；管理员契约见 `backend/app/api/admin_rag.py` 与 `backend/app/schemas/rag_settings.py`，API 入口见[接口文档](../api.md)。

| 操作 | 当前接口与行为 |
| --- | --- |
| 读取 | `GET /api/users/me/model-settings`，返回模型标识／显示名、个人凭据状态／掩码、MinerU 限制及平台当前活动嵌入／重排模型；后两项 `*_configurable=false` 仅表示个人不可编辑 |
| 保存 | `PUT /api/users/me/model-settings`；两个可选字段为 `deepseek_api_key`、`mineru_token`，最长各 128 字符；省略或 `null` 不修改，空字符串清除，非空字符串去首尾空格后保存 |
| DeepSeek 测试 | `POST /api/users/me/model-settings/test-deepseek`；使用服务端有效 Key 发出小规模推理，不是发现模型列表 |
| MinerU 测试 | `POST /api/users/me/model-settings/test-mineru`；验证有效 Token，不承诺完成真实文档 OCR |
| 存储与归属 | SQL `UserModelSetting`，主键为当前 `user_id`；无选择他人账号的参数，写入前重新校验认证版本 |

读取中的 `deepseek_key_configured` 与 `mineru_token_configured` 只代表个人字段是否非空；`mineru_using_default` 不代表默认 Token 已验证。所有读取只返回掩码，不返回完整凭据；掩码不应重新作为输入保存。

| 调用 | 取值规则 |
| --- | --- |
| 出题、对话、批卷的 DeepSeek | 当前用户 Key 优先，`settings.deepseek_api_key` 兜底 |
| 上传／重解析的 MinerU | 操作者 Token 优先，既有 `local_secrets.MINERU_DEFAULT_TOKEN` 兜底 |
| 扫描件知识点简化 | 请求受理时按上传／重解析操作者取得个人 Key，未配置时使用服务端兜底；有效 Key 显式传入目录提取、并发概括与补写 |
| 向量与重排 | 平台活动配置优先；未覆盖时默认 `BAAI/bge-m3`（默认模型为 1024 维）、`BAAI/bge-reranker-v2-m3`，使用部署地址与既有凭据兜底；管理员可配置，个人只读 |

DeepSeek 模型和地址由服务端配置，当前默认标识为 `deepseek-flash`。个人凭据变更经接口持久化后，后续请求按对应账号解析；部署环境配置变更需要重启，不能承诺运行中任务立即切换凭据。

## 异常与权限边界

- 没有有效 DeepSeek Key 时返回 `DEEPSEEK_KEY_MISSING`；没有有效 MinerU Token 时返回 `MINERU_TOKEN_MISSING`。测试连接失败使用当前 `LLM_ERROR`，页面显示可理解的失败信息。
- 清除个人凭据后仍可能使用系统默认；不能将“清除”描述为禁止该服务或撤销系统凭据。
- 保存不会自动执行模型推理、OCR 或模型列表发现；点击 DeepSeek 测试会真实调用推理服务，开发验收应使用假服务。
- 共享题库只共享被授权资料，不共享个人设置；学生、只读成员可以基于获授权资料出题。平台管理员的教学权限与个人设置路由门禁是不同边界，不能因 `users/me` 路由存在就认定管理员拥有题库访问权。
- 应用设置已移除旧知识库连接、引擎和解析器分区及对应孤立调用；题库配置使用现有题库管理入口，不因此提供多引擎或外部知识库连接器能力。

# 数据一致性与故障恢复设计

## 目标与范围

维护现有试卷、作答、学习空间、题库／资料删除、参数化出题、对话和 OCR 的一致性规则。SQL 保存业务事实，Redis 提供可重建缓存与辅助租约；跨 SQL、Chroma 与文件系统的操作采用持久意图和幂等恢复。模型凭据只在内存执行上下文传递，不写任务表。

状态：相关能力已实现并完成本地分批验证，未据此声明部署验收或单次最终版本全量全绿。本文从[数据库与 ACID 审查修复记录](../implementation/数据库与ACID审查修复记录.md)提炼现行规则；原记录保存 2026-11-15、2026-11-16 的发现、修复及执行证据，不再并行维护规则。参数化取消的后续扩展以[快速出题取消与清空](../implementation/快速出题取消与清空.md)为专项契约，运行观测以[台账基础](运维后台运行台账基础.md)为准。

## 状态与历史数据

| 对象 | 状态或字段 | 含义 |
| --- | --- | --- |
| 试卷 | `status=draft/published` | 是否已发布，与能否作答分别判断 |
| 试卷 | `closed=false/true` | 整卷开放／关闭；时间窗和空间停止状态仍独立生效 |
| 试卷 | `deleted=true` | 业务删除，仅保留历史，不允许恢复开放或继续编辑 |
| 空间发布 | `stopped=false/true` | 仅停止或恢复该空间的作答，不覆盖整卷关闭状态 |
| 作答 | `answering/grading/submitted` | 待交卷／已领取批卷权／已提交；重启将中断批卷恢复为待交卷 |
| 出题任务 | `queued/running/canceling/done/failed/interrupted/canceled` | SQL 为权威；业务终态与执行退出分别判断，取消收尾前继续占用门禁 |
| 删除操作 | `pending/vectors_deleted/sql_deleted/completed` | 已登记／向量已删／SQL 已清／文件已清；阶段可幂等重试 |

创建作答时固定题目 ID 顺序与总分。卷内移除只标记 `removed`，不改旧快照的题号、分数或答案；批卷中的试卷暂不允许删题或删卷。交卷先在短事务领取唯一运行标识，事务外调用模型，再锁定试卷、重新检查账号状态、认证版本、作答状态、关闭和发布门禁，一次保存答案及成绩。失败只释放本轮处理权，原答案保留。

普通列表默认隐藏业务删除的试卷；`GET /api/papers?include_history=true` 可包含本人试卷的已交卷归档。已有组卷记录保留个人历史复盘入口，学习空间保留学生本人已有交卷的归档，以及教师的历史讲解与统计入口；归档不提供写操作。教师通过仅创建者可用的 `GET /api/papers/{id}?history=true` 获取包含已移除题目的历史快照。已关闭／删除试卷优先打开最近一次已交卷记录，未完成的重做不会遮住旧成绩。

## 任务、删除与缓存边界

原有 SQLite、Redis 和 Chroma 本来就有持久化部署能力。进程退出后，单靠后台函数和 Redis 临时键无法证明任务属于谁、哪一轮仍有效、结果是否已写入。`generation_tasks` 保存所有者、请求参数、run、状态、批次及脱敏结果；模型凭据仅在内存执行上下文中传递。任务受理在同一用户的 SQL 门禁内检查进行中任务，旧执行者只能修改自己的 run；Redis Lua 比较 token 后才续租或释放。

对话的槽位、模式、待续消息及图片、运行和取消标识一并存入 SQL；成功轮次的两条消息、生成批次与会话状态在同一事务提交。模型和审核开始前结束 SQL 读写事务，审核语料在短读事务中物化后释放连接，进度更新和取消不依赖仍被模型调用占用的连接。取消绑定请求读取到的具体 run，旧取消不能落到后继运行。

删除先预热向量存储，再在资料变更门禁内记录不可用状态、索引 generation 和文件清单。向量清理、SQL 清理和文件清理分别持久推进；重试使用记录中的 generation，不能误删重建后的集合。SQL 已清但文件占用时仍保留恢复记录；原 DELETE 重试与启动恢复继续完成。资料入库中拒绝删除；上传与重新解析在写门禁内重检题库状态与权限，不能在已固定清理清单后新增资料。未完成删除阻止索引重建，包含题库 SQL 已清、原件尚待清理的窗口。

OCR 的 `full.manifest.json` 绑定源 PDF 的 SHA-256、字节数、页范围、分片号及解析参数，并记录 Markdown 的字节数和哈希。正文与清单使用同目录临时文件、刷盘及原子替换，清单最后发布；两次替换之间退出、正文截断、来源或参数变化均视为缓存未命中。无完成清单的旧缓存会重新识别，不通过放宽校验继续复用。

## 已确认的业务规则与交互契约

- 整卷关闭、业务删除和单个空间停止是独立状态。整卷及卷内单题删除须先关闭，整卷删除还要求所有发布停止；已有作答不得替换题目，批卷中不得删题或删卷。
- 从空间移除发布前必须停止本空间作答；在同一试卷事务门禁内按 `paper_id + space_id` 检查本空间任意状态的作答。有作答拒绝物理移除，保留历史与统计；其他空间作答不阻止本空间无作答发布撤下。DELETE 与更新 `space_ids` 共用该规则。
- 催交在业务事务内刷新整卷关闭／删除、本空间停止状态及冷却时间；不可操作时不新增通知。成员转让重新授权，统一创建者权限，容量检查串行，避免多个创建者及最后名额超员。
- 对话删除 DSL 使用 `mode=record|paper`，默认只移除组卷记录；明确要求整卷删除才进入 `paper` 模式。预览说明实际影响，不自动关闭或停止发布。多卷按 ID 排序，在同一事务调用既有服务，任一失败整体回滚；改名确认执行时同样重检删除状态。
- 提交答案拒绝重复或快照之外的题目 ID。前端交卷前读取快照，创建作答后再次核对；变化时保留匹配答案并暂停交卷。作答标识使用独立 `paper_question_id` 契约。
- 已关闭／删除整卷或本空间已停止时，历史读取优先返回最近已交卷记录，未完成重做保留但不遮住旧成绩。历史 `questions[].no` 保留原题号并可不连续，讲解、导航、作答和统计沿用返回顺序；普通详情仍连续编号。
- 最近批次恢复复核当前资源归属，失效批次返回空恢复结果；私人题目列表沿用 `created_by`，过滤删除中、已删除或归属不一致的资源。重新解析中的历史生成题目沿用既有读取政策；试卷历史快照不受源资料删除影响。
- 任务受理、认领、结果提交复核原认证版本；认领初读、参数解析或提交异常进行一次有界故障收束。轮询复核题库、资料、批次和题目，不返回已删除的缓存副本；临时网络或服务错误继续查询原任务。
- 删除列表为原创建者保留未完成操作的最小信息及同一 DELETE 重试入口。整库删除须连同此前单资料删除残留文件一起清理，全部完成才返回 204；SQL 清理同时移除持久任务里的题目及审核副本。删除中的题目禁止编辑或删除。
- 确认弹窗等待异步结果，失败显示原因并保留重试；处理中禁用重复确认和关闭。删除失败刷新阶段，删除中的资源不提供普通编辑、上传和下载，前端共享状态包含 `deleting`，不显示为入库进度。
- 作答、空间试卷、题库和资料列表使用明确响应模型，保留 `grading`、空成绩、可分别为空的开始／结束时间、删除阶段及历史状态，前后端映射与 OpenAPI 同步。

## OCR 派生稿与辅助缓存

简化稿同样使用完成清单、正文哈希与源 OCR 哈希校验，并以临时文件及原子替换发布；失败不覆盖已有完整文件。辅助 Redis 写入失败不丢弃已生成的 HyDE 文本。完成清单是缓存可复用的依据，不能将文件存在等同于发布成功。

## 数据契约与升级边界

增量迁移 `j5e6f7a8b901` 接在 `i4d5e6f7a890` 后，增加试卷 `closed/deleted`、题目 `removed`、作答 `question_ids_json/grading_run_id`、对话运行字段及 `generation_tasks/deletion_operations` 两张表。不删除既有账号、题库、作答或成绩。旧试卷默认开放、未删除，旧作答按当前题目顺序回填快照；已经在旧版本中丢失的数据无法凭空恢复。

正文证据迁移 `j5e6f7a89012` 和出题运行迁移 `k6f7a8b90123` 是另一条既有历史；合并迁移 `m8f9a0b12345` 汇合两条分支，保留已有证据与运行数据。

部署来源及迁移结构核对后，按既有迁移入口执行 `alembic upgrade head`。旧 V2 同号迁移歧义必须按[台账迁移兼容说明](运维后台运行台账基础.md)单独处理，不能直接升级或 stamp。有持久任务、删除恢复记录、关闭／删除试卷、移除题目或批卷状态时拒绝有损降级。当前仍按单 worker 启动；启动将遗留模型任务标为中断、释放批卷权，并尝试恢复删除，不自动重新消费模型费用。

保留现有出题和进度轮询入口；新增 `POST /api/papers/{id}/close`、`/reopen`，试卷响应包含 `closed/deleted`，各发布仍返回独立 `stopped`。删除前置条件失败返回 409（`PAPER_NOT_CLOSED/PAPER_PUBLICATION_OPEN/GRADING_BUSY`）；历史读取参数见状态与历史数据一节。`openapi.json` 与 `docs/api.md` 同步生成，API 索引覆盖全部路径。

### 后续迁移与故障边界

- 运维迁移 `n9a0b1c23456` 接续汇合节点；参数化请求幂等和执行退出字段由 `o0b1c2d34567` 接续，具体升级与取消规则见[快速出题取消与清空](../implementation/快速出题取消与清空.md)。历史终态回填执行结束时间；存在新增字段业务数据时拒绝有损降级。
- 旧 Redis 任务不迁移为 SQL 任务，不根据缓存恢复模型调用；找不到 SQL 记录返回明确 404，提示检查最近批次，未完成任务由用户重新生成。
- 升级时已有对话标为 `interrupted`，提示重新发送文字和图片，不自动执行旧待续输入。存在新增模式、待续输入、运行、取消或进度状态时拒绝有损降级。
- 单 worker、单实例启动收束遗留模型任务与批卷处理权并尝试恢复删除，不自动重跑模型。参数化遗留 `queued/running/canceling` 收束为 `interrupted`；取消尚未退出继续占门禁，`done` 进度须结合执行退出事实。
- 数据库持续不可写时，单次故障收束也可能失败；当前没有通用持久重试调度器。SQL 与向量、文件不承诺分布式原子事务，必须暴露不可用中间阶段并允许幂等重试。
- 学生历史复盘仍依赖可访问空间；退出、被移出或空间解散后的独立历史列表，以及历次作答选择器尚无前端入口。此边界不构成本设计已交付能力。

## 验收标准

2026-11-17 智能体合并继续使用上述门禁：历史会话与闲聊不绕过最终提交；两段出题和所有审核补齐共享 run，取消不交付部分批次；审批业务与消息同一 SQL 事务提交。前端清空只删题并保留会话，通过请求版本防止旧结果回填。平台凭据迁移与生成取消迁移在 `p1c2d3e45678` 汇合，验证记录见[智能体合并验收](../implementation/智能体分支合并验收记录.md)。

1. 双会话竞争下试卷修改、作答、交卷、发布移除和催交遵守最新状态；唯一批卷权不被重复提交覆盖，慢模型不占写事务。
2. 创建时固定题目快照；删除、停止与未完成重做不破坏历史题号、答案、成绩、讲解及统计，跨空间隔离有效。
3. Redis 丢失、租约替换、认证变化、旧 run 取消及提交回执丢失均不越权、不释放新锁、不重复发布；任务结果可由 SQL 对账。
4. 删除在向量、SQL、文件任一阶段失败后均可恢复；SQL 已清仍有重试入口，上传、重解析和重建不能绕过删除门禁。
5. OCR 正文与清单之间退出、文件截断、来源或参数改变及派生稿写入失败均不命中不完整缓存；完整旧稿不被失败覆盖。
6. 合成历史库验证无损升级及有损降级拒绝，单 worker 重启不重跑付费模型；前端网络恢复沿用原任务。
7. 使用临时 SQL、FakeRedis 和假服务执行验证，记录每轮基线、失败和复验范围；静态审查、合成 API 浏览器验证、定向测试和全量快照分别报告。具体批次仅在[实施证据](../implementation/数据库与ACID审查修复记录.md)维护，不跨批相加，也不代替真实部署验收。

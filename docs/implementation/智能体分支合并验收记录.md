## 实现与审查边界

三个实施 agent 分别负责前端、聊天与审批、LLM 与审核，主 agent 负责迁移、契约、依赖及文档。审查由未参与编写、未继承实现上下文的规范与需求两个 agent 独立执行，以本记录和现有设计为规格来源。

必须维持的事务行为：

1. 模型前释放读事务，最终提交重新验证账号、资源与 run；取消后旧运行不得落库、释放新运行或回填当前前端状态。
2. 一次生成与所有补齐沿用同一个 run，题目、批次、消息和槽位在统一事务提交；失败不部分交付。
3. 按题型缺口补齐、跨轮去重，有限轮次不足如实说明；解题失败不破坏已有有效字段，取消不变成重试或补齐。
4. 审批保持一次性消费、会话和账号绑定、执行时资源校验以及试卷锁；SQL 业务与确认消息统一提交，Redis 消费后 SQL 失败重新预览。
5. 历史加载、清空、消息请求互斥；按会话和预览请求版本隔离乱序响应，服务端删除成功后更新前端，失败可重试。
6. 两条迁移链通过 `p1c2d3e45678` 汇合，升级保留历史记录；平台配置优先级为个人、平台、部署默认，主密钥首次发布不并发覆盖，保存后失效缓存。

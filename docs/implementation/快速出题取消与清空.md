# 快速出题取消与清空

## 目标与范围

解决 #11、#13：清空当前题目时取消参数化异步任务，阻止迟到结果发布，等待该执行及所属模型线程退出后再允许重新生成。复用 SQL 持久任务、运行台账和按 token 释放的 Redis 租约。同步出题沿用原接口。对话暂停通过现有取消端点的轮次参数和轮次查询完成确认。

## 生命周期与契约

任务从 queued/running 进入 canceling，执行收尾后进入 canceled；canceling 仍占用生成门禁。queued 可直接取消，后续派发不得调用模型。SQL 执行结束时间区分业务终态与执行退出；进度 done 只有两者均成立时为真。启动请求可带 request_id，同用户同标识同参数只受理一次，支持按标识找回任务。

新增 POST /api/generate/cancel/{task_id}、GET /api/generate/requests/{request_id}；启动返回 task_id，取消返回进度及本任务实际存活的 question_ids，进度增加 status、execution_finished。question_ids 独立于普通结果完整性校验，覆盖批次部分删除及资料重新解析时的清理。取消、查询仅限所有者，取消不依赖原文档仍可用或模型密钥。参数化任务身份固定为 task_id/run_id，旧执行不能操作后继任务。

## 核心流程与并发边界

前端在发起启动前保存按账号绑定的请求标识；清空先废止旧展示回调，再找回任务并取消，持续轮询直至执行退出，最后删除原预览及本任务已完成但尚未展示的题目。保留待删除标识供失败重试。清空完成前禁用再次生成。

取消状态条件更新与发布事务竞争同一任务行。取消先提交则发布条件不成立；发布先提交则保持已完成台账事实，清空取得实际题目后删除。批次、题目和完成台账仍在一个事务提交。模型阶段不持有写事务。

生成、审核、修补、重出与独立解题使用可选取消检查。已发出的请求可等待现有超时返回，但不得继续提交新工作；线程池必须回收所有已启动工作后才确认退出。取消异常不能被生成重试或审核降级吞掉。Redis 仍仅为辅助缓存，释放必须核对 token。

## 异常与兼容

启动响应丢失时按 request_id 恢复原任务；尚未受理则使用保存的同一请求参数和标识幂等补发，避免永久等待不存在的任务。取消和删除幂等重试，失败不宣告清空成功。切换资料只使展示失效，保留任务忙碌状态。刷新恢复账号范围内的待处理操作，账号切换不得使用新身份处理旧任务。既有题目及关联收藏删除语义保持；不扩大到删除试卷或成绩。

增量迁移新增请求标识和执行结束时间，历史终态回填结束时间；单 worker 启动把遗留 queued/running/canceling 执行收束为 interrupted，不重新调用模型。存在新字段业务数据时拒绝有损降级。

## 对话暂停与预览清空

点击暂停直接发送取消请求。发送按钮显示灰色加载圆圈。服务端确认指定轮次已经停止且执行器退出前，发送、重试和清空均保持禁用。
取消响应可以通过原请求标识找回。断连后可手动重试，刷新后继续确认同一轮。
暂停前已经提交的轮次会恢复回复和仍存活的题目，并在预览恢复后开放清空。
一键清空只删除确认时预览里的题目，保留对话和历史消息。参数化任务仍由独立的恢复清理入口处理。

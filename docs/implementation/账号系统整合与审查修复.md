## 登录页居中与滚动边界（2026-11-11，已实现）

### 目标与范围

登录页居中与外层禁止滚动已实现，最终 47 组布局检查通过；本轮验证与下文历史记录分别记载。保留历史浅蓝背景、左上品牌与玻璃卡片，已取消左侧介绍及其栅格占位；实现范围为登录页结构、样式与视觉视口适配，覆盖密码登录、邮箱验证码登录及找回密码，不改变认证逻辑。

### 已确认根因

本轮浏览器检查确认，修复前 `auth-stage` 高度为 792px、`scrollHeight` 为 812px；背景 `inset: -2%`、`scale(1.01)` 的外溢与外层 `overflow-y: auto` 共同产生约 20px 滚动。原有 `.login-layout` 的 `flex: 1 0 auto` 与 `.login-card` 的 `max-height: none` 还存在长表单撑高内容的风险；Turnstile 关闭后，其空容器仍受 `.auth-challenge { min-height: 65px; }` 影响。上述问题已纳入本轮修复。

### 结构与既有接口沿用

- 外层舞台固定于动态视口，以 `100dvh` 为基础并使用 `overflow: clip`；背景、纹理、光晕等装饰独立裁切，装饰扩张不再进入外层滚动范围。
- 左上品牌独立定位；内容层移除左侧介绍与双列占位，以整个视口为基准水平、垂直居中，不以品牌下方剩余区域或原右列为中心。
- 卡片含内边距和边框的目标宽度为常规 432px、大屏 468px、窄屏 400px，并受视口可用宽度约束；手机左右各至少 16px。卡片最大高度受动态视口及上下安全间距约束，布局允许收缩，超高时仅 `login-card__body` 内部纵向滚动。
- 已监听 `visualViewport` 的 `height`、`width`、`offsetTop`、`offsetLeft`，同步可见区域的大小与偏移，支持软键盘仅改变视觉视口及页面放大时的布局适配；手机输入框字号设为 16px，避免聚焦自动放大。
- 仅在登录页作用域取消 Turnstile 有效关闭后空容器的 65px 占位，同时覆盖邮箱验证码与找回密码中的同类容器；开启、加载或错误状态仍保留验证控件、提示与重试所需空间，不影响其他页面的共用组件。

沿用 `LoginPage` 的模式切换、`EmailCodeFields`、`Turnstile` 与现有认证 API 层。`GET /api/auth/config`、`POST /api/auth/login/account`、`POST /api/auth/login/email`、`POST /api/auth/email-code`、`POST /api/auth/password/reset` 的请求、响应及发码用途保持现有契约；配置加载、校验、限流、错误处理、会话恢复／撤销、登录后角色跳转与开发账号填充条件均沿用。无新增 API 或数据契约，不恢复公开注册或历史注册身份选择。

### 异常边界

低高度窗口、横屏、浏览器缩放、软键盘仅改变视觉视口及其偏移，以及找回密码、长错误提示或开发填充区引起的内容增高，均不得撑开舞台；字段、验证控件、提交、返回及重试入口须可通过卡片内部 `login-card__body` 滚动和键盘焦点到达。装饰不得遮挡交互，品牌不得覆盖表单。认证配置不可用、Turnstile 开启／失败、验证码过期／限流和网络失败仍按现有逻辑处理，不因布局调整获得认证旁路。

## 2026-11-09 核心流程与契约（历史实施快照）

历史边界：下表保留 2026-11-09 原契约，其中绑定提交要求 current_password 已于 2026-11-12 移除。现行绑定仅提交 email、challenge_id、code 并携带有效 Bearer，额外 current_password 返回 422；解绑仍要求当前密码。现行完整契约见[用户系统实施规格](../design/用户系统实施规格.md)。

管理员开户 → 用户默认 account 密码登录 → 按需进入自身安全设置配置邮箱 → 已验证邮箱可用于“邮箱登录”及密码恢复。已有历史未验证邮箱的用户仍可密码登录，绑定时验证目标邮箱，不自动信任旧值。

| 邮箱流程 | 契约与提交条件 | 成功结果与异常边界 |
| --- | --- | --- |
| 绑定发码 | POST /api/auth/email-code：Bearer、email、purpose=email_bind；turnstile_token 可缺省或为空，有效启用时仍需有效票据 | 仅无已验证邮箱可用；challenge 绑定 user_id、auth_version、原邮箱快照与目标邮箱；同步 SMTP 失败 503 |
| 绑定提交（历史，2026-11-12 已替代） | PUT /api/users/me/email-binding：Bearer；email、current_password、challenge_id、code | 验证当前密码、用途/主体/版本/快照及目标邮箱唯一性，写入已验证邮箱，204 |
| 换绑 | POST /api/users/me/email-change；分别发送 email_change_old/email_change_new 码；PUT /api/users/me/email 提交 change_id 和旧、新 challenge_id/code | 沿用已验证旧邮箱与新邮箱双 proof，绑定事务、用户、邮箱快照、版本；不能用 email_bind 代替，204 |
| 解绑 | DELETE /api/users/me/email：Bearer；JSON {current_password} | 校验当前密码及版本，清空 email、email_normalized、email_verified_at；响应用户状态 email_verified=false，204 |

三类邮箱变更在同一 SQL 事务内消费适用 proof、更新邮箱及认证版本、撤销全部设备会话；清目标用户 Cookie，前端回默认“密码登录”，不自动签发新会话。解绑后仍可用原 account 密码登录。错密码、邮箱占用、错码/过期/重放、跨用户/用途或版本/原邮箱快照变化时不改变邮箱及资源归属；提交时再次校验版本和唯一性，不把 Redis/SQL 独立提交误称为跨存储原子事务。

登录、发会话和刷新复核原验证版本；管理员写操作在数据库锁内重新校验操作人并保护最后一个启用管理员，恢复不复活旧会话。平台任务统计为已持久化 GenerationBatch，最近 50 项仅为列表，没有真实完成时间返回 null。

## 发码安全与部署兼容

公开 login/reset_password 发码在有效启用时经 Turnstile、始终经限流后统一 202、响应后投递；不适用收件人不投递，SMTP 失败不激活 challenge，响应不泄露邮箱存在性。邮件成功且挑战仍为最新才激活；后台任务非持久队列，202 不代表已送达。email_bind 及换绑发码要求有效 Bearer，同步失败返回 EMAIL_SERVICE_UNAVAILABLE/503，失败不清限额。

安全复核补充（已修复，127 项认证相关回归通过）：公开 login/reset_password 挑战必须绑定用途、规范化邮箱、用户 ID、认证版本。发码、邮箱登录验码、密码重置验码三处使用同一绑定规则，不再仅依赖 purpose/email/version。邮箱解绑后转给另一用户，即使双方认证版本相同，旧挑战也不能登录或重置新账号。部署后旧未消费 login/reset 挑战因绑定变化失效，用户需重新发码；无数据库迁移。

验证码默认 6 位、300 秒、最多 5 次错误；60 秒冷却、每邮箱用途每小时 5 次、来源 IP 每小时 30 次，按配置调整。Redis 控制最新挑战和尝试，SQL AuthProof 唯一消费与版本校验防重放。刷新旧摘要保留到到期，proof 仅在 Redis 挑战消失后清理，错误和日志不含秘密。

## 会话、资料与资源边界

普通退出按本标签签名 Bearer 的 sid 撤销，仅注销允许 access 过期，仅清同 sid Cookie；无效 Bearer 不清共享 Cookie。改密、恢复、邮箱绑定/换绑/解绑清目标用户 Cookie，并与登录、刷新、退出共用 Web Lock，避免延迟响应覆盖另一账号 Cookie。需要续期先在锁外完成，锁内不重放安全写操作。失效通知按用户或会话定向；身份约束、会话代次与下载检查防旧响应回填。退出网络失败保留原页面内存撤销凭据和重载恢复阻断意图，不宣称服务端撤销成功。

普通资料接口不改邮箱、学工号、身份或密码。gender/phone 省略保留、null 清空；显示名空白拒绝、null 保留，school 空串清除、null 保留，保存等待服务端确认。学工号以当前密码维护，保留前导零、大小写敏感，仅为资料。头像仍限量读取，前端显示昵称首字。

个人模型配置已统一到设置页“模型与服务”的 PersonalModelSettings，个人中心仅保留资料与安全；用户 Key/Token 省略/null 保留、空串清除，界面显式清除，仅测试已保存配置及其系统兜底，未保存输入时禁用测试。状态与掩码不证明默认配置可用。系统嵌入与重排配置由管理员维护，保存与索引生效流程见[设置拆分设计](../design/设置拆分与保存反馈设计.md)。

- 上传复用认证操作边界：确保会话、记录代次、只在认证阶段明确拒绝执行的 `ACCESS_TOKEN_EXPIRED` 401 刷新并重试一次；若并发已有新 token 直接复用。其他 401、角色／用户变化、退出与旧成功响应均不得跨会话重放或回填。进度回调保持。

# 运维后台三人实施分工方案

状态：**Phoenix、甲的台账与实际入口、乙的 V2 查询已实现并在本地整合；前端 V2 已适配并完成隔离联调，部署待验收。** 本文只规定工作边界，不定义复杂联调契约。查询字段与剩余交接见[查询 V2 实现与交接](../design/运维查询V2接口与查询设计.md)，本地整合验收见[整合记录](运维后台本地整合验收.md)。

## 甲：出题入口与运行记录

- 梳理对话出题和参数化出题的实际生命周期；
- 接入并维护最小 `ops_runs` 记录；
- 通过 `current_run_id()` 复用当前追踪运行 ID；未启用扩展时台账独立生成 ID；
- 关联账号、会话／任务、题库／文档和生成批次；
- 维护 `accepted`、`running`、`completed`、`failed`、`canceled`、`unknown` 的事实来源；
- 继续使用当前普通 OpenAI 客户端，不引入 Agent SDK；
- 不建设告警、质量覆盖、依赖探测、复杂清理或正文追踪。

第一批已完成模型注册、增量迁移、统一写入及数据库／状态／事务测试；第二批接通实际生成入口、批次事务与后台 run_id，并补齐确认取消及本进程关闭未知收尾，见 [运行台账基础](../design/运维后台运行台账基础.md)与[入口接入](../design/运维后台出题入口接入.md)。乙查询已在本地与正式台账整合，前端由原分工继续实施。

## 乙：后台查询后端

- 基于运行记录提供平台概览、运行列表和基本详情；
- 实现管理员权限、筛选、分页和安全错误返回；
- 只返回现有 SQL／运行记录能够证明的字段；
- 删除依赖状态、异常中心、告警和质量扩展的后端范围；
- 在接口实现后同步 OpenAPI 和 `docs/api.md`。

三个只读路由及查询服务已实现，使用甲注册的正式 ORM；部署须先执行已有迁移。不能把未部署或读取失败显示为空台账，详细契约见[查询 V2](../design/运维查询V2接口与查询设计.md)。

## 本人：前端、文档与整合

- 保留平台概览和出题运行页面；
- 删除依赖状态、异常中心、告警通知、质量覆盖和无真实数据来源的演示类型；
- 对接真实查询接口，处理空值、未知、失败和无权限状态；
- 同步 README、模块说明、运行手册、术语和替身说明；
- 对两条真实出题入口、管理员权限及页面边界进行联调审查。

## Phoenix 独立可选扩展

Phoenix 不归入后台主链路，也不作为三人后台实现的前置条件。独立扩展负责：

- 使用普通 OpenAI 客户端调用点手工生成 OTLP 元数据；
- 默认关闭，支持独立 Docker 部署；
- 不发送任何业务正文；
- 导出失败隔离，不阻断出题；
- 提供独立的配置、权限、保留和故障说明。

Phoenix 扩展完成与否不改变后台概览和运行查询的可用性。

实施顺序：Phoenix、甲的台账与实际入口、乙查询已完成本地代码整合；前端收缩、V2 对接与隔离页面／权限联调已完成，结果见[前端 V2 与页面联调](运维后台前端V2适配与联调.md)；下一步为发布审查和部署验收。配置与结果语义见 [Phoenix 可选扩展](../design/Phoenix可选扩展.md)。

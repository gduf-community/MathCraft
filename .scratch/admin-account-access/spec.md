# 管理员与账号开通实施规格

规范来源：../../docs/design/管理员与账号开通设计.md
状态：implemented；集成测试受本机 Redis 服务未启动影响
跟踪方式：本地 Markdown
目标分支：main；实施使用 codex/ 前缀临时分支

## Problem Statement

当前平台只有教师和学生账号，登录页要求选择身份，平台没有统一的账号开通入口、管理员身份和运维面板。使用者不能自行注册，也没有一个明确的渠道获取账号。教师、学生、知识库、题库及个人记录之间的授权边界需要统一，平台管理员不能因为运维身份获得用户私有业务内容。

部署初始化还需要一个明确的手动入口：本地开发和正式部署都必须由部署者显式执行一次命令，从 .env 创建首个管理员、一个教师和一个学生；日常启动服务不能自动建号，重复执行只能补建缺失账号。

## Solution

增加平台管理员角色和管理员面板。管理员通过登录账号和密码进入独立运维界面，创建、查询和维护教师、学生及其他管理员账号，并查看约定的平台汇总信息。平台不提供公开注册；登录页只保留登录账号和密码输入，并显示获取账号或忘记密码联系管理员的提示。

提供显式的账号初始化命令。本地和正式部署使用同一入口，命令读取 .env 中配置的三个初始账号和密码，只创建缺失账号；角色匹配的已有账号即使密码不同或已禁用也保持原状，配置账号与已有账号角色冲突时命令报错。日常启动不执行该命令。

统一教师、学生和资源权限：知识库／题库由创建者按登录账号添加成员并授予创建者、可编辑成员或只读成员权限；生成题目、收藏、聊天记录和组卷记录仍按账号归属。学生不能新建知识库或题库，但历史学生创建的资源保留原归属和资料，学生继续访问已有历史资源。

学习空间沿用当前流程。教师创建空间并发布试卷，学生凭空间编号加入、查看并作答；本规格不改动没有明确提出变更的学习空间代码。

## User Stories

1. 作为部署者，我希望在 .env 中配置首个管理员、教师和学生账号，以便部署后可以直接进入平台。
2. 作为本地开发者，我希望使用与正式部署相同的初始化命令，以便本地环境和正式环境行为一致。
3. 作为部署者，我希望初始化命令必须手动执行，以便日常启动不会悄悄创建或修改账号。
4. 作为部署者，我希望重复执行初始化命令只补建缺失账号，以便初始化具备幂等性。
5. 作为部署者，我希望已有账号的密码、资料、角色和启用状态不被初始化覆盖，以便维护过的账号不会被 .env 重置。
6. 作为部署者，我希望初始化发现配置账号重复或角色冲突时明确报错，以便避免错误绑定账号。
7. 作为使用者，我希望不需要选择教师或学生身份就能登录，以便系统依据账号角色进入正确的工作台。
8. 作为管理员，我希望登录后进入独立管理面板，以便执行平台运维工作。
9. 作为管理员，我希望创建教师、学生和其他管理员账号，以便通过人工开通方式管理平台用户。
10. 作为管理员，我希望按账号、显示名称、角色和启用状态查找账号，以便快速定位需要维护的账号。
11. 作为管理员，我希望编辑显示名称、重置密码、禁用和恢复账号，以便维护账号生命周期。
12. 作为管理员，我希望不能禁用最后一个可用管理员，以便平台始终保留运维入口。
13. 作为管理员，我希望看到账户基础资料、启用状态和平台资源汇总，以便了解平台运行概况。
14. 作为管理员，我希望看到任务类型、状态、创建时间、完成时间和状态数量，以便判断后台任务运行情况。
15. 作为管理员，我希望看不到题库正文、出题对话、作答内容、用户输入、生成内容、原始错误堆栈或个人模型密钥，以便运维查看不会越过用户隐私边界。
16. 作为教师，我希望我的题目、收藏、聊天记录和组卷记录归属于我的账号，以便其他教师不能仅凭教师身份查看这些记录。
17. 作为资源创建者，我希望按登录账号添加或移除知识库／题库成员并分配权限，以便资源访问由创建者控制。
18. 作为可编辑成员，我希望能使用共享资料并维护库内资料，以便协作处理资源。
19. 作为只读成员，我希望能查看、下载、检索和基于资料出题，但不能修改共享资料，以便获得受限协作能力。
20. 作为学生，我希望不能新建知识库或题库，以便学生能力不超出已确认范围。
21. 作为历史学生资源的创建者，我希望已有库、资料和索引继续保留并可访问，以便权限收敛不会破坏历史数据。
22. 作为既有用户，我希望保留原用户 ID、账号、角色、密码状态和所有业务归属，以便账号系统升级不会改变历史记录。
23. 作为教师，我希望学习空间的创建、编号加入、试卷发布和作答流程继续可用，以便账号系统变更不影响既有教学流程。
24. 作为管理员，我希望多台设备可以同时登录同一账号，以便运维协作不会互相踢下线。
25. 作为账号持有人，我希望修改密码、管理员重置密码或账号禁用后全部旧会话失效，以便账号状态变更立即生效。
26. 作为账号持有人，我希望普通退出只影响当前设备，以便其他设备的登录不被误撤销。

## Implementation Decisions

- 平台角色增加管理员；管理员是独立运维身份，不兼任教师或学生。需要教学功能的同一人员使用独立教师或学生账号。
- 三类账号统一使用全平台唯一的登录账号和密码认证。登录账号长度为 1–64 个字符，去除首尾空格，不允许空白字符，允许中文、英文、数字、下划线、短横线和点号；登录按原文匹配，不自动改变大小写。显示名称可编辑且可重复，登录账号和角色创建后固定。
- 账号创建的必填信息为登录账号、显示名称、角色和初始密码；邮箱、手机号、学校和学工号不作为初版开通必填项。密码不回显，管理员通过沟通渠道交付初始或重置密码，账号登录后可自行修改。
- 初始账号配置只由显式初始化命令读取。配置缺失、三个配置账号重复或已有账号角色冲突时命令失败并给出可操作错误；角色匹配的已有账号直接跳过，不覆盖资料、密码或启用状态。
- 初始化命令不由应用启动钩子触发，不承担密码重置、账号恢复、数据库迁移之外的运维操作。
- 管理员可以创建、查询、编辑显示名称、重置密码、禁用和恢复账号；初版不提供永久删除和角色变更。禁用保留业务数据并撤销全部会话，恢复后必须重新登录；不能禁用最后一个可用管理员。
- 多设备会话沿用独立会话语义：新登录不挤下线，普通退出只撤销当前会话，改密、重置密码和禁用撤销该账号全部会话。
- 登录页不显示角色选择，只提交账号和密码。统一显示“获取账号或忘记密码，请联系管理员”；可从 .env 提供联系方式文字，未配置时只显示提示。
- 管理员面板只展示账号基础资料、启用状态、教师／学生数量、知识库／题库数、文档数、试卷数，以及任务类型、状态、创建时间、完成时间和状态数量。不展示用户私有内容、原始错误堆栈或个人模型密钥。
- 资源权限统一为创建者、可编辑成员、只读成员三档。创建者独占成员管理、库设置和整库管理；可编辑成员可查看、下载、检索、出题、上传和删除共享资料；只读成员可查看、下载、检索和出题但不能修改共享资料。共享资料生成的题目归操作者账号。
- 资源成员由创建者按登录账号添加、调整和移除；取消知识库／题库凭编号加入以及被移除后自行恢复成员资格。该规则不改变学习空间凭编号加入机制。
- 既有知识库／题库迁移保留创建者，将其他成员统一转为只读。历史学生创建的库、资料和索引不删除、不转移，学生继续作为历史资源创建者访问，但不能创建新库；初版不提供自动转交教师功能。
- 既有教师和学生用户保留原用户 ID、登录账号、密码状态、角色及所有资源和业务数据归属；新增管理员角色和账号状态通过数据库迁移补齐，不自动合并、改名或转移数据。
- 学习空间按当前行为保留：教师创建和管理空间，学生凭编号加入和退出，教师发布试卷，学生查看并作答。本规格不改动未明确提出变更的学习空间代码。
- 目标分支为 main，实施使用 codex/ 前缀临时分支。旧用户系统规格和 Issue 中与本规格冲突的公开注册、角色选择和权限要求标记为被取代。

## Testing Decisions

- 以外部行为为测试边界，不测试具体组件实现或重复实现细节。
- 后端认证测试覆盖三类账号统一登录、禁用账号拒绝访问、管理员独立入口、多设备会话、普通退出、改密／重置／禁用的全会话撤销。
- 初始化命令测试覆盖配置完整性、重复账号拒绝、角色冲突报错、首次创建、重复执行幂等、保留已有密码和状态，以及启动服务不自动建号。
- 管理员 API 测试覆盖账号搜索筛选、创建三类账号、显示名称编辑、密码重置、禁用／恢复、最后一个管理员保护和平台统计字段边界。
- 资源授权测试覆盖创建者、可编辑成员、只读成员的资源操作，非成员拒绝访问，个人记录归属不因资源成员关系改变，学生不能新建知识库／题库，历史学生资源保留访问。
- 学习空间相关测试只验证本规格未破坏既有教师创建、学生编号加入和试卷发布／作答行为，不为学习空间新增规则。
- 前端检查使用现有 React/TypeScript 规范，运行类型检查、Lint，并在涉及路由和构建时运行生产构建。
- 接口变更后重新生成 openapi.json 和 docs/api.md；文档检查确认 README 目录、启动方式、环境变量和设计文档与实现一致。
- 测试使用现有假账号、临时 SQLite 和隔离 Redis，不读取真实 .env 或真实模型凭据。

## Out of Scope

- 公开注册、邮箱验证、邮箱验证码登录、自助密码找回和在线申请账号。
- 管理员角色分级、超级管理员、管理员专用恢复流程、管理员查看用户私有业务内容。
- 永久删除账号、账号角色变更、查看或导出已有密码。
- 每位教师建立独立磁盘目录、组织／租户体系、新的通用权限配置平台。
- 学生新建知识库／题库，以及本规格没有明确确认的学生出题、聊天、组卷能力扩展。
- 学习空间加入机制、空间成员模型、空间发布流程和空间页面的未提出改动。
- 自动把历史学生资源转交教师，自动删除或隐藏历史资源。
- 新的监控系统、告警系统或复杂后台任务编排系统。

## Further Notes

- 本地开发和正式部署共享同一初始化命令；运行服务前由操作者显式执行，日常启动不建号。
- 管理员无法登录时由服务器运维人工处理，初始化命令不能替代恢复流程。
- 需求设计记录位于 docs/design/管理员与账号开通设计.md；术语补充位于 GLOSSARY.md。
- 完成实现后需要同步 README、.env.example、OpenAPI、API 文档、设计文档和必要的迁移说明，并按仓库约定使用中文约定式提交。
